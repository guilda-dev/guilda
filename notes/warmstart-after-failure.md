# 潮流計算の WarmStart とノーズ点付近の解（fix/warmstart-after-failure）

講義 Part7 の作業で見つかった「潮流計算が失敗したあと、既定の `WarmStart` で再計算すると発散する」件の調査と案です。
下の質問には 2026-11-18 に回答があり、案 C を実装しました（5 節）。

## 1. コードの確認（事実）

- 保持する値: `SolverPF` の private プロパティ `cv_Vwarm`（最後の収束解）と `sv_warmBus`（その母線タグ）。
- 更新: `SolverPF/solve.m` で `flag == 1`（収束）のときだけ更新します。失敗（flag 0 / -1 / -2）では更新も破棄もしません。
- 使用: `initial_voltage` で、`V0` / `Varg0` 列がなく、`WarmStart=true` で母線タグが同じ（順序も同じ）なら `cv_Vwarm` を初期値にします。
  負荷の大きさなど、条件の変化は見ていません。
- 破棄: `net.reset_solver()` だけです。
- `initialize(Method="powerflow")` は `calculate_powerflow` に `WarmStart` を渡すので、同じ保持解を使います。
- 連続潮流計算（CPF）は `solver_PF` を使わず、保持解を変えません。

つまり「失敗した計算の値が warm start に使われる」のではありません。使われるのは、失敗の直前に収束した、ノーズ点近くの解です。

## 2. 再現（R2026a、IEEE9bus、母線 5・6・8 の負荷の P と Q を k 倍）

| 手順 | 結果 |
|---|---|
| 1.0 → 2.0 → 2.37 → 2.38 → 2.37 → 2.0 → 1.0（少しずつ戻す） | 2.38 だけ flag 0（50 回）。ほかは収束 |
| 新しい系統で 1.0 → 2.38（失敗）→ 1.0 | 1.0 は収束（保持解は 1.0 の解のまま） |
| 2.37（収束）→ 2.38（失敗）→ 1.0 で `initialize` | **発散**（不平衡 1.8e26）。ネットワークは変更なし |
| 同じあと 1.0 で `calculate_powerflow` | **flag -2**（17 回） |
| 2.37（収束）→ 失敗を挟まずに 1.0 | **flag -2**（17 回）。失敗は条件ではない |
| 2.37 → 1.5 | flag -2 |
| 2.37 → 2.0 / 2.2 / 2.3 / 2.36 | 収束（7 / 6 / 6 / 4 回） |
| 2.37 → 1.0、`WarmStart=false` | 収束（4 回） |

2.37 の解から 1.0 を解いたときの Solver ごとの結果:

| Solver | WarmStart=true | WarmStart=false |
|---|---|---|
| newton（既定） | flag -2（17 回） | 収束（4 回） |
| levenberg-marquardt | 収束（6 回） | 収束（4 回） |
| fsolve | 収束（9 回） | 収束（5 回） |
| dynamic | 収束（263） | 収束（277） |

結論: 原因は「失敗」ではなく、「ノーズ点近くの収束解から、条件が大きく違う問題をニュートン法で解くこと」です。
ノーズ点近くではヤコビ行列が特異に近く、そこから大きく離れた解へのニュートンの一歩が当てになりません。
講義の手順では 2.38 の前に 2.37 を解いていたため、失敗のあとに起きたように見えました。

不具合かどうか: 仕様（「前回の収束解から始める」）どおりの動作ですが、既定の設定で、解のある問題が解けなくなります。
利用者からは原因が見えない（前回どこを解いたかに結果が依存する）ので、直すべき不具合と考えます。

## 3. 案

### 案 A: 失敗したら保持解を捨てる（または更新しない）

- 前提: 失敗の直前の収束解が悪い初期値になる、という見立て。
- 利点: 実装が数行。講義の手順（2.37 → 2.38 失敗 → 1.0）は直る。
- 欠点: 失敗を挟まない場合（2.37 → 1.0）は直らない。「更新しない」は現状と同じで効果なし。
- 失敗し得る条件: ノーズ点近くを解いたあと、大きく条件を変えた場合すべて。

### 案 B: 条件が大きく変わったらフラットスタートにする

- 前提: 条件の変化を測る指標がある。例: 保持解とフラットスタートで初期不平衡（最大 P/Q 不平衡）を比べ、小さいほうから始める。
  または、保持解を作った P/Q を覚えておき、差がしきい値を超えたらフラットにする。
- 利点: 失敗の前に避けられ、計算は 1 回で済む。
- 欠点: 初期不平衡が小さい点が、収束しやすい点とは限らない（ノーズ点近くでは特にそう）。しきい値は系統ごとに意味が変わる。
  「前回の解から始める」という説明が複雑になる。
- 失敗し得る条件: 不平衡は小さいがノーズ点近くにある初期値、しきい値の境目の条件。

### 案 C: warm start で失敗したら、フラットスタートで 1 回だけ計算し直す（推奨）

- 前提: フラットスタートは通常の系統でよく収束する（講義 Part2 の説明どおり）。保持解を使ったときだけ再試行する。
- 利点: 今回の全手順が直る（失敗の有無によらない）。収束した場合の結果・反復回数は今と同じ。説明が簡単
  （「前回の解から始め、解けなければフラットスタートからもう一度解く」）。Solver によらない。
- 欠点: 本当に解のない問題（2.38 など）では計算が 2 回になる（newton で 50 回 → 100 回。dynamic では時間がかかる）。
  `output` と反復履歴をどちらの計算のものにするかを決める必要がある。
- 失敗し得る条件: フラットスタートでも解けない問題（その場合は今と同じく失敗を返す）。
  PlotFcn で止めた場合（flag -1）は再試行してはいけない。

### 案 D: 今のままにして、ヘルプに書く

- 利点: 変更なし。
- 欠点: 既定の設定で解ける問題が解けない状態が残る。講義やチュートリアルで毎回 `WarmStart=false` を書く必要がある。
- 失敗し得る条件: ヘルプを読まない利用者すべて。

### 推奨: 案 C

案 A・B は、今回の再現のうち「失敗を挟まない場合」や「初期不平衡が小さいノーズ点近くの値」を確実には避けられません。
案 C は、収束する計算には影響せず、失敗したときだけフラットスタートを追加で試すので、既存の決定（PF の WarmStart 既定 ON、バスタグでの照合、V0/Varg0 は solve の入力列のみ）を変えずに済みます。

案 C の実装の見込み（決定後）:
- `SolverPF/solve.m` で、保持解を初期値に使って flag 0 / -2 のとき、フラットスタートで `run_method` を 1 回呼び直す。
  `V0` / `Varg0` 列を与えた場合と `WarmStart=false` の場合は再試行しない。
- テスト: `test_F2_powerflow.m` に追記（IEEE9bus 2.37 → 1.0 が既定で収束、2.38 は 2 回とも失敗して flag を返す、PlotFcn 停止では再試行しない）。
- ヘルプ: `SolverPF.m` と `calculate_powerflow.m` の `WarmStart` の説明に一文追加。

## 4. 決めてほしい点

1. 案 C（warm start で失敗したらフラットスタートで 1 回だけ再計算）を採用してよいですか。
2. 再試行は全 Solver で行いますか（推奨: はい。flag -1（PlotFcn で停止）は除く）。それとも既定の newton だけにしますか。
3. 再試行したときの戻り値: `output`、反復履歴（`cm_Vhistory`）、`iterations` は再試行の計算のものにし、
   `output.message` に「保持解からは収束せず、フラットスタートで再計算した」旨を足す、でよいですか。
   1 回目の反復回数を別のフィールド（例: `output.iterationsWarmStart`）に残しますか（推奨: 残さない。新しいメンバーを増やさない）。
4. 再試行でも失敗したとき、保持解は今どおり残しますか（推奨: 残す）。それとも案 A も併せて捨てますか。
5. 再試行したことを警告や表示で知らせますか（推奨: 知らせない。`Verbose=true` のときだけ 1 行表示）。
6. `calculate_fixed_input_powerflow` の WarmStart（保持した平衡点から開始）にも同じ問題が起こり得ます。今回の範囲に含めますか（推奨: 含めず、別件として記録）。

## 5. 決定（2026-11-18）と実装

決定:
1. 案 C を採用。保持解から始めた計算が flag 0 または -2 で終わったら、フラットスタートで 1 回だけ計算し直す。
2. 全 Solver に適用。flag -1（PlotFcn で停止）は再試行しない。
3. 再試行したときの `output`、`cm_Vhistory`、`iterations` は再試行の計算のもの。`output.message` の末尾に、保持解からは収束せずフラットスタートで計算し直した旨の 1 文を足す。新しいフィールドは作らない。
4. 再試行でも失敗したときは、保持解を今どおり残す（保持解は収束したときだけ変わる）。
5. 警告は出さない。`Verbose=true` のときだけ 1 行表示する。
6. `calculate_fixed_input_powerflow` も含める。保持した平衡点から始めた計算が失敗したら、`WarmStart=false` と同じ初期値（書き込まない潮流計算と `get_equilibrium`）で 1 回だけ計算し直す。規則は 2〜5 と同じ。

実装:
- `SolverPF/solve.m`: `initial_voltage` が、保持解を使ったかどうかを 2 番目の出力で返す。保持解を使って flag 0 / -2 なら、フラットスタートで `run_method` をもう一度呼ぶ。
  `V0` / `Varg0` 列を与えた場合と `WarmStart=false` の場合は再試行しない。
- `calculate_fixed_input_powerflow.m`: `initial_point` が、保持した平衡点を使ったかどうかを 2 番目の出力で返す。使って flag 0 / -2 なら、`initial_point(..., false)` を `InitVal` にして、同じ Method オブジェクトでもう一度解く。
- ヘルプ: `SolverPF`（WarmStart の項）、`SolverPF.solve`、`calculate_powerflow` と `calculate_fixed_input_powerflow`（WarmStart の項）。
- arguments ブロックと公開メンバーは変えていない。
- 再現（2 節）の結果: 2.37 → 1.0 と 2.37 → 1.5 は、既定の設定で 4 回の反復で収束する。2.38 は再試行のあとも失敗し、flag -2 を返す。
- テスト: `test_F2_powerflow/WarmStartThatFailsIsSolvedOnceMoreFromTheFlatStart` と `test_F3_initialize/FixedInputFromAHeldEquilibriumThatFailsIsSolvedOnceMoreFromAPowerFlow` を追加し、どちらも medium に登録した（1 件 6.4 s と 3.1 s）。
  R2026a で、small（powerflow、cpf）は 45 件 PASS 45、medium は 921 件 PASS 920 / KNOWN 0 / FAIL 0 / SKIP 1（2369 s）。large は実行していない。
