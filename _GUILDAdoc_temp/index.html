About GUILDA

GUILDA (Grid & Utility Infrastructure Linkage Dynamics Analyzer) is a numerical simulator for smart energy management, developed primarily by our laboratory in collaboration with Assistant Professor Takahiro Kawaguchi (Gunma University).

Its goal is to provide an advanced simulation environment that students and researchers in systems and control can use with only minimal background knowledge of power systems.

Supported Analyses

  • RMS Analysis: Phasor models, three-phase balanced systems.
  • Time-Domain Simulation: Initial value perturbations, load variations, input adjustments, ground faults, and controller design.
  • Linearization: Derivation of approximate linear models, Hessian calculations of energy functions.
  • Optimal Power Flow (OPF): General formulation of OPF problems.
  • Graph Plotting: Animation generation using coupled oscillator systems.

Once the installation is complete, open the installed folder in MATLAB. You need to execute the following command every time you use GUILDA. 

>> GUILDA

In this process, the following steps are automatically executed:

  • If cloned from Git, the latest version is pulled.
  • Paths for functions and class files necessary for analysis are added.
  • Toolbox installation check and tutorial live editor opening.

Basic Workflow

To perform power system analysis, a model must first be defined. Defining a model requires specifying the system configuration and the operating point (equilibrium point). Once these are established, various analyses become possible.

For users who want to learn through hands-on experience, please refer to the Hands-on Tutorial section below.

1. Modeling

In GUILDA, each component is an object. Design the system by instantiating objects and adding them to the PowerNetwork.

>> net = PowerNetwork()                           % This class serves as the foundation to which various devices are added.
>> bus = net.add_bus("Bus1")                      % Add a bus
>> mac = component.generator.classical(parameter) % Define a synchronous generator
>> bus.add_component(mac)                         % Add the generator to the bus
>> line = branch.pi(parameter)                    % Define a transmission line
>> net.add_branch(line)                           % Add the transmission line to the network

2. Power Flow Calculation

>> out = net.calculate_power_flow(option)
>> net.initialize()

3. Analysis

>> sol = net.simulate(option)
>> sys = net.get_sys(option)

2. Naming Conventions in GUILDA

Variable naming follows: [variableType][size]_[variableDescription].

Variable Type (1st Prefix Token)

  • c: complex
  • r: real
  • l: logical
  • s: symbolic variable (sym)
  • f: symbolic function
  • i: index
  • n: count/number
  • str: string

Size (2nd Prefix Token)

  • (none): scalar
  • v: column vector
  • r: row vector
  • m: matrix

Naming Composition Examples

  • cv_Vequilibrium: [c: complex] + [v: column vector] + [_Vequilibrium]
  • im_solution: [i: index] + [m: matrix] + [_solution]
  • r_gain: [r: real] + [(none): scalar] + [_gain]

Exceptional Naming Rules (Fixed Prefixes)

  • Dictionary type: dict_ + [variable description] (e.g., dict_params)
  • Function handle: fcn_ + [variable description] (e.g., fcn_objective)
  • Table type: tab_ + [variable description] (e.g., tab_bus_data)
  • GUILDA-specific class (cell array): a_ + [ClassName] (e.g., a_Controller)
  • Parameter class: params_ + [data description] (e.g., params_generator)

3. How to Define Class Documentation

Note: Please follow the exact notation below for the tag name in Help Comment <@tag>!

As part of GUILDA startup processing, class information is analyzed and exported as JavaScript files to _GUILDAdoc/database. This mechanism keeps this documentation site synchronized with the latest GUILDA information.

During this analysis, information is categorized based on <@tag>. If these tag names are changed, the documentation site will no longer be updated correctly. Text from one tag (for example, <@tag1>) up to the next tag (for example, <@tag2>) is recognized as the content of the first tag. Line breaks within that range are allowed.

Help Comments for Class Definition

Write class-level tags directly below classdef, then keep constructor usage examples concrete:

classdef MyClass
    % <@Desc> Handles state updates and utility calculations for a subsystem.
    % <@Role> CoreComponent
    % <@Constructor> Create class instance with optional gain and label.
    %  i.e.
    %  >> obj = MyClass(r_gain, str_label)
    %      - r_gain: scalar gain value (default: 1.0)
    %      - str_label: display name (default: "default")

      properties
        r_gain
        str_label
      end

      methods
        function obj = MyClass(r_gain, str_label)
          arguments
            r_gain (1,1) double = 1.0
            str_label (1,1) string = "default"
          end
          obj.r_gain = r_gain;
          obj.str_label = str_label;
        end
      end
    end

Help Comments for Methods

Add method tags immediately above each method body. Structured tags are parsed as JSON only.

Text tags: Desc, Role, Abst, DetailsCode, Argin, Argout, Option

Structured tags (JSON only): Signatures, varargin, varargout, Examples

Structured schema: varargin = Name, Type, Description, Required, Default / varargout = Name, Type, Description

methods
        function rv_y = calculate_output(obj, rv_u, r_gain)
        % <@Desc>
        % Computes an output vector from input data using a configurable gain.
        % <@Abst>
        % Typical example of method tags with parameters, return values, and examples.
        % <@Signatures>
        % [
        %   "rv_y = obj.calculate_output(rv_u, r_gain)",
        %   "rv_y = obj.calculate_output(rv_u)"
        % ]
        % <@varargin>
        % [
        %   {
        %     "Name": "rv_u",
        %     "Type": "double vector",
        %     "Description": "Input signal vector.",
        %     "Required": true,
        %     "Default": "-"
        %   },
        %   {
        %     "Name": "r_gain",
        %     "Type": "double scalar",
        %     "Description": "Scaling gain applied to the input.",
        %     "Required": false,
        %     "Default": "1.0"
        %   }
        % ]
        % <@varargout>
        % [
        %   {
        %     "Name": "rv_y",
        %     "Type": "double vector",
        %     "Description": "Scaled output vector."
        %   }
        % ]
        % <@Examples>
        % [
        %   "```matlab\nrv_y = obj.calculate_output(rv_u, 2.0);\n```",
        %   "```matlab\nrv_y = obj.calculate_output(randn(5,1));\n```"
        % ]
        end
    end

Notes: If a structured tag is omitted or invalid JSON, exporter writes an empty default value.
