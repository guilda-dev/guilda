Architectureアーキテクチャ

GUILDA has two families of classes. The model classes (PowerSystemModel) hold the power system; the analysis classes (auxiliary) run an analysis on the data the model hands them and hold the result. What a single class owns and does is on its class reference page.

GUILDA のクラスは 2 つの系統に分かれます。モデルクラス（PowerSystemModel）が電力系統を保持し、解析クラス（auxiliary）がモデルから渡されたデータで解析を行い、結果を保持します。個々のクラスが持つデータと処理は、クラスリファレンスの各ページにあります。

Class diagramクラス図

Top: the two roots and what specializes them. Bottom: who owns whom, and the read-only reference each child keeps to its parent. A name with * stands for a family of classes, one per analysis or kind.

上段は 2 つの基底クラスと、それを継承するクラスです。下段は所有関係と、子が親に対して持つ読み取り専用の参照です。* の付いた名前は、解析や種類ごとに 1 つずつあるクラスの一群を表します。

  • A model is complete when its objects are set in a PowerNetwork; every analysis starts there.
  • オブジェクトを PowerNetwork に設定するとモデルが完成します。すべての解析はここから始まります。
  • Concrete models (generators, loads, controllers, branches, networks) are subclasses in _GUILDAobject; the framework depends on none of them (see Coding Rules).
  • 具体的なモデル（発電機、負荷、制御器、ブランチ、ネットワーク）は _GUILDAobject のサブクラスです。フレームワークはどのモデルにも依存しません（コーディング規則を参照）。

Design principles設計原則

One owner per value値の所有者は 1 つ
No data is held by two classes. A derived value is a Dependent property that reads its owner; never copy a value and keep the copies in sync.同じデータを 2 つのクラスで持ちません。導出した値は所有者を読む Dependent プロパティにします。値をコピーして同期させるコードは書きません。
Real-world roles実物の役割に従う
A branch builds its own admittance matrix, a bus holds its voltage, components and controllers hold their equations.ブランチは自身のアドミタンス行列を作り、母線は電圧を持ち、機器と制御器は自身の方程式を持ちます。
Same name, same meaning同じ名前は同じ意味
A method has the same meaning and shape on every layer, and a higher layer aggregates the lower ones (e.g. get_sys, get_variable_map, get_admittance_matrix).メソッドはどの層でも同じ意味と入出力の形を持ち、上の層が下の層をまとめます（例: get_sys、get_variable_map、get_admittance_matrix）。
Solvers read data, not modelsソルバーはモデルを読まない
The network collects the data (tables, matrices) and hands them to its solver; a solver keeps no settings and never a result.ネットワークがデータ（表や行列）を集めてソルバーに渡します。ソルバーは設定も結果も保持しません。
Edits record, analyses check編集は記録、解析は確認
An edit only stores the value and records what became stale; nothing is rebuilt per edit (see Model edits).編集は値を保存し、古くなったものを記録するだけです。編集のたびに作り直すことはしません（モデルの編集を参照）。

Parent references親への参照

  • Only the parent creates a child, from a model key: add_bus, add_branch, add_global_controller, add_component, replace_component, add_local_controller. Each concrete constructor is accessible only from its parent class (e.g. Access={?Bus}).
  • 子を作るのは親だけで、モデルキーから作ります（add_bus、add_branch、add_global_controller、add_component、replace_component、add_local_controller）。具体クラスのコンストラクタは親クラスからだけ呼べます（例: Access={?Bus}）。
  • Only the parent sets the reference (SetAccess={?Parent}, no setter). A child only reads its parent and never writes upward or sideways; an edit travels upward as a call (log_edit → handle_edit).
  • 参照を設定するのも親だけです（SetAccess={?親}、セッターなし）。子は親を読むだけで、上や横には書き込みません。編集は呼び出しとして上に伝わります（log_edit → handle_edit）。
  • A removed object is deleted with the objects under it; a handle the user still holds becomes invalid. Results, scenarios and messages keep tags, not objects.
  • 取り除いたオブジェクトは、その下のオブジェクトと一緒に削除されます。ユーザーが持っていたハンドルは無効になります。結果、シナリオ、メッセージはオブジェクトではなくタグを保持します。
  • Since a model object never exists without its parent, methods do not test for a missing parent.
  • モデルオブジェクトが親なしで存在することはないため、メソッドは親がない場合を確かめません。

Identifying objects (tags)オブジェクトの識別（タグ）

  • The tag (e.g. B001) is the permanent ID: use it in saved data and scenarios. An index such as net.a_Bus{3} shifts after remove_*; never store it.
  • タグ（例: B001）が恒久的な ID です。保存するデータやシナリオではタグを使います。net.a_Bus{3} のようなインデックスは remove_* の後にずれるため、保存しません。
  • An automatic tag is the largest number in use plus one, so it never names an earlier object. Every tag is a valid MATLAB variable name (LINE20_1, not LINE20-1).
  • 自動のタグは使用中の最大の番号に 1 を足したもので、以前のオブジェクトの名前と重なりません。タグはすべて MATLAB の変数名として有効な文字列です（LINE20-1 ではなく LINE20_1）。

Model edits and stale stateモデルの編集と古い状態

  • Each layer records in sct_stale what of its own is out of date (e.g. powerflow, equilibrium, odefcn), with the message of each edit that caused it.
  • 各層は自分の古くなった部分を sct_stale に記録します（例: powerflow、equilibrium、odefcn）。原因となった編集のメッセージも残ります。
  • Only net.initialize() brings the layers up to date. Analyses only read the stale tags they need and stop with an error that names the edits and says to run net.initialize() first.
  • 各層を最新にするのは net.initialize() だけです。解析は必要な項目を読むだけで、古ければ原因の編集を示し、先に net.initialize() を実行するよう伝えるエラーで止まります。
  • Editing a scenario makes nothing stale: a scenario is not model data.
  • シナリオはモデルのデータではないため、シナリオを編集しても何も古くなりません。

Variable order and signals変数の順序と信号

  • net.get_variable_map() is the single definition of the order of states, bus voltages, inputs and signals, and of every connection between them. Simulation, linearization and results all use it; find a variable by its label, not by its position.
  • net.get_variable_map() が状態、母線電圧、入力、信号の順序と、それらの接続をただ 1 か所で定めます。シミュレーション、近似線形化、結果はすべてこれを使います。変数は位置ではなくラベルで探します。
  • Signals are connected by name. A component outputs its current to the bus and exposes its outputs and states; a controller only drives inputs. Outputs of a component depend on its states and V, not on its inputs.
  • 信号は名前で接続します。機器は電流を母線に出力し、出力と状態を制御器に見せます。制御器は入力を駆動するだけです。機器の出力は状態と V だけで決まり、入力には依存しません。

Analysis API rules解析 API の規則

Every analysis has the same call shape; a new analysis follows it too. The flow of each analysis is drawn in Analysis Flows.

すべての解析は同じ呼び出しの形を持ち、新しい解析もこれに従います。各解析の流れは解析の流れに図示しています。

[result, flag, output] = net.verb_noun(Name=Value, ...)
Entry point入口
A PowerNetwork method named verb_noun. The solver behind it (net.solver_*) is for advanced use only.verb_noun という名前の PowerNetwork のメソッドです。その裏のソルバー（net.solver_*）を直接使うのは上級者だけです。
Inputs入力
System data is set on the model beforehand. Settings come from GUILDA.setting; a Name-Value option overrides one for this call only.系統のデータは事前にモデルに設定します。解析の設定は GUILDA.setting から読み、Name-Value オプションはその呼び出しだけ設定を上書きします。
Outputs出力
Always [result, flag, output]. A main analysis returns a subclass of ResultBase, which also keeps flag, output and the effective options; a simple getter returns a MATLAB type. Plotting and files are methods of the result (plot_*, export).常に [result, flag, output] です。主な解析は ResultBase のサブクラスを返し、そこにも flag、output、実際の options が残ります。単純な取得メソッドは MATLAB の型を返します。描画とファイル出力は結果のメソッド（plot_*、export）です。
Preconditions前提条件
If one fails, stop with an error that says how to fix it. Continue with an INFO message only when a harmless default exists.満たされないときは、直し方を示すエラーで止めます。結果の意味を変えない既定値があるときだけ、INFO メッセージを出して続けます。
Side effects副作用
The verb decides: add_ remove_ replace_ set_ initialize may change the model; calculate_ simulate_ get_ disp_ plot_ export_ must not. GUILDA never picks a slack bus for the user.動詞で決まります。add_ remove_ replace_ set_ initialize はモデルを変えてよく、calculate_ simulate_ get_ disp_ plot_ export_ は変えてはいけません。GUILDA がスラック母線を勝手に選ぶことはありません。
Optionsオプション
UpperCamelCase, same name and meaning everywhere: Method (what is solved), Solver (algorithm), Type, Tolerance, MaxIteration, TimeLimit, Verbose, Progress, PlotFcn, WarmStart.UpperCamelCase で、どこでも同じ名前は同じ意味です: Method（何を解くか）、Solver（解法）、Type、Tolerance、MaxIteration、TimeLimit、Verbose、Progress、PlotFcn、WarmStart。
Deprecated names非推奨の名前
A wrapper in _GUILDAsystem/_VersionSupport/ keeps a deprecated public name working for at least one major version, with a warning._GUILDAsystem/_VersionSupport/ のラッパーが、非推奨になった公開名を警告付きで少なくとも 1 メジャーバージョンの間使えるようにします。

Settings of analyses解析の設定

  • Each analysis has a section of GUILDA.setting (e.g. PowerFlowCalculation, TimeSimulation). Its options are declared in an arguments block whose defaults read GUILDA.config("Section", "Name"); pass them on as they are, without reading the section again.
  • 解析ごとに GUILDA.setting のセクションがあります（例: PowerFlowCalculation、TimeSimulation）。オプションは arguments ブロックで宣言し、既定値は GUILDA.config("Section", "Name") から読みます。受け取った値はそのまま渡し、セクションを読み直しません。
  • The shipped defaults are @GUILDA/config/Default<Section>.json; user values go to @GUILDA/user/ (not committed). Raise the file's version when you change a default, a key, its type or options, so users start from the new defaults.
  • 既定値は同梱の @GUILDA/config/Default<Section>.json にあり、ユーザーの値は @GUILDA/user/ に保存されます（コミットしません）。既定値、キー、型、選択肢を変えたときはファイルの version を上げ、ユーザーが新しい既定値から始まるようにします。

Units and messages単位とメッセージ

Per unit単位法
Voltages, currents, powers, branch constants and dynamic parameters are per unit on the system base. No class converts physical units.電圧、電流、電力、ブランチ定数、動特性のパラメータは系統基準の単位法です。物理単位への変換はどのクラスも行いません。
Angle, time角度、時間
Radians; seconds. The nominal frequency is read with get_Hz(), and models multiply by 2π themselves.ラジアンと秒です。定格周波数は get_Hz() で読み、2π を掛けるのはモデル側です。
Current direction電流の向き
A component's current is injected into its bus (positive for generation); the network equation is I = Y*V.機器の電流は母線への注入方向です（発電で正）。ネットワークの式は I = Y*V です。
Errors and warningsエラーと警告
error(msg("GUILDA:<Object>:<Key>", ...)) and show_msg("warning" | "info", ID, ...); the English text is in SystemTools/GUILDA/en/<Object>.xml. No disp or warning of GUILDA text without show_msg.error(msg("GUILDA:<Object>:<Key>", ...)) と show_msg("warning" | "info", ID, ...) を使います。英語の本文は SystemTools/GUILDA/en/<Object>.xml にあります。GUILDA の文を show_msg を通さずに disp や warning で出しません。
