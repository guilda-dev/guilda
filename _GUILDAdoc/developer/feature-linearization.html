Linearization Feature Design近似線形化機能の設計

net.linearize linearizes the network DAE at the equilibrium (or a given point). Output: the unreduced Jacobian blocks as a ResultLIN, which also holds the reduced model in A, B, C, D, E and the names; result.get_ss and net.get_sys give the model as a struct or an ss object. The linearization uses matrices only and needs no toolbox; only the ss form needs the Control System Toolbox. This page follows one call through SolverLIN and the get_sys of each layer.

net.linearize は、ネットワークの DAE を平衡点 (または指定した点) のまわりで線形化します。結果は ResultLIN で、縮約前のヤコビアンのブロックを持ちます。縮約したモデルも A、B、C、D、E と変数名の形で保持します。result.get_ss や net.get_sys を使うと、構造体または ss オブジェクトとして取り出せます。線形化は行列演算だけで済むので、Toolbox は要りません。Control System Toolbox が必要なのは ss の形で受け取る場合だけです。このページでは、SolverLIN と各層の get_sys を通る 1 回の呼び出しを説明します。

What the feature does and how to call it機能の目的と呼び出し方

Result: the linear DAE in deviations from the point, in the order of the leading rows x, Vre, Vim, u of net.get_variable_map() (see Class Design: Order of state and input variables; the controller inputs uc are eliminated by the models of the layers, and the signals are not variables); x states, v = [Vre1; Vim1; Vre2; …] bus voltages, u component inputs:

結果は、点からの偏差で表した線形 DAE です。変数は net.get_variable_map() の先頭の行と同じく、x、Vre、Vim、u の順に並びます (クラス設計: 状態・入力変数の順序を参照。制御器の入力 uc は各層のモデルの中で消去されるので、信号は変数になりません)。x は状態、v = [Vre1; Vim1; Vre2; …] は母線電圧、u は機器の入力です。

E dx/dt = Axx x + Axv v + Bx u
      0 = Avx x + Avv v + Bv u      % current balance Y v − I of each bus

sys = result.get_ss(Method, Coordinate=…, Input=…, Output=…, Format="ss"|"struct")

sys = comp.get_sys(…, Format="GUILDAorigin"|"struct"|"ss")   % also bus, con, gc

Preconditions for the call呼び出しの前提条件

  • net.initialize() has run, with no edit since that makes a layer stale, a network Hz edit included, also when a Point is given (see Class Design: Handling of model edits). initialize builds the f_* handles.
  • net.initialize() を実行済みで、その後に層を古くする編集（ネットワークの Hz の編集も含む）をしていない状態でなければなりません (Point を与えた場合も同じです。クラス設計: モデル編集の扱いを参照)。f_* ハンドルは initialize が作ります。
  • No component equation depends on the current I (the ports are V in, I out).
  • 機器の式は電流 I に依存してはいけません (端子は V が入力、I が出力です)。
  • A Point vector has one finite value per row of the variable map.
  • Point のベクトルは、変数マップの行ごとに 1 つの有限な値を持たなければなりません。

Call sequence between classesクラス間の呼び出し順

Numbers: the IDs of the steps. LIN-07 to LIN-10 repeat for each bus and component, LIN-11 for each global controller. Dashed arrows: returns.

番号はステップの ID です。LIN-07〜LIN-10 は母線・機器ごと、LIN-11 はグローバル制御器ごとに繰り返します。破線の矢印は戻り値です。

Processing steps in detail処理ステップの詳細

  • Each step: one requirement of the feature. Steps marked on the left repeat for each bus, component or global controller.
  • n_x, n_v (= 2 × number of buses), n_u: numbers of states, bus voltage variables and component inputs of the variable map.
  • ステップ 1 つに、この機能の要件を 1 つずつ書いています。左に印のあるステップは、母線、機器、グローバル制御器ごとに繰り返します。
  • n_x、n_v (= 2 × 母線数)、n_u は、それぞれ変数マップにある状態、母線電圧変数、機器入力の数です。

  7. LIN-07 SolverLIN.solve → Bus.get_sys("port", "V2I", "Format", "struct")

    What it does処理内容
    Model of each bus with its components; inputs [Vre; Vim; u…], outputs [Ire; Iim; y…].
    • The component models side by side, their D blocks of V summed (Point passed as the rows of the bus).
    • A bus without components: no states, zero current.
    • The solver keeps the current rows and the outputs separately, with the columns of V and of the component inputs (controller inputs left out).
    各母線と機器のモデルです。入力は [Vre; Vim; u…]、出力は [Ire; Iim; y…] です。
    • 機器のモデルを並べ、V の D ブロックを合計します (Point がある場合は母線の行を渡します)。
    • 機器のない母線は、状態がなく電流が 0 のモデルにします。
    • ソルバーは電流の行と出力の行を分けて保持します。列は V と機器入力のみです (制御器の入力は除外します)。
    What it reads読み取る情報
    a_Component, rv_point(c_idxBus{i})
    Returns or changes戻り値・変更する値

  8. LIN-08 Bus.get_sys → Component.get_sys("port", "V2I", "Format", "struct")

    What it does処理内容

    • With a Point: point_values splits it into x, V, u and the controller inputs.
    すべてのローカル制御器 (深さ優先) を含む機器のモデルです。次の要素を信号名で行列により接続します (connect_blocks: 入力は同名の出力の和を受け取り、状態はすべて保持します):

    • 制御器のモデル (LIN-09)
    • 状態を読む制御器のための状態出力 (connect_states)
    • Point がある場合は、point_values が x, V, u と制御器の入力に分割します。

  11. LIN-11 SolverLIN.solve → GlobalController.get_sys("Format", "struct")

    What it does処理内容
    Model of each global controller, before the bus models: inputs, the voltages of all buses and, for each controlled unit, the outputs (else the states) named sv_u; outputs, one row for each input they drive, labelled as that input (an input of a local controller of the unit, else of the unit). At a Point, the inputs are computed at the point (gc_input). add_global_controllers then closes the loop: an observed output is a row of the bus models (Cy, Dyv), an output into a local controller acts through the columns of that input in the bus models (c_sysL), and the voltage dependence changes Axv and Avv.各グローバル制御器のモデルを、母線モデルの前に作成します。入力は全母線の電圧と、各制御対象の sv_u という名前の出力（なければ状態）です。出力は駆動する入力ごとに 1 行で、その入力の名前（制御対象のローカル制御器の入力、なければ制御対象の入力）を付けます。Point のときは入力を点で計算します (gc_input)。続いて add_global_controllers がループを閉じます。観測する出力は母線モデルの行 (Cy, Dyv) です。ローカル制御器への出力は母線モデルのその入力の列 (c_sysL) を通して作用し、電圧への依存は Axv と Avv を変更します。
    What it reads読み取る情報

    Returns or changes戻り値・変更する値

  13. LIN-13 SolverLIN.solve → tools.dcellfun, add_global_controllers

    What it does処理内容
    • Stacks the bus models block-diagonally (Axx, Axv, Bxu, Cix, Div, Diu, E).
    • Closes the global controllers: their states z after x; inputs from the bus voltages v and the observed component outputs (Cy x + Dyv v) or states; outputs added to the component inputs u or driving the inputs of local controllers (their columns in the bus models).
    • Checks the state names against the map; forms Avx = −Cix, Avv = Y − Div, Bv = −Diu.
    • 母線モデルをブロック対角に配置します (Axx、Axv、Bxu、Cix、Div、Diu、E)。
    • グローバル制御器で閉ループを作ります。状態 z を x の後に配置します。入力は母線電圧 v と、観測する機器の出力 (Cy x + Dyv v) または状態です。出力は機器の入力 u に加算するか、ローカル制御器の入力 (母線モデルのその列) を駆動します。
    • 状態名を変数マップと照合します。Avx = −Cix、Avv = Y − Div、Bv = −Diu を作成します。
    What it reads読み取る情報
    c_sysBus, c_sysY, c_sysGC, cm_Y, tab_map.Label
    Returns or changes戻り値・変更する値
    sct_block, sct_model (see参照: Data生成されるデータ)

    • Reported without changing flag: buses with |V| < 1e-8 (also printed as INFO).
    flag と output を次のように決めます:
    • "NotFinite": 非有限の要素を含むブロックがある場合です。
    • それ以外で "SingularAvv": rcond(Avv) < 1e-14 の場合です (定まらない電圧を singular_voltages で表示します)。
    • |V| < 1e-8 の母線は、flag を変えずに報告します (INFO としても表示します)。
    What it reads読み取る情報

  18. LIN-18 caller呼び出し側 → ResultLIN.get_ss

    What it does処理内容
    Reduces the blocks to a descriptor model with matrix operations, held as a struct:
    • via_kron: eliminates v (A = Axx − Axv·Avv⁻¹·Avx);
    • via_feedback: connects the bus models in I-to-V form (i2v_full) through the admittance matrix by name (connect_by_name), absorbs buses without an I-to-V form into it, removes the states that no input reaches (remove_unreachable_states), then closes the global controllers (positive_feedback). A global controller can read the voltages and component outputs of the absorbed (non-unit) buses: the network block adds them as outputs, from the current balance of those buses, only when a global controller uses them. A global controller that drives a local controller input on such a bus stops with GUILDA:ResultLIN:GlobalControllerPort;
    • via_dae: keeps v in the chosen coordinates (coordinate_filter).
    • select_output, input_index: apply Output and Input.
    • to_format: Format="ss" builds a dss with the names (Control System Toolbox).
    • Object-level result (from the get_sys of a layer): returns its port model; Input and Output select by name.
    • Stops for "NotFinite", and for "SingularAvv" except with "DAE".
    ブロックを行列演算でディスクリプタ形式のモデルに縮約します。モデルは構造体で保持します:
    • via_kron: v を消去します (A = Axx − Axv·Avv⁻¹·Avx)。
    • via_feedback: I-to-V 形式の母線モデル (i2v_full) をアドミタンス行列と名前で接続します (connect_by_name)。I-to-V 形式のない母線はアドミタンス行列に吸収します。入力から届かない状態を除去します (remove_unreachable_states)。最後にグローバル制御器を正帰還で閉ループにします (positive_feedback)。グローバル制御器は、吸収した (機器の状態のない) 母線の電圧と機器の出力も読み取れます。グローバル制御器が使う場合のみ、ネットワークのブロックがその母線の電流の釣り合いから出力に追加します。そのような母線のローカル制御器の入力を駆動するグローバル制御器は GUILDA:ResultLIN:GlobalControllerPort で停止します。
    • via_dae: v を指定した座標で保持します (coordinate_filter)。
    • select_output、input_index: Output と Input を適用します。
    • to_format: Format="ss" のとき名前付きの dss を作成します (Control System Toolbox)。
    • 層の get_sys の結果では、保持するポートのモデルを返します。Input と Output は名前で選択します。
    • "NotFinite"、および "DAE" 以外での "SingularAvv" では停止します。
