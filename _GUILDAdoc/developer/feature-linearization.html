Linearization Feature Design近似線形化機能の設計

get_sys linearizes one layer (the network, a bus, a component, a local controller or a global controller) at the equilibrium or at a given point. The same method, defined once in PowerSystemModel, serves every layer: each model object gives its own linear block (get_linear_block), get_sys takes the inputs and outputs of the layer from its variable map (local function port), and SolverLIN.solve connects the blocks along the variable map. Output: a ResultLIN holding the connected model, the Jacobian blocks and, in A, B, C, D, E with the names, the model of its Type ("ODE" or "DAE", switchable on the result); it also splits the DAE into the contributions of the elements (get_contribution); Format="struct" or "ss" returns that model directly. The linearization uses matrices only and needs no toolbox; only the ss form needs the Control System Toolbox. This page follows one call through get_sys, the blocks and SolverLIN.

get_sys は、1 つの層 (ネットワーク、母線、機器、ローカル制御器、グローバル制御器) を平衡点または指定した点のまわりで線形化します。PowerSystemModel に 1 つだけ定義した同じメソッドが、すべての層で使われます。各モデルオブジェクトは自分の線形ブロックを返し (get_linear_block)、get_sys が層の入力と出力を変数マップから決め (局所関数 port)、SolverLIN.solve が変数マップに沿ってブロックを接続します。結果は ResultLIN で、接続したモデル、ヤコビアンのブロックを保持し、A、B、C、D、E と変数名の形で Type ("ODE" または "DAE"。結果で切り替えられます) のモデルを返します。DAE を要素ごとの寄与に分けることもできます (get_contribution)。Format="struct" または "ss" では、そのモデルを直接返します。線形化は行列演算だけで済むので、Toolbox は要りません。Control System Toolbox が必要なのは ss の形で受け取る場合だけです。このページでは、get_sys、各ブロック、SolverLIN を通る 1 回の呼び出しを説明します。

Result of the network: the linear DAE in deviations from the point, in the order of the leading rows x, Vre, Vim, u of net.get_variable_map() (see Class Design: Order of state and input variables; the controller inputs uc and the signals y, yc are eliminated by the connection and are not variables); x states, v = [Vre1; Vim1; Vre2; …] bus voltages, u component inputs:

ネットワークの結果は、点からの偏差で表した線形 DAE です。変数は net.get_variable_map() の先頭の行と同じく、x、Vre、Vim、u の順に並びます (クラス設計: 状態・入力変数の順序を参照。制御器の入力 uc と信号 y、yc は接続で消去されるので、変数になりません)。x は状態、v = [Vre1; Vim1; Vre2; …] は母線電圧、u は機器の入力です。

Inputs and outputs of each layer各層の入力と出力

  • Names: the Labels of the variable map of the layer (obj.get_variable_map(); a controller has its own, with the labels of the map of its component or network), in the order of the map: all u, then all uc; all y, then all yc. The voltage of a component or local controller is named by the bus Labels (Vre_<bus>, Vim_<bus>); the current of a component carries the component tag, that of a bus the bus tag.
  • The inputs and outputs of a global controller are its own uc and yc Labels; which signals they observe and which inputs they drive is in the connection map.
  • 名前は層の変数マップ (obj.get_variable_map()。制御器も、機器またはネットワークのマップと同じ Label を持つ自分のマップを持ちます) の Label で、マップの順に並びます。すべての u の後にすべての uc、すべての y の後にすべての yc です。機器とローカル制御器の電圧は母線の Label (Vre_<bus>、Vim_<bus>) で名付けます。機器の電流には機器のタグ、母線の電流には母線のタグが付きます。
  • グローバル制御器の入力と出力は、自分の uc と yc の Label です。どの信号を観測し、どの入力を駆動するかは接続マップにあります。

The point点

  • The first argument point is [] for the equilibrium (the default); a vector of the variables of the layer in the order of the leading rows of obj.get_variable_map() (x, Vre, Vim, then u; for a controller x, Vre, Vim, then uc); or {sim, t} / {sim, t, "before"} for the state of a ResultODE at time t (network, bus and component only).
  • The column Equilibrium of the map holds these rows at the equilibrium, so obj.get_sys(tab.Equilibrium(tab.Role == "variable")) of a controller, or the leading rows for the other layers, gives the same model as obj.get_sys().
  • The point sets the variables only: the admittance matrix stays that of the model, also inside a fault.
  • 最初の引数 point は、[] で平衡点 (既定)、obj.get_variable_map() の先頭の行の順 (x、Vre、Vim、続いて u。制御器では x、Vre、Vim、続いて uc) に並べた層の変数のベクトル、または {sim, t} / {sim, t, "before"} で ResultODE の時刻 t の状態を指定します ({sim, t} はネットワーク、母線、機器だけです)。
  • マップの Equilibrium 列は、これらの行の平衡点での値です。制御器の obj.get_sys(tab.Equilibrium(tab.Role == "variable"))、他の層ではその先頭の行を与えると、obj.get_sys() と同じモデルになります。
  • この指定で決まるのは変数の値だけです。地絡中の時刻を選んでも、アドミタンス行列はモデルのものを使います。

Name-Value options and defaultsName-Value オプションと既定値

  • The options are the arguments block of get_sys: an unknown name or a value outside the list stops with the MATLAB error of the block. Type, Coordinate and PlotFcn without a value in the call take the Linearization section of GUILDA.setting, read at each run from GUILDA.config("Linearization") (@GUILDA/config/DefaultLinearization.json, overridden by a file of the same name in @GUILDA/user/). net.solver_LIN (a SolverLIN) holds no settings.
  • A Name-Value option applies to this call only; the settings file is not changed. See API Design.
  • オプションは get_sys の arguments ブロックです。未知の名前や候補にない値は、このブロックの MATLAB のエラーで停止します。呼び出しで値を与えなかった Type、Coordinate、PlotFcn は、GUILDA.setting の Linearization セクションの値を使います。この値は実行のたびに GUILDA.config("Linearization") から読み込みます (@GUILDA/config/DefaultLinearization.json。@GUILDA/user/ に同名のファイルがあればそちらが優先されます)。net.solver_LIN (SolverLIN) 自体は設定を持ちません。
  • Name-Value オプションは、その呼び出しにだけ適用します。設定ファイルは書き換えません。詳しくはAPI 設計を参照してください。

Preconditions for the call呼び出しの前提条件

  • net.initialize() has run and builds the f_* handles. Since then, no edit of the inputs and no edit of a dynamics of the layer; at the equilibrium (point = []) also no edit that makes the power flow or an equilibrium stale (see Class Design: Handling of model edits).
  • net.initialize() を実行済みでなければなりません (f_* ハンドルは initialize が作ります)。その後に入力や層の動特性を編集していないことが必要です。平衡点 (point = []) では、潮流計算や平衡点を古くする編集もしていないことが必要です (クラス設計: モデル編集の扱いを参照)。
  • No component equation depends on the current I (the ports of a component are V in, I out).
  • 機器の式は電流 I に依存してはいけません (機器の端子は V が入力、I が出力です)。
  • A point vector has one finite value per variable of the layer.
  • 点のベクトルは、層の変数ごとに 1 つの有限な値を持たなければなりません。
  • Every unit controlled by a global controller has outputs or states named as the controller inputs, and every controller output drives an input of the unit or of its local controllers.
  • グローバル制御器のすべての制御対象は、制御器の入力と同じ名前の出力または状態を持ち、制御器のすべての出力は制御対象またはそのローカル制御器の入力を駆動しなければなりません。

  • All steps up to LIN-15 are in _GUILDAsystem/_auxiliary/@PowerSystemModel/get_sys.m and its local functions, except the methods named in the step.

    What it does処理内容

  6. LIN-06 get_sys: controller inputs at the point点での制御器の入力local functions局所関数 blocks, input_values

    What it does処理内容
    Completes the values of the signals at the point, in the order of the dependencies:
    • outputs y of the components: f_Y(0, x, V);
    • local controllers, the deepest first: each input uc is the sum of its sources in the connection map (outputs, states; an "equilibrium" row adds the equilibrium value of the input; "global" rows are left out), then the outputs yc = f_Y(0, x, V, uc);
    • global controllers: inputs uc by the same sum.
    • So the controllers are linearized at the given point, also with a positional point.
    点での信号の値を、依存の順に求めます。
    • 機器の出力 y: f_Y(0, x, V) です。
    • ローカル制御器 (深いものから): 各入力 uc は接続マップの源 (出力、状態) の和です。"equilibrium" の行は入力の平衡値を足し、"global" の行は含めません。続いて出力 yc = f_Y(0, x, V, uc) を求めます。
    • グローバル制御器: 入力 uc を同じ和で求めます。
    • このため、位置引数の点でも、制御器は与えた点で線形化されます。
    What it reads読み取る情報
    rv_point, tab, tab_c, f_Y, rv_Uequilibrium of the controllers（制御器）
    Returns or changes戻り値・変更する値
    values of every row of tab (local)tab の全行の値 (局所変数)

  7. LIN-07 get_sys → Component.get_linear_block(x, V, u)

    What it does処理内容
    Linear block of the component alone (Hidden, public; controller.local_LQR calls it directly):
    • A = Axx, B = [Bxv, Bxu], C = [Cix; Cyx], D = [Div, Diu; Dyv, 0] (no feedthrough from u to y), E = f_Mass; empty blocks filled with zeros.
    • Inputs: the bus voltage Labels and the inputs u; states x; outputs: the current Ire, Iim with the component tag, then y ("Y_" + name for an output with the name of a state).
    機器単体の線形ブロックです (Hidden、public。controller.local_LQR が直接呼び出します)。
    • A = Axx、B = [Bxv, Bxu]、C = [Cix; Cyx]、D = [Div, Diu; Dyv, 0] (u から y への直達はありません)、E = f_Mass です。空のブロックは 0 で補います。
    • 入力は母線電圧の Label と入力 u、状態は x、出力は機器のタグ付きの電流 Ire、Iim と y です (状態と同名の出力は "Y_" + 名前)。

Contributions of the elements要素の寄与

[sct_value, sct_mask] = result.get_contribution(target) splits the DAE (the model of Type="DAE" of the result) by element. sct_value has A, B, C, D, E of the size of the DAE and its StateName, InputName, OutputName; sct_mask the same fields as logical matrices. Several targets are summed, and the parts of all the elements sum to the DAE.

[sct_value, sct_mask] = result.get_contribution(target) は、DAE (結果の Type="DAE" のモデル) を要素ごとに分けます。sct_value は DAE と同じ大きさの A、B、C、D、E と、その StateName、InputName、OutputName を持ちます。sct_mask は同じフィールドを logical の行列で持ちます。複数の対象は足し合わせ、すべての要素の寄与の和は DAE に等しくなります。

Where to extend the feature機能を拡張する箇所

A new model is linearized through the contract in Model Implementation. Jacobian functions: the same as in the simulation, called at t = 0 and the point. What this feature uses:

新しいモデルは、モデルの実装の契約を通じて線形化されます。ヤコビアンの関数はシミュレーションと共通で、t = 0 と点で呼び出します。この機能が使うものは次のとおりです:

ModelモデルUsed by the linearization近似線形化が使うもの
ComponentJacobi_dx, Jacobi_I returning [∂/∂x, ∂/∂V, ∂/∂u] and Jacobi_Y returning [∂/∂x, ∂/∂V] (numerical differentiation without them). fcn_Mass is E. sv_x, sv_u, sv_y name the states, inputs and outputs; an output with a state's name becomes Y_<name>. A controller that designs with the component alone (such as controller.local_LQR) calls comp.get_linear_block(x, V, u).[∂/∂x, ∂/∂V, ∂/∂u] を返す Jacobi_dx、Jacobi_I と、[∂/∂x, ∂/∂V] を返す Jacobi_Y を使います (なければ数値微分します)。fcn_Mass が E です。sv_x、sv_u、sv_y は状態・入力・出力の名前です。状態と同名の出力は Y_<name> になります。機器単体のモデルで設計する制御器 (controller.local_LQR など) は comp.get_linear_block(x, V, u) を呼び出します。
LocalControllerJacobi_dx, Jacobi_Y (with the u columns), fcn_Mass; connected to the component by the connection map, as in the simulation.Jacobi_dx、Jacobi_Y (u の列を含む)、fcn_Mass を使います。シミュレーションと同じく、接続マップで機器に接続します。
