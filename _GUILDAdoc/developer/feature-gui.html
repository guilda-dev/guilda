GUI Feature DesignGUI 機能の設計

obj.gui() shows any model (network, bus, branch, component, controller) in a window: its class and tag, the stale state, editable parameter tables, the parent and children as a tree, and pages of tables, equations, a figure and an Initialize button. The pages come from the six abstract classes, so a new model class shows them without any GUI code.

obj.gui(): 任意のモデル（ネットワーク、母線、ブランチ、機器、制御器）をウィンドウに表示する機能。表示内容はクラスとタグ、stale 状態、編集できるパラメータの表、親と子のツリー、表・数式・図・Initialize ボタンのページ。ページは抽象クラス 6 つが作成するため、新しいモデルクラスには GUI 用のコードが不要。

What the feature does and how to call it機能の目的と呼び出し方

net = network.IEEE14bus();
h = net.a_Bus{1}.gui();     % a new uifigure
h = net.gui(h_container);   % fills h_container
  • gui(obj, h_container): public method of PowerSystemModel, so every network, bus, branch, component, local and global controller has it.
  • No container (or []): a new uifigure named after the class and the tag.
  • A container: the GUI fills a uifigure, uipanel, uitab or uigridlayout whose figure was made by uifigure(); the layout follows the size of the container.
  • Output: h, a DrawerModelGUI. h.a_target is the model shown, h.h_container the container; h.render(model) shows another model in the same place.
  • A figure made by figure() is rejected, also through a panel inside it (GUILDA:DrawerModelGUI:NotUIContainer):
    • the GUI is built from UI components (uigridlayout, uitree, uitable, uihtml, uiimage, uialert), which belong in a uifigure;
    • before R2025a a figure() does not take them; since R2025a it does, so the check reads the dynamic property isUIFigure, which only uifigure() adds. The same containers work in every release.
  • gui(obj, h_container): PowerSystemModel の public メソッド。ネットワーク、母線、ブランチ、機器、局所・広域制御器のすべてが保持
  • コンテナなし（または []）: クラス名とタグを名前にした新しい uifigure
  • コンテナあり: uifigure() で作った図の uifigure、uipanel、uitab、uigridlayout に展開。レイアウトはコンテナの大きさに追従
  • 出力: DrawerModelGUI の h。h.a_target は表示中のモデル、h.h_container はコンテナ。h.render(model) で同じ場所に別のモデルを表示
  • figure() で作った図は対象外。その中のパネルも同様（GUILDA:DrawerModelGUI:NotUIContainer）:
    • GUI の部品は UI コンポーネント（uigridlayout、uitree、uitable、uihtml、uiimage、uialert）で、uifigure 用
    • R2025a より前の figure() には配置不可。R2025a 以降は配置可能なため、uifigure() だけが追加する動的プロパティ isUIFigure で判定。どのリリースでも使えるコンテナは同じ

Screen layout画面構成

  • Header: the tag and the class in bold, and below them the stale state from sct_stale: Stale: none (green), or each stale tag with its first message and the number of the others (orange).
  • Tree: the parent, the model (selected, marked ◀) and its children; the Parameter containers are left out. A click on a node shows that model in the same container; the context menu Open in new window calls gui() of that model.
  • Tabs, in this order:
    1. Parameter: one editable table per container of a_Parameter, titled by its s_tag; No parameters. when there is none;
    2. the tables of the abstract class (Summary, Equilibrium);
    3. Equations;
    4. Image;
    5. Initialize.
    A page whose source is missing has no tab (see Pages of each abstract class).
  • ヘッダ: 太字のタグとクラス。その下に sct_stale の stale 状態: Stale: none（緑）、または stale のタグごとに最初のメッセージと残りの件数（橙）
  • ツリー: 親、モデル（選択状態、◀ 付き）、その子。Parameter のコンテナは除外。ノードのクリックでそのモデルを同じコンテナに表示。コンテキストメニュー Open in new window でそのモデルの gui() を実行
  • タブ（この順）:
    1. Parameter: a_Parameter のコンテナごとに編集できる表。題は s_tag。コンテナがない場合は No parameters.
    2. 抽象クラスの表（Summary、Equilibrium）
    3. Equations
    4. Image
    5. Initialize
    元になる情報がないページはタブなし（抽象クラスごとのページを参照）

Pages of each abstract class抽象クラスごとのページ

Each abstract class puts its own pages first, then those of PowerSystemModel. Values in the tables are as of the last net.initialize(); the header shows whether they are stale.

各抽象クラスは自分のページを先に置き、続いて PowerSystemModel のページ。表の値は最後の net.initialize() の時点のもの。古いかどうかはヘッダに表示。

ClassクラスPages (type)ページ（種類）
PowerSystemModel
  • Equations (latex): the ```math blocks of the help of the class of the model, under **Equations**; no tab when there is none.
  • Image (image): @Class/image.svg of the class of the model or of the nearest superclass that has one; no tab when none has.
  • Initialize (action): a button initialize that runs initialize() of the network the model belongs to (found through the parents), then draws the GUI again; no tab outside a network.
  • Equations（latex）: モデルのクラスの help で **Equations** の下にある ```math ブロック。ない場合はタブなし
  • Image（image）: モデルのクラス、またはそれを持つ最も近い上位クラスの @Class/image.svg。どこにもない場合はタブなし
  • Initialize（action）: ボタン initialize。モデルが属するネットワーク（親をたどって発見）の initialize() を実行し、GUI を再描画。ネットワーク外ではタブなし
PowerNetwork
  • Summary (table): numbers of buses, branches, components (over all buses) and global controllers.
  • Equilibrium (table): one row per bus: Tag, Type (s_bustype), V, |V|, ∠V [rad], I.
  • Summary（table）: 母線、ブランチ、機器（全母線の合計）、広域制御器の数
  • Equilibrium（table）: 母線ごとに 1 行。Tag、Type（s_bustype）、V、|V|、∠V [rad]、I
Bus Equilibrium (table): Name and Value (text) for Type, V (a+bj), |V|, ∠V [rad], I (a+bj). Equilibrium（table）: Type、V（a+bj）、|V|、∠V [rad]、I（a+bj）の Name と Value（文字列）
Branch Equilibrium (table): rows from and to, columns Bus (tag of the end bus), V, I; no rows for a branch without end buses. Equilibrium（table）: 行は from と to、列は Bus（端の母線のタグ）、V、I。端の母線がないブランチでは行なし
Component Equilibrium (table): Kind, Name, Value (text) for each state (sv_x), each input (sv_u), then V and I (a+bj); no rows before the equilibrium is computed. Equilibrium（table）: 状態（sv_x）、入力（sv_u）ごと、続いて V と I（a+bj）の Kind、Name、Value（文字列）。平衡点の計算前は行なし
LocalController Equilibrium (table): as for Component; V and I are those of the parent component. Equilibrium（table）: Component と同じ形式。V と I は親の機器の値
GlobalController Equilibrium (table): Kind, Name, Value for each state and input; names x1, x2, … and u1, u2, … when sv_x or sv_u has another number of entries than the values. Equilibrium（table）: 状態と入力ごとの Kind、Name、Value。sv_x または sv_u の要素数が値の数と異なる場合、名前は x1, x2, … と u1, u2, …

What a model class writes for the GUIモデルクラスが GUI のために書くもの

Nothing beyond what every class has. A class made from an abstract class (a new generator, load, controller, branch, network) adds no method or property for the GUI:

  • Equations: the class help, written as in Class Documentation: Dynamic models. Every ```math block after the line **Equations**, up to the next **...** heading or <@Examples>, becomes one display equation, in order (the blocks after with included).
  • Image: image.svg in the class folder, as in Class Documentation: Figure. A class without one shows the figure of its nearest superclass that has one.
  • Tables and the Initialize button: from the properties of the abstract class (sv_x, sv_u, the equilibrium, a_Parameter), which every model already fills.

すべてのクラスが持つもの以外は不要。抽象クラスから作るクラス（新しい発電機、負荷、制御器、ブランチ、ネットワーク）には、GUI のためのメソッドもプロパティも追加なし:

  • 数式: クラスの help。クラスのドキュメント: 動的モデルの書き方に従う。**Equations** の行から、次の **...** の見出しまたは <@Examples> までのすべての ```math ブロックを、順に 1 つずつ別行の数式として表示（with の後のブロックも対象）
  • 図: クラスフォルダの image.svg。クラスのドキュメント: 図に従う。ないクラスでは、それを持つ最も近い上位クラスの図を表示
  • 表と Initialize ボタン: 抽象クラスのプロパティ（sv_x、sv_u、平衡点、a_Parameter）から作成。どのモデルも設定済み

The help is read with help(class(obj)), so only the help of the class of the model counts, not that of its superclasses. The same help gives the class page of the reference (GUILDA.doc), so the GUI and the reference show the same equations.

help は help(class(obj)) で読むため、対象はモデルのクラス自身の help のみ。上位クラスの help は対象外。同じ help からリファレンスのクラスのページ（GUILDA.doc）も作るため、GUI とリファレンスの数式は同一。

Editing parametersパラメータの編集

  • An edited cell writes the whole table of its panel to tab_parameter of that Parameter container at once (edit_parameter); there is no Apply button.
  • Parameter does the rest, as for an edit from the command line: it checks the class, names, height and row names, logs only the changed values, and marks the layers stale (see Class Design: Handling of model edits). The GUI then refreshes the stale line of the header.
  • On an error, the table goes back to the stored values and an alert shows the message; nothing is stored.
  • The equilibrium tables are not editable and keep the values of the last initialize; the Initialize tab updates them.
  • セルを編集すると、そのパネルの表全体を Parameter コンテナの tab_parameter に即座に書き込み（edit_parameter）。適用ボタンなし
  • その後の処理は、コマンドラインからの編集と同じく Parameter が担当: クラス・名前・高さ・行名の検査、変更した値だけのログ、層の stale への反映（クラス設計: モデル編集の扱いを参照）。GUI はヘッダの stale の行を更新
  • エラーの場合: 表を保存済みの値に戻し、アラートでメッセージを表示。何も保存しない
  • 平衡点の表は編集不可。値は最後の initialize の時点のもの。Initialize タブで更新

  • _GUILDAsystem/_auxiliary/@PowerSystemModel/gui_content.m and _GUILDAsystem/@<AbstractClass>/gui_content.m: the page definitions.
  • _GUILDAsystem/_auxiliary/@DrawerModelGUI/: the UI. render.m draws a model; private/ holds the parts (build_header, build_tree, build_parameter_tab, build_page, edit_parameter, update_stale, show_alert, is_ui_container) and latex_page.html.
  • _GUILDAsystem/_auxiliary/@PowerSystemModel/gui.m: 入口。f_model と DrawerModelGUI を作成
  • _GUILDAsystem/_auxiliary/@PowerSystemModel/gui_content.m と _GUILDAsystem/@<抽象クラス>/gui_content.m: ページ定義
  • _GUILDAsystem/_auxiliary/@DrawerModelGUI/: UI。render.m がモデルを描画。private/ に部品（build_header、build_tree、build_parameter_tab、build_page、edit_parameter、update_stale、show_alert、is_ui_container）と latex_page.html

Page definitions: gui_contentページ定義: gui_content

sct_page = gui_content(obj) is a protected method. It returns a struct column, one element per tab after Parameter, with the fields s_title (tab name), s_type, content and s_label (button text of an action page, "" otherwise).

sct_page = gui_content(obj): protected メソッド。Parameter の後のタブ 1 つにつき 1 要素の構造体の列を返却。フィールドは s_title（タブ名）、s_type、content、s_label（action のボタンの文字。それ以外は ""）。

DrawerModelGUI and renderDrawerModelGUI と render

  • DrawerModelGUI(a_target, h_container, f_model) (an _auxiliary class): checks the container (or opens a uifigure), keeps it and f_model, and calls render(a_target).
  • render(a_target) (public): draws the whole GUI of a model. The tree, the Initialize button and an embedding app call it; render() draws the shown model again.
  • It removes only what it drew before: the children of the container with Tag "DrawerModelGUI", and the context menu of their tree (owned by the figure). Other components of the container stay. In a uigridlayout container the new grid takes the Layout (row and column) of the old one.
  • Then it builds a 2 × 2 uigridlayout (Tag "DrawerModelGUI"): the header across the top, the tree (260 px) and the tab group below. In a uifigure container it also sets the window name.
  • Nothing is cached: each render reads the model again, so it shows the current state.
  • DrawerModelGUI(a_target, h_container, f_model)（_auxiliary のクラス）: コンテナを検査（または uifigure を作成）し、コンテナと f_model を保持して render(a_target) を実行
  • render(a_target)（public）: モデルの GUI 全体を描画。ツリー、Initialize ボタン、埋め込み先のアプリが呼び出し。render() は表示中のモデルを再描画
  • 削除するのは前に自分が描いたものだけ: コンテナの子のうち Tag が "DrawerModelGUI" のものと、そのツリーのコンテキストメニュー（図が所有）。コンテナの他の部品は残存。uigridlayout のコンテナでは、新しいグリッドが古いグリッドの Layout（行と列）を継承
  • 続いて 2 × 2 の uigridlayout（Tag は "DrawerModelGUI"）を作成: 上段にヘッダ、下段にツリー（260 px）とタブグループ。uifigure のコンテナではウィンドウ名も設定
  • キャッシュなし: render のたびにモデルを読み直し、現在の状態を表示

Why f_modelf_model を使う理由

  • parent, children and gui_content are protected members of the model. DrawerModelGUI is outside the model hierarchy, so it cannot read them.
  • gui makes an anonymous function inside a method of PowerSystemModel; it keeps the access of the place where it was made: 
    f_model = @(o) struct("parent", {o.parent}, "children", {o.children}, "pages", {o.gui_content()});
  • DrawerModelGUI keeps it in a private property and calls it for every model it shows, including the nodes of the tree. The members stay protected; no public accessor is added for the GUI.
  • parent、children、gui_content はモデルの protected メンバー。DrawerModelGUI はモデルの継承階層の外にあるため、読み取り不可
  • gui が PowerSystemModel のメソッド内で無名関数を作成。無名関数は作った場所のアクセス権を保持: 
    f_model = @(o) struct("parent", {o.parent}, "children", {o.children}, "pages", {o.gui_content()});
  • DrawerModelGUI は private プロパティに保持し、表示するすべてのモデル（ツリーのノードを含む）で呼び出し。メンバーは protected のまま。GUI のための public なアクセサーは追加なし

Why KaTeX comes through DataKaTeX を Data で渡す理由

  • uihtml reads only files in the folder of its HTML file and the folders below it. latex_page.html is in @DrawerModelGUI/private/, and KaTeX is in _GUILDAdoc/vendor/katex/, so the page cannot load it by a path.
  • The local function katex_data of build_page.m reads katex.min.js and katex.min.css, embeds each woff2 font in the CSS as a data URI, and keeps the result in a persistent variable (read once per MATLAB session).
  • build_page passes it as Data with the fields s_js, s_css and sv_math. latex_page.html adds the style and the script to the page once, then draws each equation with katex.render in display mode.
  • One copy of KaTeX serves both the reference pages and the GUI; it works offline.
  • uihtml が読めるのは HTML ファイルのフォルダとその下のフォルダのファイルのみ。latex_page.html は @DrawerModelGUI/private/、KaTeX は _GUILDAdoc/vendor/katex/ にあるため、パスでの読み込みは不可
  • build_page.m のローカル関数 katex_data が katex.min.js と katex.min.css を読み、woff2 のフォントを data URI として CSS に埋め込み、persistent 変数に保持（MATLAB のセッションごとに 1 回の読み込み）
  • build_page はこれを Data（フィールド s_js、s_css、sv_math）として渡す。latex_page.html はスタイルとスクリプトを 1 回だけページに追加し、各数式を katex.render の display モードで描画
  • KaTeX の 1 つのコピーをリファレンスのページと GUI で共用。オフラインで動作

Embedding in another app別のアプリへの埋め込み

An app passes its own panel and switches the model with render. Here a list on the left chooses the network or a bus:

アプリは自分のパネルを渡し、render で表示するモデルを切り替え。次の例では左のリストでネットワークか母線を選択:

net = network.IEEE14bus();
net.initialize();
a_model = [{net}, net.a_Bus(:).'];
sv_name = cellfun(@(m) string(m.s_tag), a_model);

fig    = uifigure("Name", "Model viewer");
h_grid = uigridlayout(fig, [1 2], "ColumnWidth", {160, "1x"});
h_list = uilistbox(h_grid, "Items", sv_name, "ItemsData", 1:numel(a_model));
h_panel = uipanel(h_grid);

h = net.gui(h_panel);                                    % the GUI fills the panel
h_list.ValueChangedFcn = @(src, ~) h.render(a_model{src.Value});
  • The list and the panel belong to the app; render replaces only the GUI inside the panel.
  • A click in the tree of the GUI also calls render, so the panel may show a model that the list does not select; read h.a_target for the model shown.
  • Closing the figure deletes the GUI with it; render on a deleted container does nothing.
  • リストとパネルはアプリのもの。render が置き換えるのはパネル内の GUI のみ
  • GUI のツリーのクリックでも render が実行されるため、パネルにリストで選んでいないモデルが表示される場合あり。表示中のモデルは h.a_target で確認
  • 図を閉じると GUI も削除。削除されたコンテナへの render は何もしない

Where to extend the feature機能を拡張する箇所

  • A new model class: nothing to add; see What a model class writes for the GUI.
  • A page for every model of a kind: in gui_content of that abstract class (_GUILDAsystem/@<AbstractClass>/gui_content.m). Put the new pages first, then gui_content@PowerSystemModel(obj), and use only the four types above. The classdef declares it as methods(Access=protected) sct_page = gui_content(obj) end.
  • A page for every model: in _GUILDAsystem/_auxiliary/@PowerSystemModel/gui_content.m.
  • A new page type: a case of build_page and the list of types in the help of PowerSystemModel.gui_content.
  • Tests: +DebugScript/test_F32_model_gui.m and test_F33_model_gui_network.m build the GUI in hidden figures; an alert there becomes the HiddenAlert warning.
  • 新しいモデルクラス: 追加不要。モデルクラスが GUI のために書くものを参照
  • ある種類のすべてのモデルに共通のページ: その抽象クラスの gui_content（_GUILDAsystem/@<抽象クラス>/gui_content.m）。新しいページを先に置き、続いて gui_content@PowerSystemModel(obj)。種類は上の 4 つのみ。classdef には methods(Access=protected) sct_page = gui_content(obj) end と宣言
  • すべてのモデルに共通のページ: _GUILDAsystem/_auxiliary/@PowerSystemModel/gui_content.m
  • 新しいページの種類: build_page の case と、PowerSystemModel.gui_content の help の種類の一覧
  • テスト: +DebugScript/test_F32_model_gui.m と test_F33_model_gui_network.m が非表示の図で GUI を作成。そこでのアラートは警告 HiddenAlert に変化
