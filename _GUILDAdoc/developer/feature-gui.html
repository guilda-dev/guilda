GUI Feature DesignGUI 機能の設計

obj.gui() shows any model (network, bus, branch, component, controller) in a window: a breadcrumb from the root, its class and tag, a Docs button, the stale state, the children as cards, editable parameter tables and the equilibrium tables. The tables come from the six abstract classes, and the meaning of the parameters and the model is in the class reference that the Docs button opens, so a new model class needs no GUI code.

obj.gui(): 任意のモデル（ネットワーク、母線、ブランチ、機器、制御器）をウィンドウに表示する機能。表示内容はルートからのパンくず、クラスとタグ、Docs ボタン、stale 状態、子のカード、編集できるパラメータの表、平衡点の表。表は抽象クラス 6 つが作成し、パラメータとモデルの説明は Docs ボタンで開くクラスのリファレンスに掲載。そのため新しいモデルクラスには GUI 用のコードが不要。

What the feature does and how to call it機能の目的と呼び出し方

net = network.IEEE14bus();
h = net.a_Bus{1}.gui();     % a new uifigure
h = net.gui(h_container);   % fills h_container
  • gui(obj, h_container): public method of PowerSystemModel, so every network, bus, branch, component, local and global controller has it.
  • No container (or []): a new uifigure named after the class and the tag.
  • A container: the GUI fills a uifigure, uipanel, uitab or uigridlayout whose figure was made by uifigure(); the layout follows the size of the container.
  • Output: h, a DrawerModelGUI. h.a_target is the model shown, h.h_container the container; h.render(model) shows another model in the same place.
  • The GUI runs no function of the model other than writing parameters (no initialize or other analysis).
  • A figure made by figure() is rejected, also through a panel inside it (GUILDA:DrawerModelGUI:NotUIContainer):
    • the GUI is built from UI components (uigridlayout, uibutton, uihyperlink, uitable, uialert), which belong in a uifigure;
    • before R2025a a figure() does not take them; since R2025a it does, so the check reads the dynamic property isUIFigure, which only uifigure() adds. The same containers work in every release.
  • gui(obj, h_container): PowerSystemModel の public メソッド。ネットワーク、母線、ブランチ、機器、局所・広域制御器のすべてが保持
  • コンテナなし（または []）: クラス名とタグを名前にした新しい uifigure
  • コンテナあり: uifigure() で作った図の uifigure、uipanel、uitab、uigridlayout に展開。レイアウトはコンテナの大きさに追従
  • 出力: DrawerModelGUI の h。h.a_target は表示中のモデル、h.h_container はコンテナ。h.render(model) で同じ場所に別のモデルを表示
  • GUI がモデルに対して実行するのはパラメータの書き込みのみ。initialize などの関数は実行しない
  • figure() で作った図は対象外。その中のパネルも同様（GUILDA:DrawerModelGUI:NotUIContainer）:
    • GUI の部品は UI コンポーネント（uigridlayout、uibutton、uihyperlink、uitable、uialert）で、uifigure 用
    • R2025a より前の figure() には配置不可。R2025a 以降は配置可能なため、uifigure() だけが追加する動的プロパティ isUIFigure で判定。どのリリースでも使えるコンテナは同じ

Screen layout画面構成

  • Header: a band in the blue of the logo over a lime line.
    • Row 1, the breadcrumb: the models from the root to the model shown, joined by ›. Each of them but the model shown is a link; a click shows that model in the same container.
    • Row 2: the tag (bold), the class, the Docs button and the stale state. Docs runs GUILDA.doc("class", class(model)), which opens the reference page of the class. The stale state, from sct_stale, is Stale: none, or each stale tag with its first message and the number of the others, in warning colors.
  • Child cards: the children, grouped by kind in the order Bus, Branch, Component, LocalController, GlobalController (then any other model), each group under a label with its count. The Parameter containers are left out.
    • A card shows the kind, tag and class of a child, in the color of its kind.
    • A click shows that model in the same container; the context menu Open in new window calls gui() of that model.
    • The column scrolls when the cards do not fit. A model without children has no card column, and the tabs take the full width.
  • Tabs, in this order:
    1. Parameter: a line that points to the Docs for the meaning of each parameter, then one panel with an editable table per container of a_Parameter, titled by its s_tag. One column per parameter; the columns fit their contents and the table scrolls sideways when they do not fit. No parameters. when there is none.
    2. the tables of the abstract class (Summary, Equilibrium; see Pages of each abstract class). The equilibrium tables are vertical: one variable per row.
  • ヘッダ: ロゴの青の帯と、その下のライムの線
    • 1 行目はパンくず: ルートから表示中のモデルまでを › で連結。表示中のモデル以外はリンク。クリックでそのモデルを同じコンテナに表示
    • 2 行目: タグ（太字）、クラス、Docs ボタン、stale 状態。Docs は GUILDA.doc("class", class(model)) を実行し、クラスのリファレンスのページを表示。stale 状態は sct_stale から作成: Stale: none、または stale のタグごとに最初のメッセージと残りの件数（警告色）
  • 子カード: 子を種類ごとにまとめて表示。順は Bus、Branch、Component、LocalController、GlobalController（その他のモデルは最後）。各グループの上に件数付きのラベル。Parameter のコンテナは除外
    • カードの内容は子の種類、タグ、クラス。色は種類の色
    • クリックでそのモデルを同じコンテナに表示。コンテキストメニュー Open in new window でそのモデルの gui() を実行
    • カードが収まらない場合は列をスクロール。子のないモデルではカードの列なし、タブが全幅
  • タブ（この順）:
    1. Parameter: 各パラメータの意味は Docs を参照するよう促す 1 行と、a_Parameter のコンテナごとに編集できる表のパネル。題は s_tag。1 パラメータ 1 列の横並び。列幅は内容に合わせ、収まらない場合は横にスクロール。コンテナがない場合は No parameters.
    2. 抽象クラスの表（Summary、Equilibrium。抽象クラスごとのページを参照）。平衡点の表は 1 変数 1 行の縦並び

Theme and colorsテーマと配色

  • A fixed light theme based on the GUILDA logo. The colors do not follow the MATLAB theme: under a dark theme, colors set on some components and left to the theme on others would leave parts unreadable.
  • All colors are in one place, @DrawerModelGUI/private/gui_palette.m, which returns them as a struct of RGB triplets. Every part sets its colors (background, text, table rows) from it.
  • A new uifigure made by gui() gets Theme="light" where uifigure has a Theme property.
  • The theme of the figure of a given container is left as it is; the GUI does not change the app it is embedded in.
  • GUILDA のロゴをもとにした固定のライトテーマ。MATLAB のテーマには追従しない。ダークテーマで一部の部品だけ色を設定し、残りをテーマに任せると読めない箇所が生じるため
  • 色はすべて @DrawerModelGUI/private/gui_palette.m に集約。RGB の 3 要素の構造体で返却。各部品は背景、文字、表の行の色をここから設定
  • gui() が作る新しい uifigure: Theme プロパティがあれば Theme="light" を設定
  • 渡されたコンテナの図のテーマは変更しない。埋め込み先のアプリは変えない方針

Embedded in a figure with a dark theme, the tab titles and the header row of the tables take the colors of that theme: uitabgroup has no color property for its tab strip, and uitable none for its header row. The rest of the GUI keeps the light colors.

ダークテーマの図に埋め込んだ場合、タブの見出しと表の見出し行はそのテーマの色。uitabgroup にはタブの見出しの色の、uitable には見出し行の色のプロパティがないため。GUI の他の部分はライトの配色のまま。

Pages of each abstract class抽象クラスごとのページ

Each abstract class puts its own pages first, then those of PowerSystemModel, whose base implementation returns none. Every page is a read-only table. Values in the tables are as of the last net.initialize(); the header shows whether they are stale.

各抽象クラスは自分のページを先に置き、続いて PowerSystemModel のページ（基底の実装は空）。ページはすべて編集不可の表。表の値は最後の net.initialize() の時点のもの。古いかどうかはヘッダに表示。

What a model class writes for the GUIモデルクラスが GUI のために書くもの

Nothing. A class made from an abstract class (a new generator, load, controller, branch, network) adds no method or property for the GUI:

  • Tables: from the properties of the abstract class (sv_x, sv_u, the equilibrium, a_Parameter), which every model already fills.
  • Meaning of the parameters and the model: in the class reference, made from the class help as in Class Documentation; the Docs button opens it.

不要。抽象クラスから作るクラス（新しい発電機、負荷、制御器、ブランチ、ネットワーク）には、GUI のためのメソッドもプロパティも追加なし:

  • 表: 抽象クラスのプロパティ（sv_x、sv_u、平衡点、a_Parameter）から作成。どのモデルも設定済み
  • パラメータとモデルの説明: クラスのリファレンスに掲載。クラスのドキュメントに従って書いたクラスの help から作成。Docs ボタンで表示

Editing parametersパラメータの編集

  • An edited cell writes the whole table of its panel to tab_parameter of that Parameter container at once (edit_parameter); there is no Apply button.
  • Parameter does the rest, as for an edit from the command line: it checks the class, names, height and row names, logs only the changed values, and marks the layers stale (see Class Design: Handling of model edits). The GUI then refreshes the stale state of the header.
  • On an error, the table goes back to the stored values and an alert shows the message; nothing is stored.
  • The equilibrium tables are not editable and keep the values of the last initialize; the GUI does not run it. Run net.initialize() from the command line, then h.render() to show the new values.
  • セルを編集すると、そのパネルの表全体を Parameter コンテナの tab_parameter に即座に書き込み（edit_parameter）。適用ボタンなし
  • その後の処理は、コマンドラインからの編集と同じく Parameter が担当: クラス・名前・高さ・行名の検査、変更した値だけのログ、層の stale への反映（クラス設計: モデル編集の扱いを参照）。GUI はヘッダの stale 状態を更新
  • エラーの場合: 表を保存済みの値に戻し、アラートでメッセージを表示。何も保存しない
  • 平衡点の表は編集不可。値は最後の initialize の時点のもの。GUI からは実行しない。コマンドラインで net.initialize() を実行し、h.render() で新しい値を表示

How it works仕組み

Filesファイル

  • _GUILDAsystem/_auxiliary/@PowerSystemModel/gui.m: the entry; makes f_model and the DrawerModelGUI.
  • _GUILDAsystem/_auxiliary/@PowerSystemModel/gui_content.m (empty base) and _GUILDAsystem/@<AbstractClass>/gui_content.m: the page definitions.
  • _GUILDAsystem/_auxiliary/@DrawerModelGUI/: the UI. render.m draws a model; private/ holds the parts (build_header, build_navigation, build_parameter_tab, build_page, edit_parameter, update_stale, show_alert, is_ui_container) and the colors (gui_palette).
  • _GUILDAsystem/_auxiliary/@PowerSystemModel/gui.m: 入口。f_model と DrawerModelGUI を作成
  • _GUILDAsystem/_auxiliary/@PowerSystemModel/gui_content.m（空の基底）と _GUILDAsystem/@<抽象クラス>/gui_content.m: ページ定義
  • _GUILDAsystem/_auxiliary/@DrawerModelGUI/: UI。render.m がモデルを描画。private/ に部品（build_header、build_navigation、build_parameter_tab、build_page、edit_parameter、update_stale、show_alert、is_ui_container）と配色（gui_palette）

Page definitions: gui_contentページ定義: gui_content

  • sct_page = gui_content(obj) is a protected method. It returns a struct column, one element per tab after Parameter, with three fields:
    • s_title: tab name;
    • s_type: "table", the only page type;
    • content: a MATLAB table, drawn as a read-only uitable whose columns fit their contents.
  • The base implementation in PowerSystemModel returns an empty column. Only the six abstract classes override it; a model class implements nothing.
  • A page of another type shows the label Unknown page type: ... in its tab.
  • sct_page = gui_content(obj): protected メソッド。Parameter の後のタブ 1 つにつき 1 要素の構造体の列を返却。フィールドは 3 つ:
    • s_title: タブ名
    • s_type: "table"。ページの種類はこれのみ
    • content: MATLAB の table。列幅を内容に合わせた編集不可の uitable で描画
  • PowerSystemModel の基底の実装は空の列を返却。オーバーライドするのは抽象クラス 6 つのみ。モデルのクラスは何も実装しない
  • 他の種類のページ: タブに Unknown page type: ... のラベルを表示

DrawerModelGUI and renderDrawerModelGUI と render

  • DrawerModelGUI(a_target, h_container, f_model) (an _auxiliary class): checks the container (or opens a light-themed uifigure), keeps it and f_model, and calls render(a_target).
  • render(a_target) (public): draws the whole GUI of a model. The breadcrumb, the child cards and an embedding app call it; render() draws the shown model again.
  • It removes only what it drew before: the children of the container with Tag "DrawerModelGUI", and the context menu of their child cards (owned by the figure). Other components of the container stay. In a uigridlayout container the new grid takes the Layout (row and column) of the old one.
  • Then it follows the parents up to the root for the breadcrumb and builds a 2 × 2 uigridlayout (Tag "DrawerModelGUI"): the header across the top, the child cards (200 px) and the tab group below; without children the tab group spans both columns. In a uifigure container it also sets the window name.
  • Nothing is cached: each render reads the model again, so it shows the current state.
  • DrawerModelGUI(a_target, h_container, f_model)（_auxiliary のクラス）: コンテナを検査（またはライトテーマの uifigure を作成）し、コンテナと f_model を保持して render(a_target) を実行
  • render(a_target)（public）: モデルの GUI 全体を描画。パンくず、子カード、埋め込み先のアプリが呼び出し。render() は表示中のモデルを再描画
  • 削除するのは前に自分が描いたものだけ: コンテナの子のうち Tag が "DrawerModelGUI" のものと、その子カードのコンテキストメニュー（図が所有）。コンテナの他の部品は残存。uigridlayout のコンテナでは、新しいグリッドが古いグリッドの Layout（行と列）を継承
  • 続いて親をたどってルートまでのパンくずを求め、2 × 2 の uigridlayout（Tag は "DrawerModelGUI"）を作成: 上段にヘッダ、下段に子カード（200 px）とタブグループ。子がない場合はタブグループが 2 列にまたがる。uifigure のコンテナではウィンドウ名も設定
  • キャッシュなし: render のたびにモデルを読み直し、現在の状態を表示

Why f_modelf_model を使う理由

  • parent, children and gui_content are protected members of the model. DrawerModelGUI is outside the model hierarchy, so it cannot read them.
  • gui makes an anonymous function inside a method of PowerSystemModel; it keeps the access of the place where it was made: 
    f_model = @(o) struct("parent", {o.parent}, "children", {o.children}, "pages", {o.gui_content()});
  • DrawerModelGUI keeps it in a private property and calls it for every model it shows, and for each parent on the way to the root. The members stay protected; no public accessor is added for the GUI.
  • parent、children、gui_content はモデルの protected メンバー。DrawerModelGUI はモデルの継承階層の外にあるため、読み取り不可
  • gui が PowerSystemModel のメソッド内で無名関数を作成。無名関数は作った場所のアクセス権を保持: 
    f_model = @(o) struct("parent", {o.parent}, "children", {o.children}, "pages", {o.gui_content()});
  • DrawerModelGUI は private プロパティに保持し、表示するすべてのモデルと、ルートまでの各親で呼び出し。メンバーは protected のまま。GUI のための public なアクセサーは追加なし

Embedding in another app別のアプリへの埋め込み

An app passes its own panel and switches the model with render. Here a list on the left chooses the network or a bus:

アプリは自分のパネルを渡し、render で表示するモデルを切り替え。次の例では左のリストでネットワークか母線を選択:

net = network.IEEE14bus();
net.initialize();
a_model = [{net}, net.a_Bus(:).'];
sv_name = cellfun(@(m) string(m.s_tag), a_model);

fig    = uifigure("Name", "Model viewer");
h_grid = uigridlayout(fig, [1 2], "ColumnWidth", {160, "1x"});
h_list = uilistbox(h_grid, "Items", sv_name, "ItemsData", 1:numel(a_model));
h_panel = uipanel(h_grid);

h = net.gui(h_panel);                                    % the GUI fills the panel
h_list.ValueChangedFcn = @(src, ~) h.render(a_model{src.Value});
  • The list and the panel belong to the app; render replaces only the GUI inside the panel.
  • A click on a breadcrumb link or a child card also calls render, so the panel may show a model that the list does not select; read h.a_target for the model shown.
  • The theme of fig is not changed; with a dark theme, the tab titles and the header row of the tables take its colors (see Theme and colors).
  • Closing the figure deletes the GUI with it; render on a deleted container does nothing.
  • リストとパネルはアプリのもの。render が置き換えるのはパネル内の GUI のみ
  • パンくずのリンクや子カードのクリックでも render が実行されるため、パネルにリストで選んでいないモデルが表示される場合あり。表示中のモデルは h.a_target で確認
  • fig のテーマは変更なし。ダークテーマでは、タブの見出しと表の見出し行がその色（テーマと配色を参照）
  • 図を閉じると GUI も削除。削除されたコンテナへの render は何もしない

Where to extend the feature機能を拡張する箇所

  • A new model class: nothing to add; see What a model class writes for the GUI.
  • A table for every model of a kind: in gui_content of that abstract class (_GUILDAsystem/@<AbstractClass>/gui_content.m). Put the new pages first, then gui_content@PowerSystemModel(obj), and use only the type table. The classdef declares it as methods(Access=protected) sct_page = gui_content(obj) end.
  • A table for every model: in _GUILDAsystem/_auxiliary/@PowerSystemModel/gui_content.m.
  • A color: in gui_palette.m only; the parts read their colors from it.
  • Tests: +DebugScript/test_F32_model_gui.m and test_F33_model_gui_network.m build the GUI in hidden figures; an alert there becomes the HiddenAlert warning.
  • 新しいモデルクラス: 追加不要。モデルクラスが GUI のために書くものを参照
  • ある種類のすべてのモデルに共通の表: その抽象クラスの gui_content（_GUILDAsystem/@<抽象クラス>/gui_content.m）。新しいページを先に置き、続いて gui_content@PowerSystemModel(obj)。種類は table のみ。classdef には methods(Access=protected) sct_page = gui_content(obj) end と宣言
  • すべてのモデルに共通の表: _GUILDAsystem/_auxiliary/@PowerSystemModel/gui_content.m
