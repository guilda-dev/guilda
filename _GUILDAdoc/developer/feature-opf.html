Optimal Power Flow最適潮流計算

net.optimize_powerflow() finds the operating point that minimizes the generation cost under the operating limits. Each bus, component, and branch adds its own variables, costs, and constraints to one optimproblem, which the Optimization Toolbox solves; the solution comes back as a ResultOPF and the network is not changed.

net.optimize_powerflow() は、運用上の制約のもとで発電コストを最小にする運転点を求めます。母線・機器・ブランチがそれぞれ自分の変数・コスト・制約を 1 つの optimproblem に加え、Optimization Toolbox がそれを解きます。解は ResultOPF として返り、ネットワークは変更されません。

Side effects and caches副作用とキャッシュ

  • The network, the solver, and the edit state are not changed, and no cache is used: the problem is built from the current parameters on every call.
  • check_edit is not called and the equilibrium is not required, so an OPF runs on a network that was never initialized or was edited since.
  • set_opffcn and reset_opffcn are logged in tab_editLog with the tag OPF; edits of operation and OPF parameters are logged too. None of them makes the equilibrium stale (see Class Design: Edit handling).
  • The result keeps a reference to the network, not a copy; OPFprob.Description is the record of the settings at the time of the run.
  • ネットワーク、ソルバー、編集状態は変更せず、キャッシュも使いません。問題は呼び出しのたびに現在のパラメータから組み立てます。
  • check_edit を呼ばず、平衡点も要求しません。初期化されていない、またはその後に編集されたネットワークでも OPF は実行できます。
  • set_opffcn と reset_opffcn はタグ OPF で tab_editLog に記録され、operation と OPF のパラメータの編集も記録されます。いずれも平衡点を古くしません（クラス設計: 編集の扱い を参照）。
  • 結果はネットワークのコピーではなく参照を持ちます。実行時の設定の記録は OPFprob.Description です。

Failure and flags失敗とフラグ

An unsolved problem is not an error: flag is the exit flag of solve (an optim.problemdef.ExitFlag such as OptimalSolution, or a number), result.l_success is true only when it is positive, output.message describes the outcome, and the tables are built from the last point the solver returned. Errors stop the call before or during the build:

解けなかった問題はエラーになりません。flag は solve の終了フラグ（OptimalSolution などの optim.problemdef.ExitFlag、または数値）で、result.l_success はそれが正のときだけ true です。output.message が結果を説明し、表はソルバーが返した最後の点から作られます。エラーは問題の組み立て前か組み立て中に呼び出しを止めます。
