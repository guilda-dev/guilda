Optimal Power Flow Feature Design最適潮流計算機能の設計

net.optimize_powerflow() finds the operating point of least generation cost within the operating limits. Buses, components, and branches each add their variables, costs, and constraints to one optimproblem; the Optimization Toolbox solves it. Output: a ResultOPF; the network is unchanged.

net.optimize_powerflow(): 運用上の制約のもとで発電コスト最小の運転点を求める機能。母線・機器・ブランチがそれぞれの変数・コスト・制約を 1 つの optimproblem に追加し、Optimization Toolbox が求解。出力は ResultOPF、ネットワークは不変。

Preconditions:

  • the Optimization Toolbox;
  • components: tab_parameter.OPF (cost HP·P² + fP·P + HQ·Q² + fQ·Q, initial point P0, Q0) and tab_parameter.operation (limits);
  • buses: operation (Vmin, Vmax) and powerflow (V0, Varg0, Varg);
  • branches: operation (Pmax, Qmax, Imax, Smax, Vargmax).

No initialize needed; the edit state is not checked. User terms: set_opffcn (see Class Design: OPF customization by models).

前提条件:

  • Optimization Toolbox
  • 機器: tab_parameter.OPF（コスト HP·P² + fP·P + HQ·Q² + fQ·Q、初期点 P0、Q0）と tab_parameter.operation（制約）
  • 母線: operation（Vmin、Vmax）と powerflow（V0、Varg0、Varg）
  • ブランチ: operation（Pmax、Qmax、Imax、Smax、Vargmax）

initialize は不要、編集状態も未確認。ユーザー定義の項は set_opffcn で設定（クラス設計: モデルによる OPF のカスタマイズ を参照）。

Side effects on the model and cachesモデルへの副作用とキャッシュ

  • Network, solver, and edit state unchanged; no cache: the problem is built from the current parameters on every call.
  • No check_edit, no equilibrium needed: runs on a network never initialized or edited since.
  • set_opffcn and reset_opffcn are logged in tab_editLog with the tag OPF; edits of operation and OPF parameters are logged too. None of them makes the equilibrium stale (see Class Design: Handling of model edits).
  • The result keeps a reference to the network, not a copy. Record of the settings of the run: OPFprob.Description.
  • ネットワーク、ソルバー、編集状態は不変。キャッシュも不使用。問題は呼び出しごとに現在のパラメータから構築
  • check_edit の呼び出しなし、平衡点も不要。未初期化のネットワークや初期化後に編集したネットワークでも実行可能
  • set_opffcn と reset_opffcn はタグ OPF で tab_editLog に記録。operation と OPF のパラメータの編集も記録。いずれも平衡点を古くしない（クラス設計: モデル編集の扱い を参照）
  • 結果が持つのはネットワークのコピーではなく参照。実行時の設定の記録は OPFprob.Description

Failure behavior and result flags失敗時の動作と結果フラグ

An unsolved problem is not an error:

  • flag: the exit flag of solve (an optim.problemdef.ExitFlag such as OptimalSolution, or a number);
  • result.l_success: true only when it is positive; output.message describes the outcome;
  • the tables: built from the last point the solver returned.

Errors stop the call before or during the build:

解けなかった問題はエラーにならない:

  • flag: solve の終了フラグ（OptimalSolution などの optim.problemdef.ExitFlag、または数値）
  • result.l_success: フラグが正のときのみ true。output.message に結果の説明
  • 表: ソルバーが返した最後の点から作成
