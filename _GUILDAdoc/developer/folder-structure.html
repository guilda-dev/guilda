Folder Structure

GUILDA separates the startup utility, the analysis framework, concrete models, tutorials, and documentation into top-level folders. This page describes what each folder contains, which folders are on the MATLAB path, and where new files should be placed.

The folders added to the path are listed in @GUILDA/config/ListPath.txt and are added by GUILDA.addpath. Subfolders that are not listed there are reachable only through MATLAB's class-folder and package mechanisms.

@GUILDA/

The GUILDA class. Its constructor runs the startup sequence (logo, git pull, addpath, toolbox check, documentation update, key-map update, tutorial). Each startup step can be switched in the startup settings.

PathContents
GUILDA.mClass definition and startup sequence.
*.mStatic methods: pwd, addpath, rmpath, gitpull, setting, config, tutorial, doc, dictionary.
private/Internal functions: configuration I/O (get_config, set_config, merge_config), check_requirement, export_class_database (documentation database), update_class_signature (key map).
config/System defaults shipped with GUILDA: Default*.json settings, ListPath.txt, ListToolbox.txt (the required toolboxes that startup checks), logo text and image. config/archive/ keeps retired settings files.
user/Per-user overrides of config/Default*.json. Written by GUILDA.setting and merged over the defaults at startup. Ignored by Git.

Note: Files in private/, config/, and user/ are read and written by the system. Edit config/ only when changing the shipped defaults, and never commit user/.

_GUILDAsystem/

The analysis framework. Code here should not depend on any concrete model in _GUILDAobject.

Core model classes

FolderClassRole
@PowerNetwork/PowerNetworkTop-level model. Holds buses, branches, and global controllers; runs power flow, OPF, simulation, and linearization.
@Bus/BusNode of the network. Holds components through cubicles.
@Branch/BranchBase class of transmission lines and transformers.
@Component/ComponentBase class of generators, loads, and other devices connected to a bus.
@LocalController/LocalControllerBase class of controllers attached to a single component.
@GlobalController/GlobalControllerBase class of controllers that observe and act on several components.

Other folders

FolderContents

Layout of a network template

+network/@IEEE14bus/
├── IEEE14bus.m             classdef IEEE14bus < PowerNetwork
├── bus/parameter.csv
├── branch/parameter.csv
└── component/
    ├── gen-park/           one folder per component key
    │   ├── main.csv
    │   ├── dynamics.csv
    │   └── opf.csv
    └── load-power/

Component data folders are named after the key constant of the component class (e.g. component.generator.park has key = "gen-park").

Layout of a model class

A model with several methods uses a class folder, with one method per file. Small models may be a single classdef file.

+component/+generator/@park/
├── park.m                  classdef park < component.generator.abstract
├── fcn_dx.m  fcn_I.m  fcn_Y.m  fcn_Mass.m
├── Jacobi_dx.m  Jacobi_I.m  Jacobi_Y.m
└── get_equilibrium.m

Placement rules for new files

What you addWhere
A new generator, load, branch, or controller modelThe matching package in _GUILDAobject/. Create a sub-package when a family of models shares a base class.
A new network template_GUILDAobject/+network/@Name/ with bus/, branch/, and component/<key>/ data folders.
A change to the model frameworkThe core class folder in _GUILDAsystem/.
A new analysis or support class_GUILDAsystem/_auxiliary/@Name/, inheriting from auxiliary.
A general-purpose helper function_GUILDAsystem/+tools/.
A helper used by one class onlyThat class's private/ folder.
A renamed or removed public APIA wrapper in _GUILDAsystem/_VersionSupport/.
A new tutorial_GUILDAtutorial/, and register it in _GUILDAdoc/database/list_Tutorials.js.
Retired code kept for referenceAn archive/ folder next to the original location (see below).

Legacy and archived folders

Code that is no longer used but kept for reference goes into a folder named archive/ placed next to its original location. Because archive/ has no @ or + prefix, it is not on the MATLAB path inside class and package folders. Do not use other names such as history, _past, _origin, or a 未 prefix.
