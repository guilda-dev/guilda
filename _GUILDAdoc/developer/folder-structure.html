_GUILDAsystem/ framework

Must not depend on any concrete model in _GUILDAobject. Two class families:

Core model classes

@PowerNetwork/

Top-level model. Holds buses, branches, and global controllers; runs power flow, OPF, simulation, and linearization.

@Bus/

Node of the network. Holds components through cubicles.

@Branch/

Base class of transmission lines and transformers.

@Component/

Base class of generators, loads, and other devices connected to a bus.

@LocalController/

Base class of controllers attached to a single component.

@GlobalController/

Base class of controllers that observe and act on several components.

Placement rules for new files

What are you adding?
  1. A new generator, load, branch, or controller model
    →
    _GUILDAobject/+<package>/the matching package; make a sub-package when a family of models shares a base class
  2. A new network template
    →
    _GUILDAobject/+network/@Name/with bus/, branch/, component/<key>/ data folders
  3. A change to the model framework
    →
    _GUILDAsystem/@<CoreClass>/the core class folder
  4. A new analysis or support class
    →
    _GUILDAsystem/_auxiliary/@Name/inheriting from auxiliary
  5. A helper function
    used by one class only?
    →
    yes<that class>/private/
    no_GUILDAsystem/+tools/
  6. A renamed or removed public API
    →
    _GUILDAsystem/_VersionSupport/a wrapper under the old name
  7. A new tutorial
    →
    _GUILDAtutorial/and register it in _GUILDAdoc/database/list_Tutorials.js
  8. Retired code kept for reference
    →
    archive/next to the original location (see Legacy)

Generated files — do not edit

These are rewritten by the system. Edit the green source, never the red output.

@Bus/add_component.m

✕ do not edit_GUILDAdoc/database/list_Classes.js and class files
✎ changesettings changed by the user
runsGUILDA.setting
✕ do not edit@GUILDA/user/*.json

All outputs above are listed in .gitignore.
