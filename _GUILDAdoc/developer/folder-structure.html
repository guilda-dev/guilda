Overview概要

Top-level foldersトップレベルのフォルダ

@GUILDA/via repository rootリポジトリルート経由

Entry point of the toolbox. Running >> GUILDA prepares the environment.ツールボックスのエントリポイント。>> GUILDA の実行で環境を準備。

Belongs here置くもの
Environment setup, user settings and their shipped defaults, and commands that open the tutorials and this documentation.環境設定、ユーザー設定とその既定値、チュートリアルとこのドキュメントを開くコマンド。
Relation関係
Puts the other code folders on the MATLAB path. Contains no power system modeling or analysis.他のコードフォルダを MATLAB パスに追加。電力系統のモデリングや解析は含まない。
_GUILDAsystem/on pathパス上

The modeling framework.モデリングのフレームワーク。

Belongs here置くもの
Base classes that define what a network, bus, branch, component, and controller are; the classes that perform analysis; general helper functions; wrappers that keep deprecated names working.ネットワーク、母線、ブランチ、機器、制御器を定義する基底クラス、解析を行うクラス、汎用の補助関数、非推奨の名前を動かし続けるラッパー。
Core classesコアクラス
@PowerNetwork, @Bus, @Branch, @Component, @LocalController, @GlobalController.
Support classes補助クラス
In _auxiliary/:_auxiliary/ 内:
  • Class categoriesクラスカテゴリ: LayerPackage, PowerSystemModel, auxiliary, @Parameter
  • Solversソルバー: @SolverPF, @NewtonRaphsonMethod, @SolverOPF, @SolverCPF, @SolverODE, @Scenario (the disturbances of a simulation, owned by a network)（ネットワークが所有するシミュレーションの外乱）, @ProgressODE, @SolverLIN
  • Result classes結果クラス: @ResultBase and its subclassesとそのサブクラス @ResultPF, @ResultOPF, @ResultCPF, @ResultODE, @ResultLIN
  • Drawing描画: @DrawerNetDiagram
Otherその他
+tools/ helpers; _VersionSupport/ wrappers for deprecated names (e.g. Continuation_Power_Flow → net.calculate_continuation_powerflow, CsvNetHandler → PowerNetwork.import_csv / net.export_csv, ODEevent → Scenario).+tools/ の補助関数、_VersionSupport/ の非推奨の名前のラッパー（例: Continuation_Power_Flow → net.calculate_continuation_powerflow、CsvNetHandler → PowerNetwork.import_csv / net.export_csv、ODEevent → Scenario）。
Relation関係
Depends on no concrete model in _GUILDAobject, so models can be added or removed without touching the framework. Network import and export are methods of PowerNetwork, not separate classes._GUILDAobject の具体的なモデルには非依存。フレームワークに手を加えずにモデルを追加・削除可能。ネットワークのインポートとエクスポートは独立したクラスではなく PowerNetwork のメソッド。
_GUILDAobject/on pathパス上

Concrete models that users put into a network.ユーザーがネットワークに組み込む具体的なモデル。

Belongs here置くもの
  • Model classes, grouped into packages by kind (branch / component / controller / network); sub-packages for model families that share a base class.種類（branch / component / controller / network）ごとのパッケージにまとめたモデルクラス。基底クラスを共有するモデル群はサブパッケージ。
  • A network template: a class that builds the network in its constructor, usually a class folder with data subfolders per element type.ネットワークテンプレート: コンストラクタでネットワークを組み立てるクラス。通常は要素の種類ごとのデータのサブフォルダを持つクラスフォルダ。
Networksネットワーク
Bundled templates:同梱のテンプレート:
  • IEEE9bus, IEEE14bus (the MATPOWER case14 data)（MATPOWER の case14 のデータ）, IEEE14bus_NoTap (transformer taps at 1)（変圧器タップを 1 に固定）, IEEE14bus_lossless (R = 0), IEEE68bus
  • IEEJ standard models電気学会標準モデル IEEJ_EAST10, IEEJ_EAST30, IEEJ_WEST10, IEEJ_WEST30: a peak/ and a night/ folder each, chosen with Section: それぞれ peak/ と night/ のフォルダ、Section で選択
  • Each constructor loads its own folder with PowerNetwork.import_csv(dir, Network=obj).各コンストラクタは PowerNetwork.import_csv(dir, Network=obj) で自身のフォルダを読み込み。
Relation関係
Every model inherits from a base class in _GUILDAsystem.すべてのモデルは _GUILDAsystem の基底クラスを継承。
_GUILDAtutorial/on pathパス上

Learning material for users.ユーザー向けの学習教材。

Belongs here置くもの
Live scripts that walk through using GUILDA, and reference scripts per model family.GUILDA の使い方を順を追って説明するライブスクリプトと、モデル群ごとの参考スクリプト。
Relation関係
Uses only the public API of _GUILDAsystem and _GUILDAobject; opened from @GUILDA. Each tutorial is listed in the documentation._GUILDAsystem と _GUILDAobject の公開 API だけを使用。@GUILDA から開く。各チュートリアルはドキュメントに掲載。
_GUILDAdoc/not on pathパス外

This documentation site, viewed in a browser.ブラウザで閲覧する、このドキュメントサイト。

Belongs here置くもの
Hand-written pages, styles, and lists, plus a class reference generated from the help comments in the MATLAB source.手書きのページ、スタイル、一覧と、MATLAB ソースのヘルプコメントから生成するクラスリファレンス。
Relation関係
Reads the code folders but is never called by them. Opened from @GUILDA.コードフォルダを参照するが、コードフォルダからは呼び出されない。@GUILDA から開く。
_GUILDAverification/not on pathパス外

Verification of the bundled models against published results, one subfolder per network.同梱のモデルを公表された結果と比較して検証。ネットワークごとに 1 つのサブフォルダ。

Belongs here置くもの
For each network (details in its README.md):ネットワークごとに（詳細はその README.md）:
  • README.md: the literature reference (link and bibliographic data only, never a copy of the paper or its figures), the criterion, the modelling differences, the latest measured agreementREADME.md: 文献の参照（リンクと書誌情報のみ。論文や図のコピーは置かない）、判定基準、モデル化の違い、最新の一致状況
  • The cases as Scenario CSV files; the published verdicts as CSVScenario の CSV ファイルとしてのケース、公表された判定の CSV
  • A comparison function比較用の関数
Relation関係
Uses the public API of _GUILDAsystem and _GUILDAobject and is never called by them. Kept in releases. Not on the path: run a comparison with run(...) or after cd into its subfolder._GUILDAsystem と _GUILDAobject の公開 API を使用し、それらからは呼ばれない。リリースにも含める。パス外のため、比較は run(...) で、またはそのサブフォルダに cd してから実行。
_GUILDAexport/not on pathパス外Git-ignoredGit 管理外

Default output folder for exported data.エクスポートしたデータの既定の出力フォルダ。

Belongs here置くもの
Files written by GUILDA's export functions. Nothing hand-written.GUILDA のエクスポート関数が書き出すファイル。手書きのファイルは置かない。
Relation関係
Created on demand; safe to delete.必要に応じて作成。削除しても問題なし。

Inside a class or package folder, a subfolder without an @ or + prefix is not on the path: for data or archived code only. A class folder keeps one method per file; a small model may be a single classdef file instead.クラスフォルダやパッケージフォルダの中で @ や + の接頭辞がないサブフォルダはパス外。データやアーカイブしたコード専用。クラスフォルダは 1 ファイル 1 メソッド。小さなモデルは単一の classdef ファイルでも可。

The generated class reference in _GUILDAdoc/database/ is never committed to source branches. It reaches the web only through the gh-pages branch, which GUILDA.publish_doc builds and pushes (see Publishing the documentation)._GUILDAdoc/database/ に生成されるクラスリファレンスは、ソースブランチには一切コミットしない。Web への公開は gh-pages ブランチ経由のみ。このブランチは GUILDA.publish_doc がビルドしてプッシュ（ドキュメントの公開 を参照）。

Archived codeアーカイブ

  • Code kept for reference only goes into a folder named archive/ next to its original location.参照用にだけ残すコードは、元の場所の隣の archive/ フォルダへ。
  • With no @ or + prefix, it stays off the MATLAB path inside class and package folders.@ や + の接頭辞がないため、クラスフォルダやパッケージフォルダの中では MATLAB パス外。
  • No other name or marker for unused or unfinished code.使わないコードや未完成のコードに、これ以外の名前や目印は不可。
