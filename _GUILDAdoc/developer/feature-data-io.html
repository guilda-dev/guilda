Data Import and Export Feature Designデータの入出力機能の設計

Reads a network and its scenarios from a model folder (CSV tables and scenario JSON files), or a network from a MATPOWER case; writes them to a model folder or a MATPOWER case struct. The importers check the input, then build the network through the public add_* methods, so an imported network is the same as one built by hand.

ネットワークとそのシナリオは、モデルフォルダ（CSV の表とシナリオの JSON ファイル）から読み込めます。ネットワークは MATPOWER のケースからも読み込めます。書き出し先は、モデルフォルダか MATPOWER のケース構造体です。読み込みでは、まず入力を検査し、それから公開の add_* メソッドでネットワークを組み立てます。そのため、読み込んだネットワークは手で組み立てたネットワークと変わりません。

  • Defaults: the arguments blocks of these functions; no solver_* setting used
  • Outputs: the network, the folder path or the struct, not [result, flag, output]; a failure is an error
  • mpc of import_matpower: a struct, a case name on the path ("case14"), a .m or .mat file, or a function handle
  • MATPOWER itself not needed
  • import is a static method: call it as PowerNetwork.import(path) (the function form import(net, path) is the MATLAB import statement); net.export(path) and export(net, path) both work
  • Scenarios: net.export writes each scenario of net.a_Scenario to scenario/<tag>.json; PowerNetwork.import adds the scenarios of the folder (see Scenario files)
  • CsvNetHandler.import(path, net, Initialize=tf) and CsvNetHandler.export(net, ModelName, savepath=d): call import / export and warn that they are deprecated
  • オプションの既定値は、各関数の arguments ブロックで決めています。solver_* の設定は使いません。
  • 戻り値はネットワーク、フォルダのパス、構造体のどれかで、[result, flag, output] の形ではありません。失敗したときはエラーになります。
  • import_matpower の mpc には、構造体、パス上のケース名（"case14"）、.m や .mat のファイル、関数ハンドルのどれでも渡せます。
  • MATPOWER 本体をインストールする必要はありません。
  • import は静的メソッドなので、PowerNetwork.import(path) の形で呼びます（関数形式の import(net, path) は MATLAB の import 文になります）。net.export(path) と export(net, path) はどちらも使えます。
  • シナリオは、net.export が net.a_Scenario の各シナリオを scenario/<tag>.json に書き出し、PowerNetwork.import がフォルダのシナリオを加えます（シナリオのファイルを参照）。
  • CsvNetHandler.import(path, net, Initialize=tf) と CsvNetHandler.export(net, ModelName, savepath=d) は、非推奨の警告を出したうえで import / export を呼びます。

Preconditions:

前提条件は次のとおりです。

  • GUILDA already run, so that add_branch and add_component know the model keys used in the files
  • For export: the parent folder exists
  • 先に GUILDA を実行しておく必要があります。そうしないと、ファイルに書かれたモデルのキーを add_branch と add_component が認識できません。
  • export では、書き出し先の親フォルダがあらかじめ存在している必要があります。

    • component/<key>/ の各サブフォルダから main.csv を読み込みます。名前が . で始まるフォルダは飛ばします。
    • main.csv に ParameterID があれば dynamics.csv、OpfID があれば opf.csv を読み込みます。
    • 列、母線の行番号、各 ID が参照先のファイルにあることを検査します。
    • component フォルダがない場合は警告します。
    • read_scenarios は、scenario/*.json をファイル名の順にすべて読みます（scenario フォルダがなければシナリオはありません）。Format、version、Time、Description、Disturbances の形、各外乱の Tag を検査します（GUILDA:PowerNetwork:ScenarioJson）。未知の項目は警告 GUILDA:PowerNetwork:UnknownScenarioField を出して取り除きます。

    What it does処理内容

    • Then sets FullTag
    • キーのフォルダごと、行ごとに、Bus が指す母線で add_component(key, "P", P, "Q", Q, ...) を呼びます。
    • 任意列も渡します。opf.csv からは、同じ OpfID を持つ行の OPF 列 8 つを渡します。

  8. IO-08 import → Bus.l_isSlack, PowerNetwork.add_scenario, Scenario.add_from_json_struct

    What it does処理内容
    • Runs after the components exist
    • First bus row whose Slack is 1 (or the text "1" / "true") becomes the slack bus
    • Runs inside evalc so that the SetSlack message is not printed
    • Then, for each scenario file in the order of the file names: net.add_scenario(<file name>) (a tag in use gets a number suffix) and sc.add_from_json_struct, which sets Time and Description and adds each disturbance by add_disturbance with its fields as options, so it is checked against the components as when added by hand
    • 機器の作成後に実行します。
    • Slack が 1（または文字列 "1" / "true"）である最初の母線の行を slack 母線に設定します。
    • SetSlack のメッセージを表示しないよう、evalc の中で実行します。
    • 続いて、シナリオのファイルごとにファイル名の順で net.add_scenario(<ファイル名>)（使用中のタグには番号が付きます）と sc.add_from_json_struct を呼びます。add_from_json_struct は Time と Description を設定し、各外乱を、その項目をオプションにした add_disturbance で加えます。そのため、手で加えたときと同じように機器と照らし合わせて検査します。

    tab_bus.Slack, the scenario files of IO-03IO-03 で読んだシナリオのファイル
    Returns or changes戻り値・変更する値
    l_isSlack (see MB-08)（MB-08 参照）, net.a_Scenario

    What it does処理内容

    • Network classes pass false and add their controllers first
    • Initialize=true（既定値）のときだけ実行します。
    • ネットワーククラスは false を渡し、先に制御器を追加します。

  10. IO-10 caller呼び出し側 → PowerNetwork.export

    What it does処理内容

    • Checks the class name (when ClassFile), the parent folder and an existing folder
    • Overwrite=true: deletes only the subfolders network, bus, branch, component, scenario and the class file
    • Then creates the four subfolders
    • 末尾の区切り文字を除去します。
    • クラス名（ClassFile のとき）、親フォルダ、既存のフォルダを検査します。
    • Overwrite=true のときは、サブフォルダ network、bus、branch、component、scenario とクラスファイルだけを削除します。
    • その後 4 つのサブフォルダを作成します。
    What it reads読み取る情報
    path, opt
    Returns or changes戻り値・変更する値
    folders on diskディスク上のフォルダ

  11. IO-11 export → bus_table, branch_table, writetable

    What it does処理内容
    • Writes the base values
    • One bus row per a_Bus entry (Tag = tag without trailing digits, Slack = 0/1)
    • One branch row per a_Branch entry (Type = key, From/To = row numbers of the end buses)
    • 基準値を書き出します。
    • a_Bus の要素ごとに母線の行を書き出します（Tag = 末尾の数字を除いたタグ、Slack = 0/1）。
    • a_Branch の要素ごとにブランチの行を書き出します（Type = キー、From/To = 両端の母線の行番号）。
    What it reads読み取る情報
    tab_parameter.base; bus母線の tab_parameter.powerflow, tab_parameter.operation, tab_parameter.dynamics, tab_parameter.graph, l_isSlack; branchブランチの key, a_Bus, tab_parameter
    Returns or changes戻り値・変更する値
    network/parameter.csv, bus/parameter.csv, branch/parameter.csv

  12. IO-12 export → component_table, writetable, write_scenarios

    What it does処理内容
    • Groups the components by key
    • Distinct dynamics rows and distinct OPF rows (unique(..., "rows", "stable")) become dynamics.csv and opf.csv
    • main.csv refers to them by ParameterID and OpfID
    • write_scenarios: each scenario to scenario/<tag>.json (Scenario.to_json_struct, jsonencode(..., PrettyPrint=true, ConvertInfAndNaN=false)); without scenarios no folder is made
    • 機器をキーごとに分類します。
    • 重複のない dynamics の行と OPF の行（unique(..., "rows", "stable")）を dynamics.csv と opf.csv に出力します。
    • main.csv は ParameterID と OpfID でそれらを参照します。
    • write_scenarios は、各シナリオを scenario/<tag>.json に書き出します（Scenario.to_json_struct、jsonencode(..., PrettyPrint=true, ConvertInfAndNaN=false)）。シナリオがなければフォルダは作りません。
    What it reads読み取る情報
    component機器の key, a_Bus, tab_parameter.powerflow, tab_parameter.operation, tab_parameter.graph, tab_parameter.dynamics, tab_parameter.OPF; net.a_Scenario
    Returns or changes戻り値・変更する値
    component/<key>/main.csv, dynamics.csv, opf.csv; scenario/<tag>.json

  13. IO-13 export → class_file, warn_controllers_not_saved

    What it does処理内容

    • Its constructor calls PowerNetwork.import(folder, Network=obj)
    • Then warns with the list of local controllers (as component/avr/pss paths) and global controllers that are not written
    • ClassFile が true なら、private/export_class.txt をひな形にして <Name>.m を書き出します。ファイルには、クラス名、日付、母線・ブランチ・発電機・負荷・その他の機器の数が入ります。
    • このクラスのコンストラクタは、PowerNetwork.import(folder, Network=obj) を呼んでネットワークを組み立てます。
    • 最後に、書き出されないローカル制御器（component/avr/pss の形のパスで示します）とグローバル制御器を並べて警告します。
    What it reads読み取る情報
    a_Bus{:}.a_Component, a_LocalController, a_GlobalController
    Returns or changes戻り値・変更する値
    <Name>.m; warning警告 GUILDA:PowerNetwork:ControllersNotSaved; path

    • Checks that the bus numbers in gen and branch exist and that no bus has type 4
    • 入力をケース構造体とケース名に変換します。.m ファイルを渡した場合は、呼び出しの間だけそのフォルダをパスに加えます。
    • フィールド baseMVA、bus、gen、branch があるかを検査します。
    • version が 1 でないこと、列数が bus で 13、gen で 10、branch で 13 以上あることを検査します。
    • gen と branch の母線番号が存在し、種類 4 の母線がないことを確認します。

  16. IO-16 import_matpower → gen_costs (local)（内部）

    What it does処理内容
    • Converts polynomial costs (MODEL 2, at most quadratic) in MW to per unit: HP = c2*baseMVA^2, fP = c1*baseMVA
    • Rows ng+1:2*ng give HQ, fQ
    • STARTUP and SHUTDOWN copied as is
    • Constant c0 dropped with a warning
    • MW 単位の多項式コスト（MODEL 2、2 次まで）を、HP = c2*baseMVA^2、fP = c1*baseMVA として単位法に直します。
    • ng+1:2*ng 行目があれば、無効電力のコスト HQ と fQ になります。
    • STARTUP と SHUTDOWN はそのまま複写します。
    • 定数 c0 は警告を出して破棄します。
    What it reads読み取る情報
    mpc.gencost (optional)（任意）
    Returns or changes戻り値・変更する値
    rm_cost (ng×6: HP, fP, HQ, fQ, startup, shutdown) or emptyまたは空

  17. IO-17 import_matpower → PowerNetwork.add_bus

    What it does処理内容
    • One bus per mpc.bus row, in row order
    • V = VG of the first in-service generator of the bus (VM without one)
    • Varg = VA in rad
    • Gshunt/Bshunt = GS/BS ÷ baseMVA; Vmin, Vmax, baseKV
    • Bus numbers serve only to resolve gen and branch rows
    • mpc.bus の行ごとに、行の順で母線を作成します。
    • V = その母線で最初に運転中の発電機の VG（なければ VM）
    • Varg = VA [rad]
    • Gshunt/Bshunt = GS/BS ÷ baseMVA、Vmin、Vmax、baseKV
    • 母線番号は gen と branch の行の解決にだけ使います。
    What it reads読み取る情報
    mpc.bus, mpc.gen
    Returns or changes戻り値・変更する値
    a_Bus (B001, B002, ...)

  18. IO-18 import_matpower → Bus.add_component, Bus.l_isSlack

    What it does処理内容
    • First a GeneratorModel per in-service gen row: P = PG/baseMVA, Q = NaN, baseMVA = MBASE, limits ÷ baseMVA, OPF initial values PG/QG ÷ baseMVA, costs of IO-16, parameter = GeneratorParameter
    • Then a LoadModel on each bus with nonzero PD or QD: P = −PD/baseMVA, Q = −QD/baseMVA, cost 0
    • First REF bus (type 3) becomes the slack bus
    • まず、運転中の gen の行ごとに GeneratorModel を追加します。値は P = PG/baseMVA、Q = NaN、baseMVA = MBASE とし、上下限と OPF の初期値（PG/QG）は baseMVA で割ります。コストには IO-16 の結果を、parameter には GeneratorParameter を渡します。
    • 次に、PD か QD が 0 でない母線ごとに LoadModel を追加します。値は P = −PD/baseMVA、Q = −QD/baseMVA で、コストは 0 です。
    • 最初の REF 母線（種類 3）を slack 母線に設定します。
    What it reads読み取る情報
    mpc.gen, mpc.bus, rm_cost, opt.GeneratorModel, opt.LoadModel
    Returns or changes戻り値・変更する値
    a_Component, l_isSlack

  19. IO-19 import_matpower → PowerNetwork.add_branch

    What it does処理内容
    • One branch per in-service row
    • Type: "pi" when TAP is 0 or 1 and SHIFT is 0, else "pi_transformer" (tap at the from end)
    • R, X, C = BR_B/2, Tap, Phase = SHIFT in rad
    • Smax = RATE_A/baseMVA (0 → Inf)
    • Vargmax = the smaller of |ANGMIN| and |ANGMAX| below 360° (Inf when both are 0 or ≥ 360°)
    • 運転中の行ごとにブランチを作成します。
    • TAP が 0 か 1 で、SHIFT が 0 のブランチは "pi" にします。それ以外は "pi_transformer" にし、タップは from 側に置きます。
    • R、X、C = BR_B/2、Tap、Phase = SHIFT [rad]
    • Smax = RATE_A/baseMVA（0 → Inf）
    • Vargmax = 360° 未満の |ANGMIN| と |ANGMAX| の小さい方（両方 0 または 360° 以上なら Inf）

  21. IO-21 caller呼び出し側 → tools.network_to_mpc

    What it does処理内容
    • Bus row i = a_Bus{i}: type PQ, PV when it has a non-load component, REF at tools.slack_bus_index (VA = its Varg)
    • VM/VA = |c_Vequilibrium|/angle(c_Vequilibrium) of the bus (1/0 before initialize)
    • Loads (component.load.abstract) add −P, −Q to PD/QD
    • Every other component: a gen row with PG/QG = OPF P0/Q0, VG = bus V (1 when NaN), limits and polynomial costs (c2 = HP/baseMVA^2, c1 = fP/baseMVA)
    • Each branch fitted from its 2×2 matrix to R, X, B, TAP, SHIFT
    • Asymmetric shunts moved to the bus GS/BS
    • 母線の i 行目は a_Bus{i} に対応します。種類は基本的に PQ で、負荷以外の機器がある母線は PV にします。tools.slack_bus_index が返す母線は REF にし、VA にはその母線の Varg を入れます。
    • VM と VA には、母線の |c_Vequilibrium| と angle(c_Vequilibrium) を入れます。initialize の前なら 1 と 0 です。
    • 負荷（component.load.abstract）は −P、−Q を PD/QD に加算します。
    • 負荷以外の機器は gen の行にします。PG と QG には OPF の P0 と Q0 を、VG には母線の V（NaN なら 1）を入れます。上下限と多項式コスト（c2 = HP/baseMVA^2、c1 = fP/baseMVA）も書き込みます。
    • 各ブランチは、2×2 のアドミタンス行列から R、X、B、TAP、SHIFT を求めます。
    • 非対称なシャントは母線の GS/BS に移します。

    bus, component and branch parameters, get_admittance_matrix母線・機器・ブランチのパラメータ、get_admittance_matrix
    Returns or changes戻り値・変更する値
    mpc (network not changed)（ネットワークは変更しません）

Scenario filesシナリオのファイル

  • One JSON object per file scenario/<tag>.json; the tag of the scenario is the file name only (not written in the file)
  • Top level: Format ("GUILDAscenario"), version (1; a larger number is refused), Description, Time ([t0, tend]), Disturbances
  • One object per disturbance, in the order of tab_disturbance, with the names of the add_disturbance options: Tag, TimeSpan, FaultBus, TripUnit, OpenBranch, OffsetUnit, OffsetState, OffsetValue, InputUnit, InputName, InputValue, InputMethod; empty fields left out
  • TimeSpan: one number for an offset at one time, else two. Lists of tags and names are arrays even for one element
  • InputValue: an array of numbers for a constant; for a time series an object with Time (from t_start) and Value (one array per point), its interpolation in InputMethod ("foh" when left out)
  • Inf and NaN are written as Infinity and NaN (not standard JSON; read back by jsondecode), so a TimeSpan that ends at Inf survives the round trip. Numbers are written with 17 digits, so the values do not change
  • ファイル scenario/<tag>.json ごとに JSON のオブジェクトを 1 つ持ちます。シナリオのタグはファイル名だけで表し、ファイルの中には書きません。

5. Side effects on the model and caches5. モデルへの副作用とキャッシュ

  • Importers build through add_bus, add_branch, add_component and l_isSlack: references, edit flags and handle states as in Model Building
  • New network: nothing logged before initialize
  • Scenarios added through add_scenario and add_disturbance; they make nothing stale
  • import(path, Network=obj): adds to obj without clearing it; overwrites its Hz and baseMVA when the file gives them
  • export and network_to_mpc: read the network only
  • export writes to disk; with Overwrite=true it deletes the five subfolders (scenario included) and the class file of an existing export (other files in the folder stay)
  • No cache involved
  • A file or struct is a snapshot: later edits of the network not reflected until the next export
  • 読み込みは add_bus・add_branch・add_component・l_isSlack で組み立てます。参照、編集フラグ、ハンドルの状態はモデル構築と同じです。
  • 新しいネットワークには、initialize を実行するまで何も記録されません。
  • シナリオは add_scenario と add_disturbance で加えます。シナリオで古くなる層はありません。
  • import(path, Network=obj) は、obj の中身を消さずに、そこへ追加します。Hz と baseMVA は、ファイルに値があれば上書きします。
  • export と network_to_mpc は、ネットワークを読み取るだけです。
  • export はディスクに書き込みます。Overwrite=true のときは、前に書き出した 5 つのサブフォルダ（scenario を含む）とクラスファイルを削除します。フォルダにあるそれ以外のファイルは残します。
  • キャッシュは関係しません。
  • ファイルや構造体はその時点の写しです。ネットワークを後で編集しても、次に書き出すまで反映されません。

6. Failure behavior and result flags6. 失敗時の動作と結果フラグ

  • import reads and checks every table and scenario file (IO-02, IO-03) before it changes the network: a wrong file, column, row number or scenario file leaves Network unchanged
  • A later failure (unknown model key, wrong dynamics column, a disturbance whose tag or value does not fit the network, failing initialize) can leave it partly built
  • import_matpower checks the case (IO-14, IO-16) before it builds
  • import は、ネットワークに手を加える前にすべての table とシナリオのファイルを読んで検査します（IO-02、IO-03）。そのため、ファイル、列、行番号、シナリオのファイルに誤りがあっても Network は変わりません。
  • その後の失敗（未知のモデルのキー、dynamics の列の誤り、タグや値がネットワークに合わない外乱、initialize の失敗など）では、途中まで組み立てた状態が残る場合があります。
  • import_matpower は組み立ての前にケースを検査します（IO-14、IO-16）。

7. Where to extend the feature7. 機能を拡張する箇所

  • Component
    • A new class is read and written without changes to the IO code
    • Key: the folder name under component/
    • Constructor must accept parameter as a one-row table and take the sv_para columns from it, as component.generator.abstract does, because dynamics.csv is passed that way
    • network_to_mpc treats it as a generator unless it derives from component.load.abstract
  • Branch
    • The CSV row holds only R, X, C, tap, phase and the limits: a branch class with other parameters cannot be stored
    • network_to_mpc accepts a branch whose admittance matrix fits the MATPOWER branch model
  • Controllers
    • Not stored
    • A network class adds them in its constructor after import(..., Initialize=false), as network.IEEE9bus does
  • New column: add it to the required or optional list in import, to the table of export, and to the add_* option it feeds
  • New disturbance field: a field of Scenario.sr_field is read and written by name; give its JSON form in Scenario.to_json_struct and its conversion back in add_from_json_struct
  • 機器
    • 新しいクラスは、入出力のコードを変えずに読み書きできます。
    • キーは component/ の下のフォルダ名です。
    • dynamics.csv の行は 1 行の table として渡されます。そのため、コンストラクタは component.generator.abstract と同じように parameter を 1 行の table で受け取り、その中の sv_para の列を使う必要があります。
    • network_to_mpc は、component.load.abstract を継承しない限り、機器を発電機として扱います。
  • ブランチ
    • CSV の行は R・X・C・tap・phase と上下限だけです。他のパラメータを持つブランチのクラスは保存できません。
    • network_to_mpc は、アドミタンス行列が MATPOWER のブランチモデルに当てはまるブランチを受け付けます。
  • 制御器
    • 制御器はファイルに保存されません。
    • 制御器が必要なら、network.IEEE9bus のように、ネットワーククラスのコンストラクタで import(..., Initialize=false) の後に追加します。
  • 新しい列: 3 か所に追加します。import の必須列か任意列の一覧、export が作る table、その値を受け取る add_* のオプションです。
  • 新しい外乱の項目: Scenario.sr_field の項目は名前で読み書きします。JSON での形を Scenario.to_json_struct に、元に戻す変換を add_from_json_struct に書きます。
