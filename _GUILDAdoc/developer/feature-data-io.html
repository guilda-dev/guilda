Data Import and Export Feature Designデータの入出力機能の設計

Reads a network from a CSV model folder or a MATPOWER case; writes it to a CSV model folder or a MATPOWER case struct. The importers check the input, then build the network through the public add_* methods, so an imported network is the same as one built by hand.

ネットワークの読み込み元は CSV のモデルフォルダまたは MATPOWER のケース、書き出し先は CSV のモデルフォルダまたは MATPOWER のケース構造体。読み込みは入力を検査してから公開の add_* メソッドで組み立てるため、読み込んだネットワークは手で組み立てたものと同一。

Preconditions:

前提条件:

  • GUILDA already run, so that add_branch and add_component know the model keys used in the files

  • GUILDA を実行済み（ファイルで使うモデルのキーを add_branch と add_component が認識するため）
  • export_csv の場合: 親フォルダが存在

  1. IO-01 caller呼び出し側 → PowerNetwork.import_csv

    What it does処理内容

    • フォルダの存在を確認
    • 与えられた Network（スカラーの PowerNetwork）を使用、または PowerNetwork(<フォルダ名>) を作成

  2. IO-02 import_csv → readtable, check_cols, check_bus_rows, read_full_tag

    What it does処理内容
    • Reads network/parameter.csv (optional), bus/parameter.csv and branch/parameter.csv
    • Maps the branch columns tap/phase to Tap/Phase
    • Checks the required columns; warns about unknown columns
    • Checks that From/To are bus row numbers
    • Reads FullTag as text
    • network/parameter.csv（任意）、bus/parameter.csv、branch/parameter.csv を読み込み
    • ブランチの列 tap/phase を Tap/Phase に対応付け
    • 必須列を検査、未知の列は警告
    • From/To が母線の行番号であることを確認
    • FullTag を文字列として読み込み
    What it reads読み取る情報
    CSV files (see Data produced)CSV ファイル（生成されるデータ参照）
    Returns or changes戻り値・変更する値

  3. IO-03 import_csv → read_components, check_ids

    What it does処理内容
    • For every subfolder component/<key>/ (not starting with .): reads main.csv
    • Reads dynamics.csv when main.csv has ParameterID, opf.csv when it has OpfID
    • Checks the columns, the bus rows and that every ID exists in the referenced file
    • Missing component folder: warning
    • component/<key>/ の各サブフォルダ（. で始まらないもの）: main.csv を読み込み
    • main.csv に ParameterID があれば dynamics.csv、OpfID があれば opf.csv を読み込み
    • 列、母線の行番号、各 ID が参照先のファイルにあることを検査
    • component フォルダがない場合: 警告
    What it reads読み取る情報
    component/<key>/main.csv, dynamics.csv, opf.csv
    Returns or changes戻り値・変更する値
    one struct per key (key, tables, column list, full tags)キーごとの構造体（キー、table、列の一覧、フルタグ）

  4. IO-04 import_csv → net.para_base

    What it does処理内容
    • Writes Hz and baseMVA when the file gives a non-NaN value
    • Otherwise the network keeps its own values
    • ファイルに NaN でない値があれば Hz と baseMVA を書き込み
    • なければネットワーク自身の値を維持
    What it reads読み取る情報
    tab_net
    Returns or changes戻り値・変更する値
    net.tab_parameter.base

  5. IO-05 import_csv → PowerNetwork.add_bus

    What it does処理内容
    • One call per row, in row order: V, Varg, FullTag and the optional columns present
    • Tag passed only when the row has no FullTag
    • Bus i of the file = net.a_Bus{i} of a new network
    • 行ごとに行の順で呼び出し: V、Varg、FullTag と、存在する任意列
    • Tag は行に FullTag がないときだけ渡す
    • 新しいネットワークでは、ファイルの母線 i = net.a_Bus{i}
    What it reads読み取る情報

    Returns or changes戻り値・変更する値
    a_Bus{i} (see MB-02)（MB-02 参照）

  6. IO-06 import_csv → PowerNetwork.add_branch, set_full_tag

    What it does処理内容
    • One call per row with Type, the tags of the buses in rows From and To, and the optional columns
    • Then sets FullTag as the tag (a "Tag" edit)
    • 行ごとに Type、From・To 行の母線のタグ、任意列で呼び出し
    • その後 FullTag をタグに設定（"Tag" の編集）
    What it reads読み取る情報

    Returns or changes戻り値・変更する値

  7. IO-07 import_csv → Bus.add_component, set_full_tag

    What it does処理内容
    • For each key folder and row: add_component(key, "P", P, "Q", Q, ...) on the bus in row Bus
    • Also passes the optional columns and the eight OPF columns of the opf.csv row with the same OpfID
    • parameter = the dynamics.csv row with the same ParameterID (a one-row table; the class takes its sv_para columns)
    • Then sets FullTag
    • キーのフォルダと行ごと: Bus 行の母線で add_component(key, "P", P, "Q", Q, ...) を呼び出し
    • 任意列と、同じ OpfID を持つ opf.csv の行の 8 つの OPF 列も渡す
    • parameter = 同じ ParameterID を持つ dynamics.csv の行（1 行の table。クラスはその sv_para 列を使用）
    • その後 FullTag を設定
    What it reads読み取る情報
    component structs機器の構造体
    Returns or changes戻り値・変更する値
    a_Bus{i}.a_Component (see MB-04)（MB-04 参照）

  8. IO-08 import_csv → Bus.l_isSlack

    What it does処理内容
    • Runs after the components exist
    • First bus row whose Slack is 1 (or the text "1" / "true") becomes the slack bus
    • Runs inside evalc so that the SetSlack message is not printed
    • 機器の作成後に実行
    • Slack が 1（または文字列 "1" / "true"）である最初の母線の行を slack 母線に設定
    • SetSlack のメッセージを表示しないよう evalc の中で実行
    What it reads読み取る情報
    tab_bus.Slack
    Returns or changes戻り値・変更する値
    l_isSlack (see MB-08)（MB-08 参照）

  9. IO-09 import_csv → PowerNetwork.initialize

    What it does処理内容
    • Only with Initialize=true (default)
    • Network classes pass false and add their controllers first
    • Initialize=true（既定値）のときのみ
    • ネットワーククラスは false を渡し、先に制御器を追加
    What it reads読み取る情報
    net
    Returns or changes戻り値・変更する値

  10. IO-10 caller呼び出し側 → PowerNetwork.export_csv

    What it does処理内容
    • Strips a trailing separator
    • Checks the class name (when ClassFile), the parent folder and an existing folder
    • Overwrite=true: deletes only the subfolders network, bus, branch, component and the class file
    • Then creates the four subfolders
    • 末尾の区切り文字を除去
    • クラス名（ClassFile のとき）、親フォルダ、既存のフォルダを検査
    • Overwrite=true: サブフォルダ network・bus・branch・component とクラスファイルだけを削除
    • その後 4 つのサブフォルダを作成
    What it reads読み取る情報
    path, opt
    Returns or changes戻り値・変更する値
    folders on diskディスク上のフォルダ

  11. IO-11 export_csv → bus_table, branch_table, writetable

    What it does処理内容
    • Writes the base values
    • One bus row per a_Bus entry (Tag = tag without trailing digits, Slack = 0/1)
    • One branch row per a_Branch entry (Type = key, From/To = row numbers of the end buses)
    • 基準値を書き出し
    • a_Bus の要素ごとに母線の行（Tag = 末尾の数字を除いたタグ、Slack = 0/1）
    • a_Branch の要素ごとにブランチの行（Type = キー、From/To = 両端の母線の行番号）
    What it reads読み取る情報
    para_base; bus母線の para_powerflow, para_operation, para_dynamics, para_graph, l_isSlack; branchブランチの key, a_Bus, para_*
    Returns or changes戻り値・変更する値
    network/parameter.csv, bus/parameter.csv, branch/parameter.csv

  12. IO-12 export_csv → component_table, writetable

    What it does処理内容
    • Groups the components by key
    • Distinct dynamics rows and distinct OPF rows (unique(..., "rows", "stable")) become dynamics.csv and opf.csv
    • main.csv refers to them by ParameterID and OpfID
    • 機器をキーごとに分類
    • 重複のない dynamics の行と OPF の行（unique(..., "rows", "stable")）を dynamics.csv と opf.csv に出力
    • main.csv は ParameterID と OpfID でそれらを参照
    What it reads読み取る情報
    component機器の key, a_Bus, para_powerflow, para_operation, para_graph, para_dynamics, para_OPF
    Returns or changes戻り値・変更する値
    component/<key>/main.csv, dynamics.csv, opf.csv

  13. IO-13 export_csv → class_file, warn_controllers_not_saved

    What it does処理内容
    • With ClassFile: writes <Name>.m from private/export_csv_class.txt (class name, date, counts of buses, branches, generators, loads and others)
    • Its constructor calls PowerNetwork.import_csv(folder, Network=obj)
    • Then warns with the list of local controllers (as component/avr/pss paths) and global controllers that are not written
    • ClassFile のとき: private/export_csv_class.txt から <Name>.m を書き出し（クラス名、日付、母線・ブランチ・発電機・負荷・その他の数）
    • そのコンストラクタは PowerNetwork.import_csv(folder, Network=obj) を呼び出し
    • その後、書き出されないローカル制御器（component/avr/pss のパス）とグローバル制御器を列挙して警告
    What it reads読み取る情報
    a_Bus{:}.a_Component, a_LocalController, a_GlobalController
    Returns or changes戻り値・変更する値
    <Name>.m; warning警告 GUILDA:PowerNetwork:ControllersNotSaved; path

  14. IO-14 caller呼び出し側 → PowerNetwork.import_matpower → load_case, check_case

    What it does処理内容
    • Turns the input into a struct and a name (a .m file's folder is added to the path for the call only)
    • Checks the fields baseMVA, bus, gen, branch
    • Checks that the version is not 1 and the column counts (≥ 13, 10, 13)
    • Checks that the bus numbers in gen and branch exist and that no bus has type 4
    • 入力を構造体と名前に変換（.m ファイルのフォルダは呼び出しの間だけパスに追加）
    • フィールド baseMVA・bus・gen・branch を検査
    • version が 1 でないこと、列数（13・10・13 以上）を検査
    • gen と branch の母線番号の存在、種類 4 の母線がないことを確認
    What it reads読み取る情報
    mpc
    Returns or changes戻り値・変更する値
    case struct, case nameケース構造体、ケース名

  15. IO-15 import_matpower → PowerNetwork

    What it does処理内容
    • Creates the network
    • Sets Hz (MATPOWER has none) and baseMVA = mpc.baseMVA
    • ネットワークを作成
    • Hz（MATPOWER にはない）と baseMVA = mpc.baseMVA を設定
    What it reads読み取る情報
    opt.Tag, opt.Hz, mpc.baseMVA
    Returns or changes戻り値・変更する値
    net

  16. IO-16 import_matpower → gen_costs (local)（内部）

    What it does処理内容
    • Converts polynomial costs (MODEL 2, at most quadratic) in MW to per unit: HP = c2*baseMVA^2, fP = c1*baseMVA
    • Rows ng+1:2*ng give HQ, fQ
    • STARTUP and SHUTDOWN copied as is
    • Constant c0 dropped with a warning
    • MW 単位の多項式コスト（MODEL 2、2 次まで）を単位法に変換: HP = c2*baseMVA^2、fP = c1*baseMVA
    • ng+1:2*ng 行は HQ・fQ
    • STARTUP と SHUTDOWN はそのまま複写
    • 定数 c0 は警告付きで破棄
    What it reads読み取る情報
    mpc.gencost (optional)（任意）
    Returns or changes戻り値・変更する値
    rm_cost (ng×6: HP, fP, HQ, fQ, startup, shutdown) or emptyまたは空

  17. IO-17 import_matpower → PowerNetwork.add_bus

    What it does処理内容
    • One bus per mpc.bus row, in row order
    • V = VG of the first in-service generator of the bus (VM without one)
    • Varg = Varg0 = VA in rad, V0 = VM
    • Gshunt/Bshunt = GS/BS ÷ baseMVA; Vmin, Vmax, baseKV
    • Bus numbers serve only to resolve gen and branch rows
    • mpc.bus の行ごとに行の順で母線を作成
    • V = その母線で最初に運転中の発電機の VG（なければ VM）
    • Varg = Varg0 = VA [rad]、V0 = VM
    • Gshunt/Bshunt = GS/BS ÷ baseMVA、Vmin、Vmax、baseKV
    • 母線番号は gen と branch の行の解決にだけ使用
    What it reads読み取る情報
    mpc.bus, mpc.gen
    Returns or changes戻り値・変更する値
    a_Bus (B001, B002, ...)

  18. IO-18 import_matpower → Bus.add_component, Bus.l_isSlack

    What it does処理内容
    • First a GeneratorModel per in-service gen row: P = PG/baseMVA, Q = NaN, baseMVA = MBASE, limits ÷ baseMVA, OPF initial values PG/QG ÷ baseMVA, costs of IO-16, parameter = GeneratorParameter
    • Then a LoadModel on each bus with nonzero PD or QD: P = −PD/baseMVA, Q = −QD/baseMVA, cost 0
    • First REF bus (type 3) becomes the slack bus
    • まず運転中の gen 行ごとに GeneratorModel を追加: P = PG/baseMVA、Q = NaN、baseMVA = MBASE、上下限 ÷ baseMVA、OPF の初期値 PG/QG ÷ baseMVA、IO-16 のコスト、parameter = GeneratorParameter
    • 次に PD または QD が 0 でない母線ごとに LoadModel を追加: P = −PD/baseMVA、Q = −QD/baseMVA、コスト 0
    • 最初の REF 母線（種類 3）を slack 母線に設定
    What it reads読み取る情報
    mpc.gen, mpc.bus, rm_cost, opt.GeneratorModel, opt.LoadModel
    Returns or changes戻り値・変更する値
    a_Component, l_isSlack

  19. IO-19 import_matpower → PowerNetwork.add_branch

    What it does処理内容
    • One branch per in-service row
    • Type: "pi" when TAP is 0 or 1 and SHIFT is 0, else "pi_transformer" (tap at the from end)
    • R, X, C = BR_B/2, Tap, Phase = SHIFT in rad
    • Smax = RATE_A/baseMVA (0 → Inf)
    • Vargmax = the smaller of |ANGMIN| and |ANGMAX| below 360° (Inf when both are 0 or ≥ 360°)
    • 運転中の行ごとにブランチを作成
    • 種類: TAP が 0 か 1 で SHIFT が 0 なら "pi"、それ以外は "pi_transformer"（タップは from 側）
    • R、X、C = BR_B/2、Tap、Phase = SHIFT [rad]
    • Smax = RATE_A/baseMVA（0 → Inf）
    • Vargmax = 360° 未満の |ANGMIN| と |ANGMAX| の小さい方（両方 0 または 360° 以上なら Inf）
    What it reads読み取る情報
    mpc.branch
    Returns or changes戻り値・変更する値
    a_Branch (EL###, ET###)

  20. IO-20 import_matpower → PowerNetwork.initialize

    What it does処理内容
    • Only with Initialize=true (default)
    • Initialize=true（既定値）のときのみ
    What it reads読み取る情報
    net
    Returns or changes戻り値・変更する値
    equilibrium平衡点

  21. IO-21 caller呼び出し側 → tools.network_to_mpc

    What it does処理内容
    • Bus row i = a_Bus{i}: type PQ, PV when it has a non-load component, REF at tools.slack_bus_index (VA = its Varg)
    • VM/VA = V0/Varg0
    • Loads (component.load.abstract) add −P, −Q to PD/QD
    • Every other component: a gen row with PG/QG = OPF P0/Q0, VG = bus V, limits and polynomial costs (c2 = HP/baseMVA^2, c1 = fP/baseMVA)
    • Each branch fitted from its 2×2 matrix to R, X, B, TAP, SHIFT
    • Asymmetric shunts moved to the bus GS/BS
    • 母線の行 i = a_Bus{i}: 種類は PQ、負荷以外の機器があれば PV、tools.slack_bus_index の母線は REF（VA = その Varg）
    • VM/VA = V0/Varg0
    • 負荷（component.load.abstract）は −P、−Q を PD/QD に加算
    • それ以外の機器: gen の行（PG/QG = OPF の P0/Q0、VG = 母線の V、上下限と多項式コスト（c2 = HP/baseMVA^2、c1 = fP/baseMVA））
    • 各ブランチは 2×2 行列から R・X・B・TAP・SHIFT に当てはめ
    • 非対称なシャントは母線の GS/BS に移動
    What it reads読み取る情報
    bus, component and branch parameters, get_admittance_matrix母線・機器・ブランチのパラメータ、get_admittance_matrix
    Returns or changes戻り値・変更する値
    mpc (network not changed)（ネットワークは変更なし）

  • tools.network_to_mpc returns version = '2', baseMVA, bus (n_bus×13), gen (n_gen×21), branch (n_branch×13), gencost (n_gen×7, or 2·n_gen×7 with Q costs) and bus_name, gen_name, branch_name (cell of GUILDA tags)
  • For network.IEEE9bus: 9×13, 3×21, 9×13, 3×7
  • tools.network_to_mpc の戻り値: version = '2'、baseMVA、bus（n_bus×13）、gen（n_gen×21）、branch（n_branch×13）、gencost（n_gen×7、Q のコストがあれば 2·n_gen×7）、bus_name・gen_name・branch_name（GUILDA のタグの cell）
  • network.IEEE9bus では 9×13、3×21、9×13、3×7

Round trips between formats形式間の往復変換

export_csv → import_csv

Kept in the round trip往復で保持されるもの
  • buses, branches and components with their keys and tags
  • power-flow, operation, OPF, dynamics and graph parameters
  • slack bus; Hz, baseMVA
  • power flow of network.IEEE9bus: reproduced exactly
  • 母線・ブランチ・機器とそのキー、タグ
  • 潮流・operation・OPF・dynamics・graph のパラメータ
  • slack 母線、Hz、baseMVA
  • network.IEEE9bus の潮流計算結果: 完全に再現
Lost or changed in the round trip往復で失われる・変わるもの
  • local and global controllers (warning)
  • equilibria (recomputed by initialize)
  • set_opffcn terms
  • solver_* settings
  • network tag (taken from the folder name)
  • ローカル制御器とグローバル制御器（警告あり）
  • 平衡点（initialize で再計算）
  • set_opffcn の項
  • solver_* の設定
  • ネットワークのタグ（フォルダ名から取得）

network_to_mpc → import_matpower

Kept in the round trip往復で保持されるもの
  • bus order, shunts, voltage limits and settings, base voltages
  • branch impedances and taps, Smax, Vargmax
  • generator limits and costs; load P and Q
  • 母線の順、シャント、電圧の上下限と設定値、基準電圧
  • ブランチのインピーダンスとタップ、Smax、Vargmax
  • 発電機の上下限とコスト、負荷の P と Q
Lost or changed in the round trip往復で失われる・変わるもの
  • component classes: every generator becomes GeneratorModel, every load LoadModel, all loads of a bus one load
  • dynamics parameters; controllers
  • tags (regenerated)
  • load OPF costs
  • branch Imax, Pmax, Qmax (the export refuses finite values)
  • generator power-flow P: PG is written from the OPF initial value P0, so after the round trip P equals the P0 before export
  • 機器のクラス: 発電機はすべて GeneratorModel、負荷はすべて LoadModel、母線の負荷は 1 つに統合
  • dynamics パラメータ、制御器
  • タグ（再生成）
  • 負荷の OPF コスト
  • ブランチの Imax・Pmax・Qmax（書き出しは有限値を拒否）
  • 発電機の潮流 P: PG は OPF の初期値 P0 から書き出すため、往復後の P は書き出し前の P0

5. Side effects on the model and caches5. モデルへの副作用とキャッシュ

  • Importers build through add_bus, add_branch, add_component and l_isSlack: references, edit flags and handle states as in Model Building
  • New network: nothing logged before initialize
  • import_csv(path, Network=obj): adds to obj without clearing it; overwrites its Hz and baseMVA when the file gives them
  • export_csv and network_to_mpc: read the network only
  • export_csv writes to disk; with Overwrite=true it deletes the four subfolders and the class file of an existing export (other files in the folder stay)
  • No cache involved
  • A file or struct is a snapshot: later edits of the network not reflected until the next export
  • 読み込みは add_bus・add_branch・add_component・l_isSlack で組み立て。参照、編集フラグ、ハンドルの状態はモデル構築と同じ
  • 新しいネットワーク: initialize の前は何も記録しない
  • import_csv(path, Network=obj): obj を空にせずに追加。ファイルにあれば Hz と baseMVA を上書き
  • export_csv と network_to_mpc: ネットワークの読み取りのみ
  • export_csv はディスクに書き込み。Overwrite=true では既存の書き出しの 4 つのサブフォルダとクラスファイルを削除（フォルダ内の他のファイルは残す）
  • キャッシュは無関係
  • ファイルや構造体はその時点の写し。ネットワークを後で編集しても、次に書き出すまで反映なし

6. Failure behavior and result flags6. 失敗時の動作と結果フラグ

  • import_csv reads and checks every table (IO-02, IO-03) before it changes the network: a wrong file, column or row number leaves Network unchanged
  • A later failure (unknown model key, wrong dynamics column, failing initialize) can leave it partly built
  • import_matpower checks the case (IO-14, IO-16) before it builds
  • import_csv はネットワークを変更する前にすべての table を読んで検査（IO-02、IO-03）。ファイル・列・行番号の誤りでは Network は不変
  • その後の失敗（未知のモデルのキー、dynamics の列の誤り、initialize の失敗など）では、途中まで組み立てた状態が残る場合あり
  • import_matpower は組み立ての前にケースを検査（IO-14、IO-16）

7. Where to extend the feature7. 機能を拡張する箇所

  • Component
    • A new class is read and written without changes to the IO code
    • Key: the folder name under component/
    • Constructor must accept parameter as a one-row table and take the sv_para columns from it, as component.generator.abstract does, because dynamics.csv is passed that way
    • network_to_mpc treats it as a generator unless it derives from component.load.abstract
  • Branch
    • The CSV row holds only R, X, C, tap, phase and the limits: a branch class with other parameters cannot be stored
    • network_to_mpc accepts a branch whose admittance matrix fits the MATPOWER branch model
  • Controllers
    • Not stored
    • A network class adds them in its constructor after import_csv(..., Initialize=false), as network.IEEE9bus does
  • New column: add it to the required or optional list in import_csv, to the table of export_csv, and to the add_* option it feeds
  • 機器
    • 新しいクラスは入出力のコードを変えずに読み書き可能
    • キー: component/ の下のフォルダ名
    • dynamics.csv はその形で渡されるため、コンストラクタは component.generator.abstract と同様に parameter を 1 行の table として受け取り、その sv_para 列を使うことが必要
    • network_to_mpc は、component.load.abstract を継承しない限り発電機として扱う
  • ブランチ
    • CSV の行は R・X・C・tap・phase と上下限のみ。他のパラメータを持つブランチのクラスは保存不可
    • network_to_mpc は、アドミタンス行列が MATPOWER のブランチモデルに当てはまるブランチを受け付け
  • 制御器
    • 保存対象外
    • ネットワーククラスが、network.IEEE9bus と同様に、import_csv(..., Initialize=false) の後にコンストラクタで追加
  • 新しい列: import_csv の必須または任意の一覧、export_csv の table、その値を受け取る add_* のオプションに追加
