Feature: Data Import and Export機能: データの入出力

A network is read from a CSV model folder or a MATPOWER case and written to a CSV model folder or a MATPOWER case struct. The importers check the input and then build the network through the public add_* methods, so an imported network is the same as one built by hand.

ネットワークは CSV のモデルフォルダまたは MATPOWER のケースから読み込み、CSV のモデルフォルダまたは MATPOWER のケース構造体に書き出します。読み込みは入力を検査してから公開の add_* メソッドでネットワークを組み立てるので、読み込んだネットワークは手で組み立てたものと同じです。

5. Side effects and caches5. 副作用とキャッシュ

  • The importers build through add_bus, add_branch, add_component and l_isSlack, so the references, edit flags and handle states are those of Model Building. On a new network nothing is logged before initialize.
  • import_csv(path, Network=obj) adds to obj without clearing it and overwrites its Hz and baseMVA when the file gives them.
  • export_csv and network_to_mpc only read the network. export_csv writes to disk, and with Overwrite=true deletes the four subfolders and the class file of an earlier export (other files in the folder stay).
  • No cache is involved. A file or struct is a snapshot: later edits of the network are not reflected until it is exported again.
  • 読み込みは add_bus・add_branch・add_component・l_isSlack で組み立てるので、参照、編集フラグ、ハンドルの状態はモデル構築と同じです。新しいネットワークでは initialize の前に何も記録されません。
  • import_csv(path, Network=obj) は obj を空にせずに追加し、ファイルにあれば Hz と baseMVA を上書きします。
  • export_csv と network_to_mpc はネットワークを読むだけです。export_csv はディスクに書き込み、Overwrite=true では以前の書き出しの 4 つのサブフォルダとクラスファイルを削除します（フォルダ内の他のファイルは残ります）。
  • キャッシュは関係しません。ファイルや構造体はその時点の写しで、ネットワークを後で編集しても再び書き出すまで反映されません。

6. Failure and flags6. 失敗とフラグ

import_csv reads and checks every table (IO-02, IO-03) before it changes the network, so a wrong file, column or row number leaves Network unchanged. A later failure, such as an unknown model key, a wrong dynamics column or a failing initialize, can leave it partly built. import_matpower checks the case (IO-14, IO-16) before it builds.

import_csv はネットワークを変更する前にすべての table を読んで検査する（IO-02、IO-03）ので、ファイル・列・行番号の誤りでは Network は変わりません。その後の失敗（未知のモデルのキー、dynamics の列の誤り、initialize の失敗など）では、途中まで組み立てられた状態が残ることがあります。import_matpower は組み立てる前にケースを検査します（IO-14、IO-16）。

7. Extension points7. 拡張ポイント

  • Component: a new class is read and written without changes to the IO code. Its key is the folder name under component/; its constructor must accept parameter as a one-row table and take the sv_para columns from it, as component.generator.abstract does, because dynamics.csv is passed that way. network_to_mpc treats it as a generator unless it derives from component.load.abstract.
  • Branch: the CSV row holds only R, X, C, tap, phase and the limits, so a branch class with other parameters cannot be stored. network_to_mpc accepts a branch whose admittance matrix fits the MATPOWER branch model.
  • Controllers: not stored. A network class adds them in its constructor after import_csv(..., Initialize=false), as network.IEEE9bus does.
  • New column: add it to the required or optional list in import_csv, to the table of export_csv, and to the add_* option it feeds.
  • 機器: 新しいクラスは入出力のコードを変えずに読み書きできます。キーは component/ の下のフォルダ名です。dynamics.csv はその形で渡されるので、コンストラクタは component.generator.abstract と同様に parameter を 1 行の table として受け取り、その sv_para 列を使わなければなりません。network_to_mpc は、component.load.abstract を継承しない限り発電機として扱います。
  • ブランチ: CSV の行は R・X・C・tap・phase と上下限だけを持つので、他のパラメータを持つブランチのクラスは保存できません。network_to_mpc は、アドミタンス行列が MATPOWER のブランチモデルに当てはまるブランチを受け付けます。
  • 制御器: 保存されません。ネットワーククラスは、network.IEEE9bus と同様に、import_csv(..., Initialize=false) の後にコンストラクタで加えます。
  • 新しい列: import_csv の必須または任意の一覧、export_csv の table、その値を受け取る add_* のオプションに加えます。

See Model Implementation: branches and networks for a network class.
