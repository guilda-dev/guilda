Git Workflow

Three kinds of branches hold the source: main for releases, a version branch for integration, and short-lived work branches. A separate gh-pages branch holds the published documentation site. Branch names and commit messages share the same change types.

Branch names

Work branches are named <type>/<issue>-<slug>:

  • #
    <issue> is the GitHub Issue number. Create the Issue first.
  • a-z
    <slug>: short English summary, lowercase words joined by hyphens (a-z, 0-9, -).
  • ≤50
    Keep the whole name under about 50 characters.

Release

  1. Review PROpen a pull request from the integration branch into main for review. Do not merge it on GitHub.
  2. release.shFrom a clean versionX.Y, run bash .claude/release/release.sh X.Y. It merges into main with --no-ff, removes the assistant config, commits chore: release vX.Y, and tags the merge commit vX.Y.
  3. PushCheck the result, then run the printed git push origin main vX.Y. GitHub marks the pull request as merged.
  4. Next branchRun bash .claude/release/start-version.sh X.Y PREV: it creates the next versionX.Y from main and restores the assistant config from versionPREV.

Assistant config never lands in main. .claude/, .codex/ and .github/copilot-instructions.md are tracked on the integration and work branches only, so users who clone main or run GUILDA.gitpull never get them.

release.sh removes them from the release merge and checks that main has none; start-version.sh brings them back. If the merge conflicts, the script aborts: merge main into versionX.Y, resolve the conflicts there, and run it again.

Publishing the documentation

The documentation site is served by GitHub Pages at https://guilda-dev.github.io/guilda/ from the gh-pages branch. The generated class reference is never committed to source branches, so the site is published by a MATLAB command that builds it and commits the result to gh-pages. Nothing else updates the site.

  1. Check outSwitch to main or versionX.Y with no uncommitted changes to tracked files.
  2. RunIn MATLAB, run GUILDA.publish_doc(). It rebuilds the class reference and commits the site to gh-pages.
  3. ConfirmConfirm the dialog to push gh-pages to origin.
  4. CheckThe site updates within a few minutes. Open it and check the changed pages.

What the command does

  • Checks the checkoutRefuses to run on any branch other than main or versionX.Y, or when tracked files have uncommitted changes.
  • Rebuilds the class referenceRegenerates _GUILDAdoc/database/ from scratch and stops if any class export reports errors.
  • Writes the siteIn a temporary Git worktree of gh-pages (created as an orphan branch the first time), writes _GUILDAdoc/, LICENSE, a root index.html that redirects to _GUILDAdoc/index.html, and an empty .nojekyll.
  • CommitsCommits docs: publish <branch>@<short-sha>, naming the source branch and commit. If nothing changed, it makes no commit.
  • PushesAsks for confirmation, then pushes gh-pages to origin.

Options

CallEffect
GUILDA.publish_doc()Build, commit, ask for confirmation, and push.
GUILDA.publish_doc("confirm", false)Push without the confirmation dialog.
GUILDA.publish_doc("push", false)Build and commit to the local gh-pages only. Push it later with git push origin gh-pages.

One-time setup. A repository admin sets Settings → Pages → Build and deployment to Deploy from a branch, with branch gh-pages and folder / (root).

The site shows the branch that was published last; the latest commit message on gh-pages names it.

Do not

  • Direct commitsCommit directly to main.
  • Manual merges into mainMerge or cherry-pick into main by hand or on GitHub; release with release.sh.
  • Force-pushForce-push to main or the integration branch.
  • Generated / personal filesCommit generated files or personal settings (see Generated files).
  • Hand edits to gh-pagesCommit to, merge into, or merge from gh-pages by hand; publish with GUILDA.publish_doc.
  • Other prefixesCreate work branches with other prefixes such as dev/ or develop/.

Enforced by Claude Code hooks (.claude/settings.json, .claude/hooks/): Claude Code sessions in this repository are blocked from creating branches with other names, committing on main, versionX.Y or non-work branches, force-pushing or deleting main / versionX.Y, running git merge or git cherry-pick on main (use release.sh), and editing generated files; a commit message that breaks the format is sent back for git commit --amend.
