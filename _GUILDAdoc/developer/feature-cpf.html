Continuation Power Flow連続潮流計算

net.calculate_continuation_powerflow() starts from the equilibrium of net.initialize, scales the power of the components on the load buses by (1 + λ), and follows the power-flow solution with a predictor-corrector method past the maximum loading point (the nose of the PV curve). The path comes back as a ResultCPF.

net.calculate_continuation_powerflow() は net.initialize の平衡点から出発し、負荷母線の機器の電力を (1 + λ) 倍しながら、予測子・修正子法で最大負荷点（PV カーブの先端）を越えるまで潮流解を追跡します。追跡した経路は ResultCPF として返ります。

Purpose and entry point目的と入口

net.initialize();
[result, flag, output] = net.calculate_continuation_powerflow(LoadBus=["B009","B014"], Name=Value, ...)

The defaults are the properties of net.solver_CPF (a SolverCPF). A new solver reads them from GUILDA.config("ContinuationPowerFlow"): @GUILDA/config/DefaultContinuationPowerFlow.json, overridden by a file of the same name in @GUILDA/user/. A Name-Value option changes the setting for this call only.

既定値は net.solver_CPF（SolverCPF）のプロパティです。ソルバーは生成時にこれを GUILDA.config("ContinuationPowerFlow")、つまり @GUILDA/config/DefaultContinuationPowerFlow.json（@GUILDA/user/ に同名のファイルがあればそれで上書き）から読みます。Name-Value オプションはその呼び出しに限って設定を変えます。

Side effects and caches副作用とキャッシュ

  • Handles: CPF-02 builds the f_* handles that are not up to date, as every analysis does.
  • Working data of the run: Bus.iv_CPFV, Component.f_PQ2Bus, and, with UseInternalState, Component.iv_CPFX are written by build_layout (only SolverCPF can set them). They stay on the objects after the run and are overwritten by the next one; nothing else reads them.
  • Edit state: only l_staleEquilibrium is read. Any edit that makes the equilibrium stale (see Class Design: Edit handling) stops the next call until net.initialize() runs again; edits of operation, OPF, and graph parameters and of the network Hz do not.
  • The solver settings are not changed; the result keeps a reference to the network.
  • ハンドル: CPF-02 は他の解析と同じく、最新でない f_* ハンドルを構築します。
  • 実行中の作業データ: Bus.iv_CPFV、Component.f_PQ2Bus、UseInternalState では Component.iv_CPFX を build_layout が書き込みます（設定できるのは SolverCPF だけです）。実行後もオブジェクトに残り、次の実行で上書きされます。他からは読まれません。
  • 編集状態: 読むのは l_staleEquilibrium だけです。平衡点を古くする編集（Class Design: Edit handling を参照）があると、net.initialize() をやり直すまで次の呼び出しは停止します。operation、OPF、graph のパラメータとネットワークの Hz の編集では停止しません。
  • ソルバーの設定は変更しません。結果はネットワークへの参照を持ちます。

Failure and flags失敗とフラグ

flag is logical: true when the largest λ lies strictly inside the path, i.e. the trace passed the nose. When it did not within MaxIterations steps, flag = false and output.message suggests a larger MaxIteration or StepSize; the partial path is still returned. A corrector that does not converge only warns, and the trace continues from the point it reached. The IDs name message entries in SystemTools/GUILDA/en/<Object>.xml and are not MATLAB identifiers (see Class Design: Conventions).

flag は logical で、λ の最大値が経路の内側にあるとき、つまり先端を越えたときに true です。MaxIterations ステップ以内に越えなければ flag = false となり、output.message が MaxIteration または StepSize を大きくするよう示します。途中までの経路は返ります。修正子が収束しなくても警告だけで、到達した点から追跡を続けます。ID は SystemTools/GUILDA/en/<Object>.xml のメッセージ項目の名前で、MATLAB の識別子ではありません（Class Design: Conventions を参照）。

Extension points拡張ポイント

  • Every component takes part through its equilibrium only (c_Vequilibrium, c_Iequilibrium, from get_equilibrium; see Initialization). Its power is held constant, scaled by (1 + λ) on the buses of LoadBus.
  • With UseInternalState=true, every component needs getCompPQ(obj, x, V, u, param), with V as [|V|; ∠V] and param the dynamics parameters in the order of sv_para, returning the injected [P; Q] [pu]. The layout treats the states of a component on a slack or PV bus like a generator: state 1 is the rotor angle (fixed on the slack bus), state 2 the speed deviation (fixed at 0), and f_dx gives the remaining equations.
  • Branches enter only through get_admittance_matrix; controllers are not part of the CPF.
  • すべての機器は平衡点（get_equilibrium による c_Vequilibrium、c_Iequilibrium。初期化を参照）だけで参加します。電力は一定に保たれ、LoadBus の母線では (1 + λ) 倍されます。
  • UseInternalState=true では、すべての機器に getCompPQ(obj, x, V, u, param) が必要です。V は [|V|; ∠V]、param は sv_para の順の動特性パラメータで、注入する [P; Q] [pu] を返します。スラック母線と PV 母線の機器の状態は発電機として扱われます。状態 1 は回転子角（スラック母線では固定）、状態 2 は速度偏差（0 に固定）で、残りの方程式は f_dx が与えます。
  • ブランチは get_admittance_matrix を通じてのみ関与し、制御器は CPF に関与しません。
