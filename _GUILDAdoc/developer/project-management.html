Project Management

All work in GUILDA is tracked with GitHub Issues. One Issue corresponds to one work branch and one pull request.

Workflow Issues Versions Keeping documentation current Definition of Done

Workflow

Issue #42  ──▶  feature/42-…  ──▶  Pull request "feat: …"  ──▶  version4.0  ──▶  main (v4.0)
 what & why      the work          review + Closes #42          integration       release
  1. Open an Issue that describes the problem or the goal.
  2. Create a work branch from the integration branch, following the branch naming rule.
  3. Commit with <type>: <summary> messages.
  4. Open a pull request into the integration branch and complete the Definition of Done.
  5. Merge, delete the branch, and let Closes #<issue> close the Issue.

Issues

  • Write the title in English as a short statement of the goal, e.g. Add grid-forming inverter model.
  • Describe the background, the expected result, and, for bugs, the steps to reproduce.
  • Add one type label that matches the branch type: feature, fix, refactor, docs, or test.
  • Split an Issue when it cannot be finished in one pull request.

Definition of Done

Check these items before requesting a review.

  • >> GUILDA starts without errors.
  • The affected tutorials or +DebugScript tasks run.
  • New and changed code follows the naming conventions and the placement rules.
  • Public members have help comment tags, and GUILDA.doc("update", true, "strict", true) reports no errors.
  • No generated files or personal settings are committed.
  • The pull request title follows <type>: <summary> and the description contains Closes #<issue>.
