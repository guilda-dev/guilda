Time Simulation Feature Design時間応答シミュレーション機能の設計

net.simulate integrates the differential-algebraic equations (DAE) of the network over time from the equilibrium of net.initialize, under the disturbances of the given scenarios (Scenario). This page follows one call: public method → SolverODE → ResultODE.

net.simulate は、net.initialize で求めた平衡点から始めて、シナリオ (Scenario) で与えた外乱のもとでネットワークの微分代数方程式 (DAE) を時間積分します。このページでは、1 回の呼び出しが公開メソッドから SolverODE、ResultODE へと進む流れを説明します。

What the feature does and how to call it機能の目的と呼び出し方

The time span is split into phases: intervals with an unchanged set of active disturbances.

  • One phase: one call of the MATLAB ode object on the DAE of the network in that phase (faulted buses and tripped units removed, opened branches left out of the admittance matrix).
  • Start of the next phase: the state at the end of a phase, after the changes of the next phase.

時間区間はフェーズに分けて扱います。フェーズとは、有効な外乱の組み合わせが変わらない区間のことです。

  • 各フェーズでは、そのフェーズのネットワークの DAE を MATLAB の ode オブジェクトで 1 回解きます。このネットワークからは地絡した母線とトリップした機器を除き、開放したブランチもアドミタンス行列から除きます。
  • 次のフェーズは、前のフェーズが終わった時点の状態に、次のフェーズで起きる変化を加えた値から始めます。
[result, flag, output] = net.simulate(time, sc1, sc2, ..., Name, Value)
[result, flag, output] = net.simulate(sc, Name, Value)
sc = Scenario(tag, Time=…, Options=…, Judge=…, Description=…)
sc.add_fault(bus, [t_start, t_end])            % also add_trip, add_open_branch, add_offset, add_input
net.add_scenario(sc)
verdict = sc.judge(result)
  • time: [t0, tend] in seconds with finite t0 < tend, [], or left out (net.simulate(sc, ...)). Without a time:
    • the Time of the scenarios;
    • else [0, 30·ceil(tmax/10)], tmax = latest disturbance time (10 s more when that equals tmax);
    • without disturbances, [0, 10].
  • time には、秒単位の [t0, tend]（有限の値で t0 < tend）か [] を渡すか、省略します（net.simulate(sc, ...)）。省略したときは次のように決めます。
    • シナリオに Time があれば、それを使います。
    • なければ [0, 30·ceil(tmax/10)] とします。tmax は外乱の中で最も遅い時刻で、こうして決めた終了時刻が tmax と等しくなる場合は、さらに 10 s 延ばします。
    • 外乱がなければ [0, 10] とします。
  • Scenarios: the leading Scenario arguments, each added to this network (net.add_scenario).
    • None: the response without disturbance. Several: disturbances combined.
    • After the first non-Scenario argument: Name-Value options.
    • Different Time, or different values of one stored option: error, unless the call gives the time or the option.
    • Verdict: not an output; call sc.judge(result) (default Scenario.out_of_step).
  • シナリオは、先頭に並べる Scenario 引数です。どれも、あらかじめ net.add_scenario でこのネットワークに加えておきます。
    • シナリオがなければ、外乱のない応答を計算します。複数あれば、外乱を合わせて扱います。
    • Scenario でない最初の引数から後ろは、Name-Value オプションとして読みます。
    • シナリオごとに Time や保存したオプションの値が違うとエラーになります。ただし、呼び出しで時間やそのオプションを指定した場合は除きます。
    • 判定結果は出力に含みません。sc.judge(result) を呼び出して求めます（既定では Scenario.out_of_step）。

Name-Value options and defaultsName-Value オプションと既定値

  • Defaults: the TimeSimulation section of GUILDA.setting, read at each run from GUILDA.config("TimeSimulation") (@GUILDA/config/DefaultTimeSimulation.json, overridden by a file of the same name in @GUILDA/user/). net.solver_ODE (a SolverODE) holds no settings.
  • Precedence, for this call only: Name-Value option of the call > stored Options of the scenarios > GUILDA.setting (scenario_settings, SolverODE.OptionMap, tools.resolve_options). The settings file is not changed.
  • Shared rules: API Design.
  • 既定値は GUILDA.setting の TimeSimulation セクションにあり、実行のたびに GUILDA.config("TimeSimulation") で読み込みます。元の値は @GUILDA/config/DefaultTimeSimulation.json にあり、@GUILDA/user/ に同名のファイルを置くと上書きできます。net.solver_ODE (SolverODE) は設定を持ちません。
  • 値は、呼び出しの Name-Value オプション、シナリオに保存した Options、GUILDA.setting の順に優先します（scenario_settings、SolverODE.OptionMap、tools.resolve_options）。この優先はその呼び出しの間だけで、設定ファイルは変わりません。
  • 共通の規則はAPI 設計にまとめています。

Disturbances given as a ScenarioScenario で与える外乱

A scenario holds a list of disturbances (sc.tab_disturbance), each with its own time span and tag.

  • Tag: the column of the disturbance in the phase table. Unique in the scenario and in one run; not t1, t2, Properties, Row, Variables, empty, or NoAction followed by digits. Defaults of the add_* methods: fault<n>, open<n>, ...
  • Buses, branches and units: named by tag; checked against the network when added and again in SIM-04.
  • sc.add_disturbance(tag, Name=Value): takes the fields below; several kinds can be combined in one disturbance.

シナリオは外乱の一覧 (sc.tab_disturbance) を持ちます。外乱にはそれぞれ時間区間とタグがあります。

  • タグは、フェーズ表で外乱の列名になります。シナリオの中でも、1 回の実行の中でも重複できません。t1、t2、Properties、Row、Variables、空文字、NoAction に数字を付けたものは使えません。add_* メソッドは fault<n>、open<n> のようなタグを自動で付けます。
  • 母線、ブランチ、機器はタグで指定します。外乱を加えるときと SIM-04 で、ネットワークと照らし合わせます。
  • sc.add_disturbance(tag, Name=Value) は次のフィールドを受け取ります。1 つの外乱に複数の種類をまとめることもできます。
Field (method)フィールド (メソッド)Effect during the disturbance外乱中の作用

Preconditions for the call呼び出しの前提条件

  • net.initialize() has run, with no edit since that makes a layer stale, a network Hz edit included (see Class Design: Handling of model edits). initialize builds the function handles f_*.
  • net.initialize() を実行してあり、その後に層を古くする編集をしていないことが前提です。ネットワークの Hz の編集もこれに含みます（クラス設計: モデル編集の扱いを参照）。関数ハンドル f_* は initialize が作ります。
  • Every scenario belongs to this network and the tags of its disturbances exist in it now, and every unit a global controller controls is on this network.
  • どのシナリオもこのネットワークのもので、外乱に書いたタグが今のネットワークに存在していなければなりません。グローバル制御器が制御する機器も、すべてこのネットワーク上にある必要があります。
  • The mass matrices of all components and controllers are constant (tools.read_mass).
  • すべての機器と制御器で、質量行列が定数でなければなりません（tools.read_mass）。

番号はステップの ID です。SIM-08〜SIM-18 はフェーズごとに繰り返します。破線の矢印は戻り値を表します。

Processing steps in detail処理ステップの詳細

  • Each step: one requirement of the feature. Steps marked on the left run once per phase.
  • n_x, n_v (= 2 × number of buses), n_u, n_uc: numbers of states, bus voltage variables, component inputs and controller inputs of net.get_variable_map(). n_z = n_x + 2·n_v + n_u + n_uc: length of the DAE vector z = [x; V; I; u; uc] (see Data produced).
  • 各ステップが、この機能の要件 1 つに当たります。左に印のあるステップは、フェーズごとに実行します。
  • n_x、n_v (= 2 × 母線数)、n_u、n_uc は、net.get_variable_map() にある状態、母線電圧変数、機器入力、制御器入力の数です。DAE ベクトル z = [x; V; I; u; uc] の長さは n_z = n_x + 2·n_v + n_u + n_uc です（生成されるデータを参照）。

    What it does処理内容
    • Accepts a scenario in place of time (net.simulate(sc, ...)); checks time (check_time).
    • Splits the leading scenarios from the options (split_events).
    • Takes the stored Time and Options of the scenarios where the call gives none (scenario_settings).
    • Takes Export out (take_call_options) and checks its extension (check_export).
    • time の位置にシナリオが来た場合も受け付けます（net.simulate(sc, ...)）。time は check_time で検査します。
    • 先頭に並んだシナリオと、オプションを分けます（split_events）。
    • 呼び出しで指定していない時間とオプションは、シナリオの Time と Options から取ります（scenario_settings）。
    • Export を取り出し（take_call_options）、拡張子を検査します（check_export）。

  4. SIM-04 SolverODE.solve → Scenario.compile, check_islands

    What it does処理内容
    • Checks that each scenario belongs to this network, and its disturbances against the network as it is now (validate).
    • Combines the disturbances of all the scenarios (tags unique in the run); without disturbances, adds one empty one ("NoAction" at t0).
    • Warns for disturbances outside time; cuts the span at every disturbance time (getTimeSpan) and marks the active disturbances of each phase. A phase without an active disturbance gets its own NoAction<k>.
    • Builds once what each phase applies: the faulted buses, tripped units, opened branches; per component, the state offset of the disturbances that start in the phase (all active ones in the first phase) and one input function of the phase time, shifted so that each disturbance function receives the time since its own t_start.
    • check_islands: stops if the opened branches of a phase leave buses without any component.
    • 各シナリオがこのネットワークのものか、その外乱が今のネットワークと合っているかを検査します（validate）。
    • すべてのシナリオの外乱を 1 つにまとめます。タグは実行の中で重複できません。外乱が 1 つもなければ、t0 に空の外乱 "NoAction" を 1 つ加えます。
    • time の範囲外にある外乱があれば警告します。外乱の時刻で区間を区切り（getTimeSpan）、フェーズごとに有効な外乱に印を付けます。有効な外乱がないフェーズには、専用の NoAction<k> を割り当てます。
    • 各フェーズで適用する内容を、最初に一度だけまとめて作ります。地絡する母線、トリップする機器、開くブランチに加えて、機器ごとの状態オフセットと入力関数です。状態オフセットはそのフェーズで始まる外乱から作ります（最初のフェーズでは有効な外乱すべてから作ります）。入力関数はフェーズ内の時刻を引数に取る関数 1 つにまとめ、各外乱の関数にはその外乱の t_start からの経過時間が渡るようにずらします。
    • check_islands は、あるフェーズでブランチを開いた結果、機器のない母線が切り離される場合に処理を止めます。
    What it reads読み取る情報
    sc.tab_disturbance (TimeSpan, FaultBus, TripUnit, OpenBranch, Offset*, Input*), sc.a_PowerNetwork; bus, branch and component tags母線・ブランチ・機器のタグ, sv_x, sv_u
    Returns or changes戻り値・変更する値
    tab_phase (table, one row per phase: t1, t2 [s], one logical column per disturbance表。フェーズごとに 1 行: t1, t2 [s] と、外乱ごとの論理値の列), sct_phase (per phaseフェーズごと: t1, t2, sr_event, sv_fault, sv_trip, sv_open, c_Xoffset, c_Uoffset)

  5. SIM-05 SolverODE.solve → SolverODE.build_index → PowerNetwork.get_variable_map

    What it does処理内容
    • Checks that no input was edited (GUILDA:SolverODE:InputEdited).
    • Collects the stale tags (sct_stale) it reads: powerflow and odefcn of the network, equilibrium and odefcn of each component, local controller and global controller. When any is not empty, stops with GUILDA:SolverODE:Stale, naming up to three different messages, and asks for net.initialize(). Rebuilds nothing.
    • Numbers the DAE vector z = [x; V; I; u; uc] from the variable map: its variable rows in map order, with the bus currents I (not in the map) after V. Records the positions of each block (component, local controller, global controller) and the owner tag of each element of z.
    • Numbers the signal vector s: the rows y, yc of the map. A component computes its outputs only when a connection reads them.
    • Builds the inputs from the connection map: S_sig (inputs × signals), S_var (inputs × z, observed states), rv_e (equilibrium of the inputs with an "equilibrium" connection).
    • Builds the equilibrium vector rv_z0 and the mass matrix rm_M (blocks from tools.read_mass).
    • An output of a global controller without a target: stops with GUILDA:SolverODE:GconNoTarget.
    • 入力が編集されていないか（GUILDA:SolverODE:InputEdited）を確かめます。
    • 使う層の stale タグ（sct_stale）を集めます。対象はネットワークの powerflow と odefcn、各機器、ローカル制御器、グローバル制御器の equilibrium と odefcn です。空でないタグがあれば、異なるメッセージを 3 件まで示して GUILDA:SolverODE:Stale で止め、net.initialize() の実行を促します。ここで作り直すことはしません。
    • 変数マップをもとに、DAE ベクトル z = [x; V; I; u; uc] の各要素に番号を振ります。変数の行はマップの順に並べ、マップにない母線電流 I は V の後に置きます。あわせて、各ブロック（機器、ローカル制御器、グローバル制御器）の位置と、z の各要素を持つオブジェクトのタグを記録します。
    • 信号ベクトル s にも番号を振ります。対象はマップの y と yc の行です。機器の出力は、接続がそれを読む場合にだけ計算します。
    • 接続マップから、入力を決める行列とベクトルを作ります。S_sig は入力 × 信号、S_var は入力 × z で観測する状態を表し、rv_e は "equilibrium" でつながる入力の平衡点です。
    • 平衡点のベクトル rv_z0 と質量行列 rm_M を作ります。各ブロックの質量行列は tools.read_mass で読みます。
    • 接続先のないグローバル制御器の出力があれば、GUILDA:SolverODE:GconNoTarget で止めます。
    What it reads読み取る情報
    net.get_variable_map() (tab, tab_connection), a_Bus, a_Component, a_LocalController, a_GlobalController, controlledUnits, f_*, rv_Xequilibrium, rv_Uequilibrium, c_Vequilibrium, c_Iequilibrium, sct_stale
    Returns or changes戻り値・変更する値
    ctx onlyのみ: n_z, n_s, iv_V, iv_I, iv_in, iv_lin, c_comp, c_lc, c_gc, S_sig, S_var, rv_e, rv_z0, rm_M (n_z × n_z, sparse疎行列), sv_owner

  14. SIM-14 ode → SolverODE.getODEFunction → f_dx, f_I, f_Y

    What it does処理内容

    • Global controllers (skipped while tripped): dx and yc from their own x, the voltages of all buses and their inputs uc.

Where to extend the feature機能を拡張する箇所

A new model takes part through the contract in Model Implementation. What this feature uses:

新しいモデルは、モデルの実装の契約に従うことで、この機能に加わります。この機能がモデルから使うものは次のとおりです。

ModelモデルUsed by the simulationシミュレーションが使うもの
Componentfcn_dx, fcn_I, fcn_Y (SIM-14); a constant fcn_Mass (SIM-05); Jacobi_dx, Jacobi_I, Jacobi_Y (SIM-15, numerical differentiation without them, which is slower). sv_x and sv_u are the names used by OffsetState and InputName. A subclass of component.generator.abstract restarts after a trip through get_equilibrium(V, 0, 0, 0) (SIM-18).fcn_dx、fcn_I、fcn_Y (SIM-14)、定数の fcn_Mass (SIM-05)、Jacobi_dx、Jacobi_I、Jacobi_Y (SIM-15) を使います。ヤコビアンがなければ数値微分で求めるので、遅くなります。sv_x と sv_u の名前は、OffsetState と InputName で指定するときに使います。component.generator.abstract のサブクラスは、トリップの後 get_equilibrium(V, 0, 0, 0) で再開します (SIM-18)。
LocalControllerfcn_dx, fcn_y, a constant fcn_Mass, Jacobi_dx, Jacobi_Y. Its inputs sv_u are read by name: an output of a nested controller, then an output of the component, then a state ("local", "observe"); its outputs sv_y drive the inputs of the same name. A component has two slots: the AVR or "local" controller, which can hold one more (a PSS under the AVR), and a governor; the two drive different inputs (GUILDA:Component:ControllerOutputOverlap).fcn_dx、fcn_y、定数の fcn_Mass、Jacobi_dx、Jacobi_Y を使います。入力 sv_u は名前で参照し、入れ子の制御器の出力、機器の出力、状態の順に探します（"local"、"observe"）。出力 sv_y は、同じ名前の入力を動かします。機器には制御器の枠が 2 つあります。1 つは AVR または "local" の制御器で、その下にもう 1 つ（AVR の下の PSS など）を持てます。もう 1 つはガバナです。2 つが同じ入力を動かすことはできません（GUILDA:Component:ControllerOutputOverlap）。
GlobalControllerfcn_dx, fcn_y, Jacobi_dx, Jacobi_Y, a constant fcn_Mass; sv_u names outputs or states, sv_y names inputs of every controlled unit. Routing by name in the connection map ("observe", "global"): an output drives every local controller of the unit with an input of that name, otherwise the component input; an input is the sum of its sources.fcn_dx、fcn_y、Jacobi_dx、Jacobi_Y、定数の fcn_Mass を使います。sv_u には各制御対象の出力か状態の名前を、sv_y には制御対象の入力の名前を書きます。接続は接続マップ（"observe"、"global"）が名前で決めます。出力は、同じ名前の入力を持つ制御対象のローカル制御器すべてにつながり、そうした制御器がなければ機器の入力につながります。入力には、接続元の値の和が入ります。
New disturbance kind新しい種類の外乱
  • Add the field to Scenario (sv_field, the empty record, an add_* method).
  • Check it in validate_disturbance; collect it per phase in Scenario.compile.
  • Apply it in SolverODE.solve (as set_admittance does for OpenBranch; variables removed through lv_FBorTC in initial_condition) and in getNextPhase (restart values).
  • Keep its per-phase state in ctx (as set_phase in solve.m does); never write to the models. Add its column to Scenario.import_csv / export_csv.
  • Scenario にフィールドを加えます（sv_field、空のレコード、add_* メソッド）。
  • validate_disturbance で検査し、Scenario.compile でフェーズごとに集めます。
  • SolverODE.solve と getNextPhase（再開時の値）に処理を加えます。SolverODE.solve では、OpenBranch に対する set_admittance のように扱い、変数を除く場合は initial_condition の lv_FBorTC を使います。
  • フェーズごとの状態は、solve.m の set_phase と同じように ctx に置き、モデルには書き込みません。Scenario.import_csv / export_csv にも列を加えます。
