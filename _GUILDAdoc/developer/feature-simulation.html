Feature: Time Simulation機能: 時間応答シミュレーション

net.simulate integrates the differential-algebraic equations (DAE) of the network over time, starting at the equilibrium of net.initialize, with the disturbances of the given scenarios (Scenario). This page follows one call from the public method through SolverODE to the ResultODE it returns.

net.simulate は、net.initialize で求めた平衡点から出発し、与えたシナリオ (Scenario) の外乱のもとでネットワークの微分代数方程式 (DAE) を時間積分します。このページでは、公開メソッドから SolverODE を経て ResultODE が返るまでの 1 回の呼び出しを順に追います。

Purpose and entry point目的と入口

The simulation splits the time span into phases: intervals in which the set of active disturbances does not change. Each phase is one call of the MATLAB ode object on the DAE of the network as it is in that phase (faulted buses and tripped units removed, opened branches left out of the admittance matrix). The state at the end of a phase, after the changes of the next phase, is the start of the next one.

シミュレーションは時間区間をフェーズに分けます。フェーズとは、有効な外乱の組が変わらない区間です。各フェーズでは、そのフェーズにおけるネットワーク (地絡した母線とトリップした機器を除き、開放したブランチをアドミタンス行列から除いたもの) の DAE を MATLAB の ode オブジェクトで 1 回解きます。フェーズ終了時の状態に次のフェーズの変化を加えたものが、次のフェーズの初期値です。

[result, flag, output] = net.simulate(time, sc1, sc2, ..., Name, Value)
[result, flag, output] = net.simulate(sc, Name, Value)
sc = Scenario(tag, Time=…, Options=…, Judge=…, Description=…)
sc.add_fault(bus, [t_start, t_end])            % also add_trip, add_open_branch, add_offset, add_input
net.add_scenario(sc)
verdict = sc.judge(result)
  • time: [t0, tend] in seconds with finite t0 < tend, [], or left out (net.simulate(sc, ...)). Without a time, the Time of the scenarios is used; when they have none, the span is [0, 30·ceil(tmax/10)] where tmax is the latest disturbance time (10 s more when that equals tmax); without disturbances, [0, 10].
  • time: 秒単位の [t0, tend] (有限で t0 < tend)、[]、または省略 (net.simulate(sc, ...))。時間がなければシナリオの Time を使います。シナリオにもなければ、外乱の最も遅い時刻を tmax として [0, 30·ceil(tmax/10)] を使います (それが tmax と等しければ 10 s 延長)。外乱がなければ [0, 10] です。
  • Scenarios: the leading Scenario arguments, each added to this network (net.add_scenario); none gives the response without disturbance. Their disturbances are combined. Everything after the first non-Scenario argument is Name-Value options. Scenarios with different Time, or different values of one stored option, stop with an error unless the call gives the time or the option. The verdict is not an output: call sc.judge(result) (default Scenario.out_of_step).
  • シナリオ: 先頭に並べた Scenario 引数で、それぞれこのネットワークに追加済み (net.add_scenario) であること。なければ外乱のない応答になります。複数の外乱は合成されます。最初の Scenario 以外の引数から後ろはすべて Name-Value オプションです。Time や保存されたオプションの値がシナリオ間で異なるとエラーになります (呼び出しで時間やそのオプションを与えた場合を除く)。判定は出力に含まれないので、sc.judge(result) を呼びます (既定は Scenario.out_of_step)。

Name-Value options and defaultsName-Value オプションと既定値

The defaults are the properties of net.solver_ODE (a SolverODE). Its constructor reads GUILDA.config("TimeSimulation") for the values marked config; the others are class defaults. The stored Options of the scenarios replace them, and a Name-Value option of the call replaces both, for this call only (scenario_settings, SolverODE.OptionMap, tools.resolve_options); net.reset_solver() replaces the solver with a new one. See API Design for the shared rules.

既定値は net.solver_ODE (SolverODE) のプロパティです。config と書いた値はコンストラクタが GUILDA.config("TimeSimulation") から読み、その他はクラスの既定値です。シナリオに保存された Options がこれを置き換え、呼び出しの Name-Value オプションはその両方を、その呼び出しに限って上書きします (scenario_settings、SolverODE.OptionMap、tools.resolve_options)。net.reset_solver() はソルバーを新しいものに置き換えます。共通の規則は API Design を参照してください。

Disturbances (Scenario)外乱 (Scenario)

A scenario holds a list of disturbances (sc.tab_disturbance), each with its own time span and tag. The tag names the column of the disturbance in the phase table, so it must be unique in the scenario and in one run and must not be t1, t2, Properties, Row, Variables, empty, or NoAction followed by digits; the add_* methods give fault<n>, open<n>, ... by default. The buses, branches and units are named by tag and checked against the network when a disturbance is added to an attached scenario, when the scenario is added to a network, and again in SIM-05. sc.add_disturbance(tag, Name=Value) takes the fields below and can combine several kinds in one disturbance.

シナリオは外乱の一覧 (sc.tab_disturbance) を持ち、外乱ごとに時間区間とタグがあります。タグはフェーズ表での外乱の列名になります。そのためシナリオの中でも 1 回の実行の中でも一意でなければならず、t1、t2、Properties、Row、Variables、空文字、NoAction + 数字は使えません。add_* メソッドの既定のタグは fault<n>、open<n> などです。母線・ブランチ・機器はタグで指定し、ネットワークに追加済みのシナリオに外乱を加えたとき、シナリオをネットワークに追加したとき、そして SIM-05 で、ネットワークと照合します。sc.add_disturbance(tag, Name=Value) は以下のフィールドを受け取り、1 つの外乱で複数の種類を組み合わせることもできます。

A scenario belongs to at most one network (net.a_Scenario, sc.a_PowerNetwork): net.add_scenario(sc) attaches it and moves it from another network, net.remove_scenario(tag) detaches it, and sc.copy() gives an unattached duplicate. Scenarios are not model data: adding, removing or editing them does not make the equilibrium stale. Scenario.import_csv and Scenario.export_csv read and write several scenarios, one row per disturbance. The deprecated ODEevent(tag, net, Name, Value) (_VersionSupport/) returns a scenario with one disturbance, already added to net.

シナリオが属するネットワークは高々 1 つです (net.a_Scenario、sc.a_PowerNetwork)。net.add_scenario(sc) で追加し (ほかのネットワークのものなら移動)、net.remove_scenario(tag) で外し、sc.copy() でどのネットワークにも属さない複製を作ります。シナリオはモデルのデータではなく、追加・削除・編集しても平衡点は古くなりません。Scenario.import_csv と Scenario.export_csv は複数のシナリオを、外乱 1 つにつき 1 行で読み書きします。非推奨の ODEevent(tag, net, Name, Value) (_VersionSupport/) は、外乱を 1 つ持ち net に追加済みのシナリオを返します。

Preconditions前提条件

  • net.initialize() has run and nothing that changes the equilibrium was edited since (see Class Design, Edit handling). Out-of-date function handles f_* are rebuilt automatically.
  • net.initialize() を実行済みで、その後に平衡点を変える編集がないこと (Class Design の Edit handling を参照)。古くなった関数ハンドル f_* は自動で作り直されます。
  • Every scenario belongs to this network and the tags of its disturbances exist in it now, and every unit a global controller controls is on this network.
  • すべてのシナリオがこのネットワークに属し、その外乱のタグが現在のネットワークに存在すること。広域制御器が制御する機器がすべてこのネットワーク上にあること。
  • The mass matrices of all components and controllers are constant (tools.read_mass).
  • すべての機器と制御器の質量行列が定数であること (tools.read_mass)。
