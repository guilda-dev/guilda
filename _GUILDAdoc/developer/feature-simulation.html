Time Simulation Feature Design時間応答シミュレーション機能の設計

net.simulate integrates the differential-algebraic equations (DAE) of the network over time from the equilibrium of net.initialize, under the disturbances of one scenario (Scenario) chosen by its tag. This page follows one call: public method → data of the run → SolverODE → ResultODE.

net.simulate は、net.initialize で求めた平衡点から始めて、タグで選んだ 1 つのシナリオ (Scenario) の外乱のもとでネットワークの微分代数方程式 (DAE) を時間積分します。このページでは、1 回の呼び出しが公開メソッドから実行のデータ、SolverODE、ResultODE へと進む流れを説明します。

What the feature does and how to call it機能の目的と呼び出し方

The time span is split into phases: intervals with an unchanged set of active disturbances.

  • One phase: one call of the MATLAB ode object on the DAE of the network in that phase (faulted buses and tripped units removed, opened branches left out of the admittance matrix).
  • Start of the next phase: the state at the end of a phase, after the changes of the next phase.
  • PowerNetwork gathers the data of the run; SolverODE reads only that data, never the network or its models.

時間区間はフェーズに分けて扱います。フェーズとは、有効な外乱の組み合わせが変わらない区間のことです。

  • 各フェーズでは、そのフェーズのネットワークの DAE を MATLAB の ode オブジェクトで 1 回解きます。このネットワークからは地絡した母線とトリップした機器を除き、開放したブランチもアドミタンス行列から除きます。
  • 次のフェーズは、前のフェーズが終わった時点の状態に、次のフェーズで起きる変化を加えた値から始めます。
  • 実行に要るデータは PowerNetwork が集めます。SolverODE はそのデータだけを読み、ネットワークやモデルは読みません。
sc = net.add_scenario(tag, Time=[t0, tend], Description=…)
sc.add_fault(bus, [t_start, t_end])     % also add_trip, add_open_branch, add_offset, add_input, add_disturbance
[result, flag, output] = net.simulate(tag, Name=Value)
sol = net.simulate(tag, Format="struct")
verdict = result.judge_out_of_step(Reference=…, Threshold=…)
result.export(filename)
net.remove_scenario(tag)
  • tag: the tag of one scenario of this network (net.add_scenario). Exactly one scenario per run. A tag that is not one stops with GUILDA:PowerNetwork:ScenarioNotFound, which lists up to 10 tags of the network. A run without disturbance uses a scenario without disturbances.
  • tag には、このネットワークのシナリオ（net.add_scenario）のタグを 1 つ渡します。1 回の実行で使うシナリオは 1 つです。ネットワークにないタグは GUILDA:PowerNetwork:ScenarioNotFound で止まり、ネットワークのタグを最大 10 個示します。外乱のない応答は、外乱のないシナリオで計算します。
  • Time: sc.Time ([0, 10] unless set), or the Time option, which replaces it for this call only. The disturbances do not change the time.
  • 時間は sc.Time（指定しなければ [0, 10]）です。Time オプションを指定すると、その呼び出しの間だけ置き換わります。外乱の時刻によって時間が変わることはありません。
  • Verdict and file: not part of the call. Call result.judge_out_of_step() and result.export(filename) on the result.
  • 判定とファイルへの書き出しは、呼び出しには含みません。結果に対して result.judge_out_of_step() と result.export(filename) を呼び出します。

Disturbances given as a ScenarioScenario で与える外乱

A scenario is a child of one network: net.add_scenario(tag) creates it (net.a_Scenario, sc.a_PowerNetwork), net.remove_scenario(tag) deletes it, and net.add_scenario(tag, From=sc) copies another one. It holds the simulation time Time, a Description and a list of disturbances (sc.tab_disturbance), each with its own time span and tag. It holds data only: no function handles and no settings of the solver.

  • Tag of the scenario: shares the name space of the buses, branches and global controllers of the network; a tag in use gets a number suffix.
  • Tag of a disturbance: the column of the disturbance in the phase table. Unique in the scenario; not t1, t2, Properties, Row, Variables, empty, or NoAction followed by digits. Defaults of the add_* methods: fault<n>, open<n>, ...
  • Buses, branches and units: named by tag; checked against the network when added and again in SIM-04.
  • sc.add_disturbance(tag, Name=Value): takes the fields below; several kinds can be combined in one disturbance.

シナリオは 1 つのネットワークの子です。net.add_scenario(tag) で作り（net.a_Scenario、sc.a_PowerNetwork）、net.remove_scenario(tag) で削除します。net.add_scenario(tag, From=sc) は別のシナリオを写します。シナリオは、シミュレーションの時間 Time、説明 Description、外乱の一覧 (sc.tab_disturbance) を持ちます。外乱にはそれぞれ時間区間とタグがあります。シナリオが持つのはデータだけで、関数ハンドルやソルバーの設定は持ちません。

  • シナリオのタグは、ネットワークの母線、ブランチ、グローバル制御器と同じ名前空間を使います。使用中のタグには番号が付きます。
  • 外乱のタグは、フェーズ表で外乱の列名になります。シナリオの中で重複できません。t1、t2、Properties、Row、Variables、空文字、NoAction に数字を付けたものは使えません。add_* メソッドは fault<n>、open<n> のようなタグを自動で付けます。
  • 母線、ブランチ、機器はタグで指定します。外乱を加えるときと SIM-04 で、ネットワークと照らし合わせます。
  • sc.add_disturbance(tag, Name=Value) は次のフィールドを受け取ります。1 つの外乱に複数の種類をまとめることもできます。

Preconditions for the call呼び出しの前提条件

  • net.initialize() has run, with no edit since that makes a layer stale, a network Hz edit included (see Class Design: Handling of model edits). initialize builds the function handles f_*.
  • net.initialize() を実行してあり、その後に層を古くする編集をしていないことが前提です。ネットワークの Hz の編集もこれに含みます（クラス設計: モデル編集の扱いを参照）。関数ハンドル f_* は initialize が作ります。
  • The tags in the disturbances of the scenario exist in the network now.
  • シナリオの外乱に書いたタグが、今のネットワークに存在していなければなりません。
  • The mass matrices of all components and controllers are constant: f_Mass([],[],[],[]) returns a matrix of the block size (SIM-07).
  • すべての機器と制御器で、質量行列が定数でなければなりません。f_Mass([],[],[],[]) がブロックの大きさの行列を返す必要があります（SIM-07）。

Processing steps in detail処理ステップの詳細

  • Each step: one requirement of the feature. Steps marked on the left run once per phase.
  • n_x, n_v (= 2 × number of buses), n_u, n_uc: numbers of states, bus voltage variables, component inputs and controller inputs of net.get_variable_map(). n_z = n_x + 2·n_v + n_u + n_uc: length of the DAE vector z = [x; V; I; u; uc] (see Data produced).
  • 各ステップが、この機能の要件 1 つに当たります。左に印のあるステップは、フェーズごとに実行します。
  • n_x、n_v (= 2 × 母線数)、n_u、n_uc は、net.get_variable_map() にある状態、母線電圧変数、機器入力、制御器入力の数です。DAE ベクトル z = [x; V; I; u; uc] の長さは n_z = n_x + 2·n_v + n_u + n_uc です（生成されるデータを参照）。

  4. SIM-04 build_simulation_data → Scenario.compile(sct_dae, time), check_islands

    What it does処理内容
    • Checks the disturbances against the network as it is now (validate). Without disturbances, adds one empty one ("NoAction" at t0).
    • Warns for disturbances outside time; cuts the span at every disturbance time and at each point after the first of a "zoh" input series, and marks the active disturbances of each phase. A phase without an active disturbance gets its own NoAction<k>.
    • Matches the tags once and gives what each phase applies as positions in sct_dae: the tripped components and global controllers, the faulted buses, the open branches, the state offsets of the disturbances that start in the phase (all active ones in the first phase), and one row per active input: its rows of tab_variable, the times from the start of the phase, the values and the interpolation (a constant and a "zoh" series: one point, the value of the phase).

  • ID は _GUILDAsystem/_auxiliary/SystemTools/GUILDA/en/<Object>.xml の項目名です。
  • SolverODE が作る MException（PhaseFailed、UnfeasibleDAE、InitialConditionFailed、AlgebraicNotSolved）は、ID を identifier に持ちます。
  • error(msg(ID)) はメッセージの本文しか渡しません。警告（show_msg("warning", ID, ...)）は、ID を identifier に持ちます。
