Initialization Feature Design初期化機能の設計

net.initialize() turns an operating point (a power flow, an AC optimal power flow, or the equilibria the components already hold) into the equilibrium of every bus, component, local controller, and global controller, checks it, and resets the edit log. Starting point of every dynamic analysis.

net.initialize() は運転点（潮流計算、交流の最適潮流計算、または機器が保持済みの平衡点）を、すべての母線・機器・局所制御器・広域制御器の平衡点として設定・検査し、編集ログをリセット。動的な解析はすべてこの平衡点が起点。

What the feature does and how to call it機能の目的と呼び出し方

[result, flag, output] = net.initialize(Name=Value, ...)
OptionオプションValues and default値と既定値
Method
  • "powerflow" (default): net.calculate_powerflow with the settings of net.solver_PF
  • "OPF": net.optimize_powerflow with Method="AC OPF" and the settings of net.solver_OPF
  • "equilibrium": the equilibria the components already hold; states and inputs recomputed from the held V and I
Default fixed in initialize; no solver_* property or GUILDA.config entry for it
  • "powerflow"（既定）: net.solver_PF の設定で net.calculate_powerflow を実行
  • "OPF": net.solver_OPF の設定で Method="AC OPF" の net.optimize_powerflow を実行
  • "equilibrium": 機器が保持済みの平衡点を使用。状態と入力は保持された V と I から再計算
既定値は initialize 内で固定。対応する solver_* のプロパティや GUILDA.config の項目はなし
other namesその他の名前
  • Passed unchanged to calculate_powerflow ("powerflow") or optimize_powerflow ("OPF")
  • Validated there against SolverPF.OptionMap / SolverOPF.OptionMap plus Plot and Export
  • Defaults: the properties of net.solver_PF / net.solver_OPF, which a new solver reads from GUILDA.config
  • "equilibrium": no other option
  • Formulation of the analysis: not an option of initialize; set net.solver_PF.Method
  • そのまま calculate_powerflow（"powerflow"）または optimize_powerflow（"OPF"）へ受け渡し
  • 渡し先で SolverPF.OptionMap / SolverOPF.OptionMap と Plot、Export により検査
  • 既定値: net.solver_PF / net.solver_OPF のプロパティ。ソルバーは生成時に GUILDA.config から読み込み
  • "equilibrium": 他のオプションは不可
  • 解析の定式化: initialize のオプションではない。net.solver_PF.Method で設定

Preconditions:

前提条件:

  • At least one bus with a component (the power flow selects a slack bus when none is set)
  • Method="equilibrium": an earlier successful initialize, and no edit since then that changes the equilibrium (edits of dynamics parameters excepted)
  • 機器を持つ母線が 1 つ以上（スラック母線が未設定なら潮流計算が選択）
  • Method="equilibrium": 先に initialize が成功済みで、その後に平衡点を変える編集（動特性パラメータの編集を除く）がないこと

The deprecated option methods and its values are converted by v3_initialize_args with a warning.

非推奨のオプション methods とその値は v3_initialize_args が警告付きで変換。

  • initialize changes the model: one of the few analysis methods that do (see API Design, rule 6)
  • Called when a network is built: by the shipped network classes and by PowerNetwork.import_csv / import_matpower (option Initialize=true, the default)
  • initialize はモデルを変更: そうした数少ない解析メソッドの 1 つ（API 設計のルール 6 を参照）
  • ネットワーク構築時に呼び出し: 同梱のネットワーククラスと PowerNetwork.import_csv / import_matpower（オプション Initialize=true、既定）

  10. INIT-08 Bus.set_equilibrium → distribute_power

    • 1 台ならすべて、複数なら QdistributionRule で分割
    • 規則: "baseMVA"（既定、operation.baseMVA に比例）または "Qmax"（すべて有限のとき Qmax − Qmin に比例）

Side effects on the model and cachesモデルへの副作用とキャッシュ

  • Written:
    • the equilibrium properties above
    • the f_* handle caches that were not up to date (INIT-02)
    • l_isSlack of the bus that the power flow selects when none is set (kept after a successful call)
    • the gain of controller.local_LQR
  • Edit state:
    • l_staleEquilibrium made true at INIT-05 (an "Initialize" row in the edit log)
    • cleared at INIT-13, which sets sct_edit.l_initialized on every layer and empties the edit log of the network
    • a call that stops between them leaves it set
  • Later edits:
    • the edit log decides what becomes stale (see Class Design: Handling of model edits)
    • nothing re-runs initialize automatically
    • simulate, linearize, and get_sys stop with GUILDA:PowerNetwork:EquilibriumStale; the continuation power flow with GUILDA:SolverCPF:StaleEquilibrium
    • after edits of dynamics parameters only: initialize(Method="equilibrium") keeps V and I and recomputes the states and inputs
  • Network frequency: an edit of Hz rebuilds the handles at the next analysis; no new initialize needed
  • 書き込むもの:
    • 上の平衡点のプロパティ
    • 最新でなかった f_* ハンドルのキャッシュ（INIT-02）
    • スラック母線が未設定のとき潮流計算が選ぶ母線の l_isSlack（呼び出しが成功すれば保持）
    • controller.local_LQR のゲイン
  • 編集状態:
    • l_staleEquilibrium は INIT-05 で true（編集ログに "Initialize" の行）
    • INIT-13 で全レイヤーの sct_edit.l_initialized の設定とネットワークの編集ログの消去とともに解除
    • その間で停止した呼び出しでは設定されたまま
  • 後からの編集:
    • 何が古くなるかは編集ログで決定（クラス設計: モデル編集の扱い を参照）
    • initialize の自動再実行はなし
    • simulate、linearize、get_sys は GUILDA:PowerNetwork:EquilibriumStale で、連続潮流計算は GUILDA:SolverCPF:StaleEquilibrium で停止
    • 動特性パラメータだけの編集後: initialize(Method="equilibrium") が V と I を保ったまま状態と入力を再計算
  • 系統周波数: Hz の編集では次の解析でハンドルを再構築。initialize のやり直しは不要

Where to extend the feature機能を拡張する箇所

A new model takes part in initialization through its get_equilibrium (see Model Implementation: Contracts a model implements):

新しいモデルは get_equilibrium を通じて初期化に参加（モデルの実装: モデルが実装する契約 を参照）

ModelモデルMust implement実装すべきもの
Component
  • [x, u] = get_equilibrium(obj, c_V, c_I, r_P, r_Q), always called with all four arguments
  • x and u: the sizes of sv_x and sv_u
  • At (x, V, u) the model holds fcn_dx = 0 and fcn_I = c_I
  • What the component receives: decided by the power-flow settings P, Q (NaN Q for a voltage-controlling unit) and operation.baseMVA
  • [x, u] = get_equilibrium(obj, c_V, c_I, r_P, r_Q)。常に 4 つの引数で呼び出し
  • x と u: sv_x と sv_u の大きさ
  • (x, V, u) でモデルが fcn_dx = 0 と fcn_I = c_I を満たすこと
  • 機器が受け取る値: 潮流計算の設定 P、Q（電圧を制御する機器は Q を NaN）と operation.baseMVA で決定
LocalController
  • get_equilibrium(obj, V, u) with no output
  • Writes rv_Xequilibrium and rv_Uequilibrium, and calls the nested controller
  • At the equilibrium: outputs must equal the inputs of the component they drive
  • 出力のない get_equilibrium(obj, V, u)
  • rv_Xequilibrium と rv_Uequilibrium を書き込み、入れ子の制御器を呼び出し
  • 平衡点: 出力が駆動する機器の入力と一致すること
GlobalController
  • [x, u] = get_equilibrium(obj)
  • Runs before the buses and components are set (INIT-06): must not read their new equilibrium
  • Outputs must be zero at the equilibrium, because they are added to the inputs of the controlled units
  • [x, u] = get_equilibrium(obj)
  • 母線と機器の設定より前（INIT-06）に実行: それらの新しい平衡点の読み取りは不可
  • 出力は制御対象の入力に加算されるため、平衡点ではゼロが必要
  • Check a new model with comp.validate() or con.validate()
  • initialize reports the remaining residuals with EquilibriumResidual
  • 新しいモデルは comp.validate() または con.validate() で確認
  • 残った残差は initialize が EquilibriumResidual で報告
