Arguments blocksarguments ブロック

Arguments are described only in arguments (Input) and arguments (Output) blocks.

引数の記述は arguments (Input) / arguments (Output) ブロックのみ。

  • Input blocks are written arguments (Input), never a bare arguments; repeating inputs are arguments (Input, Repeating). MATLAB reads both forms the same way; the written form says which side the block describes.
  • Every method declares its inputs and outputs in these blocks, each entry with a trailing % [unit] Description.; obj is listed too, even when it is the only input. Inputs: or Outputs: prose in the help is not written.
  • varargin goes in arguments (Input, Repeating) and varargout in arguments (Output, Repeating): MATLAB accepts them in no other block.
  • Exempt: property get. / set. methods, where MATLAB allows no arguments block.
  • A %#ok<...> pragma that the Code Analyzer reports as MSNU (the suppressed message is no longer generated) is removed, e.g. an %#ok<INUSL> made unnecessary by the arguments block. A pragma that still suppresses a message stays.
  • 入力のブロックの表記は arguments (Input)。arguments だけの表記は不可。繰り返し入力は arguments (Input, Repeating)。MATLAB の解釈はどちらも同じで、表記でブロックが入力側か出力側かを明示。
  • すべてのメソッドが入力と出力をこれらのブロックで宣言。各項目の行末に % [unit] Description.。入力が obj だけでも obj を記載。ヘルプに Inputs: / Outputs: の文章は書かない。
  • varargin は arguments (Input, Repeating)、varargout は arguments (Output, Repeating): MATLAB はこれ以外のブロックでは不可。
  • 例外: プロパティの get. / set. メソッド。MATLAB が arguments ブロックを許さないため。
  • Code Analyzer が MSNU（抑制したメッセージがもう出ない）と報告する %#ok<...> プラグマは削除。例: arguments ブロックで不要になった %#ok<INUSL>。まだメッセージを抑制しているプラグマは残す。

Arguments of hot-path functionsホットパス関数の引数

What a block may check depends on how often the function runs.

ブロックで検査してよい範囲は関数の呼び出し頻度で区別。

Function関数Allowed in its arguments blocksarguments ブロックで使えるもの
Entry point and public API, e.g. simulate, add_component入口と公開 API。例: simulate、add_componentFull validation: size, class, validator functions, defaults and name-value arguments.すべての検証: サイズ、クラス、検証関数、既定値、名前と値の引数。
Hot path, called per ODE right-hand side evaluation, Newton iteration or time step, e.g. SolverODE.getODEFunction, model fcn_* / Jacobi_*, power-flow mismatchホットパス関数: ODE 右辺の評価、Newton 反復、時間ステップごとに呼ばれる関数。例: SolverODE.getODEFunction、モデルの fcn_* / Jacobi_*、潮流のミスマッチSize and class with a comment. No validator functions ({mustBe...}) and no name-value arguments (opt.Name): range checks belong at the analysis entry, done once.サイズとクラス、コメント。検証関数（{mustBe...}）と名前と値の引数（opt.Name）は不可: 範囲の検査は解析の入口で一度だけ。
  • Why: validator functions and name-value parsing run on every call, while size and class checks are nearly free.
  • Size and class declarations convert the input: a row vector becomes a column, single becomes double. Declare only shapes that every caller passes; otherwise declare the class only, or write the comment only.
  • 理由: 検証関数と名前と値の引数の解析は呼び出しのたびに実行、サイズとクラスの検査はほぼ無負担。
  • サイズとクラスの宣言による入力の変換: 行ベクトルは列ベクトル、single は double に。宣言するサイズはすべての呼び出し元が渡す形のみ。形が一定でなければクラスだけ、またはコメントだけ。
function odeX = getODEFunction(ctx, t, x, RM, EM, lg)
% Right-hand side of the DAE of one phase, evaluated block by block.
    arguments (Input)
        ctx                 % Context of the run.
        t    (1,1) double   % [s] Time from the start of the phase.
        x    (:,1) double   % Reduced state vector.
        RM                  % Reduction matrix of the phase.
        EM                  % Expansion matrix of the phase.
        lg   (:,1) logical  % True for the entries of the full state vector that are solved.
    end
    arguments (Output)
        odeX (:,1) double   % Right-hand side of the reduced DAE.
    end

Dynamic models動的モデル

For a component or controller whose help lists its states, inputs and outputs. The words name the signals of the dynamical system, not the arguments of a function.

状態・入力・出力を列挙するコンポーネントとコントローラのヘルプ向け。関数の引数ではなく、動的システムの信号であることを明示する表現。

  • Lead: **Dynamic model**, then one sentence: the model is a dynamical system with state x, input u and output y (a component adds its bus voltage V and injected current I).冒頭: **Dynamic model** と 1 文の説明。モデルは状態 x、入力 u、出力 y をもつ動的システム（コンポーネントは母線電圧 V と注入電流 I も記載）。
  • Then, in this order, the parts the model has: **State variables** $x$ (`sv_x`), **Input signals** $u$ (`sv_u`; …), **Output signals** $y$ (`sv_y`; …), **Parameters** (`sv_para`, …), **Equations**. One item per variable, in the order of the property.続いて、モデルにある部分をこの順で: **State variables** $x$ (`sv_x`)、**Input signals** $u$ (`sv_u`; …)、**Output signals** $y$ (`sv_y`; …)、**Parameters** (`sv_para`, …)、**Equations**。変数ごとに 1 項目、プロパティの並び順。
  • No part for what the help does not describe: a model with no equations lists none.ヘルプで扱わない部分は省略。式のないモデルへの式の追加は不可。
  • Equations: two or more differential equations form a braced system, \left\{ \begin{aligned} … \end{aligned} \right., one equation per line aligned at =. The algebraic relations follow after with, in a second ```math block. A single equation has no brace.式: 2 本以上の微分方程式は波括弧の連立形 \left\{ \begin{aligned} … \end{aligned} \right.、1 行 1 式で = 揃え。代数式は with の後に別の ```math ブロック。1 本だけの式は波括弧なし。
  • Symbols: state the meaning of a symbol that is not a variable name in the heading, e.g. a prime for _p. Limits and non-windup rules stay in the text after the equations.記号: 変数名と異なる記号は見出しの括弧内で説明（例: プライムは _p）。リミットとワインドアップ防止は式の後の本文。
% **Dynamic model**
% The model is a dynamical system with state $x$, input $u$ and output $y$, connected
% to its bus through the bus voltage $V$ and the current $I$ it injects.
%
% **State variables** $x$ (`sv_x`)
% - `delta` [rad]: Rotor angle in the network reference frame.
% - `omega` [pu]: Rotor speed deviation from the network frequency.
%
% **Input signals** $u$ (`sv_u`; the ports driven by local controllers)
% - `Pmech` [pu]: Mechanical power (governor output).
%
% **Output signals** $y$ (`sv_y`; read by local controllers)
% - `omega` [pu]: Rotor speed deviation from the network frequency.
%
% **Parameters** (`sv_para`, the columns of `tab_parameter.dynamics`)
% - `M` [s]: Inertia constant (`M = 2H`).
% - `D` [pu]: Damping coefficient.
%
% **Equations** ($\omega_0$ is the network frequency `get_Hz()`)
% ```math
% \left\{
% \begin{aligned}
% \dot{\delta} &= 2\pi\omega_0\,\omega \\
% M\dot{\omega} &= -D\,\omega - P + P_\mathrm{mech}
% \end{aligned}
% \right.
% ```
% with
% ```math
% P = V_d I_d + V_q I_q
% ```
