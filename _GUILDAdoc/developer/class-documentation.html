How to Define Class Documentation

GUILDA class documentation is generated from MATLAB reflection metadata and exact <@TagName> tags stored next to the implementation. The exporter writes a lightweight class index and one detailed JavaScript document per class under _GUILDAdoc/database.

Collection Pipeline

  1. GUILDA.doc("update", true) obtains the PowerSystemModel class list from GUILDA.dictionary and prepends LayerPackage.
  2. export_class_database resolves each class with meta.class.fromName.
  3. Reflection supplies class, property, and method attributes; source comments supply the tagged documentation.
  4. The exporter validates tags and structured JSON, then writes the index and class documents.
  5. doc-loader.js reads the index first and loads a class document only when its class or method page is opened.

Sources and Precedence

TargetPrimary sourceFallback
ClassConsecutive comment lines immediately after classdefMATLAB help, then reflection descriptions
PropertyConsecutive comment lines immediately above the property declarationMATLAB help, then reflection descriptions
MethodConsecutive comment lines after function in a separate method fileMATLAB help, then reflection descriptions

Source comments are preferred because MATLAB's help renderer can change indentation. The exporter removes the MATLAB comment prefix but preserves meaningful leading spaces, blank lines, and text-art alignment inside tag values.

Generated Data Structure

Class Index

database/list_Classes.js registers window.GUILDA_DOC_INDEX. Its schema version is currently 2.

window.GUILDA_DOC_INDEX = {
  schema: {
    version: 2,
    classDocumentVersion: 2,
    modelCategories: [...],
    coreClasses: [...],
    tags: {...},
    legacyAliases: {...}
  },
  classes: [...],
  validation: {
    warningCount: 0,
    errorCount: 0,
    classes: [...]
  }
};

Each classes entry contains the fields below.

FieldSource / purpose
NameFully qualified MATLAB class name.
TypeDerived category: PowerSystemModel, auxiliary, or other.
ModelNearest system-model category, such as PowerNetwork, Bus, or Component.
ParentSuperclass names obtained from reflection.
Abstract, HiddenClass attributes obtained from reflection.
Summary, Desc, Role, Constructor, Notes, SeeAlso, Since, DeprecatedCanonical class tags.
pathInternal path used to lazily load the detailed class document. It is required but is not displayed as documentation.

Validation is stored centrally under validation.classes. The redundant per-index-entry fields DocumentationStatus, DocumentationWarnings, and DocumentationErrors are not generated.

Detailed Class Documents

Each class has a file in database/GUILDAsystem or database/GUILDAobject. It registers data under window.GUILDA_DOC_CLASSES[ClassName].

{
  schema: { name: "GUILDA class document", version: 2 },
  ClassName: "component.generator.park",
  properties: [...],
  methods: [...],
  validation: { Warnings: [...], Errors: [...] }
}

Property records combine reflection attributes such as Defining, GetAccess, SetAccess, Dependent, Constant, Abstract, and Hidden with property tags. Method records similarly combine Defining, Access, Static, Abstract, and Hidden with method tags.

Tag Schema

TargetCanonical tags
ClassSummary, Desc, Role, Constructor, Notes, SeeAlso, Since, Deprecated
PropertySummary, Desc, Role, Type, Size, Unit, Default, Constraints, Notes, SeeAlso, Since, Deprecated
MethodSummary, Desc, Role, Signatures, Parameters, Returns, Examples, Notes, Throws, SeeAlso, Since, Deprecated

Tags are case-sensitive field names and must use the exact form <@TagName>. For example, <Summary> is not a documentation tag. A tag value continues until the next valid tag or the end of the comment block.

Use canonical names in new code. Existing documentation can also be read through these aliases:

Authoring Rules

  • Use Summary for one concise sentence shown in reference tables.
  • Use Desc for the full explanation shown on the detail page. It does not replace a missing Summary in reference tables.
  • Single newlines, consecutive spaces, and indentation are preserved. ASCII diagrams are rendered as preformatted monospace text.
  • Signatures, Examples, and SeeAlso must be JSON arrays of strings.
  • Parameters and Returns must be JSON objects or arrays of objects.
  • Structured JSON must begin with [ or {. Do not use MATLAB arrays or cell-array syntax.
  • Leave an optional tag empty when it does not apply; the exporter supplies its type-appropriate empty value.

Class Documentation

classdef MyClass
    % <@Summary> Updates subsystem states and evaluates utility signals.
    % <@Desc> Long-form explanation of responsibilities and intended use.
    % <@Role> CoreComponent
    % <@Constructor> obj = MyClass(r_gain, str_label)
    % <@Notes> Call initialize after changing topology-related settings.
    % <@SeeAlso> ["PowerNetwork", "Component"]
    % <@Since> 4.2
    % <@Deprecated>
    ...
end

Method Documentation

Name-value options belong in Parameters with Kind: "NameValue". The normalized parameter fields are Name, Kind, Type, Unit, Description, Required, Default, and Constraints.

function rv_y = calculate_output(obj, rv_u, r_gain)
% <@Summary> Scale an input vector.
% <@Desc> Computes an output vector using a configurable scalar gain.
% <@Signatures>
% ["rv_y = obj.calculate_output(rv_u, r_gain)"]
% <@Parameters>
% [
%   {
%     "Name": "rv_u",
%     "Kind": "Positional",
%     "Type": "double vector",
%     "Unit": "pu",
%     "Description": "Input signal vector.",
%     "Required": true,
%     "Default": "-",
%     "Constraints": "finite column vector"
%   }
% ]
% <@Returns>
% [{"Name":"rv_y","Type":"double vector","Unit":"pu","Description":"Scaled output."}]
% <@Examples>
% ["```matlab\nrv_y = obj.calculate_output(rv_u, 2.0);\n```"]
% <@Notes> This method does not modify the object state.
% <@Throws> Errors when the input and gain dimensions are incompatible.
% <@SeeAlso> ["simulate", "get_sys"]
end

Property Documentation

properties
    % <@Summary> Gain applied to input/output calculations.
    % <@Desc> Scalar gain used by calculate_output.

    % <@Since> 4.2

end

Validation

The exporter records unknown or duplicate tags, missing class descriptions, and undocumented public methods as warnings. Invalid structured JSON and failed class exports are recorded as errors. Diagnostics are available both in the generated class document and in the central index validation summary.

ConditionResult
Unknown or duplicate tagWarning
Class has neither Summary nor DescWarning
Public, non-hidden method defined by the class has neither Summary nor DescWarning
Malformed structured JSONError
Class reflection or file export failureError

Use strict mode in automated checks to fail generation when one or more validation errors exist:

>> GUILDA.doc("update", true, "open", false, "strict", true);

Regenerating and Reviewing Documentation

>> GUILDA.addpath();
>> GUILDA.doc("update", true, "open", false);
>> web(fullfile(GUILDA.pwd(), "_GUILDAdoc", "index.html"));

After regeneration, review database/list_Classes.js for the index summary and open the Reference tab to verify class links, summaries, inheritance markers, and detailed class or method pages.
