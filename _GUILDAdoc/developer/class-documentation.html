Class Documentation

Write MATLAB help comments next to the code. GUILDA.doc adds what the code declares and builds the Reference pages. Three tags cover the rest.

How it works

Nobody edits the Reference by hand. GUILDA.doc re-exports only the classes whose files changed.

PartHow it works
Change checkGUILDA.doc and startup compare each source file's modification time and size with database/manifest.json. Git is not used.The rebuild rules are in Keeping it up to date.
OriginEach class gets a root by its folder: System (_GUILDAsystem), Object (_GUILDAobject) or User.
User classesA class anywhere on the MATLAB path that inherits from a GUILDA class is documented under the User root, with the same comment rules.It stays on your machine. GUILDA.publish_doc never publishes it.
PagesThe Reference keeps its index, class and method pages. A folder tree in the left sidebar shows the source folders and highlights the file on screen.

Where comments go

Write ordinary MATLAB help comments. Each numbered comment lands in the matching place on the class page. Everything without a number is read from the code.

Page partWriteNotes

Description 2The comment lines after the H1 line.Markdown: - lists, 1. lists, `code`, **bold**, # headings, [links](url) and fenced code blocks. A lone % line starts a new paragraph.Text art drawn with box characters is kept exactly as written.
See also 3A % See also A, B line.Names of classes and methods become links. MATLAB help links them too.
Property group 4A trailing comment on the properties (...) line.Without it, properties are grouped by access.
Unit 5A leading [unit] in a property comment or an arguments comment.% [MVA] Base power. The rest of the line is the summary.Examples: [pu], [MVA], [rad/s].
Method groupNothing: the verb prefix of the name.set_, get_, add_, calculate_, simulate_, plot_, export_ and the other verbs each get a group. The constructor has its own. Anything else is in Other.

Outputs 8The same, in an arguments (Output) block.Outputs without the block are listed by name only.

Which tags

A tag is only for what neither the code nor the help conventions can say. There are three.

TagClassPropertyMethodUse when
ExamplesA short usage example helps. Markdown with fenced code blocks.
DeprecatedThe member will be removed. The text names the replacement.
TypeThe declaration cannot state the class, for example an untyped property that holds a PowerFlowCalculation.

Put tags at the end of the comment block, after the description and the See also line. Write % <@Tag> value; a value can continue on the next % lines, up to the next tag or the end of the block.

Method 
% Calculate the power flow.
%
% <@Examples>
% ```matlab
% net = network_IEEE68bus();
% net.calculate_powerflow();
% ```
% <@Deprecated> Use solve_powerflow.
Property 
% Solver used by calculate_powerflow.
% <@Type> PowerFlowCalculation
a_Solver

What the exporter checks

Every run prints one line per exported class and a summary. A problem is reported where the member is defined, not again for each subclass.

LevelCheck
WarningA removed tag, with its replacement (see Removed tags).An error with "strict", true.
WarningA class, or its own public non-hidden method or property, has no H1 line.
WarningA <@Deprecated> tag with no text.The text must name the replacement.
WarningAn unknown tag, or the same tag twice (the last value is used).
WarningA method declared in the classdef with no implementation file.
CoverageDocumented / total for classes, public methods and public properties. Documented means it has an H1 line.Shown at the top of the Reference tab. Undocumented classes get a no docs marker there.

With GUILDA.doc("strict", true) the run fails when there are errors.

Keeping it up to date

  1. Edit the sourceAdd or change classes and comments under _GUILDAsystem or _GUILDAobject, or in your own subclasses.
  2. Run GUILDA.docIt re-exports what changed, then opens the pages.
  3. Check the outputRead the warnings in the Command Window and look at your class page.
ChangeWhat is exported
File time or size differs from manifest.jsonThat class and all its subclasses.Subclasses inherit members, so their pages change too.
File not in the manifestThe new class and its subclasses.
File in the manifest but goneIts class file and index entry are removed; its subclasses are re-exported.
No manifest, or one from another schema or exporterEverything.
Nothing changedNothing. The pages open as they are.
CallEffect
update="auto" (default)Export what changed, by the rules above.
update=true / falseAlways export everything, or never export. "always" and "never" work too.
"class", "PowerNetwork"Open one class page.
"open", falseOnly export.
