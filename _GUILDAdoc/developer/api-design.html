API Design for Analysis Features

Power flow, OPF, CPF, time simulation, linearization, and import/export are all called the same way: as a method of PowerNetwork, with Name-Value options, returning [result, flag, output].

Target rules for version 4.0. These rules were decided for version 4.0. Existing code does not follow all of them yet and is being migrated. Write new code to these rules, and move existing code toward them when you touch it.

Cross-cutting rules

  1. Entry point: net.verb_noun()

    Every analysis and IO feature is called as a method of PowerNetwork, named verb_noun in snake_case. Auxiliary classes such as ContinuationPowerFlow, CsvNetHandler, and odeSimulator are the implementation behind these methods. Using them directly is for advanced users only.

  2. Inputs: system data beforehand, analysis conditions at run time

    Set beforehand (properties / tab_parameter)Data that describes the system itself: line constants, power-flow specifications (V, P, Q), operating limits.
    Pass at run time (Name-Value)Conditions of one analysis: method, tolerance, time span, events.

  3. Output type: result classes for main analyses

    Power flow, OPF, CPF, and time simulation return a dedicated result class, like the existing odeSimulationResult. Simple getters keep standard MATLAB types: get_sys returns an ss, get_admittance_matrix returns a table.

  4. Output order: [result, flag, output]

    • result: the result object (or standard MATLAB type).
    • flag: success or convergence.
    • output: solver details.

    Result classes also hold flag and output as properties, so result alone is enough to check the outcome.

  5. Preconditions: stop with an error that says how to fix it

    When a precondition is not met, stop with an explicit error that tells the user what to do. For example, the edit state in str_editFlag (unset / initialized / editted) must be initialized before a simulation; otherwise the error says "run net.initialize() first".

    Only a harmless default that does not change the meaning of the result may continue, and it prints an INFO message.

  6. Side effects follow the verb

    May modify the modeladd_remove_replace_set_initialize
    Must not change model valuescalculate_optimize_simulateget_draw_export_

    Internal analysis caches are the only exception.

  7. Common Name-Value options in UpperCamelCase

    Option names follow the MATLAB style. Each analysis supports the options that apply to it, with the same name and meaning everywhere.

    MethodCalculation method. Replaces mode, methods, Algorithm.
    ToleranceConvergence tolerance.
    MaxIterationMaximum number of iterations.
    SolverNumerical solver.
    TimeLimitLimit on computation time.
    VerbosePrint progress messages.
    ProgressShow a progress display.
    PlotPlot the result.
    ExportWrite the result to a file.

Compatibility

  • These changes break existing scripts, so they belong to version 4.0 (see Versions).
  • Old names and signatures keep working through wrappers in _GUILDAsystem/_VersionSupport/ for at least one major version. This includes Continuation_Power_Flow, CsvNetHandler.import / CsvNetHandler.export, [sys, lin] = get_sys(...), and the "methods" argument.
  • New result classes (PowerFlowResult, OPFResult, CPFResult, ...) go in _GUILDAsystem/_auxiliary/@<Name>/ and inherit from auxiliary (see Folder Structure).
  • Name the options and properties of new code with the Naming Conventions, and document them with Class Documentation tags.
