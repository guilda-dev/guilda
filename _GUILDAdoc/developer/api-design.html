API Design for Analysis Features解析機能の API 設計

Every analysis and IO feature has the same call shape: a PowerNetwork method, Name-Value options in, [result, flag, output] out.

解析機能と入出力機能はすべて同じ呼び出しの形。PowerNetwork のメソッド、入力は Name-Value オプション、出力は [result, flag, output]。

1 · Entry point1 · 入口

  • The solver classes implement these methods: SolverPF, SolverOPF, SolverCPF, SolverODE, SolverLIN, held as net.solver_PF / _OPF / _CPF / _ODE / _LIN.メソッドの処理はソルバークラス SolverPF、SolverOPF、SolverCPF、SolverODE、SolverLIN が実装。net.solver_PF / _OPF / _CPF / _ODE / _LIN として保持。
  • A solver holds defaults only, never a network or a result.ソルバーが保持するのは既定値だけ。ネットワークや結果は保持しない。
  • Calling its solve directly: advanced users only.solve の直接呼び出しは上級者向け。

2 · Inputs: defaults and overrides2 · 入力: 既定値と上書き

  • System data describes the system itself; set it before the call.系統データは系統そのもの。呼び出しの前に設定。
  • Defaults persist, so repeated runs keep the last settings.既定値は保持。繰り返し実行では最後の設定を使用。
  • Each solver class has a constant OptionMap: the Name-Value names it accepts and the solver property each one sets (e.g. MaxIteration → MaxIterations).各ソルバークラスに定数 OptionMap。受け付ける Name-Value の名前と、それぞれが設定するソルバーのプロパティの対応（例: MaxIteration → MaxIterations）。
  • A name that is not in OptionMap stops with GUILDA:resolve_options:UnknownName, which lists the accepted names.OptionMap にない名前を渡すと GUILDA:resolve_options:UnknownName で停止し、受け付ける名前の一覧を表示。
  • See Class Design: Solver settings.クラス設計: ソルバーの設定 を参照。

  • Edit state s_edit.str_flag: unset, initialized or editted.編集状態 s_edit.str_flag: unset、initialized、editted のいずれか。

Effect on the modelモデルへの影響Verbs動詞

The only exceptions: internal analysis caches and per-run working data.

例外は解析の内部キャッシュと実行ごとの作業データだけ。

  • simulate writes working data during a run (see Class Design: Per-class responsibilities).simulate は実行中に作業データを書き込み（クラス設計: クラスごとの責務 を参照）。
  • On every exit, also after an error: Bus.l_isFault → false, l_isConnect of components and global controllers → true, Component.rv_Xoffset / rv_Uoffset → empty.終了時は、エラーで終わった場合も含めて必ず: Bus.l_isFault → false、機器と大域制御器の l_isConnect → true、Component.rv_Xoffset / rv_Uoffset → 空。
  • The index data (iv_ode*, lv_odeUfromLC) stays until the next run overwrites it.インデックスのデータ（iv_ode*、lv_odeUfromLC）は次の実行で上書きされるまで残る。

A failed simulation ends in one of these ways, and neither changes model values:

失敗したシミュレーションの終わり方は次の 2 つ。いずれもモデルの値は不変。

  • Numerical failure in simulate. When the solver gives up on a phase, simulate returns flag = -1. result holds the completed phases up to output.tEnd (no time points when the first phase fails), output.exception holds the MException, and the warning GUILDA:PowerNetwork:SimulationIncomplete is issued. The same warning follows a solver stop (flag = -1) and TimeLimit (flag = 0).simulate での数値的な失敗。ソルバーがあるフェーズで解けなくなると、simulate は flag = -1 を返す。result は output.tEnd までに完了したフェーズ（最初のフェーズで失敗した場合は時刻点なし）、output.exception は MException。警告 GUILDA:PowerNetwork:SimulationIncomplete。ソルバーの停止（flag = -1）と TimeLimit（flag = 0）でも同じ警告。
  • Any other error during a phase. An error of an input function or a model stops with GUILDA:SolverODE:PhaseFailed, or with InitialConditionFailed / UnfeasibleDAE during the retry from a recomputed initial condition. The original error is its cause, and no result is returned.フェーズ中のその他のエラー。入力関数やモデルのエラーは GUILDA:SolverODE:PhaseFailed で停止。初期条件を計算し直して再試行している間は InitialConditionFailed / UnfeasibleDAE で停止。元のエラーが原因（cause）として付き、結果は返らない。
