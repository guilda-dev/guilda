API Design for Analysis Features

Every analysis and IO feature is called the same way. It is a PowerNetwork method. It takes Name-Value options. It returns [result, flag, output].

1 · Entry point

The solver classes implement these methods: PowerFlowCalculation, OptimalPowerFlow, ContinuationPowerFlow, odeSimulator and odeLinearizer, held as net.solver_PF / _OPF / _CPF / _ODE / _LIN.

Each solver holds defaults only, never a network or a result. Calling its solve directly is for advanced users only.

2 · Inputs: defaults and overrides

  • System data describes the system itself. Set it before the call.
  • Defaults persist, so repeated runs keep the last settings.
  • Each solver class has a constant OptionMap: the Name-Value names it accepts and the solver property each one sets (e.g. MaxIteration → MaxIterations).
  • A name that is not in OptionMap stops with GUILDA:resolve_options:UnknownName, which lists the accepted names.
  • See Class Design: Solver settings.

3 · 4 · Outputs

Feature kindReturnsExample

Simple gettera standard MATLAB typeget_sys → ss, get_admittance_matrix / get_variable_map → table

Result classes also hold flag, output and the effective options as properties.

So result alone is enough to check the outcome.

Plotting and writing files are methods of the result: result.Plot() and result.Export(filename). The options Plot and Export of a call run them.

5 · Preconditions

SituationBehavior
Precondition metRun.
Not metStop with an explicit error that tells the user what to do.
Not met, but a harmless default existsContinue and print an INFO message. Only for a default that does not change the meaning of the result.

Example: the edit state str_editFlag is unset, initialized or editted.

A simulation or a linearization needs an up-to-date equilibrium: initialize has run, and no edit since then made the equilibrium stale. Otherwise the error says "run net.initialize() first" (see Class Design: Edit handling).

Related rules

  • Result classes (PowerFlowResult, OPFResult, CPFResult, odeSimulationResult, LinearizationResult) go in _GUILDAsystem/_auxiliary/@<Name>/ and inherit from AnalysisResult (see Folder Structure).
  • Where data lives, how edits mark results as stale, and the unit conventions are described in Class Design.
  • Name the options and properties of new code with the Naming Conventions, and document them with Class Documentation tags.
