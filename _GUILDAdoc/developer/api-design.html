API Design for Analysis Features解析機能の API 設計

Every analysis and IO feature has the same call shape: a PowerNetwork method, Name-Value options in, [result, flag, output] out.

解析機能と入出力機能は、すべて同じ呼び出しの形をとります。PowerNetwork のメソッドで、入力は Name-Value オプション、出力は [result, flag, output] です。

1 · Entry point: a PowerNetwork method1 · 入口: PowerNetwork のメソッド

  • The solver classes implement these methods: SolverPF, SolverOPF, SolverCPF, SolverODE, SolverLIN, held as net.solver_PF / _OPF / _CPF / _ODE / _LIN.メソッドの処理はソルバークラス SolverPF、SolverOPF、SolverCPF、SolverODE、SolverLIN が実装します。これらは net.solver_PF / _OPF / _CPF / _ODE / _LIN として保持されます。
  • A solver holds no settings (they are in GUILDA.setting) and never a result; SolverCPF keeps the condition of its network (LoadBus). The OPF conditions Cost, Constraint, DefaultCost, ReferenceBus are options of the call only.ソルバーは設定（GUILDA.setting にあります）も結果も保持しません。SolverCPF はネットワークの条件（LoadBus）を保持します。OPF の条件 Cost、Constraint、DefaultCost、ReferenceBus は、呼び出しのときだけ指定するオプションです。
  • SolverPF and SolverOPF also keep the last solution of the network for WarmStart. Neither reads the network: calculate_powerflow hands SolverPF the admittance matrix and the bus conditions, and calculate_optimal_powerflow hands SolverOPF tables of the buses, components and branches.SolverPF と SolverOPF は WarmStart 用に、ネットワークの最後の解も保持します。どちらもネットワークを読みません。calculate_powerflow は SolverPF にアドミタンス行列と母線の条件を、calculate_optimal_powerflow は SolverOPF に母線・機器・ブランチの表を渡します。
  • Calling its solve directly: advanced users only.solve の直接呼び出しは上級者向けです。

2 · Inputs: defaults and overrides2 · 入力: 既定値と上書き

  • System data describes the system itself; set it before the call.系統データは系統そのものです。呼び出しの前に設定します。
  • Defaults persist, so repeated runs keep the last settings.既定値は保持されます。繰り返し実行では最後の設定を使います。
  • simulate, calculate_powerflow, calculate_fixed_input_powerflow, calculate_optimal_powerflow, build_opf_problem, calculate_continuation_powerflow and get_sys take their options in an arguments block, without written defaults: the value of an option left out comes from GUILDA.config (e.g. Verbose of simulate → Verbose of the TimeSimulation section). Solver of calculate_fixed_input_powerflow is the exception: it is "newton" when left out, because the Solver of the PowerFlowCalculation section may be "gradient" or "dynamic", which that method does not use.simulate、calculate_powerflow、calculate_fixed_input_powerflow、calculate_optimal_powerflow、build_opf_problem、calculate_continuation_powerflow、get_sys は、arguments ブロックでオプションを受け取ります。既定値はブロックに書かず、省いたオプションの値は GUILDA.config から読みます（例: simulate の Verbose → TimeSimulation セクションの Verbose）。例外は calculate_fixed_input_powerflow の Solver で、省くと "newton" です。PowerFlowCalculation セクションの Solver は、このメソッドが使わない "gradient" や "dynamic" のことがあるためです。
  • Keys of GUILDA.setting: the same name and type as the Name-Value option. A setting of one solver or method is named <Solver><option> with the MATLAB option name (FsolveMaxFunctionEvaluations, FminconUseParallel, LinprogAlgorithm); one for every solver has no prefix (MaxIteration, Tolerance). NaN is the automatic value or the solver's default. An on/off setting is logical (converted to "on" / "off" where MATLAB needs it).GUILDA.setting のキーは、Name-Value オプションと同じ名前・型です。1 つのソルバー・計算方法の設定は、MATLAB のオプション名を使って <Solver 名><オプション名> とします（FsolveMaxFunctionEvaluations、FminconUseParallel、LinprogAlgorithm）。全ソルバー共通の設定には接頭辞を付けません（MaxIteration、Tolerance）。自動の値・ソルバーの既定値は NaN です。オン・オフの設定は logical です（MATLAB が求める箇所で "on" / "off" に変換します）。
  • With an arguments block, an unknown name stops with the MATLAB error MATLAB:TooManyInputs and a bad value with the MATLAB validator error.arguments ブロックでは、未知の名前は MATLAB のエラー MATLAB:TooManyInputs、不正な値は MATLAB の検証関数のエラーで停止します。
  • See Class Design: Solver settings of analyses.クラス設計: 解析のソルバー設定を参照してください。

Situation状況Behavior動作
Precondition met前提条件を満たすRun.実行します。
Not met満たさないStop with an explicit error that tells the user what to do.どうすればよいかを示す明示的なエラーで停止します。
Not met, but a harmless default exists満たさないが、無害な既定値があるContinue and print an INFO message. Only for a default that does not change the meaning of the result.INFO メッセージを表示して続行します。結果の意味を変えない既定値に限ります。

Example:

例:

  • Stale state sct_stale of each layer: per stale tag, the messages of the edits that made it out of date; empty when up to date.各層の stale 状態 sct_staleは、stale タグごとに、古くした編集のメッセージを持ちます。最新なら空です。
  • A simulation or a linearization needs every layer up to date: initialize has run, and no edit since then made a layer stale (a linearization at a given point checks the dynamics and the inputs only).シミュレーションと近似線形化には、全層が最新であることが必要です。つまり、initialize が実行済みで、その後の編集で古くなった層がない状態です（点を与えた近似線形化では、動特性と入力だけを確認します）。

6 · Side effects follow the verb6 · 副作用は動詞で決まる

Effect on the modelモデルへの影響Verbs動詞
May modify変更してよいadd_remove_replace_set_initialize
Must not change values値を変えてはならないcalculate_optimize_simulateget_disp_plot_export_

The only exceptions: internal analysis caches and per-run working data.

例外は、解析の内部キャッシュと実行ごとの作業データだけです。

  • simulate writes nothing to the models: net.build_simulation_data gathers the data of the run, and the positions of the run and the trips, faults and input events of each phase live in the run context ctx of SolverODE, which reads only that data (see Class Design: Working data of analyses).simulate はモデルに何も書き込みません。実行のデータは net.build_simulation_data が集めます。実行の位置と、フェーズごとのトリップ・地絡・入力イベントは、そのデータだけを読む SolverODE の実行の文脈 ctx に保持します（クラス設計: 解析の作業データを参照）。
  • Nothing to restore on exit, also after an error: the models are unchanged.終了時は、エラーで終わった場合も含めて復元は不要です。モデルは変わりません。

A failed simulation ends in one of these ways, and neither changes model values:

失敗したシミュレーションの終わり方は次の 2 つです。いずれの場合もモデルの値は変わりません。

  • Numerical failure in simulate. When the solver gives up on a phase, simulate returns flag = -1. result holds the completed phases up to output.tEnd (no time points when the first phase fails), output.exception holds the MException, and the warning GUILDA:PowerNetwork:SimulationIncomplete is issued. The same warning follows a solver stop (flag = -1) and TimeLimit (flag = 0), not a stop by StopOnOutOfStep (flag = 2).simulate での数値的な失敗。ソルバーがあるフェーズで解けなくなると、simulate は flag = -1 を返します。result は output.tEnd までに完了したフェーズ（最初のフェーズで失敗した場合は時刻点なし）を持ち、output.exception は MException です。警告 GUILDA:PowerNetwork:SimulationIncomplete を出します。ソルバーの停止（flag = -1）と TimeLimit（flag = 0）でも同じ警告を出します。StopOnOutOfStep による停止（flag = 2）では出しません。
  • Any other error during a phase. An error of a model stops with GUILDA:SolverODE:PhaseFailed, or with InitialConditionFailed / UnfeasibleDAE during the retry from a recomputed initial condition. The original error is its cause, and no result is returned.フェーズ中のその他のエラー。モデルのエラーは GUILDA:SolverODE:PhaseFailed で停止します。初期条件を計算し直して再試行している間は InitialConditionFailed / UnfeasibleDAE で停止します。元のエラーが原因（cause）として付き、結果は返りません。

Power flow潮流計算
net.calculate_powerflow(...)Format="GUILDAorigin"|"V"|"powerflow(mat)"|"powerflow(tab)", Solver="newton"|"gradient"|"levenberg-marquardt"|"fsolve"|"dynamic", Tolerance, MaxIteration, ...
