Model Implementationモデルの実装

How to add a new generator, load, or controller: what the framework requires of the class, a minimal generator and AVR, and how to test them.新しい発電機、負荷、制御器を追加する方法として、フレームワークがクラスに求めること、最小限の発電機と AVR の例、そのテスト方法を説明します。

Steps手順

  1. Choose the base class and the place基底クラスと置き場所を決める

    Put the class in the matching package of _GUILDAobject (see Folder Structure). A small model can be one classdef file.

    クラスは _GUILDAobject の該当するパッケージに置きます（フォルダ構成を参照）。小さなモデルなら classdef ファイル1つで構いません。

  2. Implement the contract契約を実装する

    Define the constants and methods in Contracts. Document the class with Class Documentation and name new properties with the Naming Conventions.

    契約にある定数とメソッドを定義します。クラスはクラスのドキュメントに従って記述し、新しいプロパティは命名規則に従って名付けます。

  3. Register a component or branch key機器またはブランチのキーを登録する

    Run GUILDA again. It scans the repository, finds the key of each class, and generates Bus.add_component and PowerNetwork.add_branch. Until then the key is rejected. A class that does not load gives the warning GUILDA:dictionary:ClassNotLoaded with the reason. Controllers have no such step: you create them with their constructor.

    GUILDA を再度実行します。リポジトリを走査して各クラスの key を見つけ、Bus.add_component と PowerNetwork.add_branch を生成します。それまではそのキーは受け付けられません。読み込めないクラスがあると、理由とともに警告 GUILDA:dictionary:ClassNotLoaded が出ます。制御器にはこの手順はなく、コンストラクタで作成します。

  4. Test itテストする

    Check the contract with validate, then run the checks in Testing.

    validate で契約を確認し、続いてテストの確認を行います。

Rules that apply to every modelすべてのモデルに適用されるルール

  • The model functions must not depend on I: simulate accepts it, but the linearization does not.モデル関数は I に依存してはいけません。simulate は受け付けますが、近似線形化は受け付けません。
  • sv_u must not contain the port names Vre, Vim, Ire, Iim.sv_u にポート名 Vre、Vim、Ire、Iim を含めてはいけません。
  • net.initialize evaluates the point that get_equilibrium returns. A wrong size or an error in a model function stops it (GUILDA:PowerNetwork:InitializeEquilibriumSize, InitializeModelSize, InitializeModelFailed). A point where the state moves gives the warning GUILDA:PowerNetwork:EquilibriumResidual.net.initialize は get_equilibrium が返す点を評価します。サイズの誤りやモデル関数のエラーがあると停止します（GUILDA:PowerNetwork:InitializeEquilibriumSize、InitializeModelSize、InitializeModelFailed）。状態が動く点では警告 GUILDA:PowerNetwork:EquilibriumResidual が出ます。
  • A controller can use the input names "Xall" and "Yall" to observe all the states or outputs of the component. It must then override set_inputs; see controller.local_LQR. The names "X" and "Y" are errors.制御器は入力名 "Xall" と "Yall" を使って、機器のすべての状態またはすべての出力を観測できます。その場合は set_inputs をオーバーライドする必要があります（controller.local_LQR を参照）。"X" と "Y" という名前はエラーになります。
  • A component has two slots for local controllers: one "avr" or "local" controller (with a "pss" under an AVR), and one "governor" beside it. a_LocalController and the variables list them in this order, whatever the order of attachment. A new controller replaces the one in its slot with the warning GUILDA:Component:ReplaceController.機器にはローカル制御器の枠が2つあります。"avr" または "local" の制御器1つ（AVR の下には "pss"）と、その横の "governor" 1つです。a_LocalController と変数の並びは、接続した順序によらずこの順になります。新しく接続すると、警告 GUILDA:Component:ReplaceController とともに同じ枠の制御器が置き換えられます。
  • The two top-level controllers of a component must drive different inputs. A governor and a "local" controller that both drive Pmech (such as controller.local_LQR on all the inputs) stop with GUILDA:Component:ControllerOutputOverlap. A controller whose outputs follow the component (as local_LQR does) overrides driven_inputs, so that the check runs before the attachment.機器の最上位の2つの制御器は、異なる入力を駆動しなければなりません。ガバナと、どちらも Pmech を駆動する "local" 制御器（すべての入力に対する controller.local_LQR など）を組み合わせると、GUILDA:Component:ControllerOutputOverlap で停止します。出力が機器に合わせて決まる制御器（local_LQR など）は driven_inputs をオーバーライドし、接続の前にこの確認が行われるようにします。
  • getCompPQ(obj, x, V, u, param), with V as [abs; angle], is needed only by the continuation power flow with UseInternalState=true; without it, that analysis stops with GUILDA:build_layout:MissingGetCompPQ.V を [abs; angle] として受け取る getCompPQ(obj, x, V, u, param) は、UseInternalState=true の連続潮流計算でだけ必要です。ない場合、その解析は GUILDA:build_layout:MissingGetCompPQ で停止します。

Minimal generator最小限の発電機

A constant-magnitude source behind the reactance Xs, with the swing equation. It has the same dynamics as gen-classical with Xd = Xq = Xs, which makes a useful check. The base class component.generator.abstract provides the constructor and sets the tag to "SG" + index. A load inherits from component.load.abstract in the same way.

リアクタンス Xs の背後にある大きさ一定の電源に、動揺方程式を組み合わせたモデルです。Xd = Xq = Xs とした gen-classical と同じ動特性を持つため、確認に役立ちます。基底クラス component.generator.abstract がコンストラクタを提供し、タグを "SG" + インデックスに設定します。負荷も同じように component.load.abstract を継承します。

_GUILDAobject/+component/+generator/simple_sg.m 
classdef simple_sg < component.generator.abstract
% Generator with a constant-magnitude source E behind the reactance Xs.
%
% See also component.generator.classical, Component
    properties (Constant)
        key     = "gen-simple"          % Model key used by Bus.add_component.
        sv_x    = ["delta";"omega"]     % State names.
        sv_u    = ["Pmech";"Vfield"]    % Input names.
        sv_y    = "omega"               % Output names read by local controllers.
        sv_para = ["M";"D";"Xs"]        % Dynamic parameter names, in the order of p.
    end
    methods
        function [x, u] = get_equilibrium(obj, c_V, c_I, r_P, ~)
            % Return the states and inputs at the bus voltage and current.
            c_E = c_V + 1j*obj.para_dynamics.Xs*c_I;
            x   = [angle(c_E); 0];
            u   = [r_P; abs(c_E)];
        end
    end
    methods (Static)
        function dx = fcn_dx(~, x, V, ~, u, p, omega0)
            % Return the state derivatives.
            c_E = u(2)*exp(1j*x(1));
            c_I = (c_E - [1,1j]*V)/(1j*p(3));
            dx  = [2*pi*omega0*x(2); -p(2)*x(2) - real(c_E*conj(c_I)) + u(1)];
        end
        function c_I = fcn_I(~, x, V, ~, u, p, ~)
            % Return the current injected into the bus as a complex number.
            c_I = (u(2)*exp(1j*x(1)) - [1,1j]*V)/(1j*p(3));
        end
        function y = fcn_Y(~, x, ~, ~, ~, ~, ~)
            % Return the outputs.
            y = x(2);
        end
        function M = fcn_Mass(~, ~, ~, ~, ~, p, ~)
            % Return the constant mass matrix.
            M = diag([1, p(1)]);
        end
    end
end

Xs のように、同梱の parameter.csv にないパラメータを持つ発電機では、add_component の parameter オプションにテーブルを渡す必要があります。

Using the modelモデルの使用

After GUILDA has registered the key, the model works in every analysis. Keep the objects that add_bus returns and pass their tags to add_branch: a bus index shifts when a bus is removed, and a tag does not (see Identity).

GUILDA がキーを登録すると、そのモデルはすべての解析で使えます。add_bus が返すオブジェクトを保持し、そのタグを add_branch に渡してください。母線のインデックスは母線を削除するとずれますが、タグはずれません（識別を参照）。

para = table(100, 10, 0.3, VariableNames=["M","D","Xs"]);
net  = PowerNetwork();
b1   = net.add_bus(V=1.00);
b2   = net.add_bus(V=1.02);
b3   = net.add_bus();
net.add_branch("pi", [b1.str_tag, b2.str_tag], R=0.010, X=0.085);
net.add_branch("pi", [b2.str_tag, b3.str_tag], R=0.017, X=0.092);
g1   = b1.add_component("gen-simple", "parameter",para);
g2   = b2.add_component("gen-simple", "P",0.5, "parameter",para);
b3.add_component("load-impedance", "P",-1.0, "Q",-0.2);
net.initialize();

sc  = Scenario("fault");
sc.add_fault(b3.str_tag, [1,1.05]);
net.add_scenario(sc);
sim = net.simulate([0,10], sc);
sys = net.get_sys();

Minimal controller最小限の制御器

A first-order AVR. Its output Vfield drives the input of that name of the generator. No output of the generator is called Vref or Vpss, so Vref stays at its equilibrium and Vpss reads a PSS when one is attached. The Jacobians must be written by hand. The constructor adds the parameters and builds the function handles, which are built again with the frequency of the network when the controller is attached.

1次遅れの AVR です。出力 Vfield は、発電機の同じ名前の入力を駆動します。発電機には Vref や Vpss という名前の出力がないため、Vref は平衡点の値のままで、Vpss は PSS が接続されていればその出力を読みます。ヤコビ行列は手で書く必要があります。コンストラクタはパラメータを追加して関数ハンドルを作ります。関数ハンドルは、制御器が接続されたときにネットワークの周波数で作り直されます。

_GUILDAobject/+controller/+avr/simple_avr.m 
classdef simple_avr < LocalController
% First-order AVR: Te*dVfd/dt = -Vfd + Ka*(Vref + Vpss - |V|), Vfield = Vfd.
%
% See also controller.avr.AVR_ST1, LocalController
    properties (SetAccess=protected, Hidden)
        key     = "avr"                 % Attached to the component; a PSS can hang under it.
        sv_x    = "Vfd"                 % State names.
        sv_u    = ["Vref";"Vpss"]       % Input names; no component output has these names.
        sv_y    = "Vfield"              % Output names; drives the input Vfield of the component.
        sv_para = ["Ka";"Te"]           % Dynamic parameter names, in the order of p.
    end
    methods
        function obj = simple_avr(tag, opt)
            % Create the controller with the tag "CA"+tag.
            arguments
                tag (1,1) string            % Tag suffix.
                opt.Ka (1,1) double = 30    % [pu] Gain.
                opt.Te (1,1) double = 0.05  % [s] Time constant.
            end
            obj@LocalController("CA"+tag)
            obj.para_dynamics.add_entry("Ka", opt.Ka, "double", "Te", opt.Te, "double");
        end
        function get_equilibrium(obj, V, u)
            % Set the equilibrium from the complex voltage V and the component inputs u.
            Ka = obj.para_dynamics.Ka;
            obj.rv_Xequilibrium = u(2);
            obj.rv_Uequilibrium = [u(2)/Ka + abs(V); 0];
            cellfun(@(c) c.get_equilibrium(V, u), obj.a_LocalController);
        end
    end
    methods (Static)
        function dx = fcn_dx(~, x, V, ~, u, p, ~)
            % Return the state derivative.
            dx = -x + p(1)*(u(1) + u(2) - norm(V));
        end
        function y = fcn_y(~, x, ~, ~, ~, ~, ~)
            % Return the output.
            y = x;
        end
        function M = fcn_Mass(~, ~, ~, ~, ~, p, ~)
            % Return the constant mass matrix.
            M = p(2);
        end
        function [Axx,Bxv,Bxi,Bxu] = Jacobi_dx(~, ~, V, ~, ~, p, ~)
            % Return the Jacobians of fcn_dx with respect to x, V, I and u.
            Axx = -1;
            Bxv = -p(1)*V.'/norm(V);
            Bxi = zeros(1,2);
            Bxu = [p(1), p(1)];
        end
        function [Cyx,Dyv,Dyi,Dyu] = Jacobi_Y(~, ~, ~, ~, ~, ~, ~)
            % Return the Jacobians of fcn_y with respect to x, V, I and u.
            Cyx = 1;
            Dyv = zeros(1,2);
            Dyi = zeros(1,2);
            Dyu = zeros(1,2);
        end
    end
end

Attaching a controller changes the dynamics, so run initialize again. Without it, simulate stops with GUILDA:PowerNetwork:EquilibriumStale.

制御器を接続すると動特性が変わるため、initialize を再度実行します。実行しないと、simulate は GUILDA:PowerNetwork:EquilibriumStale で停止します。

avr = controller.avr.simple_avr("a", Ka=30, Te=0.05);
pss = controller.pss.PSS1("p");
g2.add_local_controller(avr, pss);
net.initialize();
sim = net.simulate([0,10], ev);

To detach it, call g2.remove_local_controller(avr.str_tag, RemoveNested=true). The option also removes the PSS, and an AVR with a PSS cannot be removed without it.

取り外すには g2.remove_local_controller(avr.str_tag, RemoveNested=true) を呼びます。このオプションは PSS も取り外します。PSS の付いた AVR は、このオプションなしでは取り外せません。

Testingテスト

Check the contract with validatevalidate で契約を確認する

comp.validate and con.validate print the comparison and return a struct of tables. A broken model does not stop the check: it appears as FAIL. Pass false to skip the printing.

comp.validate と con.validate は比較結果を表示し、テーブルの構造体を返します。モデルに問題があっても確認は止まらず、FAIL として表示されます。表示を省くには false を渡します。

s = g2.validate(false);
s.contract        % status (PASS, FAIL, INFO) and detail of each check
s.inputs          % where each input is read

s = avr.validate(false);
s.contract
s.inputs          % Vref: "equilibrium (not connected)", Vpss: "output of CPp"
FieldフィールドWhat to look for確認する点
contractSizes of x, u, and the model functions; fcn_I complex; fcn_Mass constant and square; no dependence on I; no port names in sv_u; whether getCompPQ is defined.x、u、モデル関数のサイズ、fcn_I が複素数であること、fcn_Mass が定数の正方行列であること、I に依存しないこと、sv_u にポート名がないこと、getCompPQ が定義されているかどうか。
inputsThe source of each input. A misspelled input name is not an error when the controller is attached; it appears here as equilibrium (not connected).各入力の取得元。入力名の綴りを誤っても制御器の接続時にはエラーにならず、ここに equilibrium (not connected) と表示されます。
dx, IThe residuals at the point. They should be close to zero at an equilibrium.その点での残差。平衡点ではほぼ0になるはずです。
Axx, Bxv, ...The absolute difference between each analytic Jacobian and finite differences. A component without Jacobi_* has nothing to compare.解析的なヤコビ行列と有限差分との差の絶対値。Jacobi_* のない機器では比較するものがありません。

A component is checked at its equilibrium, or at a random point with unit V and I before net.initialize, where the residuals are not zero. A local controller must be attached to a component on an initialized network.

機器は平衡点で確認されます。net.initialize の前は、大きさ1の V と I を持つランダムな点で確認されるため、残差は0になりません。ローカル制御器は、初期化済みのネットワーク上の機器に接続されている必要があります。

Check the behavior挙動を確認する

  1. Stay at the equilibrium平衡点にとどまる

    net.simulate without scenarios keeps the states at rv_Xequilibrium.

    シナリオなしの net.simulate で、状態が rv_Xequilibrium にとどまります。

  2. Survive a disturbance外乱に耐える

    Run a fault and a trip with a Scenario (add_fault, add_trip). flag is 1 when the simulation completes. A trip calls get_equilibrium with I = P = Q = 0.

    Scenario（add_fault、add_trip）で地絡と解列（トリップ）を実行します。シミュレーションが完了すると flag は 1 になります。解列では I = P = Q = 0 で get_equilibrium が呼ばれます。

  3. Look at the linear model線形モデルを調べる

    eig(net.get_sys()). A network of synchronous machines has an eigenvalue near zero from the common rotation of the rotor angles. The other eigenvalues should be in the left half plane unless you expect otherwise. An unstable result can also come from the rest of the test network, so compare with an existing model on the same network.

    eig(net.get_sys()) を調べます。同期機からなるネットワークには、回転子角が一斉に回転することによる0付近の固有値があります。それ以外の固有値は、意図した場合を除いて左半平面にあるはずです。不安定な結果はテスト用ネットワークのほかの部分から生じることもあるため、同じネットワーク上の既存のモデルと比較してください。

  4. Compare with a known model既知のモデルと比較する

    When an existing class reduces to your model, the eigenvalues should agree, as below.

    既存のクラスが新しいモデルに帰着する場合は、以下のように固有値が一致するはずです。

Add a testテストを追加する

Add a %% section to the script of the feature in +DebugScript, or a new script test_I<issue>_<slug>.m, and run it with DebugScript.run_all("Features","I<issue>"). Each section runs as one test. Put local functions at the end of the script.

+DebugScript にあるその機能のスクリプトに %% セクションを追加するか、新しいスクリプト test_I<issue>_<slug>.m を作り、DebugScript.run_all("Features","I<issue>") で実行します。各セクションが1つのテストとして実行されます。ローカル関数はスクリプトの最後に置いてください。

+DebugScript/test_I114_new_models.m

%% AVR: contract, inputs, comparison with AVR_ST1

function [net, g2] = make_network(str_key, para)
    net = PowerNetwork();
    b1  = net.add_bus(V=1.00);
    b2  = net.add_bus(V=1.02);
    b3  = net.add_bus();
    net.add_branch("pi", [b1.str_tag, b2.str_tag], R=0.010, X=0.085);
    net.add_branch("pi", [b2.str_tag, b3.str_tag], R=0.017, X=0.092);
    b1.add_component(str_key, "parameter",para);
    g2  = b2.add_component(str_key, "P",0.5, "parameter",para);
    b3.add_component("load-impedance", "P",-1.0, "Q",-0.2);
    net.solver_ODE.Progress = "none";
    net.initialize();
end

Branches and networksブランチとネットワーク

  • Branch. Inherit from Branch in _GUILDAobject/+branch/ and define the constants key and header (the prefix of the tags), and the method get_admittance_matrix, which returns the 2×2 matrix from the parameters R, X, C, tap, and phase. Run GUILDA to register the key.ブランチ: _GUILDAobject/+branch/ で Branch を継承し、定数 key と header（タグの接頭辞）、およびパラメータ R、X、C、tap、phase から 2×2 行列を返すメソッド get_admittance_matrix を定義します。キーを登録するには GUILDA を実行します。
  • Network. Inherit from PowerNetwork in _GUILDAobject/+network/, and build the network in the constructor from CSV folders or in code (see Folder Structure).ネットワーク: _GUILDAobject/+network/ で PowerNetwork を継承し、コンストラクタの中で CSV フォルダから、またはコードでネットワークを組み立てます（フォルダ構成を参照）。
