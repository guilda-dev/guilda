Steps to add a modelモデル追加の手順

  1. Choose the base class and the place基底クラスと置き場所を決める

    Put the class in the matching package of _GUILDAobject (see Folder Structure). A small model can be one classdef file.

    クラスは _GUILDAobject の該当するパッケージに配置（フォルダ構成を参照）。小さなモデルなら classdef ファイル 1 つで可。

  2. Implement the model contractモデルの契約を実装する

    Define the constants and methods in Contracts. Document the class with Class Documentation and name new properties with the Naming Conventions.

    契約にある定数とメソッドを定義。クラスの説明はクラスのドキュメント、新しいプロパティの名前は命名規則に従う。

  3. Register a component or branch key機器またはブランチのキーを登録する
    • Run GUILDA again: it scans the repository, finds the key of each class, and generates Bus.add_component and PowerNetwork.add_branch. Until then the key is rejected.GUILDA を再実行。リポジトリを走査して各クラスの key を見つけ、Bus.add_component と PowerNetwork.add_branch を生成。それまではそのキーは不可。
    • A class that does not load: warning GUILDA:dictionary:ClassNotLoaded with the reason.読み込めないクラス: 理由とともに警告 GUILDA:dictionary:ClassNotLoaded。
    • Controllers: no such step; create them with their constructor.制御器: この手順なし。コンストラクタで作成。
  4. Test the modelモデルをテストする

    Check the contract with validate, then run the checks in Testing.

    validate で契約を確認し、続いてテストの確認。

Rules that apply to every modelすべてのモデルに適用されるルール

  • The model functions must not depend on I: simulate accepts it, but the linearization does not.モデル関数は I に依存しない。simulate は受け付けるが、近似線形化は不可。
  • sv_u must not contain the port names Vre, Vim, Ire, Iim.sv_u にポート名 Vre、Vim、Ire、Iim を含めない。
  • net.initialize evaluates the point that get_equilibrium returns. A wrong size or an error in a model function stops it (GUILDA:PowerNetwork:InitializeEquilibriumSize, InitializeModelSize, InitializeModelFailed). A point where the state moves gives the warning GUILDA:PowerNetwork:EquilibriumResidual.net.initialize は get_equilibrium が返す点を評価。サイズの誤りやモデル関数のエラーで停止（GUILDA:PowerNetwork:InitializeEquilibriumSize、InitializeModelSize、InitializeModelFailed）。状態が動く点では警告 GUILDA:PowerNetwork:EquilibriumResidual。
  • A controller can use the input names "Xall" and "Yall" to observe all the states or outputs of the component. It must then override set_inputs; see controller.local_LQR. The names "X" and "Y" are errors.制御器は入力名 "Xall" と "Yall" で、機器のすべての状態またはすべての出力を観測可能。その場合は set_inputs のオーバーライドが必要（controller.local_LQR を参照）。名前 "X"、"Y" はエラー。
  • A component has two slots for local controllers: one "avr" or "local" controller (with a "pss" under an AVR), and one "governor" beside it. a_LocalController and the variables list them in this order, whatever the order of attachment. A new controller replaces the one in its slot with the warning GUILDA:Component:ReplaceController.機器のローカル制御器の枠は 2 つ。"avr" または "local" の制御器 1 つ（AVR の下には "pss"）と、その横の "governor" 1 つ。a_LocalController と変数の並びは、接続の順序によらずこの順。新しく接続すると同じ枠の制御器を置き換え、警告 GUILDA:Component:ReplaceController。
  • The two top-level controllers of a component must drive different inputs. A governor and a "local" controller that both drive Pmech (such as controller.local_LQR on all the inputs) stop with GUILDA:Component:ControllerOutputOverlap. A controller whose outputs follow the component (as local_LQR does) overrides driven_inputs, so that the check runs before the attachment.機器の最上位の 2 つの制御器は、異なる入力を駆動。ガバナと、どちらも Pmech を駆動する "local" 制御器（すべての入力に対する controller.local_LQR など）の組み合わせは GUILDA:Component:ControllerOutputOverlap で停止。出力が機器に合わせて決まる制御器（local_LQR など）は driven_inputs をオーバーライドし、接続の前にこの確認を実行。
  • getCompPQ(obj, x, V, u, param), with V as [abs; angle], is needed only by the continuation power flow with UseInternalState=true; without it, that analysis stops with GUILDA:build_layout:MissingGetCompPQ.V を [abs; angle] として受け取る getCompPQ(obj, x, V, u, param) は、UseInternalState=true の連続潮流計算でだけ必要。ない場合、その解析は GUILDA:build_layout:MissingGetCompPQ で停止。

Minimal generator example最小限の発電機の例

  • A constant-magnitude source behind the reactance Xs, with the swing equation.リアクタンス Xs の背後にある大きさ一定の電源と動揺方程式のモデル。
  • Same dynamics as gen-classical with Xd = Xq = Xs: a useful check.Xd = Xq = Xs とした gen-classical と同じ動特性。確認に有用。
  • The base class component.generator.abstract provides the constructor and sets the tag to "SG" + index.基底クラス component.generator.abstract がコンストラクタを提供し、タグを "SG" + インデックスに設定。
  • A load inherits from component.load.abstract in the same way.負荷も同様に component.load.abstract を継承。
_GUILDAobject/+component/+generator/simple_sg.m 
classdef simple_sg < component.generator.abstract
% Generator with a constant-magnitude source E behind the reactance Xs.
%
% See also component.generator.classical, Component
    properties (Constant)
        key     = "gen-simple"          % Model key used by Bus.add_component.
        sv_x    = ["delta";"omega"]     % State names.
        sv_u    = ["Pmech";"Vfield"]    % Input names.
        sv_y    = "omega"               % Output names read by local controllers.
        sv_para = ["M";"D";"Xs"]        % Dynamic parameter names, in the order of p.
    end
    methods
        function [x, u] = get_equilibrium(obj, c_V, c_I, r_P, ~)
            % Return the states and inputs at the bus voltage and current.
            c_E = c_V + 1j*obj.para_dynamics.Xs*c_I;
            x   = [angle(c_E); 0];
            u   = [r_P; abs(c_E)];
        end
    end
    methods (Static)
        function dx = fcn_dx(~, x, V, ~, u, p, omega0)
            % Return the state derivatives.
            c_E = u(2)*exp(1j*x(1));
            c_I = (c_E - [1,1j]*V)/(1j*p(3));
            dx  = [2*pi*omega0*x(2); -p(2)*x(2) - real(c_E*conj(c_I)) + u(1)];
        end
        function c_I = fcn_I(~, x, V, ~, u, p, ~)
            % Return the current injected into the bus as a complex number.
            c_I = (u(2)*exp(1j*x(1)) - [1,1j]*V)/(1j*p(3));
        end
        function y = fcn_Y(~, x, ~, ~, ~, ~, ~)
            % Return the outputs.
            y = x(2);
        end
        function M = fcn_Mass(~, ~, ~, ~, ~, p, ~)
            % Return the constant mass matrix.
            M = diag([1, p(1)]);
        end
    end
end

Using the new model新しいモデルの使用

  • Once GUILDA has registered the key, the model works in every analysis.GUILDA がキーを登録すれば、そのモデルはすべての解析で使用可能。
  • Keep the objects that add_bus returns and pass their tags to add_branch: a bus index shifts when a bus is removed, a tag does not (see Identifying objects).add_bus が返すオブジェクトを保持し、そのタグを add_branch に渡す。母線のインデックスは母線の削除でずれるが、タグはずれない（オブジェクトの識別を参照）。
para = table(100, 10, 0.3, VariableNames=["M","D","Xs"]);
net  = PowerNetwork();
b1   = net.add_bus(V=1.00);
b2   = net.add_bus(V=1.02);
b3   = net.add_bus();
net.add_branch("pi", [b1.str_tag, b2.str_tag], R=0.010, X=0.085);
net.add_branch("pi", [b2.str_tag, b3.str_tag], R=0.017, X=0.092);
g1   = b1.add_component("gen-simple", "parameter",para);
g2   = b2.add_component("gen-simple", "P",0.5, "parameter",para);
b3.add_component("load-impedance", "P",-1.0, "Q",-0.2);
net.initialize();

sc  = Scenario("fault");
sc.add_fault(b3.str_tag, [1,1.05]);
net.add_scenario(sc);
sim = net.simulate([0,10], sc);
sys = net.get_sys();

Minimal controller example最小限の制御器の例

  • A first-order AVR. Its output Vfield drives the generator input of that name.1 次遅れの AVR。出力 Vfield が発電機の同名の入力を駆動。
  • No generator output is called Vref or Vpss: Vref stays at its equilibrium, Vpss reads a PSS when one is attached.発電機に Vref、Vpss という名前の出力はない。Vref は平衡点の値のまま、Vpss は PSS が接続されていればその出力。
  • The Jacobians are written by hand.ヤコビ行列は手で記述。
  • The constructor adds the parameters and builds the function handles; they are built again with the network frequency when the controller is attached.コンストラクタがパラメータを追加して関数ハンドルを作成。制御器の接続時にネットワークの周波数で再作成。
_GUILDAobject/+controller/+avr/simple_avr.m 
classdef simple_avr < LocalController
% First-order AVR: Te*dVfd/dt = -Vfd + Ka*(Vref + Vpss - |V|), Vfield = Vfd.
%
% See also controller.avr.AVR_ST1, LocalController
    properties (SetAccess=protected, Hidden)
        key     = "avr"                 % Attached to the component; a PSS can hang under it.
        sv_x    = "Vfd"                 % State names.
        sv_u    = ["Vref";"Vpss"]       % Input names; no component output has these names.
        sv_y    = "Vfield"              % Output names; drives the input Vfield of the component.
        sv_para = ["Ka";"Te"]           % Dynamic parameter names, in the order of p.
    end
    methods
        function obj = simple_avr(tag, opt)
            % Create the controller with the tag "CA"+tag.
            arguments
                tag (1,1) string            % Tag suffix.
                opt.Ka (1,1) double = 30    % [pu] Gain.
                opt.Te (1,1) double = 0.05  % [s] Time constant.
            end
            obj@LocalController("CA"+tag)
            obj.para_dynamics.add_entry("Ka", opt.Ka, "double", "Te", opt.Te, "double");
        end
        function get_equilibrium(obj, V, u)
            % Set the equilibrium from the complex voltage V and the component inputs u.
            Ka = obj.para_dynamics.Ka;
            obj.rv_Xequilibrium = u(2);
            obj.rv_Uequilibrium = [u(2)/Ka + abs(V); 0];
            cellfun(@(c) c.get_equilibrium(V, u), obj.a_LocalController);
        end
    end
    methods (Static)
        function dx = fcn_dx(~, x, V, ~, u, p, ~)
            % Return the state derivative.
            dx = -x + p(1)*(u(1) + u(2) - norm(V));
        end
        function y = fcn_y(~, x, ~, ~, ~, ~, ~)
            % Return the output.
            y = x;
        end
        function M = fcn_Mass(~, ~, ~, ~, ~, p, ~)
            % Return the constant mass matrix.
            M = p(2);
        end
        function [Axx,Bxv,Bxi,Bxu] = Jacobi_dx(~, ~, V, ~, ~, p, ~)
            % Return the Jacobians of fcn_dx with respect to x, V, I and u.
            Axx = -1;
            Bxv = -p(1)*V.'/norm(V);
            Bxi = zeros(1,2);
            Bxu = [p(1), p(1)];
        end
        function [Cyx,Dyv,Dyi,Dyu] = Jacobi_Y(~, ~, ~, ~, ~, ~, ~)
            % Return the Jacobians of fcn_y with respect to x, V, I and u.
            Cyx = 1;
            Dyv = zeros(1,2);
            Dyi = zeros(1,2);
            Dyu = zeros(1,2);
        end
    end
end

Attaching a controller changes the dynamics, so run initialize again. Without it, simulate stops with GUILDA:PowerNetwork:EquilibriumStale.

制御器の接続で動特性が変わるため、initialize を再実行。実行しないと simulate は GUILDA:PowerNetwork:EquilibriumStale で停止。

avr = controller.avr.simple_avr("a", Ka=30, Te=0.05);
pss = controller.pss.PSS1("p");
g2.add_local_controller(avr, pss);
net.initialize();
sim = net.simulate([0,10], sc);

To detach it, call g2.remove_local_controller(avr.str_tag, RemoveNested=true). The option also removes the PSS, and an AVR with a PSS cannot be removed without it.

取り外し: g2.remove_local_controller(avr.str_tag, RemoveNested=true)。このオプションで PSS も取り外し。PSS の付いた AVR はこのオプションなしでは取り外し不可。

Testing a new model新しいモデルのテスト

Check the contract with validatevalidate で契約を確認する

  • comp.validate and con.validate print the comparison and return a struct of tables.comp.validate と con.validate は比較結果を表示し、テーブルの構造体を返す。
  • A broken model does not stop the check: it appears as FAIL.モデルに問題があっても確認は止まらず、FAIL と表示。
  • Pass false to skip the printing.表示を省くには false を渡す。
s = g2.validate(false);
s.contract        % status (PASS, FAIL, INFO) and detail of each check
s.inputs          % where each input is read

s = avr.validate(false);
s.contract
s.inputs          % Vref: "equilibrium (not connected)", Vpss: "output of CPp"
FieldフィールドWhat to look for確認する点
contractSizes of x, u, and the model functions; fcn_I complex; fcn_Mass constant and square; no dependence on I; no port names in sv_u; whether getCompPQ is defined.x、u、モデル関数のサイズ、fcn_I が複素数であること、fcn_Mass が定数の正方行列であること、I に依存しないこと、sv_u にポート名がないこと、getCompPQ が定義されているかどうか。
inputsThe source of each input. A misspelled input name is not an error when the controller is attached; it appears here as equilibrium (not connected).各入力の取得元。入力名の綴りの誤りは制御器の接続時にはエラーにならず、ここに equilibrium (not connected) と表示。
dx, IThe residuals at the point. They should be close to zero at an equilibrium.その点での残差。平衡点ではほぼ 0。
Axx, Bxv, ...The absolute difference between each analytic Jacobian and finite differences. A component without Jacobi_* has nothing to compare.解析的なヤコビ行列と有限差分との差の絶対値。Jacobi_* のない機器は比較対象なし。
  • A component is checked at its equilibrium; before net.initialize, at a random point with unit V and I, where the residuals are not zero.機器は平衡点で確認。net.initialize の前は大きさ 1 の V、I を持つランダムな点で確認するため、残差は 0 にならない。
  • A local controller must be attached to a component on an initialized network.ローカル制御器は、初期化済みのネットワーク上の機器への接続が必要。

Check the dynamic behavior動的な挙動を確認する

  1. Stay at the equilibrium平衡点にとどまる

    net.simulate without scenarios keeps the states at rv_Xequilibrium.

    シナリオなしの net.simulate で、状態が rv_Xequilibrium にとどまる。

  2. Run through a fault and a trip地絡と解列を最後までシミュレーションする

    Run a fault and a trip with a Scenario (add_fault, add_trip). flag is 1 when the simulation completes. A trip calls get_equilibrium with I = P = Q = 0.

    Scenario（add_fault、add_trip）で地絡と解列（トリップ）を実行。シミュレーションが完了すれば flag は 1。解列では I = P = Q = 0 で get_equilibrium を呼び出し。

  3. Look at the linear model線形モデルを調べる

    eig(net.get_sys()). A network of synchronous machines has an eigenvalue near zero from the common rotation of the rotor angles. The others: in the left half plane unless intended. An unstable result can also come from the rest of the test network, so compare with an existing model on the same network.

    eig(net.get_sys()) を確認。同期機からなるネットワークには、回転子角の一斉回転による 0 付近の固有値。それ以外の固有値は、意図した場合を除いて左半平面。不安定な結果はテスト用ネットワークのほかの部分から生じることもあるため、同じネットワーク上の既存のモデルと比較。

  4. Compare with a known model既知のモデルと比較する

    When an existing class reduces to your model, the eigenvalues should agree, as below.

    既存のクラスが新しいモデルに帰着する場合、下のように固有値が一致。

Add a test to the test suiteテストスイートにテストを追加する

  • Add a %% section to the script of the feature in +DebugScript, or a new script test_I<issue>_<slug>.m.+DebugScript にあるその機能のスクリプトに %% セクションを追加、または新しいスクリプト test_I<issue>_<slug>.m を作成。

function [net, g2] = make_network(str_key, para)
    net = PowerNetwork();
    b1  = net.add_bus(V=1.00);
    b2  = net.add_bus(V=1.02);
    b3  = net.add_bus();
    net.add_branch("pi", [b1.str_tag, b2.str_tag], R=0.010, X=0.085);
    net.add_branch("pi", [b2.str_tag, b3.str_tag], R=0.017, X=0.092);
    b1.add_component(str_key, "parameter",para);
    g2  = b2.add_component(str_key, "P",0.5, "parameter",para);
    b3.add_component("load-impedance", "P",-1.0, "Q",-0.2);
    net.solver_ODE.Progress = "none";
    net.initialize();
end
