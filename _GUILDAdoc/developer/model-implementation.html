Steps to add a modelモデル追加の手順

  1. Choose the base class and the place基底クラスと置き場所を決める

    Put the class in the matching package of _GUILDAobject (see Folder Structure). A small model can be one classdef file. In a class folder @Name/, each method is its own file; the classdef keeps only the properties, the constructor, the accessors, the Abstract declarations and the signatures of methods with attributes (see Folder Structure).

    クラスは _GUILDAobject の該当するパッケージに置きます（フォルダ構成を参照）。小さなモデルなら classdef ファイル 1 つでもかまいません。クラスフォルダ @Name/ にする場合は、1 つのメソッドを 1 つのファイルに書きます。classdef に残すのは、プロパティ、コンストラクター、アクセサー、Abstract の宣言、属性付きメソッドのシグネチャだけです（フォルダ構成を参照）。

  2. Implement the model contractモデルの契約を実装する

    Define the constants and methods in Contracts. Document the class with Class Documentation and name new properties with the Naming Conventions.

    契約に挙げた定数とメソッドを定義します。クラスの説明はクラスのドキュメントに、新しいプロパティの名前は命名規則に従って書きます。

  3. Register the model keyモデルのキーを登録する
    • Run GUILDA.update_keymap (or GUILDA again): it scans the repository, reads the key of each class into GUILDA.keymap, which Bus.add_component, PowerNetwork.add_branch, Component.add_local_controller and PowerNetwork.add_global_controller use to check the key and build the model. Until then the key is rejected. No file is generated.GUILDA.update_keymap を実行します（GUILDA を再実行しても同じです）。リポジトリを走査して、各クラスの key を GUILDA.keymap に読み込みます。Bus.add_component・PowerNetwork.add_branch・Component.add_local_controller・PowerNetwork.add_global_controller は、このマップでキーを確認してモデルを作ります。登録するまで、そのキーは使えません。ファイルは生成しません。
    • A class that does not load: warning GUILDA:dictionary:ClassNotLoaded with the reason.読み込めないクラスがあると、理由とともに警告 GUILDA:dictionary:ClassNotLoaded を出します。
  4. Test the modelモデルをテストする

    Check the contract with validate, then run the checks in Testing.

    validate で契約を確認してから、テストの項目を確認します。

各モデル関数の引数は (t, x, V, u, param, omega0) です。ただし機器の出力関数 fcn_Y は (t, x, V, param, omega0) で、u を取りません。機器の出力は u に依存しないためです。

Rules that apply to every modelすべてのモデルに適用されるルール

  • No model function receives the bus current: it is the sum of all the components of the bus. A model computes its own current from its states, V and u.モデル関数は母線電流を受け取りません。母線電流は、その母線にあるすべての機器の電流の和だからです。モデル自身の電流は、状態、V、u から計算します。
  • A component output depends only on x and V, so no algebraic loop runs through the inputs. A current that depends on u (a classical generator, a load) cannot be an output; a controller computes it from V and the states.機器の出力は x と V だけに依存するので、入力を通る代数ループは生じません。u に依存する電流（古典モデルの発電機や負荷）は出力にできません。必要なら制御器が V と状態から計算します。
  • The outputs of a global controller are 0 at its equilibrium: they add to inputs whose equilibrium is set.グローバル制御器の出力は、平衡点で 0 にします。平衡点で決まった入力に足し合わされるためです。
  • sv_u must not contain the port names Vre, Vim, Ire, Iim.sv_u にポート名 Vre、Vim、Ire、Iim を含めません。
  • net.initialize evaluates the point that get_equilibrium returns. A wrong size or an error in a model function stops it (GUILDA:PowerNetwork:InitializeEquilibriumSize, InitializeModelSize, InitializeModelFailed). A point where the state moves gives the warning GUILDA:PowerNetwork:EquilibriumResidual.net.initialize は get_equilibrium が返す点を評価します。サイズの誤りやモデル関数のエラーがあれば停止します（GUILDA:PowerNetwork:InitializeEquilibriumSize、InitializeModelSize、InitializeModelFailed）。状態が動いてしまう点では、警告 GUILDA:PowerNetwork:EquilibriumResidual を出します。
  • A controller can use the input names "Xall" and "Yall" to observe all the states or outputs of the component. It must then override set_inputs; see controller.local_LQR. The names "X" and "Y" are errors.制御器は入力名 "Xall" と "Yall" を使うと、機器のすべての状態またはすべての出力を観測できます。その場合は set_inputs をオーバーライドしてください（controller.local_LQR を参照）。"X"、"Y" という名前はエラーになります。
  • A component has two slots for local controllers: one "avr" or "local" controller (with a "pss" under an AVR), and one "governor" beside it. a_LocalController and the variables list them in this order, whatever the order of attachment. A new controller replaces the one in its slot with the warning GUILDA:Component:ReplaceController.機器にはローカル制御器の枠が 2 つあります。"avr" または "local" の制御器 1 つ（AVR の下には "pss"）と、その横の "governor" 1 つです。a_LocalController と変数は、接続した順序にかかわらずこの順に並びます。同じ枠に新しく接続すると、前の制御器を置き換えて警告 GUILDA:Component:ReplaceController を出します。
  • The two top-level controllers of a component must drive different inputs. A governor and a "local" controller that both drive Pmech (such as controller.local_LQR on all the inputs) stop with GUILDA:Component:ControllerOutputOverlap. A controller whose outputs follow the component (as local_LQR does) overrides driven_inputs, so that the check runs before the attachment.機器の最上位にある 2 つの制御器は、別々の入力を駆動します。ガバナと、同じく Pmech を駆動する "local" 制御器（すべての入力を使う controller.local_LQR など）を組み合わせると、GUILDA:Component:ControllerOutputOverlap で停止します。出力が機器に合わせて決まる制御器（local_LQR など）は、driven_inputs をオーバーライドして、接続の前にこの確認を受けます。
  • getCompPQ(obj, x, V, u, param), with V as [abs; angle], is needed only by the continuation power flow with UseInternalState=true; without it, that analysis stops with GUILDA:build_layout:MissingGetCompPQ.V を [abs; angle] として受け取る getCompPQ(obj, x, V, u, param) は、UseInternalState=true の連続潮流計算でだけ必要です。定義がなければ、その解析は GUILDA:build_layout:MissingGetCompPQ で停止します。
  • The GUI (obj.gui()) needs no code in the class: the abstract class provides the tables, and the meaning of the parameters and the model is in the class reference, which the Docs button opens (see GUI).GUI（obj.gui()）のためのコードは書かなくてかまいません。表は抽象クラスが用意し、パラメータとモデルの説明は Docs ボタンで開くクラスのリファレンスに表示されます（GUIを参照）。

Minimal generator example最小限の発電機の例

  • A constant-magnitude source behind the reactance Xs, with the swing equation.リアクタンス Xs の背後に大きさ一定の電源を置き、動揺方程式で回転子を表すモデルです。
  • Same dynamics as gen-classical with Xd = Xq = Xs: a useful check.Xd = Xq = Xs とした gen-classical と同じ動特性を持つので、動作の確認に使えます。
  • The constructor only calls the base class component.generator.abstract, which reads the parameters and sets the tag to the bus tag + "SG" + index (Component puts the bus tag in front). It is declared with Access={?Bus}, so only add_component and replace_component create the model; a class without a constructor would inherit a public one (Class Design: parent references).コンストラクタは基底クラス component.generator.abstract を呼ぶだけです。基底クラスがパラメータを読み、タグを「母線のタグ + "SG" + インデックス」にします（母線のタグは Component が先頭に付けます）。Access={?Bus} で宣言するので、このモデルを作れるのは add_component と replace_component だけです。コンストラクタのないクラスは公開のコンストラクタを継承してしまいます（クラス設計: 親への参照）。
  • A load inherits from component.load.abstract in the same way.負荷も同様に component.load.abstract を継承します。
_GUILDAobject/+component/+generator/simple_sg.m 
classdef simple_sg < component.generator.abstract
% Generator with a constant-magnitude source E behind the reactance Xs.
%
% See also component.generator.classical, Component
    properties (Constant)
        key = "gen-simple"         % Model key used by Bus.add_component.
        sv_x = ["delta";"omega"]   % State names.
        sv_u = ["Pmech";"Vfield"]  % Input names.
        sv_y = "omega"             % Output names read by local controllers.
        sv_para = ["M";"D";"Xs"]   % Dynamic parameter names, in the order of p.
    end
    methods (Access={?Bus})
        function obj = simple_sg(index, parameter, varargin)
            % Create the generator (called by Bus.add_component and Bus.replace_component).
            obj@component.generator.abstract(index, parameter, varargin{:})
        end
    end
    methods
        function [x, u] = get_equilibrium(obj, c_V, c_I, r_P, ~)
            % Return the states and inputs at the bus voltage and current.
            c_E = c_V + 1j*obj.tab_parameter.dynamics.Xs*c_I;
            x   = [angle(c_E); 0];
            u   = [r_P; abs(c_E)];
        end
    end
    methods (Static)
        function dx = fcn_dx(~, x, V, u, p, omega0)
            % Return the state derivatives.
            c_E = u(2)*exp(1j*x(1));
            c_I = (c_E - [1,1j]*V)/(1j*p(3));
            dx  = [2*pi*omega0*x(2); -p(2)*x(2) - real(c_E*conj(c_I)) + u(1)];
        end
        function c_I = fcn_I(~, x, V, u, p, ~)
            % Return the current injected into the bus as a complex number.
            c_I = (u(2)*exp(1j*x(1)) - [1,1j]*V)/(1j*p(3));
        end
        function y = fcn_Y(~, x, ~, ~, ~)
            % Return the outputs (no input u).
            y = x(2);
        end
        function M = fcn_Mass(~, ~, ~, ~, p, ~)
            % Return the constant mass matrix.
            M = diag([1, p(1)]);
        end
    end
end

A generator with parameters that are not in the bundled parameter.csv, like Xs, needs a table in the parameter option of add_component.

Xs のように、同梱の parameter.csv にないパラメータを持つ発電機では、add_component の parameter オプションにテーブルを渡す必要があります。

  • A model reads and writes its parameters through tab_parameter, one column per group: dynamics, powerflow, operation, OPF, graph (a network: base). Example: obj.tab_parameter.dynamics.Xs.モデルのパラメータは tab_parameter で読み書きします。列は区分ごとに分かれ、dynamics、powerflow、operation、OPF、graph があります（ネットワークには base）。例: obj.tab_parameter.dynamics.Xs。
  • Writing tab_parameter changes only the edited values, so only they are logged as edits. A value of another class is an error and nothing is stored.tab_parameter に書き込んだとき、変わるのは編集した値だけで、編集として記録されるのもその値だけです。クラスの違う値を書くとエラーになり、何も保存されません。
  • The containers behind the table are the cell a_Parameter, one Parameter per group, found by its s_tag. Each container stores its parameters as a table; its class and size come from the defaults. A model constructor replaces its dynamics container in one line with this tag form and a struct of the defaults (field: name, value: default), e.g. obj.a_Parameter{cellfun(@(p) p.s_tag=="dynamics", obj.a_Parameter)} = Parameter(obj, "dynamics", struct("Ka", 30, "Te", 0.05)).表のもとになるコンテナは、cell の a_Parameter にあります。区分ごとに 1 つの Parameter があり、s_tag で見分けます。各コンテナはパラメータを表として持ち、クラスと大きさは既定値で決まります。モデルのコンストラクタは、次のようにタグと既定値の struct（フィールド名がパラメータ名、値が既定値）を使い、dynamics コンテナを 1 行で置き換えます（例: obj.a_Parameter{cellfun(@(p) p.s_tag=="dynamics", obj.a_Parameter)} = Parameter(obj, "dynamics", struct("Ka", 30, "Te", 0.05))）。
  • Internal code that loops over many layers may read a container by tag in one line instead of building the table, e.g. b.a_Parameter{cellfun(@(p) p.s_tag=="dynamics", b.a_Parameter)}.tab_parameter.Gshunt.多くの層を順に処理する内部のコードでは、表を作らずに、タグでコンテナを 1 行で読んでもかまいません（例: b.a_Parameter{cellfun(@(p) p.s_tag=="dynamics", b.a_Parameter)}.tab_parameter.Gshunt）。

Using the new model新しいモデルの使用

  • Once GUILDA has registered the key, the model works in every analysis.GUILDA がキーを登録すれば、そのモデルをすべての解析で使えます。
  • Keep the objects that add_bus returns and pass their tags to add_branch: a bus index shifts when a bus is removed, a tag does not (see Identifying objects).add_bus が返すオブジェクトを取っておき、そのタグを add_branch に渡します。母線のインデックスは母線を削除するとずれますが、タグはずれません（オブジェクトの識別を参照）。
para = table(100, 10, 0.3, VariableNames=["M","D","Xs"]);
net  = PowerNetwork();
b1   = net.add_bus(V=1.00);
b2   = net.add_bus(V=1.02);
b3   = net.add_bus();
net.add_branch("pi", [b1.s_tag, b2.s_tag], R=0.010, X=0.085);
net.add_branch("pi", [b2.s_tag, b3.s_tag], R=0.017, X=0.092);
g1   = b1.add_component("gen-simple", "parameter",para);
g2   = b2.add_component("gen-simple", "P",0.5, "parameter",para);
b3.add_component("load-impedance", "P",-1.0, "Q",-0.2);
net.initialize();

sc  = Scenario("fault");
sc.add_fault(b3.s_tag, [1,1.05]);
net.add_scenario(sc);
sim = net.simulate([0,10], sc);
sys = net.get_sys();

Minimal controller example最小限の制御器の例

  • A first-order AVR. Its output Vfield drives the generator input of that name.1 次遅れの AVR です。出力 Vfield が、発電機の同じ名前の入力を駆動します。
  • No generator output is called Vref or Vpss: Vref stays at its equilibrium, Vpss reads a PSS when one is attached.発電機に Vref、Vpss という名前の出力はありません。そのため Vref は平衡点の値のままです。Vpss は、PSS が接続されていればその出力になります。
  • The constant key is the model key of add_local_controller; s_role = "avr" attaches it to the component, with a PSS under it. Run GUILDA again so that the key list of add_local_controller includes "avr-simple".定数 key は、add_local_controller で使うモデルのキーです。s_role = "avr" なので機器に接続され、その下に PSS を付けられます。add_local_controller のキー一覧に "avr-simple" が入るよう、GUILDA を再実行してください。
  • The Jacobians are written by hand.ヤコビ行列は手で書きます。
  • The constructor adds the parameters to the dynamics container (tag form). It is declared with Access={?Component}, so only add_local_controller creates the controller. net.initialize builds the function handles with the network frequency.コンストラクタはパラメータを dynamics コンテナに入れます（タグで指定）。Access={?Component} で宣言するので、この制御器を作れるのは add_local_controller だけです。関数ハンドルは net.initialize がネットワークの周波数で作ります。

classdef simple_avr < LocalController
% First-order AVR: Te*dVfd/dt = -Vfd + Ka*(Vref + Vpss - |V|), Vfield = Vfd.
%
% See also controller.avr.AVR_ST1, LocalController
    properties (Constant, Hidden)
        key = "avr-simple"      % Model key used by Component.add_local_controller.
        s_role = "avr"          % Attached to the component; a PSS can hang under it.
    end
    properties (SetAccess=protected, Hidden)
        sv_x = "Vfd"            % State names.
        sv_u = ["Vref";"Vpss"]  % Input names; no component output has these names.
        sv_y = "Vfield"         % Output names; drives the input Vfield of the component.
        sv_para = ["Ka";"Te"]   % Dynamic parameter names, in the order of p.
    end
    methods (Access={?Component})
        function obj = simple_avr(tag, opt)
            % Create the controller with the tag "CA"+tag.
            arguments (Input)
                tag (1,1) string            % Tag suffix.
                opt.Ka (1,1) double = 30    % [pu] Gain.
                opt.Te (1,1) double = 0.05  % [s] Time constant.
            end
            obj@LocalController("CA"+tag)
            obj.a_Parameter{cellfun(@(p) p.s_tag=="dynamics", obj.a_Parameter)} = Parameter(obj, "dynamics", struct("Ka", opt.Ka, "Te", opt.Te));
        end
    end
    methods
        function get_equilibrium(obj, V, u)
            % Set the equilibrium from the complex voltage V and the component inputs u.
            Ka = obj.tab_parameter.dynamics.Ka;
            obj.rv_Xequilibrium = u(2);
            obj.rv_Uequilibrium = [u(2)/Ka + abs(V); 0];
            cellfun(@(c) c.get_equilibrium(V, u), obj.a_LocalController);
        end
    end
    methods (Static)
        function dx = fcn_dx(~, x, V, u, p, ~)
            % Return the state derivative.
            dx = -x + p(1)*(u(1) + u(2) - norm(V));
        end
        function y = fcn_y(~, x, ~, ~, ~, ~)
            % Return the output.
            y = x;
        end
        function M = fcn_Mass(~, ~, ~, ~, p, ~)
            % Return the constant mass matrix.
            M = p(2);
        end
        function [Axx,Bxv,Bxu] = Jacobi_dx(~, ~, V, ~, p, ~)
            % Return the Jacobians of fcn_dx with respect to x, V and u.
            Axx = -1;
            Bxv = -p(1)*V.'/norm(V);
            Bxu = [p(1), p(1)];
        end
        function [Cyx,Dyv,Dyu] = Jacobi_Y(~, ~, ~, ~, ~, ~)
            % Return the Jacobians of fcn_y with respect to x, V and u.
            Cyx = 1;
            Dyv = zeros(1,2);
            Dyu = zeros(1,2);
        end
    end
end

Check the contract with validatevalidate で契約を確認する

FieldフィールドWhat to look for確認する点
contractSizes of x, u, and the model functions; fcn_I complex; fcn_Mass constant and square; no port names in sv_u; whether getCompPQ is defined.x、u、モデル関数のサイズ、fcn_I が複素数であること、fcn_Mass が定数の正方行列であること、sv_u にポート名がないこと、getCompPQ が定義されているかどうかを確認します。
inputsThe source of each input. A misspelled input name is not an error when the controller is attached; it appears here as equilibrium (not connected).各入力をどこから取るかを示します。入力名の綴りを間違えても制御器の接続時にはエラーにならず、ここに equilibrium (not connected) と表示されます。
dx, IThe residuals at the point. They should be close to zero at an equilibrium.その点での残差です。平衡点ではほぼ 0 になります。
Axx, Bxv, ...The absolute difference between each analytic Jacobian and finite differences. A component without Jacobi_* has nothing to compare.解析的なヤコビ行列と有限差分の差を絶対値で示します。Jacobi_* のない機器では比べるものがありません。
  • A component is checked at its equilibrium; before net.initialize, at a random point with unit V and injected current, where the residuals are not zero.機器は平衡点で確認します。net.initialize の前は、大きさ 1 の V と注入電流を持つランダムな点で確認するので、残差は 0 になりません。
  • A local controller must be attached to a component on an initialized network.ローカル制御器は、初期化済みのネットワーク上の機器に接続してから確認します。

Check the dynamic behavior動的な挙動を確認する

  1. Stay at the equilibrium平衡点にとどまる

    net.simulate without scenarios keeps the states at rv_Xequilibrium.

    シナリオなしの net.simulate を実行し、状態が rv_Xequilibrium にとどまることを確かめます。

  2. Run through a fault and a trip地絡と解列を最後までシミュレーションする

    Run a fault and a trip with a Scenario (add_fault, add_trip). flag is 1 when the simulation completes. A trip calls get_equilibrium with I = P = Q = 0.

    Scenario（add_fault、add_trip）で地絡と解列（トリップ）を起こします。シミュレーションが最後まで進めば flag は 1 です。解列では I = P = Q = 0 で get_equilibrium が呼ばれます。

  3. Look at the linear model線形モデルを調べる

    eig(net.get_sys(Format="ss")). A network of synchronous machines has an eigenvalue near zero from the common rotation of the rotor angles. The others: in the left half plane unless intended. An unstable result can also come from the rest of the test network, so compare with an existing model on the same network.

    eig(net.get_sys(Format="ss")) を確認します。同期機からなるネットワークには、回転子角がそろって回る動きに対応する 0 付近の固有値があります。それ以外の固有値は、意図した場合を除いて左半平面にあるはずです。不安定な結果がテスト用ネットワークのほかの部分から来ることもあるので、同じネットワークで既存のモデルと比べてください。

function [net, g2] = make_network(s_key, para)
    net = PowerNetwork();
    b1  = net.add_bus(V=1.00);
    b2  = net.add_bus(V=1.02);
    b3  = net.add_bus();
    net.add_branch("pi", [b1.s_tag, b2.s_tag], R=0.010, X=0.085);
    net.add_branch("pi", [b2.s_tag, b3.s_tag], R=0.017, X=0.092);
    b1.add_component(s_key, "parameter",para);
    g2  = b2.add_component(s_key, "P",0.5, "parameter",para);
    b3.add_component("load-impedance", "P",-1.0, "Q",-0.2);
    net.initialize();
end
