Power Flow Feature Design潮流計算機能の設計

net.calculate_powerflow(): bus voltages from the power-flow settings of the buses and components. The network assembles the admittance matrix and the bus conditions; SolverPF only solves them. The first output takes the form of Format (a ResultPF by default; complex voltages or V, I, P, Q for the other values); nothing is written to the model.

net.calculate_powerflow() は、母線と機器の潮流設定から母線電圧を求めます。アドミタンス行列と母線の潮流条件はネットワークが組み立て、SolverPF は数値計算だけを行います。最初の出力の形は Format で決まり、既定では ResultPF、ほかの値では複素電圧または V・I・P・Q です。モデルには書き込みません。

1. What the feature does and how to call it1. 機能の目的と呼び出し方

  • Computes the steady-state voltage phasor of every bus
  • Slack bus: fixes V and Varg
  • PV bus: fixes P and V
  • PQ bus: fixes P and Q
  • P and Q of a bus: sums of tab_parameter.powerflow of its components
  • Summed Q = NaN → PV bus (a generator leaves Q = NaN)
  • すべての母線について、定常状態の電圧フェーザを求めます。
  • slack 母線では V と Varg を固定します。
  • PV 母線では P と V を固定します。
  • PQ 母線では P と Q を固定します。
  • 母線の P と Q は、その母線にある機器の tab_parameter.powerflow を足したものです。
  • Q の和が NaN になる母線は PV 母線として扱います。発電機は Q = NaN を持つためです。
[result, flag, output] = net.calculate_powerflow(Name=Value, ...)
OptionオプションDefault (source)既定値（出所）Meaning意味
Solver"newton"GUILDA.config("PowerFlowCalculation")
  • "newton": Newton-Raphson method (MethodNewtonRaphson) with the analytic Jacobian
  • "gradient": discrete gradient steps θ += α·ΔP, V += α·ΔQ/V (MethodGradient)
  • "levenberg-marquardt": damped Gauss-Newton steps with the analytic Jacobian (MethodLevenbergMarquardt)
  • "fsolve": fsolve on the power equations (MethodFsolve; Optimization Toolbox)
  • "dynamic": virtual bus dynamics integrated by ode15s until the mismatch is below the tolerance (MethodDynamic)
  • "newton": ヤコビ行列を解析的に求めるニュートン・ラフソン法です（MethodNewtonRaphson）。
  • "gradient": θ += α·ΔP、V += α·ΔQ/V の勾配ステップを繰り返します（MethodGradient）。
  • "levenberg-marquardt": 解析的なヤコビ行列を使う、減衰付きのガウス・ニュートン法です（MethodLevenbergMarquardt）。
  • "fsolve": 電力方程式を fsolve で解きます（MethodFsolve）。Optimization Toolbox が必要です。
  • "dynamic": 母線に仮想的なダイナミクスを持たせ、不平衡量が許容値を下回るまで ode15s で積分します（MethodDynamic）。
Tolerance1e-8config
  • Every method: largest P/Q mismatch [pu] of a converged solution (positive)
  • newton, levenberg-marquardt, fsolve: also the residuals of the set |V| and the slack angle
  • fsolve: its square is also passed as FunctionTolerance (a tolerance on the sum of squares) and OptimalityTolerance
  • dynamic: also sets the ODE tolerances AbsTol = min(Tolerance, 1e-5), RelTol = min(100·Tolerance, 1e-4)
  • どの計算方法でも、収束した解に残る P と Q の不平衡量の最大値 [pu] です。正の値を指定します。
  • newton、levenberg-marquardt、fsolve では、指定した |V| と slack の角度の残差もこの値で判定します。
  • fsolve では、この値の 2 乗を FunctionTolerance（二乗和の許容値）と OptimalityTolerance にも渡します。
  • dynamic では、ODE の許容誤差を AbsTol = min(Tolerance, 1e-5)、RelTol = min(100·Tolerance, 1e-4) とします。
MaxIterationNaNconfig
  • Maximum number of iterations
  • NaN: method default (newton: 50; gradient: 1e6; levenberg-marquardt: 100; fsolve: 400)
  • Unused by "dynamic"
  • 反復回数の上限です。
  • NaN なら計算方法ごとの既定値を使います（newton は 50、gradient は 1e6、levenberg-marquardt は 100、fsolve は 400）。
  • "dynamic" では使いません。
VerbosefalseconfigPrint each iteration and the final message; the local function solver_options sets Display of the Method class: "iter" (true) or "none" (false)反復ごとの表示と、終了時のメッセージを出すかどうかです。内部関数 solver_options が、true なら "iter"、false なら "none" を Method クラスの Display に設定します。
WarmStarttrueconfig
  • true: starts from the last converged solution kept by net.solver_PF, when it was solved for the same bus tags in the same order
  • false, other bus tags, or no kept solution: flat start (angle 0, magnitude 1; set V at PV and slack buses, set Varg at the slack bus)
  • gradient, dynamic: the fixed values (slack angle and voltage, PV voltages) always start at their set values
  • true なら、net.solver_PF が持つ最後に収束した解から始めます。ただし、その解を求めたときと母線のタグ（並び順を含む）が同じときに限ります。
  • false のとき、母線のタグが違うとき、保持した解がないときは、フラットスタート（角度 0、大きさ 1）で始めます。ただし PV 母線と slack 母線は指定の V、slack 母線は指定の Varg を使います。
  • gradient と dynamic では、固定する値（slack の角度と電圧、PV の電圧）は常に指定値から始めます。
PlotFcn"none"config
  • Live display during the calculation, every Solver
  • "residual": one bar per power equation (two per bus: P or the slack angle; Q or |V| at PV and slack buses), height |residual| at the iterate, log scale, Tolerance as a line; one reused figure (Tag GUILDA:PlotFcn:residual), redrawn at most every 0.2 s and at the end (dynamic: along the virtual time)
  • Function handle: stop = f(x, optimValues, state) at every iterate; x complex bus voltages, optimValues.iteration, .fval (residuals), .residual (largest), .time (dynamic); a true stop ends with flag -1
  • The figure after the calculation: result.plot_voltage() of Format="GUILDAorigin"
  • 計算中の経過をライブで表示します。どの Solver でも使えます。
  • "residual" は、電力方程式 1 本につき 1 本の棒を描きます。母線ごとに 2 本で、P または slack の角度と、Q または PV・slack の |V| です。棒の高さはその反復の |残差| で、対数軸に Tolerance を破線で示します。図は 1 枚を使い回し（Tag GUILDA:PlotFcn:residual）、描き直すのは 0.2 秒以上の間隔と終了時です。dynamic では仮想時間に沿って更新します。
  • 関数ハンドルを渡すと、反復ごとに stop = f(x, optimValues, state) を呼び出します。x は母線の複素電圧です。optimValues には optimValues.iteration、.fval（残差）、.residual（最大値）、.time（dynamic のみ）が入ります。stop に true を返すと、flag -1 で終わります。
  • 計算後の図は、Format="GUILDAorigin" の結果の result.plot_voltage() で描きます。

  • "V": 母線の複素電圧 [pu] を、net.a_Bus の順に並べた列ベクトルです。
  • "powerflow(mat)": n_bus×4 の複素行列です。列は V、I（フェーザ）、P、Q（ネットワークへの注入）[pu] です。
  • "powerflow(tab)": 同じ内容の table です。変数は V、I、P、Q で、行名は母線のタグです。
  • "GUILDAorigin"（既定）: ResultPF を返します（生成されるデータを参照）。

  • Name-Value options override it for that call only; the settings file is not written
  • Other settings: no Name-Value option; set in GUILDA.setting
    • NewtonStepSize (1; newton)
    • GradientStepSize (NaN: α = 0.5/(max|Y_ii|·Vmax²), Vmax the largest set bus voltage or 1; gradient)
    • FsolveUseParallel (false), FsolveMaxFunctionEvaluations (NaN: the fsolve default) (fsolve)
    • Names: <Solver><option> for a setting of one Solver; NaN is the automatic value of every setting that has one
    • WhenFailed ("WARN")
  • dynamic: the class defaults of MethodDynamic (Mass = 0, Damper = 1, foh_PQ = 0); no setting
  • net.solver_PF: no settings; keeps only the warm start solution (see Side effects)
  • Name-Value で指定できる名前は上の 7 つで、calculate_powerflow の arguments ブロックが検査します。
  • 既定値は GUILDA.setting の PowerFlowCalculation セクション（GUILDA.config("PowerFlowCalculation", ...)）から、呼び出しのたびに読み込みます。元の値は @GUILDA/config/DefaultPowerFlowCalculation.json にあります。
  • Name-Value オプションは、その呼び出しの間だけ設定を上書きします。設定ファイルには書き込みません。
  • 次の設定は Name-Value では指定できず、GUILDA.setting で変更します。
    • NewtonStepSize（1。newton）
    • GradientStepSize（gradient 用）。NaN なら α = 0.5/(max|Y_ii|·Vmax²) を使います。Vmax は指定された母線電圧の最大値で、指定がなければ 1 です。
    • FsolveUseParallel（既定値 false）と FsolveMaxFunctionEvaluations（NaN なら fsolve の既定値）。どちらも fsolve 用です。
    • 1 つの Solver だけに効く設定は <Solver 名><オプション名> という名前にします。自動で決まる値を持つ設定は、どれも NaN にすると自動になります。
    • WhenFailed（"WARN"）
  • dynamic には設定項目がなく、MethodDynamic のクラスの既定値（Mass = 0、Damper = 1、foh_PQ = 0）を使います。
  • net.solver_PF は設定を持たず、ウォームスタート用の解だけを持ちます（副作用を参照）。

Preconditions and notes:

前提条件と注意点は次のとおりです。

  • At least one bus, and a slack bus or at least one bus with a component
  • net.initialize() not needed
  • MATLAB alone: every method except "fsolve"
  • "fsolve" needs Optimization Toolbox; without it the call stops with GUILDA:require_toolbox:Unavailable
  • 母線が 1 つ以上必要です。さらに、slack 母線があるか、機器を持つ母線が 1 つ以上なければなりません。
  • net.initialize() を先に実行する必要はありません。
  • "fsolve" 以外の計算方法は、MATLAB 本体だけで動きます。
  • "fsolve" には Optimization Toolbox が必要です。ないときは GUILDA:require_toolbox:Unavailable で止まります。

Data of the power flow: get_pf_condition潮流計算のデータ: get_pf_condition

sct_PFcondition = net.get_pf_condition(Display=true)
  • Returns what calculate_powerflow solves, the same way get_opf_condition does for the OPF: Bus (the rows of Bus.get_pf_condition: Type, Varg, V, P, Q; row names = bus tags) and Y (the table of get_admittance_matrix)
  • When no bus is the slack bus, the bus that would be selected is the slack bus of the table (INFO SlackSelected); l_isSlack is never written, so the network is not changed
  • Display=true (default) prints the Bus table, not Y
  • calculate_powerflow が解くデータを、OPF の get_opf_condition と同じ形で返します。Bus（Bus.get_pf_condition の行。列は Type, Varg, V, P, Q、行名は母線のタグ）と Y（get_admittance_matrix の table）です。
  • スラック母線がないときは、選ばれる母線を表の中でスラック母線にします（INFO SlackSelected）。l_isSlack は書かないので、ネットワークは変わりません。
  • Display=true（既定）では Bus の表を表示します。Y は表示しません。

Power flow with the inputs held: calculate_fixed_input_powerflow入力を固定した潮流計算: calculate_fixed_input_powerflow

[result, flag, output] = net.calculate_fixed_input_powerflow(Name=Value, ...)
  • Solves the equilibrium with the inputs the components hold (rv_Uequilibrium, edited with Component.set_input), not the power-flow settings: the unknowns are the states, the currents of the components, the bus voltages and the Pmech of the first generator of the slack bus; the slack bus angle is 0
  • Options: Format (the same four values and default as above; the ResultPF has the solver "FixedInput" and no tab_PFcondition), Solver ("newton" when left out, "levenberg-marquardt", "fsolve"; "gradient" and "dynamic" stop with GUILDA:PowerNetwork:InitializeFixedInputSolver), Tolerance, MaxIteration (NaN: 50, 100 or 400), Verbose, WarmStart (true: from the held equilibrium; false, or a component without one: from a power flow that is not written). The values left out come from the PowerFlowCalculation section, except Solver
  • output.tab_component: one row per component (row names = component tags) with Bus, X, U, I
  • The equations are built in the method file (residual, Jacobian, initial point) and solved by MethodNewtonRaphson, MethodLevenbergMarquardt or MethodFsolve; net.solver_PF is not used
  • Writes nothing; the slack bus and Y come from get_pf_condition, which selects a slack bus for the calculation when none is set, as for calculate_powerflow. net.initialize(Method="FixedInput") writes the solution (see Initialization)
  • Every component must hold its inputs (InitializeInputNotSet) and the slack bus needs a generator (InitializeNoSlackGenerator). A network split into islands does not converge; initialize checks the islands before the call
  • 潮流設定ではなく、機器が保持する入力（rv_Uequilibrium。Component.set_input で編集）を固定して平衡点を求めます。未知数は状態、機器の電流、母線電圧と、スラック母線にある 1 台目の発電機の Pmech です。スラック母線の位相角は 0 です。
  • オプションは Format（上と同じ 4 つの値と既定値。ResultPF のソルバーは "FixedInput" で、tab_PFcondition は持ちません）、Solver（省くと "newton"。ほかに "levenberg-marquardt"、"fsolve"。"gradient" と "dynamic" は GUILDA:PowerNetwork:InitializeFixedInputSolver で止まります）、Tolerance、MaxIteration（NaN なら 50、100、400）、Verbose、WarmStart（true なら保持している平衡点から、false のときや平衡点のない機器があるときは書き込まない潮流計算から始めます）です。Solver 以外の省いた値は PowerFlowCalculation セクションから読みます。
  • output.tab_component は機器ごとに 1 行（行名は機器のタグ）の table で、変数は Bus、X、U、I です。
  • 方程式（残差、ヤコビ行列、初期点）はメソッドのファイル内で組み立て、MethodNewtonRaphson、MethodLevenbergMarquardt、MethodFsolve で解きます。net.solver_PF は使いません。
  • 何も書き込みません。スラック母線と Y は get_pf_condition から取ります。スラック母線がなければ、calculate_powerflow と同じくこの計算のために 1 つを選びます。解を書き込むのは net.initialize(Method="FixedInput") です（初期化を参照）。
  • すべての機器が入力を持つこと（InitializeInputNotSet）、スラック母線に発電機があること（InitializeNoSlackGenerator）が必要です。分断されたネットワークでは収束しません。initialize は呼び出しの前に分断を確かめます。

  2. PF-02 PowerNetwork.calculate_powerflow → PowerNetwork.get_pf_condition

    What it does処理内容
    • Stops with GUILDA:PowerNetwork:NoBus (no bus) or NoSlackCandidate (no bus with a component)
    • Stacks the rows of PF-03 and adds Y (PF-04): sct_PFcondition.Bus and sct_PFcondition.Y
    • When no bus is the slack bus: the bus of tools.slack_bus_index (first bus with a component with Q = NaN, else first bus with a component) is the slack bus of the table, its row the one of a slack bus ([Varg, V]); INFO SlackSelected, and SlackWithoutQnan when none of its components has Q = NaN
    • l_isSlack is never written: a get_ method does not change the network
    • 母線がなければ GUILDA:PowerNetwork:NoBus、機器を持つ母線がなければ NoSlackCandidate で止まります。
    • PF-03 の行を積み、Y（PF-04）を加えます。返すのは sct_PFcondition.Bus と sct_PFcondition.Y です。
    • slack 母線が 1 つもないときは、tools.slack_bus_index の母線（Q = NaN の機器を持つ最初の母線、なければ機器を持つ最初の母線）を表の slack 母線とし、その行を slack 母線の行（[Varg, V]）にします。INFO SlackSelected を表示し、その母線に Q = NaN の機器がなければ SlackWithoutQnan の警告を出します。
    • l_isSlack は書きません。get_ のメソッドはネットワークを変えません。

  3. PF-03 PowerNetwork.get_pf_condition → Bus.get_pf_condition

    What it does処理内容
    • Decides the bus type and the specified values
    • Slack → [Varg, V]
    • Otherwise: sums P and Q of the components
    • Q = NaN → PV, else PQ
    • 母線の種類と指定値を決めます。
    • slack → [Varg, V]
    • slack 以外の母線では、機器の P と Q を合計します。
    • Q が NaN なら PV 母線、そうでなければ PQ 母線とします。
    What it reads読み取る情報
    l_isSlack, bus母線の tab_parameter.powerflow (V, Varg), component機器の tab_parameter.powerflow (P, Q)
    Returns or changes戻り値・変更する値

  4. PF-04 PowerNetwork.get_admittance_matrix → Branch.get_admittance_matrix

    What it does処理内容
    • Adds the 2×2 matrix of every branch at its two end buses
    • Adds the bus shunt Gshunt + 1j*Bshunt on the diagonal
    • get_pf_condition returns the table as Y; calculate_powerflow takes the matrix out of it in the order of the bus tags
    • 各ブランチの 2×2 行列を、両端の母線に当たる位置に足し込みます。
    • 母線のシャント Gshunt + 1j*Bshunt を対角に足します。
    • get_pf_condition がこの table を Y として返し、calculate_powerflow が母線のタグの順に行列を取り出します。
    What it reads読み取る情報
    branchブランチの tab_parameter.dynamics (R, X, C, tap, phase), Branch.a_Bus; bus母線の tab_parameter.dynamics (Gshunt, Bshunt)
    Returns or changes戻り値・変更する値
    cm_Y (n_bus×n_bus complex [pu], rows and columns in the order of a_Bus)（n_bus×n_bus の複素数 [pu]。行と列は a_Bus の順に並びます）

  5. PF-05 PowerNetwork → SolverPF.solve

    What it does処理内容
    • calculate_powerflow measures the time of this call (tic, toc): r_elapsed of the result, the solver alone
    • private/power_equation builds the residual, the Jacobian and the gradient direction from cm_Y and tab_PFcondition at every call
    • Initial voltages (local initial_voltage): the kept solution when WarmStart = true and its bus tags equal the row names of tab_PFcondition (same order); otherwise the flat start
    • Local run_method: a non-slack bus without branches (a zero row of cm_Y) gives flag −2 before any method (dynamic included) runs, as its voltage is not determined; otherwise PF-06 or PF-07
    • Keeps cv_V and its bus tags as the warm start solution when flag == 1
    • calculate_powerflow はこの呼び出しの時間を測ります（tic、toc）。結果の r_elapsed は、ソルバーだけの時間です。
    • private/power_equation が、cm_Y と tab_PFcondition から残差、ヤコビ行列、勾配の方向を呼び出しのたびに作ります。
    • 初期電圧は内部関数 initial_voltage で決めます。WarmStart = true で、保持している解の母線タグが tab_PFcondition の行名と（並び順も含めて）同じなら、その解を使います。そうでなければフラットスタートにします。
    • 内部関数 run_method は、ブランチが 1 本もつながっていない slack 以外の母線（cm_Y の行がすべて 0）があると、電圧が決まらないので、計算方法（dynamic も含む）を実行せずに flag −2 を返します。それ以外は PF-06 か PF-07 を実行します。
    • flag == 1 で収束したら、cv_V とその母線タグを次のウォームスタート用に保持します。

  6. PF-06 SolverPF → MethodNewtonRaphson / MethodGradient / MethodLevenbergMarquardt / MethodFsolve

    What it does処理内容
    • private/power_equation: residual F(x) and sparse Jacobian of the power equations; x = real and imaginary parts of the bus voltages
    • Two residuals per bus: slack (angle, |V|), PV (P, |V|), PQ (P, Q)
    • Jacobian: J_V + J_I*Y
    • Starts from the initial voltages of PF-05 (warm or flat start)
    • run_method of SolverPF.solve creates the Method object from the settings (NaN → the method default) and maps its results to cv_Vbus, flag, output, cm_Vhistory, rv_step
    • Every Method class inherits MethodBase and returns flag and output itself; converged when the largest |F| is at most Tolerance
    • newton: MethodNewtonRaphson with Fcn = F, Jac = Jacobian; a singular Jacobian (island without a slack bus) gives minimum norm steps (lsqminnorm); a step at the rounding level of x while |F| > Tolerance gives flag −2
    • gradient: MethodGradient with the direction [ΔP; ΔQ/V] of power_equation; polar coordinates; slack angle and voltage and PV voltages fixed at their set values; θ += α·ΔP (non-slack), V += α·ΔQ/V (PQ); stops when the largest |ΔP|, |ΔQ| is at most Tolerance
    • levenberg-marquardt: MethodLevenbergMarquardt; (JᵀJ + μI) dx = −JᵀF; μ ÷ 3 after a step that reduces |F|, μ × 4 and a retry otherwise; stops when the largest |F| is at most Tolerance
    • fsolve: tools.require_toolbox("optim", ...), then fsolve with SpecifyObjectiveGradient (MethodFsolve); flag 1 when exitflag > 0 and the largest |F| is at most Tolerance, 0 for exitflag 0, −2 otherwise
    • Every iterate is recorded (gradient: every iterate up to 1000, then every 1000th and the last)
    • private/power_equation は、電力方程式の残差 F(x) と疎なヤコビ行列を返します。x は母線電圧の実部と虚部を並べたものです。
    • 残差は母線ごとに 2 つです。slack では角度と |V|、PV では P と |V|、PQ では P と Q を使います。
    • ヤコビ行列は J_V + J_I*Y で求めます。
    • 初期値には PF-05 の初期電圧（ウォームスタートかフラットスタート）を使います。
    • SolverPF.solve の内部関数 run_method が、設定から Method オブジェクトを作り（NaN は計算方法の既定値の意味）、その結果を cv_Vbus、flag、output、cm_Vhistory、rv_step に直します。
    • Method クラスはどれも MethodBase を継承し、flag と output を自分で作ります。|F| の最大値が Tolerance 以下になれば収束です。
    • newton は、Fcn に F、Jac にヤコビ行列を渡した MethodNewtonRaphson です。slack 母線のない島があってヤコビ行列が特異になるときは、最小ノルムのステップ（lsqminnorm）を使います。|F| が Tolerance を上回ったままステップが x の丸め誤差ほどに小さくなると、flag −2 で終わります。
    • gradient は、power_equation から得た方向 [ΔP; ΔQ/V] を使う MethodGradient です。極座標で計算し、slack の角度と電圧、PV の電圧は指定値のままにします。更新は θ += α·ΔP（slack 以外）と V += α·ΔQ/V（PQ）です。|ΔP| と |ΔQ| の最大値が Tolerance 以下になると止まります。
    • levenberg-marquardt は MethodLevenbergMarquardt で、(JᵀJ + μI) dx = −JᵀF を解いて進みます。|F| が減ったら μ を 3 で割り、減らなければ μ を 4 倍してやり直します。|F| の最大値が Tolerance 以下になると止まります。
    • fsolve は、tools.require_toolbox("optim", ...) で確認したあと、SpecifyObjectiveGradient を指定した fsolve を実行します（MethodFsolve）。exitflag > 0 で |F| の最大値が Tolerance 以下なら flag 1、exitflag が 0 なら flag 0、それ以外は flag −2 です。
    • 各反復の値を記録します。gradient では 1000 回目までは毎回、その後は 1000 回ごとと最後の値を記録します。
    What it reads読み取る情報
    cm_Y, tab_PFcondition, sct_options (Tolerance, MaxIteration, Display, NewtonStepSize, GradientStepSize, FsolveMaxFunctionEvaluations, FsolveUseParallel)
    Returns or changes戻り値・変更する値
    cv_Vbus (n_bus×1 complex [pu])（n_bus×1 の複素数 [pu]）, flag (1 converged, 0 MaxIteration reached, −1 stopped by PlotFcn, −2 diverged or no solution)（1 収束、0 反復回数の上限、−1 PlotFcn による停止、−2 発散または解なし）, output (iterations, algorithm, residual, message; fsolve: also exitflag)（iterations, algorithm, residual, message。fsolve: exitflag も）, cm_Vhistory (n_bus×n_step), rv_step

  7. PF-07 SolverPF → MethodDynamic → ode15s

    What it does処理内容
    • Integrates angle, its rate, |V| and its rate of every bus (4·n_bus states), driven by the P and Q mismatch
    • Mass matrix and Jacobian pattern specified
    • Slack bus fixed; PV bus keeps |V| = V
    • Initial voltages: those of PF-05 (columns Varg0, V0 added to the PFcondition table it receives), slack and PV values at their settings
    • ODE tolerances: AbsTol = min(Tolerance, 1e-5), RelTol = min(100·Tolerance, 1e-4)
    • Already converged at the start (e.g. a warm start): returns at once with flag 1
    • Stops (event functions or the end of the interval [0, 1e4]): convergence (largest |ΔP| non-slack, |ΔQ| PQ at most Tolerance) → flag 1; voltage collapse (a PQ bus below 0.01 pu), angle instability (|angle| ≥ 10π) or integration failure → flag −2; virtual time 1e4 (safety limit) → flag 0
    • Last point = solution
    • 各母線の角度と |V|、およびそれぞれの変化率（合わせて 4·n_bus 個の状態）を積分します。動きを生むのは P と Q の不平衡量です。
    • 質量行列と、ヤコビ行列の非ゼロパターンを指定します。
    • slack 母線は動かしません。PV 母線は |V| を V に保ちます。
    • 初期電圧には PF-05 の初期電圧を使います。受け取った PFcondition の table に、列 Varg0 と V0 として加えます。slack と PV で固定する値は指定値です。
    • ODE の許容誤差は AbsTol = min(Tolerance, 1e-5)、RelTol = min(100·Tolerance, 1e-4) です。
    • ウォームスタートなどで最初から収束しているときは、すぐに flag 1 で終わります。
    • 積分はイベント関数で止まるか、区間 [0, 1e4] の終わりで止まります。slack 以外の |ΔP| と PQ の |ΔQ| の最大値が Tolerance 以下になれば収束で、flag 1 です。電圧崩壊（PQ 母線が 0.01 pu 未満）、角度の不安定（|角度| ≥ 10π）、積分の失敗では flag −2 です。安全のための上限である仮想時間 1e4 に達したときは flag 0 です。
    • 最後の点を解とします。
    What it reads読み取る情報
    cm_Y, tab_PFcondition, sct_options.Tolerance → properties Y, PFcondition, Tolerance of MethodDynamic; Mass = 0, Damper = 1, foh_PQ = 0 are its class defaultsMethodDynamic のプロパティ Y、PFcondition、Tolerance に渡します。Mass = 0、Damper = 1、foh_PQ = 0 はクラスの既定値のままです。
    Returns or changes戻り値・変更する値
    cv_Vbus (n_bus×1), flag (1 / 0 / −2)（1 / 0 / −2）, output (iterations = number of ODE steps, algorithm, residual, message)（iterations = ODE のステップ数、algorithm、residual、message）, cm_Vhistory (n_bus×n_t), rv_step = virtual times仮想時刻

5. Side effects on the model and caches5. モデルへの副作用とキャッシュ

  • Nothing is written to the network. A slack bus that get_pf_condition selects (PF-02) is the slack bus of this calculation only: l_isSlack stays false, and the snapshot of the ResultPF records it as the slack bus
  • net.solver_PF: no settings; sct_options is built for each call
  • net.solver_PF keeps only the last converged solution and its bus tags (private cv_Vwarm, sv_warmBus):
    • used only with WarmStart = true and the same bus tags in the same order
    • a renamed, added, removed or reordered bus → flat start; a branch or parameter edit keeps it (it changes only the start point)
    • net.reset_solver() replaces the solver and discards it
  • No cache: the conditions (PF-03), the admittance matrix (PF-04) and the power equations (PF-05) are built at every call, so the next call reflects every edit; no revision counter is read
  • No stale check; no use or build of the f_* handles; no read or change of sct_stale
  • Unused: the equilibrium, the dynamics parameters of components, the OPF parameters; the operation parameters only for tab_violation
  • A ResultPF holds the snapshot struct(net, false), tab_PFcondition and cm_Y, no network handle: a later edit of the network changes neither its values nor its exports
  • Without Format="GUILDAorigin", neither a ResultPF nor a snapshot is built
  • ネットワークには何も書き込みません。get_pf_condition が選んだ slack 母線（PF-02）はこの計算だけの slack 母線で、l_isSlack は false のままです。ResultPF のスナップショットには、計算の slack 母線として記録します。
  • net.solver_PF は設定を持ちません。sct_options は呼び出しのたびに作ります。
  • net.solver_PF が持つのは、最後に収束した解とその母線タグだけです（private の cv_Vwarm と sv_warmBus）。
    • 使うのは、WarmStart = true で、母線のタグが並び順も含めて同じときだけです。
    • 母線のタグの変更、母線の追加・削除・並べ替えがあるとフラットスタートになります。ブランチやパラメータの編集では解を保持します。変わるのは初期値だけです。
    • net.reset_solver() はソルバーを新しくするので、この解も消えます。
  • キャッシュは持ちません。潮流条件（PF-03）、アドミタンス行列（PF-04）、電力方程式（PF-05）は呼び出しのたびに作るので、次の呼び出しにはすべての編集が反映されます。版番号は読みません。
  • stale は確かめません。f_* ハンドルは使わず、作りもしません。sct_stale は読みも書きもしません。
  • 平衡点、機器の dynamics パラメータ、OPF パラメータは使いません。operation パラメータを使うのは tab_violation だけです。
  • ResultPF は、スナップショット struct(net, false)、tab_PFcondition、cm_Y を持ち、ネットワークのハンドルは持ちません。そのため、あとでネットワークを編集しても、結果の値も書き出す内容も変わりません。
  • Format="GUILDAorigin" でないときは、ResultPF もスナップショットも作りません。

7. Where to extend the feature7. 機能を拡張する箇所

  • Component
    • The power flow calls no model function
    • Reads only P and Q of tab_parameter.powerflow, filled by the Component constructor from the add_component options
    • A source that controls its voltage sets Q = NaN in its constructor, as component.generator.abstract does
    • Its state equilibrium comes later, from get_equilibrium in net.initialize()
  • Branch
    • Implement get_admittance_matrix (2×2 complex [pu], [V_from; V_to] to the currents into the branch)
    • Used for the bus admittance matrix (PF-04)
    • Also used for the branch flows of ResultPF (PF-10): Branch.struct stores it as cm_Y in the snapshot, so a new class needs nothing more
  • Bus type: a new type needs
    • a Type in Bus.get_pf_condition
    • its two residuals and their Jacobian rows in private/power_equation
    • its fixed and updated values in the gradient direction of power_equation and in MethodDynamic
  • Method: add
    • the name to the options of Solver in @GUILDA/config/DefaultPowerFlowCalculation.json and to the mustBeMember list of Solver in the arguments block of calculate_powerflow
    • a Method* class in _auxiliary/ (settings as public properties set by Name-Value in the constructor, then solve)
    • a case in run_method of SolverPF.solve that creates it and maps its results to [cv_Vbus, flag, output, cm_Vhistory, rv_step]
    • for PlotFcn: calls of f_iter(x, k, state) ("init", each iterate "iter", "done"; a true return ends with flag -1) and the map of its iterate x to the bus voltages in voltage of @SolverPF/private/live_residual.m
  • Live display: a new key in the options of PlotFcn (DefaultPowerFlowCalculation.json), in the key list given to tools.check_plotfcn by calculate_powerflow (mustBePlotFcn and solver_options), and its drawing in live_residual
  • Controllers: no part in the power flow
  • 機器
    • 潮流計算は、モデルの関数を呼び出しません。
    • 読むのは tab_parameter.powerflow の P と Q だけです。これらは Component のコンストラクタが add_component のオプションから設定します。
    • 電圧を制御する電源は、component.generator.abstract と同じように、コンストラクタで Q = NaN にしておきます。
    • 状態の平衡点は、あとで net.initialize() の中の get_equilibrium が決めます。
  • ブランチ
    • get_admittance_matrix を実装します。返すのは 2×2 の複素数行列 [pu] で、[V_from; V_to] からブランチへ流れ込む電流を求めるものです。
    • この行列は、母線アドミタンス行列（PF-04）の計算に使います。
    • ResultPF のブランチ潮流（PF-10）にも使います。Branch.struct がこの行列を cm_Y としてスナップショットに入れるので、新しいクラスでほかに加えるものはありません。
  • 母線の種類: 新しい種類を加えるには、次の箇所に手を入れます。
    • Bus.get_pf_condition の Type
    • private/power_equation の 2 つの残差と、それに対応するヤコビ行列の行
    • power_equation の勾配の方向と、MethodDynamic で固定する値と更新する値
  • 計算方法: 新しい方法を加えるには、次のものを用意します。
    • @GUILDA/config/DefaultPowerFlowCalculation.json の Solver の options と、calculate_powerflow の arguments ブロックにある Solver の mustBeMember の一覧に加える名前
    • _auxiliary/ に置く Method* クラス。設定はコンストラクタの Name-Value で public プロパティに渡し、そのあと solve を呼びます。
    • SolverPF.solve の run_method に加える分岐。そのクラスを作り、結果を [cv_Vbus, flag, output, cm_Vhistory, rv_step] に直します。
    • PlotFcn への対応。f_iter(x, k, state) を "init"、反復ごとの "iter"、"done" で呼び、true が返れば flag -1 で終えます。また、@SolverPF/private/live_residual.m の voltage に、反復値 x を母線電圧に直す処理を加えます。
  • ライブ表示: 新しいキーを加えるには、PlotFcn の options（DefaultPowerFlowCalculation.json）、calculate_powerflow が tools.check_plotfcn に渡すキーの一覧（mustBePlotFcn と solver_options）、live_residual の描画の 3 か所を変えます。
  • 制御器: 潮流計算には関わりません。
