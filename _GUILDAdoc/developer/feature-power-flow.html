Feature: Power Flow機能: 潮流計算

net.calculate_powerflow() solves the bus voltages from the power-flow settings of the buses and components. SolverPF builds the equations and runs fsolve or ode15s; the values are returned in a ResultPF and are not written to the model.

net.calculate_powerflow() は、母線と機器の潮流設定から母線電圧を求めます。SolverPF が方程式を組み立てて fsolve または ode15s を実行し、結果は ResultPF として返されます。モデルには書き込まれません。

1. Purpose and entry point1. 目的と入口

The power flow computes the steady-state voltage phasor of every bus. The slack bus fixes V and Varg, a PV bus fixes P and V, and a PQ bus fixes P and Q. P and Q of a bus are the sums of tab_parameter.powerflow of its components; a bus whose summed Q is NaN (a generator leaves Q = NaN) is a PV bus.

潮流計算は、すべての母線の定常電圧フェーザを求めます。slack 母線は V と Varg、PV 母線は P と V、PQ 母線は P と Q を固定します。母線の P・Q は、その母線にある機器の tab_parameter.powerflow の和です。Q の和が NaN になる母線（発電機は Q = NaN を持ちます）は PV 母線になります。

Nothing is stored back on the model objects. net.initialize() (Method "powerflow") calls calculate_powerflow and writes result.tab_bus to the buses with Bus.set_equilibrium, which sets Bus.c_Vequilibrium and distributes P and Q to Component.set_equilibrium (see Initialization).

5. Side effects and caches5. 副作用とキャッシュ

  • The only write to the network is PF-03. The slack bus it sets stays set after the call; net.initialize() releases it again only when its own power flow fails.
  • net.solver_PF is only read; s_options is a copy.
  • The power flow does not call check_edit, does not use or build the f_* handles, and does not read or reset s_edit or tab_editLog. It does not use the equilibrium, the dynamics parameters of components, or the operation and OPF parameters.
  • There is no power-flow cache: every call reads the current parameters, so a later edit is reflected in the next call. A ResultPF created earlier keeps its values, but its a_PowerNetwork is the live network, so a JSON export after an edit reads the edited bus types and admittance matrix.
  • ネットワークへの書き込みは PF-03 だけです。設定された slack 母線は呼び出し後も残ります。net.initialize() は、自身の潮流計算が失敗したときだけそれを解除します。
  • net.solver_PF は読むだけです。s_options はコピーです。
  • 潮流計算は check_edit を呼ばず、f_* ハンドルを使うことも作ることもせず、s_edit や tab_editLog を読むこともリセットすることもしません。平衡点、機器の dynamics パラメータ、operation・OPF パラメータは使いません。
  • 潮流計算のキャッシュはありません。呼び出しのたびに現在のパラメータを読むので、後の編集は次の呼び出しに反映されます。以前に作られた ResultPF は値を保ちますが、その a_PowerNetwork は現在のネットワークなので、編集後の JSON 書き出しは編集後の母線の種類とアドミタンス行列を読みます。

7. Extension points7. 拡張ポイント

  • Component: the power flow calls no model function. It reads only P and Q of tab_parameter.powerflow, which the Component constructor fills from the add_component options. A source that controls its voltage sets Q = NaN in its constructor, as component.generator.abstract does. Its state equilibrium comes later from get_equilibrium in net.initialize().
  • Branch: implement get_admittance_matrix (2×2 complex [pu], [V_from; V_to] to the currents into the branch). It is used for the bus admittance matrix (PF-05) and the branch flows (PF-09).
  • Bus type: a new type needs a Type in Bus.get_pf_set, a private/PFconst_* function returning [con, jacobi_V, jacobi_I] (2×1, 2×2, 2×2) and a case in solve_algebraic and solve_dynamic.
  • Method: add the name to the validators of SolverPF.Method and validate_options, a case in SolverPF.solve, and a method returning [cv_Vbus, flag, output, cm_Vhistory, rv_step].
  • Controllers take no part in the power flow.
  • 機器: 潮流計算はモデル関数を呼びません。読むのは tab_parameter.powerflow の P と Q だけで、これは Component のコンストラクタが add_component のオプションから設定します。電圧を制御する電源は、component.generator.abstract と同様にコンストラクタで Q = NaN にします。状態の平衡点は、後で net.initialize() の get_equilibrium で求まります。
  • ブランチ: get_admittance_matrix（2×2 の複素数 [pu]。[V_from; V_to] からブランチへ流れ込む電流への写像）を実装します。母線アドミタンス行列（PF-05）とブランチ潮流（PF-09）に使われます。
  • 母線の種類: 新しい種類には、Bus.get_pf_set の Type、[con, jacobi_V, jacobi_I]（2×1、2×2、2×2）を返す private/PFconst_* 関数、solve_algebraic と solve_dynamic の分岐が必要です。
  • 計算方法: SolverPF.Method と validate_options の検証に名前を加え、SolverPF.solve に分岐を、[cv_Vbus, flag, output, cm_Vhistory, rv_step] を返すメソッドを追加します。
  • 制御器は潮流計算に関与しません。
