Class Design

Which class owns which data, which class does which job, and how the classes refer to each other. Read this before you add a property or a method to a model class.

Design principles Per-class responsibilities Parent references Identity Solver settings Edit handling Variable order Optional analyses OPF customization Conventions

The class structure is stable on purpose: other developers build on it, so these rules decide where data and logic go inside the existing classes instead of introducing new ones. The rules apply to all code in GUILDA.

Design principles

  1. No data is held by two classes

    Each value has a single owner. Anything that can be derived from it is a Dependent property that reads the owner when it is accessed. Code that copies a value and keeps the copies in sync is a source of bugs; do not write it.

    Examples: PowerNetwork.cv_Vequilibrium / cv_Iequilibrium / rv_Xequilibrium (collected from the buses), Branch.cv_Vequilibrium / cv_Iequilibrium (from the end buses and its own admittance), Component.tab_parameter (assembled from the Parameter objects), and Component.rv_Xequilibrium_all (the component plus its controllers).

  2. Data and functions follow real-world roles

    A class holds what the physical element has and computes what the physical element determines. A branch holds its impedances and builds its own admittance matrix. A bus holds the algebraic variable, its voltage V. Components and controllers hold the differential equations and output equations.

  3. Same method name, same meaning on every layer

    A method with the same name means the same thing on every class and has the same shape of inputs and outputs. A higher layer aggregates the lower ones.

    • get_sys: on LocalController, the linearized model of the controller alone; on Component, the model of the component and its controllers; on Bus, the aggregate of its components; on PowerNetwork, the whole system. On every layer the input, state, and output names are unique, and states are never outputs. An output with the name of a state of its owner is labelled Y_ + name.
      • LocalController: inputs V, ucon; states xcon; outputs ycon.
      • Component: inputs the port (V for "V2I", I for "I2V"), umac, ucon; states xmac, xcon; outputs the other port, ymac, ycon. The signals from the component to its controllers are connected inside.
      • Bus: the same, aggregated over its components, with the bus port.
    • get_admittance_matrix: on Branch, its 2×2 matrix; on PowerNetwork, the matrix of the whole network.
    • get_variable_map: on Component and Bus, the rows of the network map that belong to it, in the same relative order (see Variable order).
    • build_opf_problem and set_opffcn: each class adds its own variables, cost, and constraints; PowerNetwork collects them.
  4. Edits only record; analyses check

    Editing a parameter or a mode only updates the value and records what became stale. Nothing is rebuilt on each edit. An analysis checks the flags when it starts (see Edit handling).

Observes

Parent references

Each child keeps a read-only reference to its parent: Bus.a_PowerNetwork, Branch.a_PowerNetwork, Component.a_Bus, LocalController.a_Component, GlobalController.PowerNetwork, and the parent of each Parameter. They follow these rules:

  1. Only the parent sets and clears it

    The reference is set by the parent's constructor or add_* method and cleared by its remove_* method, so a removed object no longer points to its old parent. No other code writes it.

  2. A child only reads its parent

    For the tag path, for edit notification, and for shared settings such as the frequency.

  3. A child never writes upward or sideways

    It does not write to its parent or to its siblings, and it never stores a copy of its parent's data.

Identity: tags, not indices

Tag (e.g. B001)

The permanent ID of an object. Use it in saved data and in event definitions.

Index (e.g. net.a_Bus{3})

Only the current position. It shifts after remove_*, so never store it.

An automatic tag takes the largest number in use plus one (buses B###, branches ###, components per bus). A number is never reused while a larger one exists, so a new tag never names an existing or earlier object. A global controller's tag is chosen by the user and must be unique.

Solver settings

Persistent defaults: net.solver_*

The solver objects hold the default settings of each analysis. A change made there stays, so repeated runs keep the last settings.

Run-time Name-Value options

Override the defaults for that call only. They do not change the stored defaults.

System data (line constants, power-flow specifications, limits) is not a solver setting: it is set beforehand on the model objects through properties and tab_parameter (see API Design, rule 2).

When an analysis starts:

  • Stale function handles are rebuilt automatically, for the affected components only.
  • If the equilibrium is stale, simulate, linearize, and get_sys stop with GUILDA:PowerNetwork:EquilibriumStale, which names the edits and says to run net.initialize() first (see API Design, rule 5).
  • The check is part of each solver's solve (solver_ODE, solver_LIN), so calling a solver directly checks it too.

Variable order

net.get_variable_map() is the single definition of the order of the model variables. Every analysis that lists variables uses it: the Jacobian blocks of a linearization, the Point option, and simulation results. Do not define another order.

BlockOrder
1. states xFor each bus, for each component: the component's states, then its local controllers' states (depth first: an AVR, then the PSS under it). Then the states of each global controller.
2. bus voltagesVre, Vim of each bus, interleaved per bus.
3. inputs uFor each bus, for each component: its inputs.

The Label column of the map equals the state and input names of get_sys, so find a variable by its label, not by its position. net.linearize(Point=x) linearizes at any state x given in this order, or at a time of a simulation result (Point={sim, t}).

Optional analyses: Hessians

An analysis that only some models support is a method on the base class with a per-class contract. get_hessian on Component, LocalController, and GlobalController works this way.

The class supports it

It defines static Hessian_dx (required), Hessian_I, and Hessian_Y with the arguments of Jacobi_*. Each returns n_eq × n_z × n_z with z = [x; V; I; u].

The class does not

The base method stops with GUILDA:<Layer>:HessianNotSupported, which names the class.

Each class supplies its own derivatives. No symbolic differentiation is used, so the Symbolic Math Toolbox is not required.

OPF customization

Each object holds its own OPF terms, set with obj.set_opffcn("Cost", @(v,p) ..., "Constraint", @(v,p) struct(...), "DefaultConstraint", false) and restored with obj.reset_opffcn(). v holds the object's optimization variables and p its parameters.

TermEffect
CostReplaces the default cost of the object. A load has no default cost.
ConstraintAdded to the default constraints. Each field name labels the constraint and its dual in result.lambda.Constraints.
DefaultConstraintfalseRemoves the object's default constraints (e.g. the bounds of a component). The bus power balance always stays.
network levelnet.set_opffcn takes terms over several objects; its v reaches each object's variables by tag (e.g. v.Component.(tag).P).

DC OPF uses |V| = 1 and the MATPOWER branch susceptance b = 1/(X·tap).

Conventions

TopicConvention
Per-unit system Voltages, currents, powers (P, Q), and branch constants (R, X, C) are per unit on the system base (the system baseMVA on PowerNetwork). Component dynamics parameters are also per unit on the system base; Component.baseMVA is the machine rating, used only to share reactive power. No class converts physical units: Bus.baseKV is stored but not used in any calculation.
Angles Radians: bus angle Varg / Varg0, branch phase, rotor angle. Degrees appear only in labels of the network diagram.
Time and frequency Time t in seconds. The nominal frequency Hz is a system base value on PowerNetwork, and models read it through r_Hz. The argument omega0 passed to models is this nominal frequency in Hz, and models multiply by 2π themselves (e.g. ddelta = 2*pi*omega0*omega); the rotor speed omega is a per-unit deviation.
Current direction A component's current I is the current it injects into its bus, so P + jQ = V·conj(I) is positive for generation; a load has negative injection (e.g. impedance load I = -V/Z). The network equation is I_bus = Y·V, where I_bus is the sum of the injections at each bus.
Complex vs [real; imag] Complex numbers: stored equilibria and power-flow results (c_*, cv_*), admittance matrices, and the inputs of get_equilibrium(V, I, P, Q).
Real 2×1 vectors [re; im]: V and I passed to fcn_* and Jacobi_*, and the state vector of the simulator. Inside a model, convert with [1, 1j]*V.
fcn_I returns a complex scalar. The input/output ports of a linearized component are set by GUILDA.config("Model","port_vw") (default [Vre,Vim] to [-Iim,Ire]).
