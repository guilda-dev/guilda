Feature: Model Building機能: モデル構築

A network is a tree of handle objects. The parent's add_* method creates or attaches each child and sets the child's reference back to it; every change is reported up to the network, which records what became stale.

ネットワークはハンドルオブジェクトの木。親の add_* メソッドが子を作成または接続し、子から親への参照を設定。すべての変更はネットワークまで伝わり、古くなった対象をネットワークが記録。

1. Purpose and entry point1. 目的と入口

Model building produces a PowerNetwork with its buses, branches, components, local controllers and global controllers, and the power-flow, operation, OPF, dynamics and diagram parameters of each. Three ways:

モデル構築の成果物は PowerNetwork と、その母線・ブランチ・機器・ローカル制御器・グローバル制御器、およびそれぞれの潮流・operation・OPF・dynamics・図のパラメータ。方法は 3 通り:

  • By hand
  • By a shipped network class (network.IEEE9bus() and the other classes in _GUILDAobject/+network)
  • By import (see Data Import and Export)
  • 手で組み立てる
  • 同梱のネットワーククラス（network.IEEE9bus() など _GUILDAobject/+network のクラス）
  • 読み込み（データの入出力参照）
net = PowerNetwork("ThreeBus");
b1  = net.add_bus(V=1.0, Varg=0);
b2  = net.add_bus();

gen = b1.add_component("gen-1axis", P=0.5);
b2.add_component("load-power", P=-0.5, Q=-0.1);
gen.add_local_controller(controller.avr.AVR_ST1("avr1"), controller.pss.PSS1("pss1"));

2. Call sequence2. 呼び出し順

3. Steps3. 処理ステップ

  1. MB-01 caller呼び出し側 → PowerNetwork (constructor)（コンストラクタ）

    Does処理
    • Set the tag
    • Create para_base (Parameter(obj,"base") with Hz and baseMVA)
    • Call reset_solver: creates SolverPF, SolverOPF, SolverCPF, SolverODE and SolverLIN
    • Called implicitly by a network class such as network.IEEE9bus, so its tag is "PowerNetwork"
    • タグを設定
    • para_base（Hz と baseMVA を持つ Parameter(obj,"base")）を作成
    • reset_solver を呼び出し、SolverPF・SolverOPF・SolverCPF・SolverODE・SolverLIN を作成
    • network.IEEE9bus などのネットワーククラスが暗黙に呼び出すため、タグは "PowerNetwork"
    Reads読み取り
    tag, GUILDA.config("Model","Hz"), GUILDA.config of each solver（各ソルバー）
    Returns / changes戻り値・変更
    net with empty a_Bus, a_Branch, a_GlobalController (0×1 cell); s_edit = unset / unset / false（a_Bus・a_Branch・a_GlobalController は空の 0×1 cell。s_edit = 未設定 / 未設定 / false）

  2. MB-02 caller呼び出し側 → PowerNetwork.add_bus → Bus

    Does処理
    • Tag: Tag + three digits (tools.next_tag_number: largest number in use + 1), or FullTag when given
    • Ignore the option baseMVA and remove it from the options (v3_bus_baseMVA)
    • Bus constructor (access: PowerNetwork, Bus): set a_PowerNetwork first, then the tag (a tag used by another bus gets a suffix)
    • Create four Parameter objects
    • Append the bus to a_Bus
    • タグ: Tag + 3 桁（tools.next_tag_number: 使用中の最大番号 + 1）、FullTag があればそれを使用
    • オプション baseMVA は無視し、オプションから削除（v3_bus_baseMVA）
    • Bus のコンストラクタ（アクセス: PowerNetwork、Bus）: 先に a_PowerNetwork、次にタグを設定（他の母線が使用中のタグには接尾辞を付与）
    • 4 つの Parameter を作成
    • 母線を a_Bus に追加
    Reads読み取り
    options (defaults: V 1, Varg 0, V0 1, Varg0 0, Gshunt 0, Bshunt 0, Vmin 0.5, Vmax 1.5, baseKV 230, Xaxis/Yaxis NaN, Marker "s"), tags of a_Busオプション（既定値: V 1, Varg 0, V0 1, Varg0 0, Gshunt 0, Bshunt 0, Vmin 0.5, Vmax 1.5, baseKV 230, Xaxis/Yaxis NaN, Marker "s"）、a_Bus のタグ
    Returns / changes戻り値・変更
    bus; para_dynamics (Gshunt, Bshunt), para_operation (baseKV, Vmin, Vmax), para_powerflow (V, Varg, V0, Varg0), para_graph (Xaxis, Yaxis, Marker); edit編集 "Topology"

  3. MB-03 caller呼び出し側 → PowerNetwork.add_branch → Branch

    Does処理
    • Before any change: check Type against the generated key list, resolve from_to (indices of a_Bus or tags), reject equal ends and R = X = 0
    • Create the class of the key (mkInst)
    • Branch constructor: set the tag header + three digits, assert real R, X, C, create three Parameter objects
    • Call set_bus({from; to}) and set_network(net)
    • Append to a_Branch
    • 変更前に検査: Type を生成済みのキー一覧で検査、from_to（a_Bus の番号またはタグ）を解決、両端が同じもの・R = X = 0 を拒否
    • キーのクラスを作成（mkInst）
    • Branch のコンストラクタ: タグ header + 3 桁を設定、R・X・C が実数であることを assert、3 つの Parameter を作成
    • set_bus({from; to}) と set_network(net) を呼び出し
    • a_Branch に追加
    Reads読み取り
    options (defaults: R 0, X 1, C 0, Tap 1, Phase 0, Smax/Imax/Pmax/Qmax Inf, Vargmax π/2, Marker "-"), a_Bus, tags of a_Branchオプション（既定値: R 0, X 1, C 0, Tap 1, Phase 0, Smax/Imax/Pmax/Qmax Inf, Vargmax π/2, Marker "-"）、a_Bus、a_Branch のタグ
    Returns / changes戻り値・変更
    br; para_dynamics (R, X, C, tap, phase), para_operation (Smax, Imax, Pmax, Qmax, Vargmax), para_graph (MidXaxis, MidYaxis, Marker); br.a_Bus (2×1 cell), br.a_PowerNetwork; edit編集 "Topology"

  4. MB-04 caller呼び出し側 → Bus.add_component → Component

    Does処理
    • Tag: class prefix + next number among the components of this bus + bus tag (e.g. SG1B001)
    • Subclass constructor calls Component(str_tag, opt): creates five Parameter objects; replaces a NaN cost HP / fP by 0 for a load, 1 otherwise
    • Subclass adds sv_para to para_dynamics
    • Generator: force Q = NaN
    • Call comp.set_bus(bus): marks the handles of the component and its controllers stale (mark_odefcn)
    • Append to a_Component
    • タグ: クラスの接頭辞 + この母線の機器の中での次の番号 + 母線のタグ（例: SG1B001）
    • サブクラスのコンストラクタが Component(str_tag, opt) を呼び出し: 5 つの Parameter を作成、NaN のコスト HP / fP を負荷なら 0、それ以外は 1 に置換
    • サブクラスが sv_para を para_dynamics に追加
    • 発電機: Q = NaN に固定
    • comp.set_bus(bus) を呼び出し: 機器とその制御器のハンドルを古い状態に（mark_odefcn）
    • a_Component に追加
    Reads読み取り
    options (P 0, Q 0, baseMVA 100, Pmin/Qmin −Inf, Pmax/Qmax Inf, OPF P0/Q0 0, HP/fP NaN, HQ/fQ 0, Marker "o"), parameter, class parameter.csvオプション（P 0, Q 0, baseMVA 100, Pmin/Qmin −Inf, Pmax/Qmax Inf, OPF P0/Q0 0, HP/fP NaN, HQ/fQ 0, Marker "o"）、parameter、クラスの parameter.csv
    Returns / changes戻り値・変更
    comp; para_operation (baseMVA, Pmin, Pmax, Qmin, Qmax), para_powerflow (P, Q), para_OPF (P0, Q0, HP, HQ, fP, fQ, startup, shutdown), para_graph, para_dynamics; comp.a_Bus; s_edit.str_odefcn = unset; edit編集 "Topology"

  5. MB-05 caller呼び出し側 → Component.add_local_controller → LocalController.set_parent

    Does処理
    • Check every controller before any change:
      • key "avr", "pss", "local" or "governor"
      • not attached elsewhere
      • outputs sv_y match inputs of the target (the component, or the AVR for a PSS)
      • the AVR or "local" controller and the governor drive different inputs (GUILDA:Component:ControllerOutputOverlap)
    • AVR or "local" controller: becomes a_LocalController{1}; an existing one is detached with a warning, and its PSS moves to the new AVR unless a PSS is given
    • PSS: goes under the AVR
    • Governor: placed after the AVR in a_LocalController; an existing governor is detached with a warning
    • set_parent: set a_Component, resolve the observed signals (resolve_observe: expand "Xall" / "Yall", set iv_obsY / iv_obsX), call mark_odefcn
    • 変更前にすべての制御器を検査:
      • キーが "avr"・"pss"・"local"・"governor" のいずれか
      • 他に未接続
      • 出力 sv_y が接続先（機器、PSS なら AVR）の入力と一致
      • AVR または "local" の制御器とガバナが異なる入力を駆動（GUILDA:Component:ControllerOutputOverlap）
    • AVR・"local" の制御器: a_LocalController{1} に配置。既存のものは警告付きで切り離し、PSS の指定がなければその PSS は新しい AVR へ移動
    • PSS: AVR の下に配置
    • ガバナ: a_LocalController で AVR の後ろに配置。既存のガバナは警告付きで切り離し
    • set_parent: a_Component を設定、観測する信号を解決（resolve_observe: "Xall" / "Yall" を展開、iv_obsY / iv_obsX を設定）、mark_odefcn を呼び出し
    Reads読み取り
    con.key, con.sv_y, con.sv_u, con.a_Component, comp.sv_u, comp.sv_x, comp.sv_y
    Returns / changes戻り値・変更
    comp.a_LocalController, avr.a_LocalController, con.a_Component, comp.l_hasController; edit編集 "Topology" per controller（制御器ごと）

  6. MB-06 caller呼び出し側 → GlobalController (subclass constructor)（サブクラスのコンストラクタ）

    Does処理
    • Resolve each controlled unit (component object or tag) among the components of net.a_Bus
    • Network only read: a_PowerNetwork stays empty until MB-07
    • 制御対象（機器のオブジェクトまたはタグ）を net.a_Bus の機器から解決
    • ネットワークは読み取りのみ: a_PowerNetwork は MB-07 まで空
    Reads読み取り
    net.a_Bus{:}.a_Component
    Returns / changes戻り値・変更
    gc; gc.controlledUnits (cell of components)（機器の cell）, para_dynamics

  7. MB-07 caller呼び出し側 → PowerNetwork.add_global_controller → GlobalController.set_parent

    Does処理
    • Check:
      • the tag is unused
      • every unit belongs to this network (handle comparison through unit.a_Bus.a_PowerNetwork)
      • sv_u are states and sv_y inputs of every unit
    • Append the controller
    • set_parent(net): set a_PowerNetwork, call mark_odefcn
    • 検査:
      • タグが未使用
      • すべての制御対象がこのネットワークに所属（unit.a_Bus.a_PowerNetwork によるハンドル比較）
      • sv_u が各対象の状態、sv_y が入力
    • 制御器を追加
    • set_parent(net): a_PowerNetwork を設定、mark_odefcn を呼び出し
    Reads読み取り
    gc.str_tag, gc.controlledUnits, gc.sv_u, gc.sv_y, unit対象の sv_x, sv_u
    Returns / changes戻り値・変更
    net.a_GlobalController, gc.a_PowerNetwork; edit編集 "Topology"

  8. MB-08 caller呼び出し側 → Bus.set.l_isSlack

    Does処理
    • No-op when the value is unchanged
    • true: needs a component
    • Print the component that takes the remaining power (the first with Q = NaN, else the first)
    • Warn when no component has Q = NaN
    • Log a "Slack" edit
    • PowerNetwork.handle_edit: set l_isSlack = false on every other bus, so at most one slack bus
    • 値が不変なら何もしない
    • true: 機器が必要
    • 残りの電力を受け持つ機器（Q = NaN の最初の機器、なければ最初の機器）を表示
    • Q = NaN の機器がなければ警告
    • "Slack" の編集を記録
    • PowerNetwork.handle_edit: 他のすべての母線を l_isSlack = false に設定。slack 母線は高々 1 つ
    Reads読み取り
    a_Component, component機器の para_powerflow.Q, other buses他の母線の l_isSlack
    Returns / changes戻り値・変更
    l_isSlack of this and other buses（この母線と他の母線）; edit編集 "Slack"

  9. MB-09 caller呼び出し側 → Parameter (set method and listeners)（set メソッドとリスナー）

    Does処理
    • obj.tab_parameter = tab: assign para_<group>.<name> column by column
    • obj.para_*.Name = v: assign one value
    • Set method of the dynamic property (Parameter.add_entry → attach_callbacks): check the class
    • PreSet listener: store the old value
    • PostSet listener: compare with isequaln; when the value changed, call log_edit and the CallbackChanged of the container
    • obj.tab_parameter = tab: para_<group>.<name> に列ごとに代入
    • obj.para_*.Name = v: 1 つの値を代入
    • 動的プロパティの set メソッド（Parameter.add_entry → attach_callbacks）: クラスを検査
    • PreSet リスナー: 元の値を保存
    • PostSet リスナー: isequaln で比較。値が変わっていれば log_edit とコンテナの CallbackChanged を呼び出し
    Reads読み取り
    new value, class given to add_entry, old value新しい値、add_entry で指定したクラス、元の値
    Returns / changes戻り値・変更
    the parameter value; editパラメータの値、編集 "Parameter(<group>)" with log "edit <name>" and before/after values（ログ "edit <name>" と変更前後の値）

  10. MB-10 any layer各層 → LayerPackage.log_edit → parent親の log_edit → PowerNetwork.handle_edit

    Does処理
    • Build one log row (time, tag path, log, tag, before, after)
    • Decide with LayerPackage.edit_effect what the edit makes stale
    • Dynamics parameter: mark its owner's handles "editted"
    • Layer below the network: set its own str_flag = "editted", pass the row to its parent
    • Network, once initialized (str_flag ~= "unset"):
      • set str_flag = "editted"
      • raise l_staleEquilibrium for dynamics, base (baseMVA), powerflow, Topology and Slack edits
      • append the row to tab_editLog
    • Network: always call handle_edit
    • Network Hz edit: mark the handles of every layer
    • ログの 1 行（時刻、タグのパス、ログ、タグ、変更前、変更後）を作成
    • LayerPackage.edit_effect で古くなる対象を決定
    • dynamics パラメータ: 所有者のハンドルを "editted" に
    • ネットワークより下の層: 自身の str_flag = "editted" を設定し、行を親に渡す
    • ネットワーク（初期化済み、str_flag ~= "unset" の場合）:
      • str_flag = "editted" に設定
      • dynamics・base（baseMVA）・powerflow・Topology・Slack の編集で l_staleEquilibrium を立てる
      • 行を tab_editLog に追加
    • ネットワーク: handle_edit を常に呼び出し
    • ネットワークの Hz の編集: すべての層のハンドルを古い状態に
    Reads読み取り
    log row, parent chain, network s_editログの行、parent の連鎖、ネットワークの s_edit
    Returns / changes戻り値・変更
    s_edit.str_flag, s_edit.str_odefcn, s_edit.l_staleEquilibrium, net.tab_editLog

  11. MB-11 caller呼び出し側 → network.IEEE9bus (constructor)（コンストラクタ）

    Does処理

    • Call initialize
    • 同梱のネットワーク: +network/@<Name>/ にある PowerNetwork のサブクラス
    • コンストラクタ: クラスファイルの隣の CSV フォルダから PowerNetwork.import_csv(dir, Network=obj, Initialize=false) で自身を構築（MB-02〜MB-04、MB-08 を実行）
    • CSV 形式が持たないものを追加（IEEE9bus: LocalController=false でなければ、controller/avr と controller/pss から発電機ごとに AVR_ST1 と PSS1）
    • initialize を呼び出し
    Reads読み取り

    Returns / changes戻り値・変更

  12. MB-12 caller呼び出し側 → PowerNetwork.remove_bus / remove_branch / remove_global_controller

    Does処理

    • Bus not removable while a global controller controls one of its components
    • Bus not removable while branches end at it, unless RemoveBranches=true (then remove_branch runs first)
    • Take the removed objects out of the cell and detach them: bus.set_network([]), br.set_bus(cell(0,1)) and br.set_network([]), gc.set_parent([])
    • A removed bus keeps its components
    • 先にタグを検査
    • グローバル制御器が母線の機器を制御している間は母線の削除不可
    • ブランチがその母線につながっている間は母線の削除不可（RemoveBranches=true なら先に remove_branch を実行）
    • 削除したオブジェクトを cell から外して切り離し: bus.set_network([])、br.set_bus(cell(0,1)) と br.set_network([])、gc.set_parent([])

    Reads読み取り

    Returns / changes戻り値・変更

  13. MB-13 caller呼び出し側 → Bus.remove_component / Bus.replace_component

    Does処理
    • Refuse a component that a global controller controls (private/controlling_gcon, handle comparison)
    • remove_component: take it out, call comp.set_bus([])
    • replace_component:
      • create the new type with the powerflow, operation, graph and OPF settings and the number of the old one, and attach it
      • give it a placeholder equilibrium (the bus voltage and the old current)
      • Controllers="keep": move the local controllers, after checking that the new component has their ports
      • "drop": leave them on the old component with a warning
      • detach the old component
    • グローバル制御器が制御している機器は拒否（private/controlling_gcon、ハンドル比較）
    • remove_component: 機器を外して comp.set_bus([]) を呼び出し
    • replace_component:
      • 元の機器の powerflow・operation・graph・OPF の設定と番号で新しい種類を作成して接続
      • 仮の平衡点（母線電圧と元の電流）を付与
      • Controllers="keep": ローカル制御器を移動（新しい機器にそのポートがあることを先に検査）
      • "drop": 警告付きで元の機器に残す
      • 元の機器を切り離し
    Reads読み取り
    a_Component, net.a_GlobalController, old component parameters and controllers元の機器のパラメータと制御器
    Returns / changes戻り値・変更
    bus.a_Component; new component (replace)新しい機器（replace）; edit編集 "Topology"

    Does処理

    • Detach the removed controllers (set_parent([])); they can be attached again
    • タグで最上位の制御器（RemoveNested=true のときだけその PSS も）または PSS だけを削除
    • 削除した制御器を切り離し（set_parent([])）。再接続可能
    Reads読み取り
    a_LocalController, tagsタグ
    Returns / changes戻り値・変更

  15. MB-15 caller呼び出し側 → LayerPackage.set.str_tag

    Does処理

    • Log the rename
    • Tags of child layers do not follow
    • 兄弟（parent.children）が使用中のタグ: 002 から始まる 3 桁の接尾辞を付与し、Info を表示
    • 名前の変更を記録

5. Side effects and caches5. 副作用とキャッシュ

  • Before the first initialize: the network's str_flag is "unset", so no row is added to tab_editLog and the equilibrium flag is not raised. handle_edit still keeps a single slack bus
  • After initialize: an edit marked stale in Class Design: edit handling sets str_flag = "editted" and l_staleEquilibrium = true; simulate, linearize and get_sys then stop until initialize runs again. Operation, OPF, graph and tag edits: logged, equilibrium stays valid
  • Handle cache: constructors do not build f_* (str_odefcn = "unset"). Attaching (Component.set_bus, LocalController.set_parent, GlobalController.set_parent) and a dynamics or network Hz edit turn "updated" into "editted". check_edit at the start of the next analysis rebuilds them (see Initialization)
  • Detached objects: a removed object has no parent, so its later edits stop at it (log_edit returns) and do not reach the network
  • Copies: no deep-copy method; b = a copies a handle. For an independent network, save and load through a MAT file or CSV export. PowerNetwork.loadobj attaches the parameter listeners again after a MAT load (warning GUILDA:PowerNetwork:IncompleteLoad when a layer is still loading)
  • 最初の initialize の前: ネットワークの str_flag は "unset" のため、tab_editLog への行の追加なし、平衡点のフラグも立たない。handle_edit は slack 母線を 1 つに維持
  • initialize の後: クラス設計: 編集の扱いで古くなるとされる編集は str_flag = "editted"、l_staleEquilibrium = true に設定し、simulate・linearize・get_sys は再び initialize を実行するまで停止。operation・OPF・graph・タグの編集: 記録のみ、平衡点は有効なまま
  • ハンドルキャッシュ: コンストラクタは f_* を作らない（str_odefcn = "unset"）。接続（Component.set_bus、LocalController.set_parent、GlobalController.set_parent）と、dynamics またはネットワークの Hz の編集で "updated" を "editted" に変更。次の解析の最初の check_edit が再構築（初期化参照）
  • 切り離されたオブジェクト: 削除されたオブジェクトには親がないため、その後の編集はそこで停止し（log_edit が戻る）、ネットワークには届かない
  • コピー: ディープコピーのメソッドはなし。b = a はハンドルのコピー。独立したネットワークには MAT ファイルへの保存と読み込み、または CSV への書き出しを使用。PowerNetwork.loadobj は MAT からの読み込み後にパラメータのリスナーを再設定（層がまだ読み込み中なら警告 GUILDA:PowerNetwork:IncompleteLoad）

7. Extension points7. 拡張ポイント

  • Component: a class in +component with the constants key, sv_x, sv_u, sv_y, sv_para, and a constructor (index, parameter, opt) that calls the Component constructor with the tag and adds every sv_para to para_dynamics with add_entry. Run GUILDA again so that add_component knows the key
  • Branch: a class in +branch with the constants key and header and get_admittance_matrix. The constructor (index, opt) is inherited
  • Local controller: key "avr", "pss" or "local"; outputs named after the inputs they drive; inputs named after the outputs or states they observe ("Xall" / "Yall" need an override of set_inputs; resolve_ports may adapt the ports to the component)
  • Global controller: constructor (net, tag, units...) calling the GlobalController constructor. sv_u must be states and sv_y inputs of every unit
  • Network class: a PowerNetwork subclass in +network/@<Name>/ with the CSV folders, whose constructor calls PowerNetwork.import_csv(dir, Network=obj). net.export_csv(".../@<Name>") writes such a class
  • 機器: +component のクラス。定数 key・sv_x・sv_u・sv_y・sv_para と、タグを付けて Component のコンストラクタを呼び、すべての sv_para を add_entry で para_dynamics に加えるコンストラクタ (index, parameter, opt) を持つ。add_component がキーを認識するよう GUILDA を再実行
  • ブランチ: +branch のクラス。定数 key・header と get_admittance_matrix を持つ。コンストラクタ (index, opt) は継承
  • ローカル制御器: key は "avr"・"pss"・"local"。出力名は駆動する入力の名前、入力名は観測する出力または状態の名前（"Xall" / "Yall" には set_inputs のオーバーライドが必要。resolve_ports でポートを機器に合わせることも可能）
  • グローバル制御器: コンストラクタ (net, tag, units...) が GlobalController のコンストラクタを呼び出し。sv_u は各対象の状態、sv_y は入力であることが必要
  • ネットワーククラス: CSV フォルダを持つ +network/@<Name>/ の PowerNetwork サブクラス。コンストラクタが PowerNetwork.import_csv(dir, Network=obj) を呼び出し。net.export_csv(".../@<Name>") はこの形のクラスを書き出し
