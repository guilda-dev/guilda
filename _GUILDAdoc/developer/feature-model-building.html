Feature: Model Building機能: モデル構築

A network is a tree of handle objects. The parent's add_* method creates or attaches each child and sets the child's reference back to it; every change is reported up to the network, which records what became stale.

ネットワークはハンドルオブジェクトの木です。親の add_* メソッドが子を作成または接続し、子から親への参照を設定します。すべての変更はネットワークまで伝えられ、ネットワークが何が古くなったかを記録します。

1. Purpose and entry point1. 目的と入口

Model building produces a PowerNetwork with its buses, branches, components, local controllers and global controllers, and the power-flow, operation, OPF, dynamics and diagram parameters of each. It can be done by hand, by a shipped network class (network.IEEE9bus() and the other classes in _GUILDAobject/+network), or by import (see Data Import and Export).

モデル構築は、PowerNetwork と、その母線・ブランチ・機器・ローカル制御器・グローバル制御器、そしてそれぞれの潮流・operation・OPF・dynamics・図のパラメータを作ります。手で組み立てる方法、同梱のネットワーククラス（network.IEEE9bus() など _GUILDAobject/+network のクラス）を使う方法、読み込みによる方法（データの入出力参照）があります。

net = PowerNetwork("ThreeBus");
b1  = net.add_bus(V=1.0, Varg=0);
b2  = net.add_bus();
net.add_branch("pi", [b1.str_tag, b2.str_tag], R=0.01, X=0.085);
gen = b1.add_component("gen-1axis", P=0.5);
b2.add_component("load-power", P=-0.5, Q=-0.1);
gen.add_local_controller(controller.avr.AVR_ST1("avr1"), controller.pss.PSS1("pss1"));
b1.l_isSlack = true;

5. Side effects and caches5. 副作用とキャッシュ

  • Before the first initialize: the network's str_flag is "unset", so no row is added to tab_editLog and the equilibrium flag is not raised; handle_edit still keeps a single slack bus.
  • After initialize: an edit marked stale in Class Design: edit handling sets str_flag = "editted" and l_staleEquilibrium = true; simulate, linearize and get_sys then stop until initialize runs again. Operation, OPF, graph and tag edits are logged but leave the equilibrium valid.
  • Handle cache: constructors do not build f_* (str_odefcn = "unset"). Attaching (Component.set_bus, LocalController.set_parent, GlobalController.set_parent) and a dynamics or network Hz edit turn "updated" into "editted". check_edit at the start of the next analysis rebuilds them (see Initialization).
  • Detached objects: a removed object has no parent, so its later edits stop at it (log_edit returns) and do not reach the network.
  • Copies: there is no deep-copy method; b = a copies a handle. Save and load through a MAT file or CSV export for an independent network. PowerNetwork.loadobj attaches the parameter listeners again after a MAT load (warning GUILDA:PowerNetwork:IncompleteLoad when a layer is still loading).
  • 最初の initialize の前: ネットワークの str_flag は "unset" なので、tab_editLog に行は追加されず、平衡点のフラグも立ちません。handle_edit は slack 母線を 1 つに保ちます。
  • initialize の後: Class Design: 編集の扱いで古くなるとされる編集は str_flag = "editted"、l_staleEquilibrium = true にし、simulate・linearize・get_sys は再び initialize を実行するまで停止します。operation・OPF・graph・タグの編集は記録されますが、平衡点は有効なままです。
  • ハンドルキャッシュ: コンストラクタは f_* を作りません（str_odefcn = "unset"）。接続（Component.set_bus、LocalController.set_parent、GlobalController.set_parent）と、dynamics またはネットワークの Hz の編集は、"updated" を "editted" にします。次の解析の最初の check_edit が作り直します（初期化参照）。
  • 切り離されたオブジェクト: 削除されたオブジェクトには親がないので、その後の編集はそこで止まり（log_edit が戻る）、ネットワークには届きません。
  • コピー: ディープコピーのメソッドはありません。b = a はハンドルのコピーです。独立したネットワークが必要なら、MAT ファイルへの保存と読み込み、または CSV への書き出しを使います。PowerNetwork.loadobj は MAT からの読み込み後にパラメータのリスナーを付け直します（層がまだ読み込み中なら警告 GUILDA:PowerNetwork:IncompleteLoad）。

7. Extension points7. 拡張ポイント

  • Component: a class in +component with the constants key, sv_x, sv_u, sv_y, sv_para; a constructor (index, parameter, opt) that calls the Component constructor with the tag and adds every sv_para to para_dynamics with add_entry. Run GUILDA again so that add_component knows the key.
  • Branch: a class in +branch with the constants key and header and get_admittance_matrix; the constructor (index, opt) is inherited.
  • Local controller: key "avr", "pss" or "local"; outputs named after the inputs they drive; inputs named after the outputs or states they observe ("Xall" / "Yall" need an override of set_inputs; resolve_ports may adapt the ports to the component).
  • Global controller: constructor (net, tag, units...) calling the GlobalController constructor; sv_u must be states and sv_y inputs of every unit.
  • Network class: a PowerNetwork subclass in +network/@<Name>/ with the CSV folders, whose constructor calls PowerNetwork.import_csv(dir, Network=obj). net.export_csv(".../@<Name>") writes such a class.
  • 機器: +component のクラスで、定数 key・sv_x・sv_u・sv_y・sv_para を持ち、コンストラクタ (index, parameter, opt) がタグを付けて Component のコンストラクタを呼び、すべての sv_para を add_entry で para_dynamics に加えます。add_component がキーを認識するよう、GUILDA を再実行します。
  • ブランチ: +branch のクラスで、定数 key・header と get_admittance_matrix を持ちます。コンストラクタ (index, opt) は継承されます。
  • ローカル制御器: key は "avr"・"pss"・"local"。出力は駆動する入力の名前、入力は観測する出力または状態の名前にします（"Xall" / "Yall" には set_inputs のオーバーライドが必要。resolve_ports でポートを機器に合わせることもできます）。
  • グローバル制御器: コンストラクタ (net, tag, units...) が GlobalController のコンストラクタを呼びます。sv_u は各対象の状態、sv_y は入力でなければなりません。
  • ネットワーククラス: CSV フォルダを持つ +network/@<Name>/ の PowerNetwork サブクラスで、コンストラクタが PowerNetwork.import_csv(dir, Network=obj) を呼びます。net.export_csv(".../@<Name>") はこの形のクラスを書き出します。

Step-by-step instructions and the model contracts are in Model Implementation (steps, contracts, controller, branches and networks).

手順とモデルの約束は Model Implementation（手順、約束、制御器、ブランチとネットワーク）にあります。
