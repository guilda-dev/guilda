Model Building Feature Designモデル構築機能の設計

A network is a tree of handle objects. The parent's add_* method creates or attaches each child and sets the child's reference back to it; every change is reported up to the network, which records what became stale.

ネットワークは、ハンドルオブジェクトでできた木構造です。子を作ったりつないだりするのは親の add_* メソッドで、そのとき子から親への参照も設定します。どの変更もネットワークまで伝わり、何が古くなったかをネットワークが記録します。

1. What the feature does and how to call it1. 機能の目的と呼び出し方

Model building produces a PowerNetwork with its buses, branches, components, local controllers and global controllers, and the power-flow, operating-limit (operation), OPF, dynamics and diagram parameters of each. Three ways:

モデル構築で作るのは、PowerNetwork とその母線、ブランチ、機器、ローカル制御器、グローバル制御器です。それぞれが潮流、運転制約（operation）、OPF、dynamics、図のパラメータを持ちます。作り方は次の 3 通りです:

  • By hand
  • By a shipped network class (network.IEEE9bus() and the other classes in _GUILDAobject/+network)
  • By import (see Data Import and Export)
  • 手で組み立てる
  • 同梱のネットワーククラスを使う（network.IEEE9bus() など _GUILDAobject/+network のクラス）
  • ファイルから読み込む（データの入出力を参照）
net = PowerNetwork("ThreeBus");
b1  = net.add_bus(V=1.0, Varg=0);
b2  = net.add_bus();
net.add_branch("pi", [b1.s_tag, b2.s_tag], R=0.01, X=0.085);
gen = b1.add_component("gen-1axis", P=0.5);
b2.add_component("load-power", P=-0.5, Q=-0.1);
avr = gen.add_local_controller("avr-ST1", parameter=struct(kap=30));
pss = gen.add_local_controller("pss-PSS1");
b1.l_isSlack = true;

2. Call sequence between classes2. クラス間の呼び出し順

3. Processing steps in detail3. 処理ステップの詳細

  1. MB-01 caller呼び出し側 → PowerNetwork (constructor)（コンストラクタ）

    What it does処理内容
    • Set the tag
    • Set a_Parameter to the base container (Parameter(obj,"base") with Hz and baseMVA)
    • Call reset_solver: creates SolverPF, SolverOPF, SolverCPF, SolverODE and SolverLIN
    • Called implicitly by a network class such as network.IEEE9bus, so its tag is "PowerNetwork"
    • タグを設定します。
    • a_Parameter に base のコンテナ（Hz と baseMVA を持つ Parameter(obj,"base")）を設定します。
    • reset_solver を呼び出し、SolverPF・SolverOPF・SolverCPF・SolverODE・SolverLIN を作成します。
    • network.IEEE9bus などのネットワーククラスが暗黙に呼び出すので、タグの既定値を "PowerNetwork" にしています。
    What it reads読み取る情報
    tag, GUILDA.config("Model","Hz"), GUILDA.config of each solver（各ソルバー）
    Returns or changes戻り値・変更する値
    net with empty a_Bus, a_Branch, a_GlobalController (0×1 cell); sct_stale.powerflow and .odefcn = "initialize has not been run"（a_Bus・a_Branch・a_GlobalController は空の 0×1 cell。sct_stale.powerflow と .odefcn = "initialize has not been run"）

  2. MB-02 caller呼び出し側 → PowerNetwork.add_bus → Bus

    What it does処理内容
    • Tag: Tag + three digits (tools.next_tag_number: largest number in use + 1), or FullTag when given
    • Ignore the option baseMVA and remove it from the options (v3_bus_baseMVA)
    • Bus constructor (access: PowerNetwork, Bus): set a_PowerNetwork first, then the tag (a tag used by another bus gets a suffix)
    • Create four Parameter objects
    • Append the bus to a_Bus
    • タグは Tag + 3 桁（tools.next_tag_number: 使用中の最大番号 + 1）です。FullTag を指定した場合はそれを使います。
    • オプション baseMVA は無視し、オプションから削除します（v3_bus_baseMVA）。
    • Bus のコンストラクタ（呼び出せるのは PowerNetwork と Bus）は、先に a_PowerNetwork、次にタグを設定します（他の母線が使用中のタグには接尾辞を付けます）。
    • 4 つの Parameter を作成します。
    • 母線を a_Bus に追加します。
    What it reads読み取る情報
    options (defaults: V 1, Varg 0, Gshunt 0, Bshunt 0, Vmin 0.5, Vmax 1.5, baseKV 230, Xaxis/Yaxis NaN, Marker "s"), tags of a_Busオプション（既定値: V 1, Varg 0, Gshunt 0, Bshunt 0, Vmin 0.5, Vmax 1.5, baseKV 230, Xaxis/Yaxis NaN, Marker "s"）、a_Bus のタグ
    Returns or changes戻り値・変更する値
    bus; tab_parameter.dynamics (Gshunt, Bshunt), tab_parameter.operation (baseKV, Vmin, Vmax), tab_parameter.powerflow (V, Varg), tab_parameter.graph (Xaxis, Yaxis, Marker); edit編集 "Topology"

  3. MB-03 caller呼び出し側 → PowerNetwork.add_branch → Branch

    What it does処理内容
    • Before any change: check Key against the generated key list, resolve from_to (indices of a_Bus or tags), reject equal ends and R = X = 0
    • Create the class of the key (mkInst)
    • Branch constructor: set the tag header + three digits, assert real R, X, C, create three Parameter objects
    • Set bra.a_Bus = {from; to} and bra.a_PowerNetwork = net (writable only by PowerNetwork)
    • Append to a_Branch
    • 変更前に検査します。Key を生成済みのキー一覧で検査し、from_to（a_Bus の番号またはタグ）を解決し、両端が同じもの・R = X = 0 を拒否します。
    • キーのクラスを作成します（mkInst）。
    • Branch のコンストラクタは、タグ header + 3 桁を設定し、R・X・C が実数であることを assert し、3 つの Parameter を作成します。
    • bra.a_Bus = {from; to} と bra.a_PowerNetwork = net を代入します（書き込めるのは PowerNetwork だけです）。
    • a_Branch に追加します。
    What it reads読み取る情報
    options (defaults: R 0, X 1, C 0, Tap 1, Phase 0, Smax/Imax/Pmax/Qmax Inf, Vargmax π/2, Marker "-"), a_Bus, tags of a_Branchオプション（既定値: R 0, X 1, C 0, Tap 1, Phase 0, Smax/Imax/Pmax/Qmax Inf, Vargmax π/2, Marker "-"）、a_Bus、a_Branch のタグ
    Returns or changes戻り値・変更する値
    br; tab_parameter.dynamics (R, X, C, tap, phase), tab_parameter.operation (Smax, Imax, Pmax, Qmax, Vargmax), tab_parameter.graph (MidXaxis, MidYaxis, Marker); br.a_Bus (2×1 cell), br.a_PowerNetwork; edit編集 "Topology"

  4. MB-04 caller呼び出し側 → Bus.add_component → Component

    What it does処理内容
    • Tag: bus tag + class prefix + next number among the components of this bus (e.g. B001SG1)
    • Subclass constructor calls Component(s_tag, opt): creates five Parameter objects; replaces a NaN cost HP / fP by 0 for a load, 1 otherwise
    • Subclass adds sv_para to the dynamics container of a_Parameter
    • Generator: force Q = NaN
    • Set comp.a_Bus = bus (writable only by Bus), then report a "Topology" edit on the component (comp.log_edit("connected to <bus>", "Topology")): its equilibrium becomes stale; a new component already holds "initialize has not been run" in equilibrium and odefcn
    • Append to a_Component
    • タグは、母線のタグ + クラスの接頭辞 + この母線の機器の中での次の番号です（例: B001SG1）。
    • サブクラスのコンストラクタが Component(s_tag, opt) を呼び出します。5 つの Parameter を作成し、NaN のコスト HP / fP を負荷なら 0、それ以外は 1 に置き換えます。
    • サブクラスが sv_para を a_Parameter の dynamics コンテナに追加します。
    • 発電機では Q = NaN に固定します。
    • comp.a_Bus = bus を代入し（書き込めるのは Bus だけです）、機器の "Topology" の編集として報告します（comp.log_edit("connected to <bus>", "Topology")）。これで機器の equilibrium が古くなります。新しい機器は equilibrium と odefcn に "initialize has not been run" をすでに保持しています。
    • a_Component に追加します。
    What it reads読み取る情報
    options (P 0, Q 0, baseMVA 100, Pmin/Qmin −Inf, Pmax/Qmax Inf, OPF P0/Q0 0, HP/fP NaN, HQ/fQ 0, Marker "o"), parameter, class parameter.csvオプション（P 0, Q 0, baseMVA 100, Pmin/Qmin −Inf, Pmax/Qmax Inf, OPF P0/Q0 0, HP/fP NaN, HQ/fQ 0, Marker "o"）、parameter、クラスの parameter.csv
    Returns or changes戻り値・変更する値
    comp; tab_parameter.operation (baseMVA, Pmin, Pmax, Qmin, Qmax), tab_parameter.powerflow (P, Q), tab_parameter.OPF (P0, Q0, HP, HQ, fP, fQ, startup, shutdown), tab_parameter.graph, tab_parameter.dynamics; comp.a_Bus; sct_stale.equilibrium, .odefcn = "initialize has not been run"; edit編集 "Topology"

  5. MB-05 caller呼び出し側 → Component.add_local_controller → LocalController.resolve_observe

    What it does処理内容
    • Build one controller per call: the class of Key (checked against the generated key list) with the constructor (tag, Name=Value); parameter (struct or one-row table) gives the Name=Value, omitted ones keep the class defaults
    • Tag: component tag + class header + next number among the controllers of this component (nested ones included), e.g. B001SG1CA1 (header CA AVR, CP PSS, CG governor, CL LQR)
    • Check the new controller before any change:
      • role s_role "avr", "pss", "local" or "governor"
      • outputs sv_y match inputs of the target (the component, or the AVR for a PSS)
      • the AVR or "local" controller and the governor drive different inputs (GUILDA:Component:ControllerOutputOverlap)
    • s_role decides the slot:
      • AVR or "local" controller: becomes a_LocalController{1}; an existing one is deleted with a warning, and its PSS moves to a new AVR (deleted when the new controller is not an AVR)
      • PSS: goes under the AVR
      • Governor: placed after the AVR in a_LocalController; an existing governor is deleted with a warning
    • Attach: set con.a_Component (writable only by Component and LocalController), resolve the observed signals (resolve_observe: expand "Xall" / "Yall", set iv_obsY / iv_obsX), report a "Topology" edit on the controller ("attached to <parent>"): its equilibrium becomes stale. A replaced controller is deleted (tools.delete_layers)
    • When a global controller controls the component: compare the "global" rows of the connection map (net.get_variable_map()) before and after the edit, and list the outputs that go elsewhere now in an INFO message (GUILDA:Component:GconRouteChanged; -> (no input) when none)
    • Return the new controller
    • 1 回の呼び出しで制御器を 1 つ作成します。Key（生成済みのキー一覧で検査）のクラスをコンストラクタ (tag, Name=Value) で作成します。Name=Value は parameter（struct または 1 行の table）から取り、省略したものはクラスの既定値になります。
    • タグは、機器のタグ + クラスの接頭辞 + この機器の制御器（入れ子も含む）の中での次の番号です（例: B001SG1CA1。接頭辞は AVR CA、PSS CP、ガバナ CG、LQR CL）。
    • 変更する前に、新しい制御器が次の条件を満たすか検査します:
      • 役割 s_role が "avr"・"pss"・"local"・"governor" のいずれかであること
      • 出力 sv_y が接続先（機器、PSS なら AVR）の入力と一致すること
      • AVR または "local" の制御器とガバナが異なる入力を駆動すること（GUILDA:Component:ControllerOutputOverlap）
    • 配置先は s_role で決まります:
      • AVR・"local" の制御器: a_LocalController{1} に配置します。既存のものは警告を出して削除し、その PSS は新しい AVR へ移します（新しい制御器が AVR でなければ削除します）。
      • PSS: AVR の下に配置します。
      • ガバナ: a_LocalController で AVR の後ろに配置します。既存のガバナは警告を出して削除します。
    • 接続では、con.a_Component を代入し（書き込めるのは Component と LocalController だけです）、観測する信号を解決し（resolve_observe: "Xall" / "Yall" を展開し、iv_obsY / iv_obsX を設定）、制御器の "Topology" の編集として報告します（"attached to <parent>"）。これで制御器の equilibrium が古くなります。置き換えた制御器は削除します（tools.delete_layers）。
    • グローバル制御器がこの機器を制御する場合: 接続マップ（net.get_variable_map()）の "global" の行を編集の前後で比較し、接続先が変わった出力を INFO で表示します（GUILDA:Component:GconRouteChanged。接続先がなければ -> (no input)）。
    • 新しい制御器を返します。
    What it reads読み取る情報
    Key, parameter, tags of the controllers of compcomp の制御器のタグ, con.s_role, con.sv_y, con.sv_u, comp.sv_u, comp.sv_x, comp.sv_y
    Returns or changes戻り値・変更する値
    con; comp.a_LocalController, avr.a_LocalController, con.a_Component, comp.l_hasController; edit編集 "Topology" per controller（制御器ごと）

  6. MB-06 caller呼び出し側 → PowerNetwork.add_global_controller → GlobalController (subclass constructor)（サブクラスのコンストラクタ）

    What it does処理内容
    • Build one controller per call: the class of Key (checked against the generated key list) with the constructor (net, tag, units..., Name=Value); parameter (struct or one-row table) gives the Name=Value, omitted ones keep the class defaults
    • Tag: network tag + class header + next number among the global controllers of this network, e.g. IEEE9busAGC1
    • Resolve each controlled unit of a_Unit (component object or tag) among the components of net.a_Bus
    • Network only read: a_PowerNetwork stays empty until MB-07
    • 1 回の呼び出しで制御器を 1 つ作成します。Key（生成済みのキー一覧で検査）のクラスをコンストラクタ (net, tag, units..., Name=Value) で作成します。Name=Value は parameter（struct または 1 行の table）から取り、省略したものはクラスの既定値になります。
    • タグは、ネットワークのタグ + クラスの接頭辞 + このネットワークのグローバル制御器の中での次の番号です（例: IEEE9busAGC1）。
    • a_Unit の制御対象（機器のオブジェクトまたはタグ）を net.a_Bus の機器から解決します。
    • ここではネットワークを読むだけで、a_PowerNetwork は MB-07 まで空のままです。
    What it reads読み取る情報
    Key, a_Unit, parameter, tags of net.a_GlobalControllernet.a_GlobalController のタグ, net.a_Bus{:}.a_Component
    Returns or changes戻り値・変更する値
    gc; gc.controlledUnits (cell of components)（機器の cell）, tab_parameter.dynamics (rows named by controlledUnits)（行名は controlledUnits）

  7. MB-07 PowerNetwork.add_global_controller → GlobalController.log_edit

    What it does処理内容
    • Check:
      • the tag is unused
      • every unit belongs to this network (handle comparison through unit.a_Bus.a_PowerNetwork)
    • Append the controller
    • Set gc.a_PowerNetwork = net (writable only by PowerNetwork)
    • Check in the connection map of net.get_variable_map() that, for every unit, each input of the controller has an "observe" connection (an output or state of the unit) and each output a "global" connection (an input of a local controller of the unit, else of the unit); otherwise remove the controller again and stop with GUILDA:PowerNetwork:GconPorts
    • Report a "Topology" edit on the controller (not on the network): its equilibrium becomes stale, the power flow stays up to date
    • Show the "global" connections of the controller as Source -> Target (labels) in an INFO message (GUILDA:PowerNetwork:GconRoute); nothing is stored on the controller
    • Return the controller
    • 次の条件を満たすか検査します:
      • タグが未使用であること
      • すべての制御対象がこのネットワークに所属していること（unit.a_Bus.a_PowerNetwork によるハンドル比較）
    • 制御器を追加します。
    • gc.a_PowerNetwork = net を代入します（書き込めるのは PowerNetwork だけです）。
    • net.get_variable_map() の接続マップで、各対象について制御器の各入力に "observe" の接続（対象の出力または状態）、各出力に "global" の接続（対象のローカル制御器の入力、ない場合は対象の入力）があるか確認します。なければ制御器を外して GUILDA:PowerNetwork:GconPorts で停止します。
    • 制御器（ネットワークではない）の "Topology" の編集として報告します。制御器の equilibrium が古くなり、潮流は最新のままです。
    • 制御器の "global" の接続を Source -> Target（ラベル）で INFO に表示します（GUILDA:PowerNetwork:GconRoute）。制御器には保存しません。
    • 制御器を返します。
    What it reads読み取る情報
    gc.s_tag, gc.controlledUnits, gc.sv_u, gc.sv_y, net.get_variable_map() (tab, c_idxGC, tab_connection)
    Returns or changes戻り値・変更する値
    gc; net.a_GlobalController, gc.a_PowerNetwork, gc.sct_stale; edit編集 "Topology"

  8. MB-08 caller呼び出し側 → Bus.set.l_isSlack

    What it does処理内容
    • No-op when the value is unchanged
    • true: needs a component
    • Print the component that takes the remaining power (the first with Q = NaN, else the first)
    • Warn when no component has Q = NaN
    • Log a "Slack" edit
    • PowerNetwork.handle_edit: set l_isSlack = false on every other bus, so at most one slack bus
    • 値が変わらなければ何もしません。
    • true にするには機器が必要です。
    • 残りの電力を受け持つ機器（Q = NaN の最初の機器、なければ最初の機器）を表示します。
    • Q = NaN の機器がなければ警告します。
    • "Slack" の編集を記録します。
    • PowerNetwork.handle_edit: 他のすべての母線を l_isSlack = false に設定します。slack 母線は高々 1 つです。
    What it reads読み取る情報
    a_Component, component機器の tab_parameter.powerflow.Q, other buses他の母線の l_isSlack
    Returns or changes戻り値・変更する値
    l_isSlack of this and other buses（この母線と他の母線）; edit編集 "Slack"

  9. MB-09 caller呼び出し側 → Parameter (set method of tab_parameter)（tab_parameter の set メソッド）

    What it does処理内容
    • obj.tab_parameter = tab (PowerSystemModel): each column goes to the container of a_Parameter whose s_tag is the column name; an unknown column is an error (GUILDA:PowerSystemModel:UnknownParameterGroup) and nothing is written
    • obj.tab_parameter.<group>.<name> = v: reads the table and writes it back, so only that value changes
    • Parameter.set.tab_parameter: the stored table and the new one must have the same parameter names (any order), height and row names, else GUILDA:Parameter:TableMismatch
    • A column is changed when isequaln fails or its class differs; a changed class is GUILDA:Parameter:ClassNameMismatch
    • Every column is checked before anything is stored: an error stores nothing and logs nothing
    • Stores the new table, then calls log_edit for each changed column, in column order
    • obj.tab_parameter = tab（PowerSystemModel）: 各列を s_tag が列名と同じ a_Parameter のコンテナへ書き込みます。未知の列はエラー（GUILDA:PowerSystemModel:UnknownParameterGroup）となり、何も書き込みません。
    • obj.tab_parameter.<group>.<name> = v: 表を読んで書き戻すため、変わるのはその値だけです。
    • Parameter.set.tab_parameter: 保持する表と新しい表で、パラメータ名（順序は問いません）、行数、行名が同じである必要があります。違えば GUILDA:Parameter:TableMismatch になります。
    • isequaln が偽、またはクラスが違う列を変更とみなします。クラスの変更は GUILDA:Parameter:ClassNameMismatch になります。
    • 保存の前にすべての列を検査します。エラーなら保存も記録もしません。
    • 新しい表を保存し、変わった列ごとに列の順で log_edit を呼び出します。
    What it reads読み取る情報

5. Side effects on the model and caches5. モデルへの副作用とキャッシュ

  • Before the first initialize: every stale tag holds "initialize has not been run" from the constructor, so edits add no message. handle_edit still keeps a single slack bus
  • After initialize: an edit marked stale in Class Design: Handling of model edits appends its message to the stale tags it affects; simulate and get_sys then stop with their stale errors (e.g. GUILDA:PowerNetwork:SimulateStale) until initialize runs again. Operation, OPF, graph and tag edits: nothing stale
  • Handle cache: constructors do not build f_* (they stay empty). initialize builds the stale ones (set_odefcn, see Initialization); analyses only check, and nothing else builds handles. After an edit without initialize, a get_sys at a given point uses the previous ones
  • Removed objects: the removal is a "Topology" edit of the parent (a removed global controller: nothing), and the removed object is deleted (Class Design: parent references), so it cannot be edited or attached again; add_* builds a new one
  • Copies: no deep-copy method; b = a copies a handle. For an independent network, save and load through a MAT file or CSV export. A loaded network, or a lower layer saved alone, keeps its parameter tables, so its edits are checked and logged as before saving
  • 最初の initialize の前: すべての stale タグがコンストラクタの "initialize has not been run" を保持するため、編集はメッセージを追加しません。handle_edit は slack 母線を 1 つに保ちます。
  • initialize の後: クラス設計: モデル編集の扱いで古くなるとされる編集は、影響する stale タグにメッセージを追加します。simulate・get_sys は、再び initialize を実行するまでそれぞれの stale のエラー（例: GUILDA:PowerNetwork:SimulateStale）で停止します。operation・OPF・graph・タグの編集は何も古くしません。
  • ハンドルキャッシュ: コンストラクタは f_* を作りません（空のままです）。古いものは initialize が作成し（set_odefcn、初期化を参照）、解析は確認するだけで、ほかにハンドルを作るものはありません。initialize を挟まない編集の後、点を与えた get_sys は以前のハンドルを使います。
  • 削除したオブジェクト: 削除は親の "Topology" の編集です（グローバル制御器の削除では編集はありません）。削除したオブジェクトは delete されるため（クラス設計: 親への参照）、編集も再接続もできません。add_* で新しく作成します。
  • コピー: ディープコピーのメソッドはありません。b = a はハンドルのコピーです。独立したネットワークには、MAT ファイルへの保存と読み込み、または CSV への書き出しを使います。読み込んだネットワークや単独で保存した下の層もパラメータの表を保持し、編集の検査と記録は保存前と同じです。

7. Where to extend the feature7. 機能を拡張する箇所

  • Component: a class in +component with the constants key, sv_x, sv_u, sv_y, sv_para, and a constructor (index, parameter, opt) that calls the Component constructor with the tag and replaces the dynamics container with one that holds every sv_para (obj.a_Parameter{cellfun(@(p) p.s_tag=="dynamics", obj.a_Parameter)} = Parameter(obj, "dynamics", sct), sct: a struct of the defaults), declared with Access={?Bus}. Run GUILDA again so that add_component knows the key
  • Branch: a class in +branch with the constants key and header and get_admittance_matrix, and a constructor (index, opt) with Access={?PowerNetwork} that calls the Branch constructor
  • Local controller: the constant key, the model key of a concrete class (e.g. "avr-ST1"), and the constant s_role "avr", "pss", "local" or "governor", which decides where it goes; a constructor (tag, Name=Value) with Access={?Component}; outputs named after the inputs they drive; inputs named after the outputs or states they observe ("Xall" / "Yall" need an override of set_inputs; resolve_ports may adapt the ports to the component). Run GUILDA again so that add_local_controller knows the key
  • Global controller: the constants key (model key, e.g. "agc-PI") and s_role (e.g. "agc"); constructor (net, tag, units..., Name=Value) with Access={?PowerNetwork}, calling the GlobalController constructor. sv_u must be outputs or states of every unit, and sv_y inputs of every unit or of one of its local controllers. Run GUILDA again so that add_global_controller knows the key
  • Network class: a PowerNetwork subclass in +network/@<Name>/ with the CSV folders, whose constructor calls PowerNetwork.import(dir, Network=obj). net.export(".../@<Name>") writes such a class
  • 機器: +component のクラスです。定数 key・sv_x・sv_u・sv_y・sv_para と、タグを付けて Component のコンストラクタを呼び、すべての sv_para を持つ dynamics コンテナに置き換えるコンストラクタ（obj.a_Parameter{cellfun(@(p) p.s_tag=="dynamics", obj.a_Parameter)} = Parameter(obj, "dynamics", sct)、sct は既定値の struct） (index, parameter, opt) を Access={?Bus} で持ちます。add_component がキーを認識するよう GUILDA を再実行します。
  • ブランチ: +branch のクラスです。定数 key・header と get_admittance_matrix、Branch のコンストラクタを呼ぶコンストラクタ (index, opt) を Access={?PowerNetwork} で持ちます。
  • ローカル制御器: 定数 key は具象クラスのモデルのキー（例: "avr-ST1"）、定数 s_role は配置先を決める役割 "avr"・"pss"・"local"・"governor" です。コンストラクタは (tag, Name=Value) で、Access={?Component} にします。出力名は駆動する入力の名前、入力名は観測する出力または状態の名前です（"Xall" / "Yall" には set_inputs のオーバーライドが必要です。resolve_ports でポートを機器に合わせることもできます）。add_local_controller がキーを認識するよう GUILDA を再実行します。
  • グローバル制御器: 定数 key（モデルのキー、例: "agc-PI"）と s_role（例: "agc"）を持ちます。コンストラクタ (net, tag, units..., Name=Value) は Access={?PowerNetwork} で、GlobalController のコンストラクタを呼び出します。sv_u は各対象の出力または状態、sv_y は各対象またはそのローカル制御器の入力である必要があります。add_global_controller がキーを認識するよう GUILDA を再実行します。
  • ネットワーククラス: CSV フォルダを持つ +network/@<Name>/ の PowerNetwork サブクラスです。コンストラクタが PowerNetwork.import(dir, Network=obj) を呼び出します。net.export(".../@<Name>") はこの形のクラスを書き出します。
