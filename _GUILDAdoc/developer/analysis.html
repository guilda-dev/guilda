Analysis Flows解析の流れ

What a user does with GUILDA, and which classes each analysis passes through. Every analysis has the same shape: net.verb_noun() → solver → result, returned as [result, flag, output].

ユーザーが GUILDA で行うことと、各解析が通るクラスを示します。どの解析も net.verb_noun() → ソルバー → 結果という同じ形で、[result, flag, output] を返します。

Use casesユースケース

Common call sequence共通の呼び出し順

  • result is a subclass of ResultBase. It also keeps flag, output, the effective options and l_success, so the result alone tells how the run went.
  • result は ResultBase のサブクラスです。flag、output、実際の options、l_success も保持するため、結果だけで実行の様子が分かります。
  • Only initialize and the add_ / remove_ / replace_ / set_ methods change the model; the analyses leave it as it was, also after an error.
  • モデルを変えるのは initialize と add_ / remove_ / replace_ / set_ のメソッドだけです。解析はエラーの後もモデルを変えません。
  • The rules behind this shape: Analysis API rules. Where to look when a step fails: Debugging Guide.
  • この形の規則は解析 API の規則に、段階が失敗したときに見る場所はデバッグガイドにあります。

Building a modelモデルの構築

  • Build in code with net.add_bus, net.add_branch, bus.add_component, comp.add_local_controller and net.add_global_controller, each taking a model key; or load a folder with PowerNetwork.import(path) (MATPOWER: PowerNetwork.import_matpower) and write one with net.export(path).
  • コードでは net.add_bus、net.add_branch、bus.add_component、comp.add_local_controller、net.add_global_controller にモデルキーを渡して組み立てます。フォルダからは PowerNetwork.import(path)（MATPOWER は PowerNetwork.import_matpower）で読み込み、net.export(path) で書き出します。
  • The model keys are read from the classes into GUILDA.keymap; an unknown key is rejected before anything changes.
  • モデルキーはクラスから GUILDA.keymap に読み込まれます。未知のキーは何も変更する前に拒否されます。
  • The user sets the slack bus (bus.l_isSlack = true). A model can be inspected in a window with net.launch_gui().
  • スラック母線はユーザーが設定します（bus.l_isSlack = true）。モデルは net.launch_gui() のウィンドウでも確かめられます。

Power flow潮流計算

  • SolverPF receives only the admittance matrix and the bus conditions; Solver= chooses the algorithm class (Method*). Format= can return voltages or an array instead of ResultPF.
  • SolverPF が受け取るのはアドミタンス行列と母線の条件だけです。Solver= で解法のクラス（Method*）を選びます。Format= を使うと ResultPF の代わりに電圧や配列を返します。

Initialization初期化

  • The only analysis that writes to the model. It solves only what is stale (or what Method= asks for) and clears the stale state at the end; a failure stops with an error and leaves the model unchanged.
  • モデルに書き込む唯一の解析です。古くなった部分（または Method= で指定したもの）だけを解き、最後に古い状態を消します。失敗するとエラーで止まり、モデルは変わりません。
  • Simulation, linearization and the continuation power flow need it first.
  • シミュレーション、近似線形化、連続潮流計算の前に必要です。

Time-domain simulation時間応答シミュレーション

  • One scenario per run, chosen by its tag (net.add_scenario(tag)). Its events (Event*) split the run into phases.
  • 1 回の実行で 1 つのシナリオを、タグで選んで使います（net.add_scenario(tag)）。シナリオのイベント（Event*）が実行を区間に分けます。
  • SolverODE reads only the data of the run, never a model object; the result keeps a snapshot struct(net, false).
  • SolverODE は実行用のデータだけを読み、モデルのオブジェクトは読みません。結果はスナップショット struct(net, false) を保持します。

Linearization近似線形化

  • get_sys exists on every layer (network, bus, component, controller) with the same meaning. The point is the equilibrium by default, or any state, or a time of a simulation result.
  • get_sys はどの層（ネットワーク、母線、機器、制御器）にも同じ意味で存在します。線形化の点は既定で平衡点ですが、任意の状態やシミュレーション結果の時刻も指定できます。
  • ResultLIN keeps the unreduced model in the order of get_variable_map; Type="ODE" | "DAE" and get_ss give the state-space form.
  • ResultLIN は縮約前のモデルを get_variable_map の順で保持します。状態空間表現は Type="ODE" | "DAE" と get_ss で得ます。

Optimal power flow最適潮流計算

  • The model holds parameters only. User costs and constraints are call options (Cost, Constraint); a problem built by net.build_opf_problem can be edited and passed back with Problem=.
  • モデルが持つのはパラメータだけです。ユーザーのコストと制約は呼び出しのオプション（Cost、Constraint）です。net.build_opf_problem で作った問題を編集し、Problem= で渡すこともできます。

Continuation power flow連続潮流計算

  • The buses whose load is scaled are the condition LoadBus kept by net.solver_CPF. flag is true when the path passed the nose.
  • 負荷を増やす母線は net.solver_CPF が保持する条件 LoadBus です。flag は解曲線がノーズを越えたときに true です。

Plotting描画

  • Every plot_* returns a graph object (a subclass of GraphBase); styles, playback and video export go through that object. A result can also be opened in a window with result.launch_gui().
  • plot_* はすべて図のオブジェクト（GraphBase のサブクラス）を返します。スタイル、再生、動画の書き出しはそのオブジェクトを通して行います。結果は result.launch_gui() でウィンドウに開くこともできます。
