Naming Conventions in GUILDA

Variable naming follows [variableType][size]_[variableDescription].

Example: lv_faultflag, cv_SGvoltage, lm_xresponse

Variable Type (1st Prefix Token)

  • c: complex
  • r: real
  • l: logical
  • s: string
  • f: function handle (cell array if the variable itself is an array)
  • i: index
  • n: count

Size (2nd Prefix Token)

  • (none): scalar
  • v: column vector
  • r: row vector
  • m: matrix

Naming Composition Examples

  • cv_Vequilibrium: [c: complex] + [v: column vector] + [_Vequilibrium] — a complex-valued vector of equilibrium voltages
  • im_solution: [i: index] + [m: matrix] + [_solution] — a matrix of indices for an analysis result
  • r_gain: [r: real] + [(none): scalar] + [_gain]

Exceptional Naming Rules (Fixed Prefixes)

  • Table type: tab_ + [variable description], regardless of argument or output count (e.g., tab_bus_data)
  • GUILDA-specific class (cell array): a_ + [ClassName] (e.g., a_Controller)
  • Parameter class: para_ + [data description], only for properties holding GUILDA's Parameter class (e.g., para_generator)
